## 0.1.0-beta.18 (2026-10-19)

- The gallery opens a recorded run in a chat + report view (`apps/viewer/chat.html?r=<id>`): the run's recorded conversations on the left, the agent's report on the right. The inspection replay is one link away, "How this ran" (`./?r=<id>`).
  The left side is made from the recording's generic events, the same for every run: the run's input as given as the user's message, then each conversation as a thread (its messages as recorded without the prompt the host composed to open it, the assistant's text as bubbles between the cards, the run's own thinking folded, one card per tool call titled by the tool and its arguments, consecutive calls of one tool showing the first three, and under each tool card every model call it made as its own card with its scores, the boxes it drew and its raw output, a judge's calls marked with the judge's accent), and a session timeline of workflow nodes, LLM calls, tool calls and the model calls a tool makes, nested under it and labelled as their cards.
  The right side is the agent's own artifact when the recording carries one (`manifest.artifact`), shown in a frame that runs no script, its citations opening the cited page or frame with its region boxed; otherwise the run's cited answer, or the result record it submitted, labelled as the answer; otherwise its final assistant text.
  The view shows no counters, costs, process or kill markers, and no thinking the run did not record.
- The Jev runner honours `Retry-After` on HTTP 429 and 503. It waits the larger of the server's time and its own backoff, never past the request's timeout or its abort signal, and gives up at once when the server asks for longer than is left. A request still rate-limited after its retries ends as before: `JevError` with code `http` and status 429.
- **`apps/viewer`: the gallery and a replay's header name no process or kill**
  - The killed and resumed reference job (`ten-kills-seed21`) leaves the gallery and is kept with the test fixtures
    (`apps/viewer/test/fixtures/`), where the tests that read a killed run beside the clean one find it.
  - The gallery's line reads "Replays a run recorded as agentrun.recording/1.", each run in its list is followed by its
    model alone, and a replay's header no longer counts processes and kills. The counters stay under `?debug=durability`.
- The vision agent example (`examples/vision-agent`) with a gateway set (`VIDEO_MODEL_BASE_URL`) now reaches an Anthropic lead or eyes model over Anthropic's own Messages API at the gateway's root (`/v1/messages`), under the gateway's key, instead of over chat completions. Through chat completions the gateway answered with thinking off (0 reasoning tokens, no reasoning field); over the Messages API the agent node's `thinking` level (medium) is Anthropic's adaptive thinking at that effort, and the model's thinking comes back as thinking blocks when it thinks (adaptive thinking is the model's choice at that effort: on a live probe Sonnet 5.5 returned a thinking block at `high` and none at `medium`). A gateway that serves an Anthropic model only on its OpenAI-compatible endpoints must also serve `/v1/messages` for it. `--thinking low|medium|high` sets the agent node's thinking for a run (the default stays `medium`; any other value, or an input it cannot be put in (a file, a capture name, none), is refused before anything starts), which is how a Claude lead is asked to think at `high`. OpenAI and Google models, and runs on a provider's own key, are unchanged.
- The vision agent example (`examples/vision-agent`) finds its example folder as the one argument that is neither a flag nor the value of a flag that takes one, so `npm run demo:vision -- --live examples/document-check` asks that folder's question over its files instead of silently running the default question over none. The flags that take a value are the host's string options and `--thinking`; a test holds the list to the host's. A second folder, a stray token, or a folder that is not an example is refused before anything starts, with one line and nothing written, where it used to be skipped or to end in a stack trace.
- On fakes, the vision agent's scripted lead looks at a first file that is a still image (PNG, JPEG, WebP or GIF) as it is, and cites the image itself. Before, it read any file that was not a PDF as a film and asked for its frame at second 1, which a still image does not have, so a free `examples/lake-mead` run stopped with "the model did not answer". PDFs and films are read as before.
- The vision agent example (`examples/vision-agent`) with a gateway set (`VIDEO_MODEL_BASE_URL`) no longer asks for `TYPESAFE_API_KEY`: Jev goes through the gateway's `/typesafe`, so its key is `TYPESAFE_API_KEY` when given and the gateway's `VIDEO_MODEL_API_KEY` otherwise; without a gateway `TYPESAFE_API_KEY` is still required. A live run now checks every key before it starts anything, naming each one that is missing and what it is for (`--live is missing TYPESAFE_API_KEY (typesafe.ai: ...); OPENAI_API_KEY (the lead openai/gpt-6-luna)`), and stops with a failing code, a message and nothing written: no recording, no run directory and no `cost: unknown` line, where it used to start the recorder first and leave a recording of the refusal behind. `demo.json`, the README and the setup prompt say the same. The scripted lead of a run on fakes now writes its report as `report/index.html`, the name the report skill gives a live run's, and the instructions of a package without the skill name it too.
- The vision agent example reads the report page its answer names only from under `work/report/`. A path that leaves `report/`, by its parts or through a link (`report/` itself, a folder in it, or the page), gives the record it gives for a missing page, with a note on the answer's row that says why, and nothing it names is read or kept. A file in `report/` that is a link is not kept with the report. The Answer schema refuses a report path with a `.` or `..` part.
- Two more questions for the vision agent, each a folder with no code: `examples/lake-mead` (thirteen Landsat images of Lake Mead, 1984 to 2024, committed; when the water fell most and every shoreline it left, boxed and dated) and `examples/market-street` (the 1906 film down Market Street from the Library of Congress, fetched by URL; every vehicle that crosses in front of the camera, to the second, boxed and counted). `ASSETS.md` records each source and its licence as the source page states it.

Off by default; the sandbox has no network, process or file access of its own, and a command it runs can do what the environment's shell can.
  The repository now declares `@earendil-works/pi-codemode` as a root devDependency, the one extra install code mode needs.
- The supervisor writes `delegation` host lines from `place.status()`'s `delegations` when one appears or its orphaned or pending state changes, and a `revoke` line from `recover()`'s `{ revoked, ms }`; a place without them writes none.
  The supervisor writes a `box.receipt` host line for each box `place.status().boxes` reports once its `to` appears (or at the final read): the box as a `box-N` label, seconds, the published per-second price and the cost (null with no price), the source and whether it was priced; never the provider's id. A place that reports none writes none.
  The example's cost (`examples/reference/fold.ts`) counts each `box.receipt`'s `cost_usd` once per box label; a receipt with none (an unpriced box, or one still open at the final read) makes the cost unknown, never 0.
- The reference entry takes `Fakes.input` (the no-key default input, a smaller slice than the job's own; `--input` wins), reports the models the live parts chose (`LiveParts.models`, handed to `manifest()` as `models`, so a demo needs no file handshake between its two hooks), and prints why a child stopped in the summary.
  A demo's vision lane, `fakes.vision(host, running, { input })` and the live parts' `vision(host, running, { input })`, is handed the input the run was given (`--input`, else the mode's default), so scripted eyes need not read the entry's environment.

- `models.judge.caps` in demo.json (`{ requests, tokens }`, each a positive integer at most 4 times the default of 50 and 40,000) sets the demo's own Jev caps; a value past the ceiling is refused at load, the run still refuses past the caps and `--max-usd` still applies. A demo that names `models.judge` (Jev) without a `keys` group for `TYPESAFE_API_KEY` or `OPENROUTER_API_KEY` is refused at load, naming the group to add.
- A `--kill` with `n` counts every crossing of its point and lands at the first eligible one at or after the nth (not while a tool call is between its dispatch and its kept answer), so it always lands when the run reaches the point n times or more; the kill line's `crossing.n` is the ordinal it landed on, `DemoResult.kills` carries `n` and `planned`, and the summary says `planned n=10, landed at n=12` when they differ.
- The place answers where a kill request is written (`Place.requestFile(attempt)`), and the child writes it durably (a synced temporary file, renamed, the directory synced). The supervisor mints a random nonce for each attempt (`KILL_NONCE`, which the child reads once and removes from its environment) and honors a request only with that nonce, writing a `kill.request.ignored` host line for one without it. One fresh run id per invocation (`<demo name>-<8 hex>`, `DemoResult.runId`) reaches the place as `paths.id` and the child as `RUN_ID`, so a second run of one demo on a shared disk never finds the first's run or signals.
- A reference kill takes `where: { field: value }`: it fires only at an announced crossing whose info has those values (`cross(point, { info })`, which the crossing log records), and composes with `n` as the nth matching crossing. `transport.tool.started` fires for every tool, so `{ point: "transport.tool.started", where: { tool: "install" } }` lands on the install step. A storm takes no `where`.
- A `--live` run's judge and model have the crossings the fakes' have (`judge.asked <label>`, `judge.answered <label>`, `model.request turn <n>`, `model.answered turn <n>`, the same names and counting), so a kill lands before a paid question or request is sent, or after its answer and before the run keeps it, and the resume pays the judge once (a kill does not cut a request while the provider has it outstanding).
- `--record` follows the run: `events.jsonl` is appended to as the lines arrive (whole lines, section 3's order, a memo after its commit is complete), blobs are written whole before any line names them, and the manifest is last, so a viewer in follow mode reads a live run and its replay as one file; the finished file equals a fresh export. The manifest's `job` blob is always written when the entry knows the job.

On fakes nothing changes.
- `--operator-kill <file>`: a control file the supervisor watches. When it appears while a process runs, the supervisor removes it, writes a `kill` host line (`crossing` null, label `operator`), kills through the place and resumes as usual; a kill still planned for the ended attempt moves to the next.
- The reference entry has a place seam: `demo({ place })` takes a `Place` (where the session lives and how its process starts, stops and restarts), and `localPlace` is the child process of this machine. The supervisor decides when to kill and writes the kill line first; the place decides how. A place whose runner opens a claim is handed a fresh mount token on the runner's standard input for each attempt, never in argv or env, and a place that cannot lose its machine refuses a box kill.

The supervisor hands every order `RECORD_STARTED` (the recording's clock) and `RECORD_GEN`; the child's recorder syncs its spool, rolls it into 1 MB segments, and redacts its own machine's host name and boot id with no sign-in file.

- Use the optional Jev adapter for typed decisions or the Pi extension to author and run workflows with the active Pi model.
- Run the support quickstart without credentials, then connect the same workflow to your own tools, Jev and agent runtime.

Live Pi demos keep status and cancellation commands responsive. Support example failures preserve the original error and eventual tool outcome for host reconciliation while keeping JSON reports redacted. Dry-run accepts valid empty-only output schemas.

Code and documentation use Apache-2.0. All three packages are available on npm under the `beta` tag. Pi workflows are session-local; durable storage and external delivery belong to the host. See [compatibility](docs/compatibility.md) and [execution limits](docs/guide.md#limits).
