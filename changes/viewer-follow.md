The run viewer follows a run while it goes (`apps/viewer`, `?follow=<url>`): given a recording directory served over HTTP that grows (`events.jsonl` gaining whole lines, read from the last byte with a `Range` request; each blob in `blobs/` before a line names it; `manifest.json` written last, once the run finished), it reads what is new about once a second, places it in the format's file order (the order a recorder's merge writes), and redraws every panel keeping the reader's place, with the time cursor on the newest line unless the reader scrubbed back. Kills and later processes arrive as lines like any other, and a file the writer replaced whole is read again from its start. While the run goes, its cost reads unknown and a blob not read yet shows as loading; a URL on another server is refused. When the manifest appears, the page reads the file whole, as a fresh load does, checks it against the format, and plays it as any recording. A panel's view is told when the run it draws is still going (`ViewContext.following`).
