Render: releasing or listing a computer no longer depends on its sandbox answering. When a server doesn't already know a sandbox's labels (after a restart, or in another process), it reads them from a file inside the sandbox, and that read is now held to the call's own time limit. A read that fails or gets no answer gives the two labels the sandbox's name carries, so release still finds and terminates a wedged sandbox instead of leaving it to bill until its timeout. A listing reads at most 4 files at once, and one failed read no longer fails the whole listing: that sandbox carries its name's labels, so a listing by its name still finds it, while a listing by any other label leaves it out. A sandbox that Render still reads as running just after its terminate is no longer read through its guest, so release settles. The server forgets a sandbox's labels once Render reads it terminated or not found, or once a whole listing no longer shows it. Sandbox ids are sent encoded in paths instead of being held to the `sbx-…` form, so a sandbox whose id has a new form is still terminated. `prepareImage()` calls that run at the same time share one import, and a build of the box image that is still pending or running is waited for instead of being imported again.
