Render: releasing a computer no longer depends on its sandbox answering, and one run's listing no longer depends on another run's sandbox. When a server doesn't already know a sandbox's labels (after a restart, or in another process), it reads them from a file inside the sandbox, and that read is now held to the call's own time limit. For a read of one sandbox, a read that fails or gets no answer gives the two labels the sandbox's name carries, so release still finds and terminates a wedged sandbox instead of leaving it to bill until its timeout. A sandbox's name now carries its run's hash and its epoch after the computer's name (`computer-<12 hex>-r<run hash>-e<epoch>`), so a listing by run reads only the sandboxes that may be that run's: another run's wedged or ending sandbox can no longer fail a claim or a run's end. Of those it reads, a listing reads at most 4 files at once, all within the listing's time limit. If any of them can't be read by then, the listing fails with an error naming each such sandbox and why, because it can't tell whether that sandbox carries the labels asked. Before, every computer's file in the workspace was read at once, and the first failure failed the listing without waiting for the rest. A listing by name alone reads no file. What a server knows of a workspace's sandboxes (their labels, and which it terminated) is now shared by every provider of that workspace in the process, so a sandbox one claim terminated, which Render still reads as running, is not read through its guest by the next claim's listing, and release settles. The server forgets a sandbox's labels once Render reads it terminated or not found, or once a listing no longer shows it. Sandbox ids are sent encoded in paths instead of being held to the `sbx-…` form, so a sandbox whose id has a new form is still terminated. `prepareImage()` calls in one process that run at the same time for the same workspace and API key share one import, even when they go through different providers (a server makes one per claim), and a build of the box image that is still pending or running is waited for instead of being imported again. A Render sandbox made by an earlier release, named `computer-<12 hex>` alone, is no run's computer to a listing by run, so a later claim or a run's end doesn't find it; Render still ends it at its timeout, at most a day after its create.
