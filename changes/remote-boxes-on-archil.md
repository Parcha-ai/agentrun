packages: @parcha/agentrun-serve, @parcha/pi-durable-disk, @parcha/pi-transport, @parcha/pi-durable-agent
kind: breaking
---
A Daytona or Modal sandbox now mounts its run's `work/` from the owner's Archil disk instead of getting a copy of it, and nothing is copied in or out. The seed, the pull at each turn's end and at the run's end, the per-file mirror, `box-sync.json` and `box-mirrored.jsonl` are gone. Who breaks: a server that runs remote boxes. To keep them, set `AGENTRUN_ARCHIL_DISK`, `AGENTRUN_ARCHIL_REGION` and `AGENTRUN_ARCHIL_TOKEN`, mount the disk at `<data>/disk` with `--conditional`, and use a box image or snapshot that ships the archil client, the root helper (`box/agentrun-archil`, at `/usr/local/sbin/agentrun-archil`), the `agentrun-tool` user and their sudoers lines (the README's "A box on another machine"). Without Archil, capabilities show both boxes unavailable with what to do, a save of such a place is refused in the same words, and a run of one is refused 409 `agent_not_runnable`.
- The box mounts exactly `agents/<agent>/runs/<run>/work` at `/workspace`, exclusively, through the helper, which takes `mount`, `revoke`, `sync` and `checkin` and checks every argument itself. At each turn's end the box syncs the folder; at the run's end it syncs and checks it in, and only then is it destroyed. A box that is lost leaves its hold on the folder: the run's next box destroys every other box of the run first, then takes the folder back (`revoke`), since a client whose hold is forced off is told its buffered writes are done and loses them. The helper refuses to mount in a box whose `/proc` is not mounted `hidepid=2` (or `invisible`). `AGENTRUN_DAYTONA_SNAPSHOT` and `AGENTRUN_VM_IMAGE` name what a remote box starts from; without one, that box is unavailable.
- The disk token reaches a box only on the helper's fd 0: the Modal sandbox's stdin, or on Daytona a file in a new 0700 folder, opened and removed before the helper starts. It is never an argument or in an environment a tool reads. The run's tools run as `agentrun-tool`, which has no sudo.
- A run's `work/` on the disk is the shared group's (`AGENTRUN_ARCHIL_GID`, default 2510), mode 2770: Archil keeps ids as they are between machines.
- The Modal sandbox is now made on Modal's VM runtime with FUSE, which an Archil mount needs.
- A remote box's tools have no network yet, and capabilities say so ("remote boxes on an Archil disk: tools have no network yet") with how it is held. The Modal sandbox's whole network is `AGENTRUN_ARCHIL_ALLOW`, Archil's IPv4 ranges, as its provider's CIDR allowlist (without it, that box is unavailable). A Daytona box is made with its provider network open, and the helper's `netlock` locks it before the mount: for IPv4 and IPv6, the tool user sends nothing but to loopback, and root reaches DNS, the region's mount endpoint on 8100 and any address on 32050. It reads the rules back whole; no iptables or ip6tables, no CAP_NET_ADMIN or a read-back that differs refuses the box in words, and it is destroyed. Daytona's domain list is no longer asked for.
- pi-durable-disk: a run's process fsyncs `store/run.sqlite`, then its folder, as soon as the store opens, before the run is reported started.
- pi-transport: a Daytona box takes `killAs`, the words a timed-out or aborted program's kill runs under, for programs started as another user.
- pi-durable-agent: a run's folder, every folder above it up to the disk, and its store folder are made 0700 whatever the umask, and a folder found looser is tightened.
