Bring your own harness, door 1: a recipe. A JSON file names an ACP agent's registry release (the archive's URL and sha256, the binary inside it), its model billing (through AgentRun's model proxy, or the owner's plan with turn and tool-call limits), its literal env, files and session folders in the private HOME, and what it declares. `agentrun harness install --recipe FILE` installs the release, and `agentrun harness-check --recipe FILE --model PROVIDER/MODEL` runs it for real: the agent's own tools off, its environment an allowlist, the cap or plan limits, the pinned binary at every start, no side request (stage 2); a SIGKILL then resume, a denied call, one of AgentRun's tools over MCP, a second runner (stage 3). It writes a JSON report and prints the three facts a harness row carries: `resume`, `tool_gate`, `billing`. See [docs/harness-recipe.md](https://github.com/Parcha-ai/agentrun/blob/main/docs/harness-recipe.md) and [HARNESS-SCORECARD.md](https://github.com/Parcha-ai/agentrun/blob/main/HARNESS-SCORECARD.md), which rates 25 agents.

The loader refuses a recipe that breaks one of five rules by its code: a key that is not the harness's own (`RECIPE_KEY_NOT_OWN`), a binary not pinned to a registry archive (`RECIPE_BINARY_UNPINNED`), a file or folder outside the private HOME (`RECIPE_PATH_OUTSIDE`), an install step of its own (`RECIPE_INSTALLS_ITSELF`), an environment beyond the allowlist (`RECIPE_ENV_NOT_ALLOWLIST`). A release whose registry entry lists no binary digest is pinned to the first one its owner's install records; a later binary that differs is refused (`HARNESS_BINARY_MISMATCH` at an install, `ACP_BINARY_DRIFT` at a check). The ACP adapter logs each permission the agent asks for (`acp: the agent asked permission`).
