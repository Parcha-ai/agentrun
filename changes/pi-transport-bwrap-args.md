A bwrap box's arguments are built in one place, every variable input is checked, and a probe says whether a Linux host can run such a box and, when it can't, why. A bwrap box runs each command of a box under bubblewrap, with a host directory as its workspace. The module is internal (`src/box/bwrap-args.ts`, not exported): the provider that uses it comes in a later release.
- `bwrapArgs` builds the whole `bwrap` argv of one command. It makes new user, pid, network, IPC, UTS and cgroup namespaces, with no `-try` form, and passes `--disable-userns`, `--cap-drop ALL`, `--die-with-parent`, `--new-session` and a hostname of the box's own. A private `/proc`, `/dev` and `/tmp` are mounted before any bind. The system is read-only: `/usr`, the `/bin`, `/sbin` and `/lib*` beside it or linked into it, and a named part of `/etc`. The box gets its own `/etc/passwd` and `/etc/group` (its user and `nobody`) and `/etc/hosts` on fixed descriptors. The workspace is bound read-write at the box's working directory, the root is remounted read-only, and `--clearenv` leaves only the spec's environment. `/run`, `/var` and the host's `/tmp` are never bound.
- The workspace must be its own real path, with no link in it. These are refused by name: a relative path, a `..` segment, a path not in normal form, `/` and the shared roots (`/home`, `/tmp`, `/var`, `/srv` and others), anything in the system, `/etc`, `/proc`, `/sys`, `/dev`, `/run`, `/boot` or `/root`, the server's home, and a hidden path the caller names, or what holds one.
- A home or a hidden path that lies inside a bound system directory, as named or through its links, is masked in the box after that bind by an empty tmpfs of mode 555, remounted read-only on its own, since the root's remount doesn't reach it. A part of `/etc` inside one is left out. One that is or holds a system root is refused, since masking it would leave the box without its system.
- The network is `none`, with a loopback of the box's own. `open` would share the host's network namespace and its loopback services, so it is `unsupported`, and so is an allowlist.
- `probeBwrap` reads and runs bwrap and changes nothing on the host. It runs one box built as an exec's, running `true`, and matches what bwrap says against the known denials. It answers missing, setuid, older than 0.8.0, root without `CAP_SETFCAP`, a user namespace denied (naming AppArmor's restriction of unprivileged user namespaces, or the sysctl that denies them, and leaving the fix to the administrator), a run killed at its time bound, or available with its version.
