A bwrap box's arguments are built from an allowlist and checked against it, and a probe says whether a Linux host can run such a box and, when it can't, why. A bwrap box runs each command of a box under bubblewrap, with a host directory as its workspace. The module is internal (`src/box/bwrap-args.ts`, not exported): the provider that uses it comes in a later release.
- `bwrapArgs` builds the whole `bwrap` argv of one command. It makes new user, pid, network, IPC, UTS and cgroup namespaces and passes `--disable-userns`, `--cap-drop ALL`, `--die-with-parent`, `--new-session` and a hostname of the box's own. A private `/proc`, `/dev` and `/tmp` are mounted before any bind. The system is read-only: `/usr`, the `/bin`, `/sbin` and `/lib*` beside it or linked into it, and a named part of `/etc`. The box gets its own `/etc/passwd`, `/etc/group` and `/etc/hosts` on fixed descriptors. The workspace is bound read-write at the box's working directory, the root is remounted read-only, and `--clearenv` leaves only the spec's environment.
- The workspace is checked as given and again through its links. These are refused by name: a relative path, a `..` segment, a path not in normal form, `/` and the shared roots (`/home`, `/tmp`, `/var`, `/srv` and others), anything in the system, `/etc`, `/proc`, `/sys`, `/dev`, `/run`, `/boot` or `/root`, the server's home, and a hidden path the caller names, or what holds one.
- A home or a hidden path that lies inside a bound system directory, as named or through its links, is masked in the box by an empty tmpfs after that bind, and a part of `/etc` inside one is left out. One that is or holds a system root is refused, since masking it would leave the box without its system. `checkBwrapArgs` works out the masks an argv needs from its own read-only binds, so an argv missing one is refused whatever built it, and so is a tmpfs anywhere else.
- The network is `none`, with a loopback of the box's own. `open` would share the host's network namespace and its loopback services, so it is `unsupported`, and so is an allowlist.
- `checkBwrapArgs` refuses an argv that differs from the one built. That covers an option a box never uses (`--share-net`, `--cap-add`, `--dev-bind`, `--args` and the rest), a second `--bind`, a read-only bind outside the system, a flag missing or given twice, a mount that would hide a bind, and a `--setenv` before `--clearenv`.
- `probeBwrap` reads and runs bwrap and changes nothing on the host. It answers missing, setuid, older than 0.8.0, a user namespace denied (naming AppArmor's restriction of unprivileged user namespaces, or the sysctl that denies them), a run killed at its time bound, or available with its version.
