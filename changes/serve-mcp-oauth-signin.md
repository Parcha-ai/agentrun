Sign in to a remote MCP server with OAuth, run by the server: `POST /v2/settings/mcp-servers/{name}/oauth/start` with `{url, scopes?, client_id?, client_secret?}` answers the `authorization_url` the owner opens, and `GET /v2/settings/mcp-servers/oauth/callback` (no token; a random state, used once, good for 10 minutes) exchanges the code, seals the token set under `AGENTRUN_SEAL_KEY` bound to the server's name, lists the tools and redirects to the console's MCP servers page. The official MCP SDK does discovery (RFC 9728, RFC 8414), PKCE S256 and the RFC 8707 resource; the client is the owner's pre-registered one, else the server's client metadata document (`GET .../oauth/client.json`, from a public https address only), else dynamic registration. Reads show `credential: sealed` and `oauth: {expires_at, scopes, client}`, never a token; `auth.type: "oauth"` is accepted on a `PUT`, which keeps the token set. Every launch of a run that grants the server's tools refreshes its token within 5 minutes of expiry (once at a time per server) and hands the run the access token alone; one that expires mid-run is refreshed at the next launch, and its calls meanwhile say to sign in again; a refused refresh reads `credential: "expired"` and asks to sign in again in Settings → MCP servers. Capabilities' `mcp_client.auth` gains `oauth`.
