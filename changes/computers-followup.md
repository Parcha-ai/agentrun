A stopped run's end no longer deletes the machine a follow-up message took back. When a follow-up queued the run again and its claim took the kept desktop, phone or sandbox back before the stop's end ran, that end deleted the machine from under the follow-up's turn. A run's end now lets nothing go once a later claim has the run, or when it can't read the run to tell, and says so in the runner's log; that claim lets the run's machines go at its own end, and otherwise the run's next end or the computer janitor does. On E2B, Daytona, Modal, Morph, Browserbase, Kernel and the phone harness the janitor ends only a machine a park kept: another machine left there runs until the vendor's own lifetime ends it. A keep that lapsed no longer haunts the run: the run's end removes its ended keep, so a follow-up message no longer says again that the desktop wasn't kept because its 10 minutes passed. That needed a janitor pass before, which never runs under `--faux`. A follow-up whose take-back of the kept machine a stopped run's end beat no longer says the machine wasn't kept because its 10 minutes passed when they hadn't; it says it's a new one. A paired computer's files note no longer tells the model the computer is deleted when the run ends; it says what's saved there stays on it. A computer that gives the run no shell (a desktop, phone or browser that doesn't mount the run's folder) now says so in its own words in GET /v2/computers, instead of "No computer on this server". A provider whose machines dial the server, on a runner in a process of its own, now names both fixes when it refuses: give the runner `AGENTRUN_PUBLIC_URL`, or run the server and its runner in one process.
