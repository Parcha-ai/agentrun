serve gains the Archil backend of the Workspace port, unused until the cutover: a run's folder on the owner's Archil disk, through the disk's file API and serverless exec (Archil's Node SDK, `disk` 1.12.0, pinned). It takes the disk, its region, the name of the variable holding the account API key, and the disk's S3 endpoint (the setting `AGENTRUN_ARCHIL_S3_URL`), which no public part of the SDK names; the SDK and the ranged read both use that one endpoint. Nothing is mounted on the server or a runner, and no program runs there. Every key it sends is under the run's folder. A write is one put and returns once Archil has committed it; an append is cut into calls of at most 1 MiB, in order; a read with a range sends the Range header; grep is the disk's grep, its matches sorted, stopping at its cap or its deadline. exec runs argv with exactly the given environment in a container that checks out the run's folder, refuses a deadline over Archil's 300 s, refuses a symbolic link on the way to its cwd, and answers once the command has ended, so onOutput gets each stream once. attach and background programs are refused: background programs need a computer.
