A workflow run takes a spend cap (`max_cost_usd`, `cap_mode`), on its start, from its agent's default (a workflow definition now keeps one), and from a trigger, which may now start a workflow. Each paid step is held to the cap before it is sent, as an agentic run's are: a model node's request, a call node's `llm` call and paid tool call, and a decision at its provider's price (Parallel's list price, Jev's published price, an OpenRouter Decisions model's catalog price). A step the cap has no room for waits unsent where it stands: the run is `input_required` with `pending.kind` budget and `pending.node`, and `PATCH /runs/{id}` sends it, in the same process or, after 10 minutes paused, in one opened again from the run's journal, with no completed node sent again. A capped start whose node runs on a model with no price here, or whose decision pins an OpenRouter Decisions model the catalog does not price, is refused before it starts (409 `agent_not_runnable`, the node and the fix in `error.fields`), as an agentic run's is. A decision whose price cannot be read mid-run (OpenRouter's catalog down) is read again, then fails unsent as a connection error that the node's attempts take, never as the cap's stop; a decision an earlier process asked and never saw answered holds nothing and never pauses for a raise; and a decision's cost counts on the next process from its receipt when its booking was lost, or at its hold, kept in the run's store before the request is sent, when its process died with the request out.
- `@parcha/agentrun-dsl`: `WorkflowDeps.held(executionPath)`, the time a host held a call, which its deadline does not count; `chargedCost` is exported.
- `@parcha/agentrun-decisions`: the OpenRouter provider's `priceOf(model)`, the model's catalog price.
- `@parcha/pi-durable-agent`: a workflow revision keeps `maxCostUsd` and `capMode`.
