A new computer provider, `northflank`: a Linux sandbox on a Northflank service (a Kata microVM on Northflank's cloud) in your own project, over the Northflank API and its command-exec WebSocket, with no SDK. It takes `NORTHFLANK_API_TOKEN`, the name Northflank's own client reads, and `NORTHFLANK_COMPUTER_PROJECT_ID`, which is required and has no default (not `NORTHFLANK_PROJECT_ID`, which Northflank sets inside its own services), with `NORTHFLANK_COMPUTER_TEAM_ID` for an organisation token. It loads from `@parcha/agentrun-computer/northflank` or `providerFor("northflank", { token, projectId })`. A computer starts from the box image's public tag, or the spec's image, under `sleep infinity`, on the plan of its size; it is a sandbox alone for now: no desktop and no Archil mount. Create sets the service's expiry at the backstop, so a computer whose server is gone is paused and deleted by Northflank. The exec is the command-exec socket's JSON messages, bytes as latin1 strings, the token in the first message and never in the URL, and `kill` the shared pid wrapper's, as Northflank has none. Serve offers it as a box once `AGENTRUN_BOXES` lists `northflank` and the token and project are set, and the launcher holds `NORTHFLANK_API_TOKEN` with the other secrets. No live run has been made yet: latin1 byte for byte, 75 s of exec silence, output trailing the exit message, root, a taken name's 409, the id being the name, annotations read back as given, the scale call after create, a deleted service's 404, amd64 with no vendor agent on TCP, and root's network namespace are unverified until then.
