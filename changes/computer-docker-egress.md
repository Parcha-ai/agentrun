A Docker computer takes network `{ allow: [names or CIDRs] }` beside `none` and `open`: `capabilities().network` is `["none", "open", "allow"]`, and an allowlist holds exact names, `*.suffix` names and CIDRs (host bits zero, over no range the address rule refuses), at most 256 of each, on ports 80 and 443. The computer itself stays `--network none`. Its one way out is its own egress proxy, serve's proxy and address table moved into `src/docker/egress-proxy.ts` and `src/docker/egress-table.ts`, which runs in a second container the provider makes, reads back and removes with it.
- `create` makes a tmpfs volume (`computer-<hex>-egress`, mode 0700, the computer's uid:gid), starts the proxy container on Docker's default bridge alone (no port, the computer's user, a read-only root, no capability, `no-new-privileges`, bounded memory, pids and log; `EGRESS_IMAGE`, node:22.23.4-bookworm-slim pinned by digest, or `egress.image`), and waits for its ready line (`egress.readyMs`, 10 s) before it runs the computer, which mounts the volume read-only at `/opt/agentrun/egress`. A proxy that ends first, or is not ready in time, fails create in words, and the proxy and the volume are removed.
- computerd `init --egress <socket>` relays its loopback port 3128 to the proxy's socket and gives every program it starts `HTTP_PROXY`, `HTTPS_PROXY`, their lowercase forms and `NO_PROXY`. A program that ignores them reaches nothing. Init refuses to start when it cannot listen.
- The proxy refuses, before any socket opens, a name off the list (before any lookup), an IP literal outside a listed CIDR, any port but 80 and 443, and a listed name or address that is private, loopback, link-local, metadata or this machine's own, in any form; it resolves a name once and dials the checked address, never follows a redirect, refuses SOCKS5 BIND and UDP ASSOCIATE, and logs no path, query or header. It ends itself at the computer's deadline.
- `network`, `list` and `attach` read the allowlist back from Docker: the computer's network mode, its egress volume and relay, and the proxy container's label, deadline, state, hardening, mounts and argv. Anything less, a crashed proxy included, reads back `{ other }` in words, and `attach` refuses it. `network(ref, policy)` returns an allowlist the computer has, in any order; every change is refused, since a Docker computer's network is fixed at create.
- `release` stops or removes the computer's proxy and, on delete, its volume, each found by the label `agentrun.computer.egress=<computer>`, so the janitor's sweep and `releaseOlder` remove them too. The conformance cases `provider.network-allow` and `provider.network-switch-allow` now run and pass on Docker.
