A Docker computer takes network `{ allow: [names or CIDRs] }` beside `none` and `open`: `capabilities().network` is `["none", "open", "allow"]`, and an allowlist holds exact names, `*.suffix` names and CIDRs (host bits zero, over no range the address rule refuses), at most 256 of each, on ports 80 and 443. The computer itself stays `--network none`. Its one way out is its own egress proxy, serve's proxy and address table moved into `src/docker/egress-proxy.ts` and `src/docker/egress-table.ts`, which runs in a second container the provider makes, reads back and removes with it.
- `create` makes a tmpfs volume (`computer-<hex>-egress`, mode 0700, the computer's uid:gid), starts the proxy container on Docker's default bridge alone (no port, the computer's user, a read-only root, no capability, `no-new-privileges`, bounded memory, pids, CPU (half of one), open files and log; `EGRESS_IMAGE`, node:22.23.4-bookworm-slim pinned by digest, or `egress.image`), and waits for its ready line (`egress.readyMs`, 10 s) before it runs the computer, which mounts the volume read-only at `/opt/agentrun/egress`. A proxy that ends first, or is not ready in time, fails create in words, and the proxy and the volume are removed. On a host that remaps user ids (userns-remap, rootless Docker) `check` and `create` refuse an allowlist in words before anything is made, as they do a bind. So they do when this provider's interfaces are not the Docker host's (it runs in a container, or `docker context inspect` names a daemon that is not a local unix socket), unless `egress.hostAddresses` names the host's addresses, which the proxy then refuses as `this-host`. Before it makes anything, `create` makes sure the computer's image and the proxy's are on the Docker host (`docker image inspect`, then `docker pull` for one that is not; a failed pull fails create in words naming the image), and both containers run with `--pull never`, so no pull happens while the sweep could take the new proxy for a leftover.
- computerd `init --egress <socket>` relays its loopback port 3128 to the proxy's socket and gives every program it starts `HTTP_PROXY`, `HTTPS_PROXY`, their lowercase forms and `NO_PROXY`. A program that ignores them reaches nothing. Init refuses to start when it cannot listen.
- The proxy refuses, before any socket opens, a name off the list (before any lookup), an IP literal outside a listed CIDR, any port but 80 and 443, and a listed name or address that is private, loopback, link-local, metadata or this machine's own, in any form; it resolves a name once and dials the checked address, never follows a redirect, refuses SOCKS5 BIND and UDP ASSOCIATE, and logs no path, query or header. It ends itself at the computer's deadline.
- `network`, `list` and `attach` read the allowlist back from Docker: the computer's network mode, its egress volume and relay, and the proxy container's label, deadline, state, hardening, bounds (memory, swap, pids, CPU quota, open files, IPC and cgroup namespaces, log), mounts and argv, whose `--local` must hold every one of the Docker host's own addresses the provider requires now (this machine's public ones and `egress.hostAddresses`; a host whose addresses changed since reads as other). Anything less, a crashed proxy included, reads back `{ other }` in words, and `attach` refuses it. `network(ref, policy)` returns an allowlist the computer has, in any order; every change is refused, since a Docker computer's network is fixed at create.
- `release` stops or removes the computer's proxy and, on delete, its volume, each found by the label `agentrun.computer.egress=<computer>`, so the janitor's sweep and `releaseOlder` remove them too. Parts left with no computer (one removed by hand, or a provider that died between its proxy and its computer) the sweep removes through the new optional `ComputerProvider.sweepLeftovers`: a proxy or volume with the egress label whose deadline has passed, or whose computer is gone past a create's grace; `Swept.leftovers` names them. The conformance cases `provider.network-allow` and `provider.network-switch-allow` now run and pass on Docker.
