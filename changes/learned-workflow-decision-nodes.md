A learned workflow can hold decision nodes (judge, pick, sift, a route by question, an ask predicate, a verify), under the run's spend cap. Each decision is admitted on the run's cap before it is sent, priced the way a workflow agent's decision is, and booked at what it charged. If the cap has no room, the decision is never sent: the run pauses at the cap, and the `learned_workflow` call says why. A decision node's provider (the one it names, else the default, `jev`) is checked against the run's tool settings: each provider is a settings key of its own (`jev`, `parallel`, `openrouter`), allow by default, allow or deny. Set to deny for the agent or on the server, the workflow is refused before any node runs, in the gate's words. A workflow agent's own decisions read no such setting. A provider the run has no key for refuses the workflow too. A run with no decision providers still refuses decision nodes, as before. A decision's spend is in the run's cost (its row, its view, `/v2/usage`), beside its model requests and paid tool calls, and a decision of unknown cost leaves the run's unknown. The run is handed the keys of the providers its learned workflows name, unless the provider is denied; a denied one, or one the server has no key for, refuses the workflow at its call, and nothing is sent. A run's new workflow draft with a decision node is checked against the server's decision providers, so it is proposed and graded like any draft.
Upgrading: nothing to do. To keep an agent's learned workflows from asking a provider, set that provider's id (`jev`, `parallel`, `openrouter`) to deny in the agent's tool settings.
