An owner can drive a run's computer from anywhere, and a run can hold its computer for its owner.
- POST /runs/{run_id}/computer/call `{ method, params }` sends a running run's sandbox, desktop or phone one computer protocol call and answers what the computer answered, verbatim. The call is a command row the run's runner answers: it waits while a person holds the computer, as the agent's calls do, and a runner beside the server answers in about 10 ms (a runner in another process finds the row at its next command poll). A method outside the computer protocol is refused. The call's params (text it types, say) leave the store once the call settles. The route takes the owner's token or session, never a run's.
- `hold: true` on POST /agents/{agent_id}/runs (an agent's run, not a workflow's) claims the run's computer and waits, the agent not started, until POST /runs/{run_id}/start; after the agent ends, the run keeps the computer until POST /runs/{run_id}/computer/release, or until `hold_minutes` (default 30, at most 120) pass with no call from the owner. A stop of a held run ends its agent and keeps the computer the same way, and the run ends `stopped` at the release; a cancel ends the run at once and lets the computer go. GET /runs/{run_id} says where the hold is in `computer.held`, and the Timeline says each change. A benchmark sets a task up, starts the agent, checks the computer after, then lets it go.
- Each tool call's computer protocol calls are on its `tool_result` Timeline row as `computer_calls`: method, outcome, time, error code, and for `ui.act` each step's kind, route and readback. No param value, no screenshot bytes, no typed text.
- GET /runs/{run_id}'s `computer.state` reads `taken_over` while the owner holds the run's desktop or phone, and `ready` again after the hand-back.
- **Breaking for a SQLite data directory.** The store's SQLite schema is now version 7 (a command row keeps its answer). A server or runner of this release refuses a data directory an earlier release set up, with `SchemaVersionUnknown`: start this release on a new, empty data directory and add your agents, MCP servers, keys and sign-ins there again, or keep the old directory with the earlier release. A Postgres store migrates itself (migration 0005).
