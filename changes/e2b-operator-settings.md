An E2B computer can now run on a cloud that speaks E2B's API, or start from a template of the operator's own, by three optional settings beside `E2B_API_KEY`, set in the environment or saved in Settings → Computers: `AGENTRUN_E2B_DOMAIN` (the cloud's domain; unset, `e2b.app`), `AGENTRUN_E2B_API_URL` (its API's URL where that isn't `https://api.<domain>`: https alone, with no login, query or fragment, else refused naming the setting before any call) and `AGENTRUN_E2B_TEMPLATE` (the template every E2B computer starts from in place of the box template, as `AGENTRUN_DAYTONA_SNAPSHOT` names Daytona's snapshot; an agent's `computer.image` may name it). The key in `E2B_API_KEY` goes to whichever cloud the domain names, and the proxy follows that domain and API URL. In the computer package these are E2B's `domain`, `apiUrl` and `template` options. With none set, nothing changes. The computer package's README lists seven clouds that speak E2B's API (Maritime, Orble, SUFY, Alibaba Cloud Agent Sandbox, PPIO, UCloud and Tencent Cloud Agent Runtime) with each one's settings; none has been run live yet.
