On Goose and Cursor, a permission request for a tool the agent is not given is now refused at once, and the run goes on. Before, the request went to the host's gate like any other, and since there is no grant for a person to approve, the run parked (`parked`, with no summary) on a question nobody could answer usefully. Now the ACP adapter answers it `reject_once` without asking the gate or journaling it, and the run's timeline gets a line saying `tool "<name>" isn't granted to this agent`. ACP's permission answer carries no words, so the agent reads its own vendor's refusal; the line is for the person. An agent that calls such a tool without asking now gets those same words from the adapter's MCP server, which said `unknown tool: <name>` before. A tool the agent is given whose setting asks (a write behind the gate) still asks a person and parks as before, and a native call with effects of its own (a shell, an edit) still goes to the gate whatever its title says. claude-agent, codex and pi never asked about such a tool: their tool bridge answers a call of a tool it does not hold `unknown tool: <name>` before the gate. serve's computer claim drops its `refuseKind` hook, which nothing called once every CLI harness got the browser.
