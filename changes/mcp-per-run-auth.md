An MCP server can take its credential from each run: the owner saves it with `auth: {type: "per_run", headers?}` (it keeps none; `headers` only list its tools at the save; the save is a secret write, since its address is where every run's credential goes) and hand each run its own as `mcp_auth: {"<server>": {"headers": {...}}}` on `POST /v2/runs`, `POST /v2/agents/{agent_id}/runs` and `POST /v2/runs/{run_id}/messages`. The run's calls of that server carry those headers, to the origin the server had at the run's start only. The credential is sealed into the run's launch record for the run's life (a resume, a restart or a lost lease uses it again), erased by the write that ends the run, and never in the run's saved body, timeline, view, a log line or an `Idempotency-Key`'s fingerprint; a message's `mcp_auth` replaces it in the message's own write, so the turn it starts uses the new one. A name that is not a saved per_run server is 422 at `mcp_auth.<server>`; a run handed none for a server it calls has those calls refused unsent, in words.
