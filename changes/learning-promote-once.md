kind: breaking

A learned workflow is compiled once and checked once against the agent's own answers. An agent definition's `learning` takes an object, `{ compile_after?, agree_min?, alone_min? }`, which is on (as `true`) with those numbers set; each one left out is its default (20, 0.8, 0.7), and `true` is every default. A number out of range or an unknown key is a 422 `wrong_type` on `definition.learning`.
  - The first compile is asked once the agent has `compile_after` completed runs of its own. A count of kept notes no longer triggers it.
  - A new revision's first claim replays it on the inputs of the agent's last `compile_after` completed runs. Each input is scored against the agent's own recorded answer, not a grade. The revision is promoted when it answered at least `alone_min` of them alone and at least `agree_min` of those said what the agent said. An input an escalate hands back is not answered alone. Every reserved input counts in `n`: a replay run never created, or not ended by the check's deadline, is a failed input. A draft with nothing to check it on (no input of the agent's it takes, or every input skipped at a write) is never promoted: it stops (`check.stopped`, `n: 0`) with a reason that starts "nothing to check it on", shown as the compile's draft error, and asks no recompile. Under either bar it is held, and the agent's next run asks one revision with the inputs it disagreed on. That revision is checked the same way; held again, it stops (`check.stopped`), the agent keeps its runs, and nothing compiles again.
  - The promotion record carries `check`: the bar, `n`, `agreed`, `alone`, the runs read, the tools that stopped skipped inputs (`skipped_tools`), and on a hold the disagreements. A promotion by check is not moved by later grades, and a newer revision waits for a running check instead of queueing.
  - Upgrading: promotion is now by agreement with the agent's own answers, not by grades. To compile sooner or hold drafts to a stricter bar, set `learning: { compile_after: 5, agree_min: 0.9 }` on the agent. A client that reads `definition.learning` as a boolean or `"notes"` must also accept an object, and treat it as on.
