kind: feature
---
serve's web tools now run Jev by default on any server that already holds a TypeSafe key (`TYPESAFE_API_KEY`, set or saved), and that sends run content to TypeSafe. Each `web_search` sends TypeSafe its objective and each result's URL, title and snippet. Each `web_fetch` given an objective sends TypeSafe the page's text, up to 1,000,000 characters in chunks, and the objective. A fetch with no objective sends nothing. TypeSafe bills every request to the server's TypeSafe key. To keep the old behaviour, set `AGENTRUN_WEB_JEV_OFF=1` on the server. Jev (`jev-1.14.0`) scores each search result against the objective and reorders the results by that score (rerank+label). It keeps every result, gives each a `relevance` (0 to 1), and adds a `sift` line saying how they were ranked, or why not. Each Jev request is held on the run's spend cap at Jev's published price and settled at the cost Jev reported, never above the hold. A server with only an OpenRouter key runs no web ranking. GET /capabilities' `why` for each tool says what it sends TypeSafe, or that Jev is off.
- A Jev failure leaves the results as the provider gave them, with a `sift` line saying it did not run.
- A `web_fetch` given an objective has Jev pick the chunks of the page most likely to hold it (`found`), its requests held and booked as a search's are. One with no objective is never judged: it asks Jev nothing, its page is whole and its answer has no `sift` field. In web, a fetch given a decider but no task now comes back with no `sift` field (it said "not run (no task given); this part is whole"); its classifier record still says `skipped: "no task"`.
- serve's `web_destinations` start line gains `classifier`: `"jev jev-1.14.0 rerank+label"`, or `off`. It never holds a key.
- `AGENTRUN_WEB_JEV_OFF=1` on the server turns Jev off for every run created while it is set, on every runner host: the run's plane carries it (`jev: "off"`) and keeps it at every later launch, so a runner started without the switch hands no TypeSafe key and runs no Jev for that run. A runner's own switch can add off, never remove it.
- The runner hands TypeSafe's key to a run only when one of its web tools is the run's own and Jev is not turned off, as it hands Parallel's: `web_fetch` wherever it runs, and `web_search` on Parallel, keyless Firecrawl or Exa, or pi's hosted search, never a harness's own search inside its CLI (codex's, claude-agent's), where no Jev call can happen. A codex run on its own search with `web_fetch` still gets the key, for the fetch.
- web: `jevWebDecider` builds this decider from what it is handed (the key, `jevProvider`, a price, a fetch), never from the environment, and `null` gives none. `Pay` gains an optional `charged`, the cost a request reported once it was answered, which `decisionPay` passes for each decision request.
- web: a decision request's line in `receipt.cost` is now what it was charged: the cost its provider gave (reported, or estimated where it reported none, the line's `basis` says which), never above its hold, and the hold where it gave none. It was the hold, which the cap also booked; now that the cap books the charge, the line follows it, so receipt and ledger say one figure. `DecisionPay`'s `costOf` now returns the answer's `Cost` (`usd` and `basis`).
- web: `webFetchText`'s line for a provider that gave no page before the direct fetch now reads "Parallel gave no page (answered 500); this one was fetched directly.": it no longer says the provider was picked, which under `auto` it was not.
- web: `Pay` gains an optional `settled`, told whether the cap's settle of an answered request was written. `decisionPay` moves a decision request's line to its charge only once that settle is written; when it fails, the cap keeps the hold and so does the line, its `basis` saying the settle failed and naming the charge it would have booked. A $0 unbilled line follows the same rule. `unmetered` never calls `settled`, so with no cap the lines are as before.
