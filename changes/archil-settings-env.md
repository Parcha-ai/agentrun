The Archil settings that turn Mode 2 on can now come from the server's environment, for a server no owner's session can save them on (API only, or `AGENTRUN_ACCOUNTS=0` reached beyond loopback): `AGENTRUN_ARCHIL_REGION` and `AGENTRUN_ARCHIL_S3_URL` together, and `AGENTRUN_ARCHIL_IMAGE` for an exec image pinned by digest, beside the account key in `ARCHIL_API_KEY`. Each agent's disk is then made on its first run, as with saved settings. Each value is checked as `PUT /v2/workspace/archil` checks it, and one of the region and S3 URL without the other, or a value the PUT would refuse, stops the server's start (and a runner's, `agentrun-serve runner`) in words naming each variable. Set, they win over saved settings and nothing is written to the store: `GET /v2/workspace/archil` says where the settings come from (`source`: `env`, or `console` for saved ones), and `PUT` and `DELETE` are `409 key_set_by_server` while the environment sets them. Unset, nothing changes. A runner started on its own reads them from its own environment, as it reads `ARCHIL_API_KEY`. The server's read-only view of a run's files now reads the server's environment too, so it finds `ARCHIL_API_KEY` there as a run does.
