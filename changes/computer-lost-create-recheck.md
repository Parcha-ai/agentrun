Browserbase and Kernel: a lost create's browser left for another create's converge is read again before it is kept. The recovery reads the request's browsers every 2 s for up to half of `cleanupMs` (once at least, and sooner when that half is under 2 s, so a short `cleanupMs` still bounds the recovery). In that read, a Browserbase session found both running and ended reads as ended, and a Kernel browser listed twice reads as deleted once either row says so. Once a newer browser has ended (a converge that answers the older releases its own first), the lost create's browser is left running. Where every newer one still runs at the end, no converge answered it and it is released, where before it ran to its lifetime. A newer browser that ended without answering it (its create aborted or failed after releasing its own, or its reply lost too) reads the same as a converge, so there it still runs to its lifetime, and the create's failure says so. The README names the gaps that are not covered: a lost create's only browser that another create answered by its lookup, and Orgo's delete by name after a POST with no answer.
