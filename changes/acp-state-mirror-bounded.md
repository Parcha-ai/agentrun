An ACP run (Cursor, Goose, or a harness recipe) no longer stalls after many turns. Before, the adapter copied the agent's whole session store into the run's records at every turn, so the records grew with the square of the turn count. After about 20 Cursor turns they no longer fit the 32 MiB channel to the run's process: an approval answered 204, and the run then waited for good. Now the mirror stores each file as 64 KiB pieces, each written once per session, so a store that grows by appending costs only its new bytes. It never copies SQLite's `-shm` file, and holds at most 8 MiB per session. Past that, the run's timeline says "The agent's session state passed 8 MiB, so a resume starts it fresh with the conversation so far." and the mirror stops. A run whose records no longer cross to its process now fails at once, naming the size and the limit, and the approval that woke it is answered that the run failed. Adapters get a `notice` event, which serve shows as a step on the run's timeline. Records written by an earlier version still restore.
