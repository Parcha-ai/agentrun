A person sees and controls what an agent has learned, through the API (`learning/1`): `GET /v2/agents/{agent_id}/learning` (the index, the notes, the log of changes by run or by person, and the runs' counts), its `notes` and `log` pages, one note as text with its `ETag`, and `GET /v2/runs/{run_id}/learning` (with the grader's verdict and its item for each new note: kept or not, the rubric's question it failed, and why) and `.../learning/diff` for one run.
- `PUT /v2/agents/{agent_id}/learning/files/{file}` takes the note's whole text (as text, or as JSON `{text}` from the console's page) and edits a note (`If-Match`) or creates one (`If-None-Match: *`), and `POST .../retire` retires one; a stale ETag is 412, a write with no precondition 428 (`precondition_required`, a new error code). A person's note passes the same structural checks as a run's, with no grader, and lands as one host commit on `main` with a `Changed-By: user` trailer and `MEMORY.md` rebuilt. A refused note is 400 with `problems` on the error; a retire checks only the note's format (its front matter, and the cap with the status line on top), never its secrets, so a leaking note can always be revoked. The view and the pages read a commit's notes once (kept for the few commits last read), and a log page reads only its own commits. A file name holding one of the server's secrets (a value made secret after the note was written) reads `[redacted]` in the notes, the log and a run's diff.
- The server's learning code (`src/learn/`) gains `checkNote(path, bytes, refuseValues)`, which checks one note by itself, as a person writes it, and `retire(text)`, which marks a note retired.
