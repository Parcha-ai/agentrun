A boxd provider: `providerFor("boxd", { apiKey })` makes each computer a boxd machine, an isolated KVM microVM running Ubuntu 24.04, as a sandbox (kind `linux`, the default) or a desktop (`kind: "desktop"`, Xvfb started through the daemon). The daemon is a child of boxd's own agent, started with `--own-network`; network none is the machine's egress allowlist `["none"]`, read back, and the daemon's own network namespace. Its lifetime is the janitor's, by the deadline label; `extend` moves init's deadline and that label; `deleteTimer: true` adds boxd's own delete timer just past the most a computer may live, as a backstop. Settings takes `BOXD_API_KEY`, with `BOXD_ORG` and `BOXD_REGION` optional. A boxd computer takes no mount yet, so serve refuses a boxd sandbox in both modes and runs a boxd desktop in either. The host installs `@boxd-sh/sdk` (0.3.1); the package itself depends on nothing new. `AGENTRUN_COMPUTER_LIVE_BOXD=1 COMPUTER_BOXD_API_KEY=... npm run test:boxd -w @parcha/agentrun-computer` runs the conformance suite on real boxd.
