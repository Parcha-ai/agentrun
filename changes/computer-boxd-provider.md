A boxd provider, contributed by Michiel Voortman: `providerFor("boxd", { apiKey })` makes each computer a boxd machine, an isolated KVM microVM running Ubuntu 24.04, as a sandbox (kind `linux`, the default) or a desktop (`kind: "desktop"`, Xvfb started through the daemon). It is a `MachineHost` on the shared adapter, as E2B and Modal are: `src/boxd.ts` maps boxd's SDK calls, and the adapter does the computer's name, idempotent create, the daemon, the probe, extend and release. Network none is the machine's egress allowlist `["none"]`, set once the machine is ready, and the daemon's own network namespace. Its lifetime is the janitor's, by the deadline label, and boxd's own delete timer ends every machine at the adapter's backstop, 5 minutes past the most a computer may live. Settings takes `BOXD_API_KEY`, with `BOXD_ORG` and `BOXD_REGION` optional. A boxd computer takes no mount yet, so serve refuses a boxd sandbox in both modes and runs a boxd desktop in either. The host installs `@boxd-sh/sdk` (0.3.1); the package itself depends on nothing new. `AGENTRUN_COMPUTER_LIVE_BOXD=1 COMPUTER_BOXD_API_KEY=... npm run conformance -w @parcha/agentrun-computer -- --provider boxd` runs the conformance kit on real boxd, and `sweep.js --provider boxd` checks it left nothing behind.
