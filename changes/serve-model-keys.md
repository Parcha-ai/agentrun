A model provider's key is saved from the page like a tool key: `PUT /v2/settings/tool-keys/{anthropic|openai|openrouter}`, rows of `kind: "model"` in `GET /v2/settings/tool-keys` (the tool keys are `kind: "tool"`), kept sealed the same way. Every run gets it, as every run gets the launcher's model keys. With no `AGENT_MODEL`, such a key, saved or the server's own, now gives the default model, the first of `anthropic/claude-sonnet-5-5`, `openai/gpt-6.1-sol` and `openrouter/anthropic/claude-sonnet-5.5` whose key is here: each its provider's capable everyday model, not its dearest. claude-agent takes only the Anthropic one, codex only the OpenAI one, each harness's `default_model` in capabilities shows the one it gets, and `AGENT_MODEL` still wins for a harness that runs it: one that can't (claude-agent on a gateway's own id) takes its own key's default. Capabilities' `models` gain `ready`, whether a revision that names no model runs here, and `needs` (`key` or `model`, null when ready); both change with a key's save or delete, with no restart.
