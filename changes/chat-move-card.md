The chat view marks a planned move between hosts. Where the recording holds a host `handoff` line (a run released to its disk on one host and opened on another), the conversation's timeline holds one card there, between the last line of the generation that ended and the first of the next: "after the 5th charge on host-1 (daytona)" over "Moved to host-2 (daytona) from the same disk; the conversation goes on", or, where the holder's recorded label is the one it left, "Reopened on host-1 (local) from the same disk; the conversation goes on". It is read from fields only: the handoff's `point` and `n` (an `effect.kept <tool>` point reads "after the <n>th <tool>", any other point drops that clause), its `from`, and the holder of the generations' `run.json` lines (a host named only by its recorded `host-N` label, a driver only by a kind: local, daytona or modal). The handoff's prose, a process id and a boot id are never read, so none can appear; a `handoff.failed` line draws no card, and a run with no handoff line draws none. A move that happened while a folded conversation was the active one is drawn after that fold, in the run's own timeline. The process lane stays behind `?debug=durability`, and the Muse layout is unchanged.
