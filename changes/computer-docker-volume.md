`DockerProvider` takes a `volume: { name, root }` option for a provider that runs in a container of the Docker it drives, given its socket (the server under `docker compose`). Without it, `create` bind-mounted the daemon's copy and the run's folder by this process's own paths, which exist only in its container, so every Docker computer failed at create. With it, both are mounted as subpaths of the named volume `name`, which this process has mounted at `root`: `--mount type=volume,src=<name>,dst=…,volume-subpath=<path below root>,volume-nocopy`, read-only for the daemon, never the volume's root. A `daemonCache` that is not at or below `root` throws in words when the provider is made. `check` and `create` refuse, in words, a run folder that is not below `root`, Docker Engine older than 26 (`volume-subpath` needs 26 or later; the engine is read with `docker info` and is `host().engine`), and, for now, a network allowlist (its egress proxy's code is still bound from the package's build). `attach` and `list` read the run's folder back as the path below `root`, and the drift check holds both mounts to the volume's subpaths. Without the option nothing changes. `DockerVolume` and `VOLUME_SUBPATH_ENGINE` are exported.
