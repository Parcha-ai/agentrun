`DockerProvider` takes a `volume: { name, root }` option for a provider that runs in a container of the Docker it drives, given its socket (the server under `docker compose`). Without it, `create` bind-mounted the daemon's copy and the run's folder by this process's own paths, which exist only in its container, so every Docker computer failed at create. With it, both are mounted as subpaths of the named volume `name`, which this process has mounted at `root`: `--mount type=volume,src=<name>,dst=…,volume-subpath=<path below root>,volume-nocopy`, never the volume's root, and always a directory: the daemon is staged as `daemonCache/daemon-<sha256>/computerd` (with an empty `egress/`), and that directory is mounted read-only at `/opt/agentrun`, so the daemon is still `/opt/agentrun/computerd`. A `daemonCache` that is not at or below `root` throws in words when the provider is made. `check` and `create` refuse, in words, a run folder that is not below `root`, and Docker Engine older than 26 (`volume-subpath` needs 26 or later; the engine is read with `docker info` and is `host().engine`). An allowlist's egress proxy, whose code was bound from the package's build, gets that code staged below the volume's root first (`daemonCache/egress-<sha256>/`: `docker/` with the three modules and `package.json`, 0755 directories and 0644 files, written atomically and reused when identical) and mounts that one directory whole at `/code` as the volume's subpath, read-only. `attach` and `list` read the run's folder back as the path below `root`, and the drift check and the network read-back hold every mount to the volume's subpaths. Without the option nothing changes. `DockerVolume` and `VOLUME_SUBPATH_ENGINE` are exported.
