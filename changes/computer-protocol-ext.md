The computer protocol extension's types and conformance cases: a computer has a kind, a daemon mode and groups, and the suite's Core depends on them.
- `capabilities()` gains `kind` (`linux`, `desktop`, `android`, `ios`), `groups` (`exec`, `files`, `processes`, `screen`, `input.pointer`, `input.keys`, `input.touch`, `apps`, `apps.install`, `apps.ui_tree`) and `maxLifetimeMs`, and `daemon` becomes a mode (`pid1`, `child` or `none`) instead of a list. Hello reports `kind` and `groups` in place of `capabilities`; the drift check and Docker's `connect` refuse a hello whose kind or groups differ, in either direction. Docker declares `linux`, `pid1`, exec, files and processes, and a 30-day cap. Code that read `capabilities().daemon` or `hello.capabilities` reads `groups`; the `DaemonCapability` type is removed (use `Group`).
- `protocol.ts` has the screen, input and apps methods' types, `KEYS`, `UiNode`, `ComputerClient` (which `DaemonClient` implements) and a typed `deadline.extend`; `checkActions()` is the batch check of `input.actions`. `checkLifetime()` is one lifetime rule for every provider's `check()`, `kindRefusals()` names an invalid kind, os and daemon, and a provider may offer `extend()` (an earlier deadline, or one past create + `maxLifetimeMs`, is refused with the deadline unchanged) and `stream()`. The janitor deletes a computer whose deadline is more than `maxLifetimeMs` past now.
- `coreGroups(kind, daemon)` replaces `CORE_CAPABILITIES`. A Core case missing what its kind requires now fails in words instead of skipping; one missing an optional group skips, is named in `undeclared`, and is left out of Core's count. Thirteen new cases (`health.kind-consistent`, and the `screen`, `input`, `touch`, `apps` and `lifetime` groups) check effects against a fixture's event log, named with `--fixture`; on Docker the twelve that need a group or method it lacks skip in words, and Core reads `53/53`. `readPng()` decodes a whole 8-bit, non-interlaced PNG when it reads it, bounded by its IHDR. The report names the kind and daemon mode. The conformance `Group` type is now `CaseGroup`; `Group` is the protocol's.
