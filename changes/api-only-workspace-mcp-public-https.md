An API-only server can let a workspace save a `per_run` MCP server at any public https origin, not only at the origins `AGENTRUN_API_ONLY_MCP_ORIGINS` lists: set `AGENTRUN_API_ONLY_WORKSPACE_MCP_PUBLIC_HTTPS=1`. It is off by default, and off nothing changes. Under it, a workspace's token (the `AgentRun-Workspace` header) saves and previews `"auth": {"type": "per_run"}` at an https address off the list, and its runs use it. Plain http or any other scheme, headers, a bearer token, a Composio server and the token with no header stay at the listed origins, any other body the refused route's `404`.
Every request to such a server, at its save, preview and refresh and at each request of a run's calls, resolves the name again and goes only to a public address, the connection pinned to the address checked. It refuses loopback, private networks, CGNAT, link-local (cloud metadata included, `fd00:ec2::254` too), `0.0.0.0/8` and `::`, the IPv4-mapped form of any of them, and a literal address in any of them, whatever `AGENTRUN_MCP_ALLOW_LOOPBACK` or the owner's private hosts allow. It refuses the cloud metadata names by name. A name that resolves public at the save and inward later is refused at that request, with nothing sent. No redirect is followed. A refused save is `422 not_allowed` at `url`. `GET /capabilities` lists the switch under `switches`.
