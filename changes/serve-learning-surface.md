Learning you can see, through the API (`learning/2`, additive): a run's `learning` block, on `GET /v2/runs/{run_id}` and in every run list, gains `used` (the notes the run's job read from `.learning/`, found once as it settles from its timeline on any harness and kept in `serve.json`, never `MEMORY.md` nor a read of its end-of-run turn) and `learned` (the notes its merge added, with the notes each superseded), each absent when it holds no note and cut of the server's secrets as they are now. `GET /v2/agents/{agent_id}/learning` gains `impact`: the agent's completed runs before its first note against those that started from one, each side's run count, median run time and median cost, from the runs' rows and the learning ledger (whose line now carries `seed_notes`), null unless both sides count 2 runs. Every learning `detail`, and the run's learning row in its timeline, which now says the same, is in a person's words ("Started from 2 notes.", "Learned: Check units (replaces 1 older note)", "Nothing new to remember from this run.", "Not kept: <the grader's reason, its first sentence>"); the reason codes do not change.
