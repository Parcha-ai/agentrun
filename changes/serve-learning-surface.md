Learning you can see, through the API (`learning/2`, additive): a run's `learning` block, on `GET /v2/runs/{run_id}` and in every run list, gains `used` (the notes the run's job read from `.learning/`, found once as it settles from its timeline on any harness and kept in `serve.json`, never `MEMORY.md` nor a read of its end-of-run turn) and `learned` (the notes its merge added, with the notes each superseded), each absent when it holds no note and cut of the server's secrets as they are now. `GET /v2/agents/{agent_id}/learning` gains `impact`: the agent's completed runs before its first note against those that started from one, each side's run count, median time to the answer (before the run looks back), median job cost without the look-back (with `cost_runs`, the runs whose cost is known) and median of what learning itself cost a run (`median_learning_usd`: its look-back and its grade), from the runs' rows and the learning ledger (whose line now carries `seed_notes`, `answered_at`, `job_cost_usd` and `look_back_usd`), null unless both sides count 2 runs. Each note in the agent's view and its pages carries its `etag`, the one its file's GET answers, and each run list's row carries the run's learning `detail`, cut to 140 characters. Every learning `detail`, and the run's learning row in its timeline, which now says the same, is in a person's words ("Started from 2 notes.", "Learned: Check units (replaces 1 older note)", "Nothing new to remember from this run.", "Not kept: <the grader's reason, its first sentence>"); the reason codes do not change. The end-of-run turn's message reads "Looking back on this run." in the timeline, never the prompt the model is sent, and `GET /v2/runs/{run_id}/learning` carries `used` and `learned` too.
