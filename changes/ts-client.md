New package `@parcha/agentrun-client`: a typed TypeScript client for a self-hosted AgentRun server, with no dependencies (fetch, Node.js 22.19 or newer). `new AgentRun({ baseUrl, apiKey })`, defaulting to `AGENTRUN_BASE_URL` and `AGENTRUN_API_KEY`, has a method per operation the server offers, grouped as the CLI's commands are (`client.agents.create(body)`, `client.runs.start(agentId, body)`, `client.runs.raiseCap(runId, body)`), with request and response types from the server's OpenAPI document. It reads no file: finding the server started on this machine stays the CLI's.
- `client.runs.wait(runId, { timeoutMs, signal })` long-polls the timeline and resolves to the run once it ends or waits on a person; past `timeoutMs` it throws `AgentRunTimeout` and the run goes on. `client.runs.follow(runId)` is an async iterator of the timeline's pages over its event stream, resumed with `Last-Event-ID`. A download resolves to its bytes as a `Uint8Array`, or to the `Response` with `{ stream: true }`. An operation whose answer carries an ETag (`agents.get`, `agents.update`, `learning.read`, `learning.write`) resolves to `{ body, etag }`, the `etag` for a later write's `If-Match`.
- One error class per outcome: `AgentRunRefused` (`status`, `code`, the server's `error` object), `AgentRunAuthError`, `AgentRunUnsupported`, `AgentRunUnreachable`, `AgentRunUsage` and `AgentRunTimeout`. No message holds the API key or the server's message text, and the key is cut from the error object. A key that is not a valid header value, a base URL with a query, fragment or credentials, and a path argument with a `.` or `..` segment are refused before any request.
- The key goes only to the base URL's origin: a redirect is followed only for a GET within it. A GET, or a request with an `Idempotency-Key`, is tried again after a 429, a 5xx or a dropped connection (a body cut midway included), never sooner than `Retry-After`; anything else is sent once. `runs.follow` waits out a gateway's `Retry-After` before it reconnects. A secret body (`toolKeys.save`, `mcpServers.save`, `mcpServers.preview`) has its values cut from the answer as JSON values, and a refusal of it keeps only its code.
- `node scripts/generate-clients.mjs` writes `packages/client/src/operations.generated.ts` from the same projection and resource map as the CLI's command table, and `--check` covers it. The projection now holds each request body's and JSON answer's type, so every generated file's hash moves when a type changes, and not when a description does.
- Upgrading: the launcher's README names `@parcha/agentrun-client` as the TypeScript client for this server.
- Upgrading: `mcp-servers oauth-start` is removed; start an MCP sign-in from the console. The sign-in's callback requires the cookie its start's answer sets, so a start from the CLI or a client can never finish. A raw `api` call to its route still takes its body only from stdin or a file.
