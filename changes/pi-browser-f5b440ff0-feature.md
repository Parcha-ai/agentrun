`@parcha/pi-browser`: a live view for the cdp provider, from the new `@parcha/pi-browser/live-view` export. `createLiveView` serves a viewer page and a loopback WebSocket for one person at a time: the first message must be the hello with the session's token, a wrong or missing token, a bad Origin or a second viewer is refused, the screencast frames are never written anywhere, the viewer says it is connecting and refuses input out loud until it is ready, and the view ends when the session is released. `liveViewProvider` wraps the cdp provider and reports the viewer's URL to `onSession` and nowhere else. While a person drives the viewer, every browser tool call (and `browser_release` and `browser_relaunch`) is refused with a typed, retryable `person_driving` before it does anything, the person's input is discarded while the agent acts (one shared gate per session, `drivingGates`), and an idle window never releases a session a person drives or watches. Custody can hold a session for a person behind a per-session fence: `CustodyPort` gains `current()`, a page action the fence stopped before any driver call got through is settled as not sent, and a held session the provider ended no longer holds up the conversation. `FrameRecorderOptions.hold` keeps a person-driven session out of the recording (one `frame.gap` marks the span), and when a hold lifts one frame is captured on demand so the replay does not end at the hold. `RunAction` types the actions of `run` per op. `browser_upload` runs behind a `WorkspaceFiles` port (it refuses swapped parents, pipes and host-private files, and is journaled like a run), `browser_downloads` works, and a `use_website` child is offered neither. A site child's browser can be the session the host reserved for it: the new `@parcha/pi-browser/providers/assigned` export never creates or ends a browser, takes its assigned session as the run's only browser, and is never relaunched or idled away. A screenshot's result carries the captured image's own facts in `details.media` (`kind`, `path`, `mime`, `bytes`, `width`, `height`, `ask`), and a screenshot can capture one region, by clip, snapshot id or CSS selector. The index exports custody's vocabulary, and a session's record and `relaunch`'s answer say the settings the provider applied. `browser_request_handoff` hands the browser to a person for a step only a human can do, such as a 2FA or a captcha, and waits durably for the host's answer. It is listed only when the host gives a `HandoffPort`, a rerun never asks again once the answer is kept, `done`, `cancelled` or `expired` give the session back under a new fence, and every other call answers `waiting_for_human` meanwhile. A refusal from the port, or a failure before it answers, gives the session straight back.
