Learning's live checks run on real models every Monday and on demand (`Learning live weekly`, never on a pull request): the grader on the held-out eval set over the grade models the variable `LEARNING_LIVE_GRADE_MODELS` names (`learn-eval.mjs --set heldout --grade-models`), and one seed of the learning bench on pi (`learn-bench.mjs`). Each has a dollar cap, and the run fails when either stops at it. Results are kept as an artifact, and the summaries are the run's job summary. It runs only where the repository has the secrets `LEARNING_LIVE_MODEL_BASE_URL` and `LEARNING_LIVE_MODEL_API_KEY` and the variables `LEARNING_LIVE_MODEL` and `LEARNING_LIVE_GRADE_MODELS`; elsewhere its summary says which are missing. `learn-eval.mjs` takes `--max-usd`: it sends no further model request once its spend reaches the cap, or once a request's cost can't be read, and exits 3. `learn-bench.mjs`'s `--max-usd` is read before each step: a step starts only when the server's spend so far, learning's grades included, plus that step's worst case (its run's cap and its graders' caps) fits under it, so only a step's learning grade, which has no cap of its own, can pass it. A bench that stops at its cap, its deadline or a lesson that did not settle exits 3; before, it exited 0. Upgrading: nothing to do.
