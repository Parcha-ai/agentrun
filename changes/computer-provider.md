`DockerProvider` finds, checks and sweeps computers. `attach({ id } | { labels })` finds exactly one computer, `list(labels)` reads back each one's labels, deadline, state and network, and `network(ref, policy?)` reads the network back (`none`, `open`, or anything else in words) and refuses any change, since a Docker computer's network is fixed at create.
- `create()` ends with a drift check, `drift(spec, inspected, hello, expected)`: the network, dropped capabilities, `SecurityOpt` exactly `["no-new-privileges"]`, private IPC and cgroup namespaces, the `runc` runtime, Docker's masked and read-only paths, the pids, memory and CPU quota (with serve's defaults when the spec names none), the user it runs as, the image, workdir and `HOME`, exactly the `/work` and `/run/agentrun` tmpfs mounts with that user's uid and gid, mode 0700 and their sizes, the read-only daemon mount and no other mount (an image's `VOLUME` included), the entrypoint and `init --deadline <the label's deadline>`, the labels, the host's AppArmor profile or SELinux label, and hello's version, os, capabilities and architecture must match what was declared, or the computer is deleted and `create()` refuses with every mismatch in words.
- The drift check is closed: every other `HostConfig` and `Config` field, one a later Docker adds included, must be Docker's empty default (`PidMode`, `UsernsMode`, `Devices`, `Sysctls`, `OomKillDisable`, `PortBindings`, `ExtraHosts` and the rest), but for a few with a stated default (no restart policy) and a few that widen nothing (the log driver, `ShmSize`, `Ulimits`, the image's own settings). `inspectDrift` is its inspect half. `create` now passes `--ipc private --cgroupns private`.
- `host()` and `hostOf(info)` read the Docker host once per provider: its architecture, AppArmor and SELinux, and whether it enforces memory, swap, pids and CPU limits and has seccomp, not unconfined. `create()` and `attach()` refuse a host that lacks any of these in words before any other Docker call ("this Docker host does not enforce memory limits, so a computer's memory size is only configuration"), and `check()` does too once the host is read.
- `attach()` runs the same drift check on what it finds, inspect and, when the computer runs, hello, against the spec read back from the computer and held to what `check()` allows, and refuses a computer that drifts with every mismatch, leaving it as it is.
- `/work` is a tmpfs of half the computer's memory (`size=2048m` by default) and `/run/agentrun` one of 1 MiB, so filling `/work` fails with "No space left on device" instead of an OOM kill.
- The provider's `user` option refuses root's group as well as root (`"1000:0"` throws), and the default user is this process's uid:gid only when neither is 0, else `1000:1000`. A spec may still ask for gid 0.
- `create(spec, { signal })` honours the signal throughout: an abort during `docker info` makes nothing, and one while inspect or hello is pending deletes the computer and returns `aborted`, never ok.
- `list()` inspects 50 computers at a time and reads only the fields it reports, so a large fleet is listed (and swept) whole.
- `connect()` refuses a daemon of another version, or one missing a capability the provider declares.
- `sweep(provider, { labels?, now? })` deletes the computers of a `lifetime: "janitor"` provider whose deadline has passed or is missing, stopped (as a computer is once its deadline ends it) or running, and keeps the rest; it refuses a provider whose vendor ends computers itself. A caller runs it on a schedule.
