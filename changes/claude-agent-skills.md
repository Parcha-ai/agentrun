A host's skills reach the Claude Agent model: `claudeAgentAdapter({ skills: [{ name, files }] })`. Each session writes them as a local plugin in its own private directory and starts the CLI with that plugin and those skills alone (as `agentrun:<name>`), still with no settings sources, so the CLI's bundled skills and any skill in a home directory are neither listed nor loadable. With skills the model is offered the Skill tool, which the session's tool proxy now lets through; without them it is not. A loaded skill survives a crash: it is part of the history the session store restores. The skills are checked when the adapter is made (`skillProblems`): plain names, a `SKILL.md` whose front matter names the skill and describes it, plain relative paths, 1 MiB in all. With skills the model also gets `read_skill_file` (`readSkillFileTool`, from `@parcha/agentrun-kernel`, for any harness): a read-only, replay-safe host tool that reads one of a skill's own listed files, exactly. A path that climbs (`..`) or is absolute is refused before any filesystem call, an unlisted path or another skill's file is refused by name, and no link is followed anywhere in the path (checked part by part, opened without following one, and checked again after the open).
