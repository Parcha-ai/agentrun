The computer library reads no environment: every provider is built by its file's `create(options)`, and every setting, a vendor key included, is an option. `ENV`, `fromEnv`, Daytona's `optionsFromEnv`, Modal's `modalServerUrl` and the registry's `providerFromEnv` are gone; `providerFor(id, options)` builds a provider by id. Daytona's API URL (default Daytona's own) and target are `apiUrl` and `target`; Modal's token, app and server are `tokenId`, `tokenSecret`, `app` (required, refused in words naming the option) and `serverUrl`; E2B's key is `apiKey`. Serve passes its own existing names at the cutover (`DAYTONA_API_KEY`, `DAYTONA_API_URL`, `DAYTONA_TARGET`, `MODAL_TOKEN_ID`, `MODAL_TOKEN_SECRET`, `AGENTRUN_BOX_APP`, `AGENTRUN_DOCKER_IMAGE`, and `E2B_API_KEY` as its new one), so an owner's settings keep working. Only `src/conformance/` (the conformance CLI, each provider's conformance module and the sweeps) reads the `COMPUTER_*` names, through each module's `settingsFromEnv(env)`, so the live scripts run unchanged. A default never comes from the environment either: Docker's `daemonCache` defaults to `~/.cache/agentrun-computer` and no longer reads `XDG_CACHE_HOME` (pass `daemonCache` to keep the copy elsewhere; the conformance CLI reads `COMPUTER_DOCKER_DAEMON_CACHE`). Two guards stay, each against a vendor SDK that reads the environment on its own: Modal's provider refuses an ambient `MODAL_SERVER_URL` and sets it only around the client's construction, now one construction at a time and put back after each; E2B's refuses an ambient `E2B_SANDBOX_URL`. `scripts/check-env.mjs` reads `src/` with TypeScript's parser and fails on any other use of `process.env` outside `src/conformance/`.
