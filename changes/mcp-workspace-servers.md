On an API-only server, a request in a workspace (`AgentRun-Workspace`) is served the MCP servers' list, names, read, preview (of its own server, or an address at the operator's MCP origins), save, Composio save, refresh and delete, and reaches its workspace's own servers alone: another workspace's server of a name reads as a name never saved, a save of the name makes the workspace's own, and its agents reach their own server of a name before the install's shared one. A workspace's server is kept as `<workspace>/<name>`, with no schema change, and its sealed credential is bound to that row. A save in a workspace is of an address at the operator's MCP origins: `per_run`, or `headers` or `bearer`, whose credential is sealed in the workspace's own row and sent by its own agents' runs alone; or a per-run Composio save with `api_key_env` (a `user_id` of its own or an `auth_config_id` is 422 `not_allowed`). The token with no header still writes no credential. A workspace's sealed server at an origin taken off `AGENTRUN_API_ONLY_MCP_ORIGINS` can't be used, and a run already going stops sending its credential at its next call, as with a token's `per_run` server; its preview or refresh by name is the refused route's 404, nothing sent. A run started on a workspace's agent checks its `mcp_auth` against that workspace's servers, whoever starts it. A delete removes at Composio only what no server in any workspace stands on. A run's claim still refuses a binding to a Composio user the owner calls as when the owner's shared server stands behind the workspace's own server of that name, saved after the run was queued.
