`@parcha/pi-browser`: a `web_fetch` backup's refusal (a private or local host, too many redirects, a redirect out of http(s), a page that is not text, one over 5 MiB) reaches the model as `refused`, not as a retryable `command_failed` that said "Try once more". A provider's 429 on a create or an attach is `rate_limited` on the browser plane, as it already was on the web plane (retryable when the call acted on nothing; an effectful call says to take a snapshot first). The coding agent refuses a whitespace-only Browserbase or Kernel key as `auth`, naming the key, as the providers read keys. The provider reset also lets go of profile writer claims, so a claim left before a reset no longer refuses a later session. `directFetch` is undici's fetch with no silent fallback to the proxied global fetch: a failed undici load is a broken install and now throws. The live-grid and ask-site examples (in the repository, not the npm package) keep a tile on the open page after a popup closes, run through a symlink, import cleanly from a script read through stdin, and work on an IPv6 host. The rest of the batch changes no behaviour: one way to build a refusal in core, `BrowserFailure` declares `next` and `evidence`, the failure classifier reads facts through one typed reader, the two hosts share their keep-for-a-person and redaction rules, and the extension worker, the sealed Stagehand's create-once-more step and the pi-durable adapter's internals are named, tested modules.
