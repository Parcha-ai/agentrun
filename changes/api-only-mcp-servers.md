An API-only server (`AGENTRUN_API_ONLY=1`) saves Composio MCP servers with the server's token and deletes the MCP servers that token saved, and never writes a secret doing it. A Composio server is saved with `"api_key_env": "COMPOSIO_API_KEY"` in place of `api_key`: the server keeps the variable's name, never its value, and reads it at each use (the save's calls to Composio, each run's connection, a delete's), as the server and each runner were started with it, so a new value takes effect when they start again. `COMPOSIO_API_KEY` is on the launcher's list of secrets: it reaches the server and each runner over the launcher's pipe, neither process's environment holds it, and no run is handed it. The runner sends it only as the MCP header of a Composio server the run is granted a tool of. The token deletes only a server the token saved: one the owner saved, sealing a credential or not, is `403` to the token on every server, it stays, and nothing is sent to Composio. Any other name is `422 invalid` under `api_key_env`, an unset or blank variable `422 missing`, and a run of a server whose variable is unset is refused before it starts (`409 agent_not_runnable`), naming it. That key is only ever sent to Composio's own origin, fixed in code: a server whose saved address is anywhere else is refused by name at a save, a refresh and a run's start, and nothing is sent. A Composio save's body names no address or headers (`url` or `headers` is `422 not_allowed`, on every server). The token lists the saved servers through `GET /settings/mcp-server-names` alone; it has no list or read of a server. `api_key` from the token stays `403`, as does the token's `api_key_env` on the full server, where the owner's signed-in session saves a Composio server either way.

The token also saves a `per_run` server (`PUT /settings/mcp-servers/{name}`), which keeps no credential (each run hands its own), at an origin the operator lists in the new `AGENTRUN_MCP_TOKEN_ORIGINS`: comma-separated exact origins, each `https://host[:port]`, or one `http://127.0.0.1:<port>` (or `http://[::1]:<port>`) that counts only with `AGENTRUN_MCP_ALLOW_LOOPBACK=1`. An entry with a path, query, fragment, user or wildcard stops the server's or runner's start, in words; unset, no origin is listed. An address at any other origin (a lookalike host, another port, a path that names a listed one) is `422 not_an_option` under `url`, naming no listed origin; any `auth.type` but `per_run`, or none, is `403`. The save's `toolkit` is recorded, so a template's need for that toolkit maps onto the server at an apply, and the token may delete the server. Each run's claim checks the server's origin against the runner's own list again: one no longer listed is refused by the server's name, and nothing is sent.
