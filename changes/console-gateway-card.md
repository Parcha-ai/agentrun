On a server that sends its models to a gateway, the first screen's card no longer offers the ChatGPT sign-in or a provider key where neither runs an agent: with no gateway model named it says to name one (AGENT_MODEL, or Settings → Model keys → Use a model gateway), and with a gateway address AgentRun refuses it says why, in the server's words. `GET /v2/settings/model-gateway`'s `problem`, which Settings → Model keys → Use a model gateway shows too, now gives every refusal a run meets, Particle's API among them, not only the address rule's, and saving a gateway there refuses Particle's API the same way. The card reads that view again with each new read of the capabilities, so an address fixed at a restart stops showing refused. Where the gateway server's own default is a plan model (`AGENT_MODEL=chatgpt/…`), the card offers the ChatGPT sign-in, which runs it. A plan model a gateway names under its prefix (`agent-model/chatgpt/…`) reads as the plan's ("… · on your ChatGPT plan") wherever a model is labelled.
