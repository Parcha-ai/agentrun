CI builds once per Node version and shards the tests by time. A `build (<node>)` job runs `npm run build` and packs its output (every workspace's dist and the console's, about 10 MB) for the jobs that test it; each of those still runs `npm ci`, then unpacks the output and refuses one built from another tree or on another Node (`scripts/ci-build-output.mjs`). The test shards and the pi legs' parts get their files from `scripts/ci-plan.mjs`: each suite's test files, weighted by `scripts/ci-timings.json` (seconds from CI's own logs, refreshed with `node scripts/ci-timings.mjs <job logs>`), assigned longest first to the shards of their pool (`scripts/ci-shards.json`). Every shard job plans every shard and fails unless they cover each test file once, so a new package or test file runs without an edit. `checks` is split into `checks`, `packages` (verify-packages) and `source` (the downloaded source's consumer), which ran one after the other. The pi legs run as a consumer job and seven parts per pi version (`pi-leg.mjs --shard`), which build what they test themselves and do not wait for the build job. The required checks `verify (22.19.0)`, `verify (22.23.2)` and `lean` keep their names and what they gate.
