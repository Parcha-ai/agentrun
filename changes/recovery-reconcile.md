`@parcha/agentrun-dsl/recovery`: `RecoveryOptions.reconcile` lets a host settle the effects a killed process left unknown through the driver's own open of the run. `openRecovery` calls it once, after the open and before anything resumes, with the unknown effects (each with its `intent`, `args` and any `calls` it kept) and a `complete(id, value, receipt?)` that records one's result, `receipt` being `{ intent?, calls? }`; a settled effect is answered from it and never dispatched again, one left unknown is refused as before (`FROZEN_EFFECT_UNKNOWN`), and a throw fails the open with `RECOVERY_RECONCILE_FAILED` (cause kept) before anything is dispatched. An effect now keeps the arguments it was admitted with (`RecoveryEffect.args`, an optional field on the `agentrun.effects` record; `RecoveryStore.admit` takes them as a seventh argument), so a call the host's door never received can be re-sent from `reconcile`'s list, and `complete(id, value, receipt)` takes `receipt.calls`, the call records (`{ outcome: "applied" | "failed" | "unknown", ... }`) the host made or found applied while settling the effect, so that its calls list every applied call once, which the driver keeps on it before it completes, as a dispatch keeps its own, after the calls an earlier process kept (`RecoveryEffect.calls` carries them from the journal); a record written before has none and reads as it did. A host that opened the journal itself before the driver (`documentStore().open`) raised the run's generation twice per process; with `reconcile` it is one per process. `WorkflowTaskHost.options` passes it through and is told its `phase`: the task's abort handler opens the driver too, so `reconcile` also runs during a cancel unless the host returns none for `"abort"`. The stored format changes only by the one optional `args` field on `agentrun.effects` (document version 1, no version bump): additive, and a reader that does not know it reads the record as before.
