`npx @parcha/agentrun` keeps its data in `~/.agentrun` wherever it is run, so a new folder is not a new install: an earlier version's `~/.agentrun` stops the start ("holds an earlier version's data", or a store an earlier release set up). Started that way, the refusal now gives the two ways on as commands to paste. First, `mv` of the old folder aside whole, after which the same command starts fresh where it was, every later command finds it with no `--data`, and the earlier version still opens the old data with `--data`. Then the same command on a new, empty folder (`npx @parcha/agentrun@<version> --data <folder>`, a folder that is not there yet), which each later command then takes too. Nothing is deleted either way, and an earlier installer's `bin/agentrun` in that folder is said to move with it. The README's first step says the data is in `~/.agentrun`, not the folder you run it in.

Two servers on one machine no longer sign each other out. On plain http the console's session cookie was named for the server's own socket port, which is 7340 for a server in a container whose 7340 is published at 7350, the same as `npx @parcha/agentrun` on 7340 beside it, and cookies are kept per host, not per port. It is now named for the port the browser opened (the Host header's: `agentrun-7350-session`), and a Host with no port keeps the socket's. A server opened at a port other than its socket's (a published container port, an `ssh -L` tunnel) asks for one sign-in again after the upgrade. https keeps `__Host-agentrun-session`. Signing out through one port ends the same browser's sessions with that server at its other ports too (a browser sends a host's cookies to every port), and clears each; another server's cookie on the same host is left as it is.
