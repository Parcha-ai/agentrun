New package `@parcha/agentrun-import`: the session readers serve's import used (Claude Code, Codex, pi), as a library of their own, with a registry a new source joins in one line. A reader discovers locators (`{ file, id? }`, the id for a file that holds many sessions) under a home and reads one into sessions from a cursor it owns. serve's import, its summary, eval-previous and the remote history export now read through it; `import-sources.ts` is gone from serve. What changed in the numbers:
- Claude Code: a session's id is its file's name, as Claude Code names it; serve took the first record's `sessionId`, which put a resumed session's file that opens with a copied record under the session it copied from. A record copied into a later file counts only in the first, and a file holding nothing but copies is no session. A request's key is now its message id with its request id; a store imported before holds the bare message id, which still marks a later file's copy of that request, so it is not counted twice.
- Claude Code: a request written as several lines (one per content block, same `message.id` and `requestId`) counts at its last line's usage, which holds the final counts; serve took each field's largest value across the lines (`most()`), which could pair one line's input with another's output.
- One usage reading for every source, `normalizeUsage`: `input` is the input neither read from nor written to the cache (Anthropic's `input_tokens` as written; OpenAI's and Codex's with `cached_input_tokens` taken out), `cacheWrite1h` its own bucket, and `reasoning` kept beside `output` where the source gives it. Codex counts each request's `last_token_usage`, never `total_token_usage`.
- `parseHome(home, { sources })` returns each session's totals, its subagents' requests counted under it and not again as sessions of their own (a subagent whose session is not under the home is a line of its own, with no turns of the person's). A JSONL file's cursor (device, inode, byte offset) lets a second pass read only the bytes appended since; a truncated or replaced file is read from its start, and a last line still being written is not consumed. A second pass returns what a fresh one would: when a file holding a copied record now comes before the file it counts in, the source is read again.
- `node packages/import/dist/cli.js <home> [--sources claude-code,codex,pi] --known-answer` prints one JSONL line per session, sorted by key (the sha256 of its path relative to the home): tokens, cost (null when unknown), turns and calls. Numbers only: no content, titles, directories or paths. `--help` prints the usage and exits 0. A file that cannot be read prints no answer: one stderr line per file (source, key, error code) and exit 1; `parseHome` hands such files back in `failures`, or throws `ReadFailures` without it. The CLI imports pi-ai statically for its prices (a dependency of the package, so `npx @parcha/agentrun-import` runs it), so it compiles with `bun build --compile` (pi-ai bundled) and prints the same bytes as under Node; without pi-ai the build or the run fails instead of pricing nothing.
