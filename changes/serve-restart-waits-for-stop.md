A server started on a data root whose server is still stopping now waits for that stop instead of refusing. A stop keeps the data root until its runs' processes have drained and exited, which takes up to the drain timeout and a second (31 s by default), and the API keeps answering, with runs `working`, meanwhile. A start in that window used to exit at once with "another server holds this data root: stop it". Now a stopping server prints `agentrun-serve: stopping: waiting up to N s for N runs to finish their turn` as its close begins, when runs' processes are left to finish, and writes `<data>/server.stopping` (its pid, and when its stop is over at the latest), which it removes as it ends. A start that finds the lock held reads that file, prints `agentrun-serve: the server on this data root (pid N) is stopping; waiting for it, up to N s`, takes the lock once the stop is over, and opens the runs the stop cut again. A start on a data root whose server runs is refused at once, as before, and so is one whose mark names a process that is gone or a time that has passed. `startServe` takes `notice`, called with both lines in place of standard error.
