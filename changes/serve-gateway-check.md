A model gateway the server cannot reach is now said when it starts and when a definition is saved, not 15 s into a run's first request as "Connection error." with no address. With `AGENT_MODEL_BASE_URL` set, the server asks the gateway `GET <base>/models`, which runs no model and costs nothing. When the gateway does not answer, or refuses the key (401 or 403), the start writes a line to stderr and the save's `201` or `200` carries a `not_set_up_here` warning at `definition.model` (or `definition.workflow`). Each names the address (without any user or password it carries), the cause and the fix; a loopback address also says that a container's loopback is its own. A workflow with no model node never asks the gateway. A gateway that answers anything else, a 404 included, passes. The warning does not refuse a run, which tries the gateway again. The serve README's "A gateway on this machine" gives the `docker run` line for a gateway on the host's loopback: `--network host`, with the server kept on `--listen 127.0.0.1`.
