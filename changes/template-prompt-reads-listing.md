The console's template prompts ("Use this template", "Run", "Set it up with an agent") and the `agentrun-serve` skill's "Create an agent" section now send a coding agent to the template's entry in `GET /v2/templates`, not to the whole package at `GET /v2/templates/{template}`. The entry has what an apply needs (parameters, defaults, secrets, MCP servers, tool grants, harness, model, triggers, budget), and none of the package's instructions or skill files. The Run prompt no longer reads the created agent's definition before its run, because the definition holds the package's instructions. If a requirement goes beyond the apply schema, the prompts now name it as a separate change the user can ask for. They used to propose a revision of the definition. An imported package's instructions and skill files are a third party's text, and they no longer reach the coding agent. Applying still copies them to the new agent. This reverses #3439's pointer to the package's own URL. `template get` and `GET /v2/templates/{template}` still read a package whole, so a person can read it before applying, and their summary still says the text is the new agent's, not instructions to the reader.
