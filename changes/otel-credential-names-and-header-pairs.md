OTLP redaction catches more credential names and the credentials inside a header value. A query parameter or header named `apiKey2` or `token2`, a lowercase compound starting with a credential word (`tokenvalue`, `passwordhash`, `jwtpayload`), `jwt`, `session`, `sessionid` and names ending in `passwd`, `pwd` or `authorization` are now named like credentials, so an OTLP endpoint's such parameter is held; `tokens`, `sessions` and `sessioncount` are not, and every name ending in `key` is held as before. Inside any `OTEL_EXPORTER_OTLP_HEADERS` value, a credential-named `name=value` pair's value, read over the whole value with a URL's query and fragment included (a cookie's `session=<token>`, `?region=us;session=<token>`, `#access_token=<token>`, sentry's `sentry_key=<key>` without the comma after it), and the user, password and key parameters of every URL in it (a DSN's `https://<key>@host/1`, a URL nested in another's query or path, a scheme-relative or slash-escaped one; a quoted URL ends at its closing quote, an unquoted one is also read past a quote to the next space, and its password is read whole as RFC 3986 reads it, with any `;`, `&`, `=`, `,`, `'` or `@` in it, as written and decoded) are held and cut from the tracer's `[otel]` lines alone, where before only the whole value was, so an exporter's error quoting the token alone printed it; a harmless pair such as `theme=dark` is left. A value with thousands of `@` reads at most 16 of its userinfo's readings, so the tracer still starts at once. The serve README lists every word.
