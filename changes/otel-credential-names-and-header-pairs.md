OTLP redaction catches more credential names and the credentials inside a header value, and no longer holds a value only because its name ends in `key`. A query parameter or header named `apiKey2` or `token2`, a lowercase compound starting with a credential word (`tokenvalue`, `passwordhash`, `jwtpayload`), `jwt`, `session`, `sessionid` and names ending in `passwd`, `pwd` or `authorization` are now named like credentials, so an OTLP endpoint's such parameter is held; `tokens`, `sessions` and `sessioncount` are not. Inside any `OTEL_EXPORTER_OTLP_HEADERS` value, a credential-named `name=value` pair's value (a cookie's `session=<token>`) and a URL's user, password and key parameters (a DSN's `https://<key>@host/1`; a quoted URL ends at its closing quote, and its password is read whole as RFC 3986 reads it, with any `;`, `&`, `=`, `,` or `@` in it, as written and decoded) are held and cut from the tracer's `[otel]` lines alone, where before only the whole value was, so an exporter's error quoting the token alone printed it; a harmless pair such as `theme=dark` is left. A lowercase `*key` name is held only after a word that names a credential (`apikey`, `accesskey`, `secretkey`, `privatekey`, `writekey`, `clientkey`, `authkey`, `signingkey`, `subscriptionkey`, ...); `routingkey`, `sortkey`, `primarykey`, `partitionkey` and `cachekey` are no longer held. The serve README lists every word.
