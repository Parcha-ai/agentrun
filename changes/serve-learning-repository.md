AgentRun Server keeps a learning repository for each agent that learns. A run of that agent starts from the repository's `main` at one commit, and once the run's end is carried back the server leaves its branch `runs/<run id>` there with a memo.
- `learning` is this server's own definition field, as `model` is. Its values are `auto` and `approve`, and it is for agentic agents only. A new agentic agent gets `auto`, stored in its revision. An edit that leaves the field out keeps the current value, unlike every other field, and `learning: null` turns it off. A revision without the field does not learn, and its id is unchanged (`AgenticBody.learning` and `LEARNING_MODES` in `@parcha/pi-durable-agent`). A workflow definition with `learning` is `422 not_an_option`. The `learn` tool comes with learning, so naming `learn` in `tools` while learning is off is a `422` with that fix.
- Learning needs git 2.40 or later on `PATH`. On a host without it, a new agent does not learn, a definition that asks for learning saves with a `not_set_up_here` warning, and its runs are refused (`409 agent_not_runnable`).
- The repository is a bare git repository at `DATA/agents/<id>/learning.git`, beside the store, and no tool of a run reaches it. Its `main` carries `AGENTS.md` and `agent.json` for the agent's current revision. The server writes them as one commit, with a `Revision` trailer, whenever the current revision changes. Every write to the repository goes through one queue per agent.
- A run's process resolves `main` once and journals that commit in the run's store, so a run opened again keeps its base. The notes active at that commit go to `work/.agent/learnings/` and into the `<learned>` section of the prompt, and the skills the agent wrote join the revision's own; a revision skill of the same name wins.
- Once a run's end is carried back, the server proposes what the run learned as `runs/<run id>` from that commit, and records the proposal in `DATA/agents/<id>/learning/runs/<run id>.json`. The memo's front matter is `run`, `base`, `harness: pi`, `outcome` (`completed`, `failed` or `stopped`), `untrusted` (the run called an external tool) and `cost_usd`. A failed proposal never changes how the run ended. At start, the server proposes every ended run of a learning agent that has no record yet, and the `Run-Id` trailer makes a second proposal of the same run add nothing. Nothing merges into `main` yet.
- `@parcha/pi-agent-learn` adds `readCandidates(store)`: a run's candidates, read from its store file once no process holds it open.
