An Orgo desktop provider (`orgo` in the registry, its Settings entry the desktop kind with `ORGO_API_KEY`, no mount, metered): `create({ apiKey, workspaceId })` makes Linux desktops on Orgo with computerd inside, on Orgo's own X display, so a desktop speaks the same protocol as every computer. It reads no environment: serve passes `apiKey` from its `ORGO_API_KEY` setting. The module exports `CAPABILITIES` and `MOUNT` (`[]`), and `testConnection()` is one read of the workspace's computers, which makes nothing.
- It declares a Linux desktop (exec, files, processes, screen, input.pointer, input.keys), daemon child, network `"none"`, lifetime `janitor` (Orgo ends a computer only in whole hours, so `ends_in_hours` is the backstop and the janitor deletes it at its exact deadline), release `delete`, `extend`, `vendorAgentPorts` (Orgo's VNC 5999, websockify 6080 and desktop API 8080), and no mount yet.
- Orgo has no egress control, so the tools' isolation is init's own network namespace (`computerd init --own-network`): network none is read back from inside, by a probe refused at the outside and, on both loopbacks, at the declared ports and every TCP port root listens on in Orgo's own network (read at create and named in its notes).
- Before init starts, `create` makes every path unix socket of Orgo's desktop root's alone (owner root, mode 0600) but the display's own and computerd's, and names them in its notes: the tools reach the X server and nothing else. A socket it cannot lock, or a scan that fails, refuses the create and deletes the computer. Root's D-Bus buses were open to the tool user, and polkit over the system bus is a known privilege door.
- Each deployment's computers live in one Orgo workspace. A computer's name, `computer-<12 hex>-r<the run's hash>-e<the epoch>-d<its deadline in base-36 seconds>`, lets `list`, the takeover and the janitor filter by run and epoch and read the deadline with nothing run inside; `extend` renames it (PATCH) with the deadline init took, a computer's extends run in turn, the name's deadline never moves back, and a ref made before still reaches it. Every label and the deadline are in the root-owned `/opt/agentrun/labels.json`, which `attach` reads as the truth.
- `create` refuses, and deletes, a computer whose daemon's sha256 differs, whose X server has no path socket (`/tmp/.X11-unix/X99`: the tools' network namespace cuts the abstract one), whose daemon drifts (its network not its loopback alone included), or whose probe reaches an address. An `extend` to a deadline earlier than the current one is refused in words.
- Everything inside a computer goes through an `OrgoChannel` (`run`, `start`, `stdio`, `upload`); the default is Orgo's bash and upload calls and its root terminal WebSocket, made raw, so SSH can replace it. The key is only in the Authorization header, and the VNC password only in the terminal socket's URL.
- The conformance module (`--provider orgo`) runs behind `AGENTRUN_COMPUTER_LIVE_ORGO=1`, reads `COMPUTER_ORGO_API_KEY`, `COMPUTER_ORGO_WORKSPACE`, `COMPUTER_ORGO_API_URL` and `COMPUTER_ORGO_TEMPLATE` in `settingsFromEnv` (listed in its `ENV`), and caps every computer at 1 h.
