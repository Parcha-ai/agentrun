A model key set for one of pi-ai's other providers (`GEMINI_API_KEY`, `DEEPSEEK_API_KEY`, `XAI_API_KEY`, Bedrock's `AWS_*` keys, about forty in all) is now held like `OPENAI_API_KEY`: the launcher takes it out of the server's environment, and a run's process gets it over its pipe only when its model is that provider's. Every model key now goes only to the runs whose model needs it: a pi run its model's provider's (per tier for a workflow), or `AGENT_MODEL_API_KEY` through the gateway; a codex run `OPENAI_API_KEY`, or the gateway's; a claude-agent run `ANTHROPIC_API_KEY`. Before, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `OPENROUTER_API_KEY` and `AGENT_MODEL_API_KEY` went to every run. Before, the launcher named four providers' keys, and every other one stayed in the server's environment and in every run's, where Codex's process, a program a run started or any process of the same user could read it. Operators set the same variables.

- No run's environment, nor docker's probe's, holds a variable named like a key, on the launcher's list or not: one of its `_`-separated segments, in any case, is `KEY`, `TOKEN`, `SECRET`, `PASSWORD`, `PASSWD`, `PASS`, `PAT`, `CREDENTIAL`, `CREDENTIALS` or `DSN`, or its last is `PWD` after another (never `PWD` or `OLDPWD`). It is pi-durable-disk's rule, and the import's cut and a harness's log take it too. A credential an SDK finds through such a variable (Bedrock's web identity token file or container role, `GOOGLE_APPLICATION_CREDENTIALS`, `ANTHROPIC_IDENTITY_TOKEN_FILE`) is not supported for runs.
- A run on Bedrock passes the AWS keys its process holds to each request, as pi-ai's Bedrock request reads them, instead of from an environment.
- The decision keys go only where a run needs them, still on their own descriptor: Jev's (by its route) to a workflow with a node that names Jev or none, Parallel's to one with a Parallel node or to a run that binds `web_fetch`, OpenRouter's to one with an OpenRouter node. A workflow with no decision node, like an agentic run without `web_fetch`, gets no descriptor; before, every workflow got every decision key the server held.
- Not covered: a key-shaped variable the launcher's list does not name stays in the server's own environment; Bedrock credentials by container full URI with `AWS_CONTAINER_AUTHORIZATION_TOKEN` are not supported for runs; a pi run on a `typesafe/` model does not get `TYPESAFE_API_KEY`, a decision key.
