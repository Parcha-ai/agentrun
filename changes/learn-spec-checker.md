New package `@parcha/agentrun-learn`, held (not on npm yet): self-learning on any harness, as files. `SPEC.md` is the contract of an agent's own learning repository: `learnings/INDEX.md`, notes at `learnings/L-<12 hex>.md`, skills at `.agents/skills/<name>/SKILL.md`, workflow drafts at `workflows/<name>/workflow.json` with a `README.md`, and a memo per run at `memos/<run id>.md` on the run's own branch, `runs/<run id>`. `AGENTS.md` and `agent.json` are never touched.
- `agentrun-learn check --base <ref> [--head <ref>] [--branch runs/<run id>]` validates a run's branch before any merge, in a plain checkout, a pre-push hook or CI; `checkBranch` and `checkRun` do the same from code. It is structural only: the layout, the memo's front matter and sections, the note format (a note the Pi learning loop wrote is valid), the caps (4096 bytes a note, 8 new notes a run, 4096 bytes for the index; over a cap is refused, never cut), the untouched files, the run's own memo and its base, and text shaped like a secret. `--refuse-values-from-env NAME,...` refuses the values of the named variables. A refused value is never printed.
- A workflow draft must run on the workflow DSL on any harness: the DSL's own `validateWorkflow` checks it without running its code, and a draft that names a harness's built-in tool (Codex's `exec_command`, Pi's `bash`, Claude Code's `Bash`, and the rest in `tools.json`) or a tool outside the shared tool layer is refused. `--tools` replaces the shared layer's names and may only add built-in names.
