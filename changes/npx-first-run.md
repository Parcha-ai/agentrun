On a server started with `npx @parcha/agentrun`, a harness that is not set up (claude-agent without the Claude Agent SDK, codex without Codex) now says the one command that starts the same AgentRun again with it, on the same data: `npx -p @parcha/agentrun@<version> -p @parcha/agentrun-serve@<version> -p @anthropic-ai/claude-agent-sdk@0.3.286 agentrun`. It keeps any other harness package already there, so setting up one never takes the other away, and it adds `--data` only when the server's data is not in the default place. A server started with `npx @parcha/agentrun-serve` says the same with `agentrun-serve`. `npx @parcha/agentrun` keeps its data where the server does, `~/.local/share/agentrun/agents` (under `$XDG_DATA_HOME` when it is set), so the command, `agentrun-serve`, `import`, `reset-password` and every hint open one store. When the server can't be downloaded, the command says so ("Couldn't download the AgentRun server (@parcha/agentrun-serve: not on npm). Your network or the release is the problem; nothing was started.") and exits 1, instead of saying the server did not start on a port.
