On a server started with `npx @parcha/agentrun`, a harness that is not set up (claude-agent without the Claude Agent SDK, codex without Codex) now says the one command that starts the same AgentRun again with it, on the same data: `npx -p @parcha/agentrun@<version> -p @parcha/agentrun-serve@<version> -p @anthropic-ai/claude-agent-sdk@0.3.286 agentrun --data ~/.agentrun` (with the store's absolute path). It keeps any other harness package already there, so setting up one never takes the other away. A server started with `npx @parcha/agentrun-serve` says the same with `agentrun-serve`, and adds `--data` only when its data is not in its default place. `npx @parcha/agentrun` keeps its data in `~/.agentrun` and hands it to the server, `import` and `reset-password` as `--data`, and its hint names that store as an absolute path, so the pasted line opens the same store from any directory; `agentrun-serve`'s own default, `~/.local/share/agentrun/agents`, does not change. When the server can't be downloaded, the command says so ("Couldn't download the AgentRun server (@parcha/agentrun-serve: not on npm). Your network or the release is the problem; nothing was started.") and exits 1, instead of saying the server did not start on a port.
