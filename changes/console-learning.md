The console shows what an agent learns. The agent page has a Learning tab: each note the agent wrote for itself, with its type, its body, the run it was learned in and, on a server that says what runs read, how many runs used it. A person edits a note in place (name, description and type as fields, the body as markdown; Ctrl or ⌘+Enter saves, Esc cancels), adds one, or retires one after a confirm. Each write names the version the person saw (the note's own ETag on its card), so a note changed in the meantime is never written over or retired unseen: the newest version loads, and the person's edit stays on screen to copy. Notes that were replaced or retired are listed under Earlier notes. Beside them are the learning switch, the latest runs that kept nothing with the reason in plain words, what the next run reads, and, from a server that has it, the before and after ("Since it learned: run time 18s → 12s, cost $0.11 → $0.03, on 4 runs"). An agent with no notes shows one sentence on what learning is, with the switch. The editor's Settings step has a "Learns from its runs" switch, which says when the agent still needs the write tool. A run's header and its rows on the agent page and Mission Control say "Used 1 note" and "Learned 1 note", naming the notes on hover; the header's chips open the notes in the Learning tab. An ended run whose learning is still deciding is read again until it settles. From a server that holds notes for the owner's OK (a note that changes what the agent trusts or skips), those notes sit at the top of the tab under "Waiting for your OK", each with Retire and, from a server that approves from the console, Approve, made on the card's version (until then a quiet line says approving comes in the next update); a note from the person reads "From you", and a run that kept one says "1 note waits for your OK", linking to it. In the timeline, the row that says how a run's learning ended is labelled Learning, and the message that starts the look back is no longer labelled as the person's.
