`GET /v2/agents/{agent_id}` carries `run_blockers` (this server's own property of the contract's Agent, marked `x-agentrun-serve: "runblockers/1"` in the OpenAPI document, and in the generated client types): what the run's own check would refuse now (`409 agent_not_runnable`), as `{message, fields}`, or null when a run would start. The console's agent page shows each blocker as a warning before Run ("A run of this agent is refused until this is fixed: …"), so an agent that can't run (an agent imported with empty instructions or a model no key here reaches, a harness this server doesn't run, a key a granted tool needs) says why on its page, not only after Run. Native and SDK agents, archived agents, and a revision whose MCP tools its first run would pin read null. The read asks no other service: under the agent's spend cap, an OpenRouter decision model's missing price is named once a save or a start has read OpenRouter's catalog, and a catalog that could not be read is named by the start alone.
