A run's cost (`GET /runs/{id}` and each `GET /runs` row) carries its model requests' `tokens` (`input`, `output`, `cache_read`, `cache_write`, `requests`, `unmetered`), and its `basis` says how the figure was reached instead of always reading `estimate`: `reported` when every priced request had the provider's or gateway's own figure (LiteLLM's `x-litellm-response-cost`, OpenRouter's usage `cost`), `estimate` when any was priced from a price table, `unpriced` when no request was priced. A run through a model gateway (`AGENT_MODEL_BASE_URL`) now shows its tokens, not only an estimated cost.
`GET /stats` (`cost.basis`) and `GET /usage` (`basis`) say the same words over the runs they sum. A run that ended before this change counts as `estimate` when it cost anything, and so does an imported session read at the model catalog's estimate; an imported session with neither a recorded cost nor an estimate reads `unpriced`. The console shows the tokens beside a run's cost and marks a reported figure `reported`, as it marks an estimate `est.`.
A native or SDK run's cost (its harness's own figure for its whole task) reads `estimate`, with that task's tokens and no request count. A client that treated `basis` as always `estimate` (or `charge`) must accept `reported` and `unpriced`. A run with no model request now reads `basis: "unpriced"` (it read `estimate`).
