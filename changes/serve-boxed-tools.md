An agent whose place is `{"mode": "sandbox", "box": "docker"}` runs its `read`, `write`, `edit` and `bash` in a Docker container, on pi, claude-agent and codex alike, while its loop, its log, its model calls and every key stay on the server. The container is made on the run's first such call and labelled with the run's id. It binds the run's `work/` alone at `/run/agentrun/run/work` (a mount source through a link is refused), has no network, gets `LANG` and `HOME` and nothing of the server's environment, and runs as the server's user. It is found again by its label after a crash, the commands the dead process left killed first, and destroyed when the run ends, when it is archived, and by the next start once its run has ended. `bash` takes pi's arguments, with a 300 s default timeout and its output's tail. `read`, `write` and `edit` take a path in the box's work directory only, and their errors name the box's paths, never the server's. A run request's `place: "runner"` narrows a run to the runner, without `bash`. `bash` is refused on a runner place, and so is a sandbox place on a workflow. `AGENTRUN_DOCKER_IMAGE` names the image (default `debian:bookworm-slim`). In pi-transport, `dockerBoxes({ user })` runs a box's programs as that uid:gid, and `endLeftCommands(box)` kills the command groups a gone host left in a box.
