A paired computer works under a runner in a process of its own (`--no-runner`; the image's default `server-and-runner`) when the runner knows the server's public address (`AGENTRUN_PUBLIC_URL`), the relay a dial provider's machines already take. A run's claim writes the computer's route, one settings row per computer naming the runner, its process, the run and the hold's end, by compare-and-set. A route held by a live run on a live runner refuses the claim (`<name> is held by run <run> on runner <runner>: one run at a time`); one whose runner is gone or restarted, or whose run is final (completed, failed or cancelled), is taken. Once a second the server closes a paired computer's socket that is not where its route says (close 1001), and the driver's redial lands there: relayed to the run's runner, or on the server itself once the run releases it or its hold ends. A redial to a stale route is `503` in words the server keeps on the route. A run on the runner beside the server takes a route of its own too, so a runner apart's claim for another run is refused in the same words while it holds the computer, which stays on the server. A run cancelled, failed or whose claim is lost while it holds a paired computer lets it go as it ends. The run's create waits for the computer about 80 s and fails in words naming the runner when it does not arrive. `GET /v2/computers` lists a paired computer's `held_on` (the runner its run's hold is on) and `hold_note` (the server's note of a refused relay, or that it is attached nowhere), and Settings → Computers shows both on its row. `runs_refused` on a pairing code, the pair answer and a paired computer is null once a runner relays, and names both fixes until one does.
