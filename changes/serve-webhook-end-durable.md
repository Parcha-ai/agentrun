A run's `run.ended` webhook is no longer lost, or sent twice under two ids, across a crash or a refused write. The server now chooses a run's end time once and gives it to the agent store, so the store's `ended_at` and the message's `webhook-id` name one time (`carryBack` takes it as `endedAt`, an ISO time in UTC; with none it stamps now, as before). `run.ended` is queued only once the agent store has the end, and the webhook outbox keeps which end of each run it queued in the same write as the message; a server that starts queues any end of the last day that the agent store holds and the outbox does not, under the same id, so neither a kill nor a crash of the machine loses it; the first start after this change records when it began (`DIR/end-notices-since`), and an end before it, or before the webhook was set, is never sent. Behaviour changes: while the agent store refuses a run's end, `run.ended` waits until the end is stored (a later try or the next server), where it used to go out at once, and a receiver that reads the run back on its message reads it ended; a run is continued only once its end's `run.ended` is in the outbox, `503` with a retry meanwhile, so the continued run's next end has its own id.
