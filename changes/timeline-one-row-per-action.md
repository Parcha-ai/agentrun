A run's timeline shows one row per action. A tool call is one row, its call's `tool_use` row, changed in place as the call goes: `tool_status` is `running` and `ended_at` null until it ends, when `ended_at` says when, then `success`, `failed`, `missing` (a read of a path the run never wrote that found nothing: a probe, shown quietly as "not found", not counted as an error) or `interrupted` (no result ever came). Its `summary` is the action and a one-line result ("Wrote stats.py: ok", "Read AGENTS.md: not found"), and `tool_result_preview` the result as readable text: a JSON result one field per line, its strings with their own line breaks.
- No `tool_result` row follows a call any more, no "Saved <file>" row follows a write (the write's row has the file in `path`), and a call never gets a second "interrupted" row. A result stored before its call, as a harness bridge could write one, is that call's.
- An `ask_person` question is one row: the waiting row while the run waits for the person, the call's "Asked you: …" row once they answer, under one id.
- Labels show no tool wire name (`mcp__hands__…`), no "Using tool: X" (a tool with no label reads "Used X") and no absolute path under the run's workspace.
- Web and paid calls read in the person's words. A search: `Searched the web for "<q>": 6 sources · nodejs.org, endoflife.date, github.com · Exa keyless`, `no results` as a quiet `missing`, the query and the provider alone when the provider reports no results (`· Codex's own search`), and a rate-limited free search names the fix; its preview lists each result. A page: `Read <host/path>: "<title>" · 12 KB` (`· via Parallel`, or the first characters of how many when cut), or why it was not read (refused, `404 Not Found`, `timed out after 15 s`), an HTTP error now a failure. monid: `Found 3 monid endpoints for "<q>"`, `Checked <endpoint>: $0.0030 a call`, `Ran <endpoint>: ok · charged $0.0049`. `registerOutcome` takes `{ errors }` and its outcome may give `line`, `sep`, `missing` and `preview`.
- A settled run's usage row is its total: "Total: $0.0062 · 5 model requests · 31 s", from the run's start to its end.
- A paid tool's charge (monid's `agentrun.tool_cost`) shows on its call's own row, "Ran faux /person/enrich: ok · charged $0.0030", with the charge as that row's `usage`, whichever was written first; no "Tool cost" row follows, except for a charge whose call never shows.
- The run's tool metrics count each call once. A read that found nothing at a path the run never wrote is not an error.
- **What a client does differently:** read a call's outcome from its `tool_use` row (`tool_status`, `summary`, `tool_result_preview`), which the timeline serves again, under the same id and `seq`, each time it changes; stop pairing `tool_result` rows with calls. `GET /v2/capabilities` says this shape with `features.timeline.actions: true`, and `GET /v2/openapi.json` marks it, the widened `tool_status` values and `ended_at` `timeline/2`. A run stored before this reads the same way. Runs that ended before this keep the tool metrics they were stored with.
