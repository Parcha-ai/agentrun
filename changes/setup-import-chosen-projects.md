Setup's import of this machine's sessions takes only the projects the owner chooses, and a large history no longer exhausts the server's memory. The console's setup page lists the projects found, each with how many sessions it holds, from which tools, and how long ago the latest ended. None is ticked, and nothing is imported unless a project is ticked. Before, one box imported every project, and a session with many subagents was read into memory at once: about 5 GB of them took the server to 3.9 GB in six seconds, the import stopped with nothing written, and every later start tried again.
- `GET /v2/setup/import` before the owner is set now also answers `candidates`: one `{id, name, path, sessions, sources, last_active}` per project, the latest active first, at most 500. `projects` and `sessions` still count everything found.
- `POST /v2/setup` takes `import` as a list of those ids (at most 500) and imports those projects alone: no other project is read for keys or written. `import: true` still imports every project. `false`, an empty list or no field imports nothing. Anything else is a 422 on `import`, and sets no owner. The choice is kept with the owner's yes, so an import a stop interrupted goes on with the same projects at the next start. `skipped` then counts what was left out of the chosen projects alone, not of projects the owner did not choose.
- A run is read whole, so a session whose files and subagents' files are over 256 MB together is left out whole and counted in `skipped` (the CLI says "sessions over 256 MB"). It is never cut short: one subagent file over 256 MB leaves its session out too, where before the session was imported without that subagent's usage and nothing said so. The rest of the history imports. `agentrun-serve import` and its `--dry-run` leave the same sessions out.
- The import's worker has a heap of its own, at most 2 GB. An import that needs more ends as a stopped import, with the reason in the server's log.
- An import that three starts began and none ended (its worker failed, or the server ended during it) is given up: the owner's yes is dropped, later starts do not take it up, and `GET /v2/setup/import` answers `{"state": "failed"}` to the owner, which the console says. A stop by the server's own shutdown is not counted. To try again, run `agentrun-serve import` with the server stopped. The three starts are counted across the whole import, a start that took some sessions before the server was killed included, and `failed` is answered until the next start, after which the route answers as with no import asked. A kept choice that cannot be read (a damaged file) is given up at once and imports nothing: it is never taken for "every project".
- The projects listed before the owner is set (`candidates`) are named as the import would name them: a key's value in a folder's name is cut from `name` and `path`. They are answered only where the import is offered, a server on this machine's loopback with open setup and no public address, to a request from its own page.
