---
packages: @parcha/pi-durable-disk, @parcha/agentrun-harness
kind: breaking
---
pi-durable-disk's lease is gone: no lease file, no `owner.lock`, no heartbeat, no lease watchdog and no seal. A run keeps its record (its status, generation, holder, `wakeAt` and `detail`) in its own store, and the store's own exclusive lock keeps a second writer out: a second open is refused with `HeldError` `store` (exit 76) before it reaps anything. `openDurableRun` takes `epoch` for a host that holds the run's claim (agentrun-serve); without one, the generation is the previous record's plus 1, read under the store's lock. `pi-durable-disk run` now requires `--epoch N` and refuses without it (exit 2, "--epoch is required"), and its `--heartbeat-ms`, `--lease-expiry-ms` and `--lease-margin-ms` flags are gone. `readLocalRunStatus(root)` reads the record from the run's store once no process holds the run, and refuses with `HeldError` `store` while one does; on a store nobody holds, its close checkpoints the WAL's committed frames into the database file. Deleted: the `./lease` entry, `openRunLease`, `RunLease`, `LeaseOptions`, `OWNER_LOCK`, `LeaseLapsedError`, `StoreBehindSealError`, `leaseParkTarget`, the record's `sealedSeq` and `heartbeatAt`, `PlaceStatus` and `localPlace`'s `status()`, and from the internals entry `RUN_JSON`, `isLeaseFresh` and `parseRunRecord`. A new run is one with no record in its store, so a seed that failed runs again on the next open. The harness demo's place passes each runner's number as its epoch, and its recording no longer has the disk host lines (`run.json`, `delegation`, `revoke`); the viewer's disk panel that read them is gone.

Upgrading: start a run with `pi-durable-disk run --dir DIR --epoch N`, N one more than the last start's. A library caller on one machine may leave `epoch` out. Read a run's record with `readLocalRunStatus` after its process released it. Leftover run.json and owner.lock files in a run's directory are ignored.
