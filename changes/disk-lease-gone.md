---
packages: @parcha/pi-durable-disk, @parcha/agentrun-harness
kind: breaking
---
pi-durable-disk's lease is gone: no lease file, no `owner.lock`, no heartbeat, no lease watchdog and no seal. A run keeps its record (its status, generation, holder, `wakeAt` and `detail`) in its own store, and the store's own exclusive lock keeps a second writer out: a second open is refused with `HeldError` `store` (exit 76). The open probes that lock before it reaps anything, but the probe holds nothing: across the layout, the commands reap, `afterClaim` and a new run's seed the lock is free, so two library openers with no host can both pass the probe in that window, and the store's own open then refuses one of them (`localPlace`'s release probes and then reaps in the same way). An open refuses a record that names another run, or a malformed one (`RunRecordError`, exit 65). `run.release()` writes the record in the store before it closes the Harness, and closing the Harness closes the store, so a Harness closed before `release()` leaves the record nowhere to go: `setStatus()` and `release()` then refuse with `RunError` `RELEASE_ORDER` ("release() before closing the Harness: …", exit 1), nothing is fenced, and the record stays as the open wrote it, as after a crash. `openDurableRun` takes `epoch` for a host that holds the run's claim (agentrun-serve); without one, the generation is the previous record's plus 1, read under the store's lock. `pi-durable-disk run` now requires `--epoch N` and refuses without it (exit 2, "--epoch is required"), and its `--heartbeat-ms`, `--lease-expiry-ms` and `--lease-margin-ms` flags are gone. `readLocalRunStatus(root)` reads the record from the run's store once no process holds the run, and refuses with `HeldError` `store` while one does; on a store nobody holds, its close checkpoints the WAL's committed frames into the database file. Deleted: the `./lease` entry, `openRunLease`, `RunLease`, `LeaseOptions`, `OWNER_LOCK`, `LeaseLapsedError`, `StoreBehindSealError`, `leaseParkTarget`, the record's `sealedSeq` and `heartbeatAt`, `PlaceStatus` and `localPlace`'s `status()`, and from the internals entry `RUN_JSON`, `isLeaseFresh` and `parseRunRecord`. A new run is one with no record in its store, so a seed that failed runs again on the next open. The harness demo's place passes each runner's number as its epoch, and its recording no longer has the disk host lines (`run.json`, `delegation`, `revoke`); the viewer's disk panel that read them is gone.

Upgrading: start a run with `pi-durable-disk run --dir DIR --epoch N`, N one more than the last start's. A library caller on one machine may leave `epoch` out. Close the Harness only through `release()`; a Harness closed before `release()` makes it refuse (`RELEASE_ORDER`). Read a run's record with `readLocalRunStatus` after its process released it. Leftover run.json and owner.lock files in a run's directory are ignored.
