A new computer provider, `instabox`: a Linux sandbox on an InstaBox machine (a Firecracker microVM), over the InstaBox API and SSH, with no SDK. It takes `INSTABOX_API_KEY`, the name InstaBox's own CLI and SDK read, and loads from `@parcha/agentrun-computer/instabox` or `providerFor("instabox", { apiKey })`. A computer starts from one of InstaBox's templates, `"minimal"` by default, or a snapshot of the key's workspace, so it is a sandbox alone: no desktop and no Archil mount. The exec is SSH through InstaBox's gateway, logged in as a token the API mints per machine, with the gateway's host key pinned to the fingerprint the token names; the shared SSH exec takes a `hostKey` pin for that, which no other provider sets. A computer switches off InstaBox's idle pause and maximum run, which only a paid plan allows; the free plan's refusal is a `refused` that says so. Serve offers it as a box once `AGENTRUN_BOXES` lists `instabox` and the key is set, and the launcher holds `INSTABOX_API_KEY` with the other secrets. No live run has been made yet: the token's none auth and its host key, a taken name's 409, a deleted machine's read, sshd as the one vendor listener, `minimal` on every paid plan, the metadata bound on compact JSON, 75 s of SSH silence and root's network namespace are unverified until then.
