An agent's cost page (`GET /agents/{id}/learning/cost`), a run's cost (`GET /runs/{id}`) and the launch's money rule now read one ledger and get the same figures. The store keeps a row for each run and a spend row for each compile, check and audit, filed under the workflow version it was for. Postgres gets them through migration 0027. One pure `summarize` turns those rows into every figure. Before this, the run read and the money rule each had their own cost formula, and the money rule had its own by-hand baseline: a mean of all-in costs over the newest 500 runs. That baseline was not the cost page's `before`, so the two could disagree on the same run. The money rule now uses `summary.before` as its by-hand side, which is the job's own $. A revision with compile spend but no promote record now shows on the bill at the default K instead of falling into unattributed. The fields are only added to, never renamed: a run's `cost` and the cost page's `runs[]` gain `compile_usd`, `followup_usd`, `shadow_usd` and `share_usd`, which split the run's `learning_usd` into its parts, and `runs[]` gains `not_served`.
