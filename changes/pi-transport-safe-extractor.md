`@parcha/pi-transport/sync` unpacks a tar archive a box made, on the host, with the package's own reader (`extractTar`, or `openExtractor` fed a chunk at a time) instead of `tar`. It writes regular files and directories only: a symbolic or hard link, a device, a pipe or any other member is skipped, counted by reason and never created, and a link's skip carries its `target` so a caller can keep it as data. A name is refused when it is absolute, holds `.`, `..`, an empty segment or a NUL, or passes 255 bytes a segment or 4095 a path; `admit` limits what may be written. Every directory is opened from a held handle with `O_NOFOLLOW`, so nothing lands outside the destination and no link already there is followed; each file is written under a temporary name and renamed into place; modes are capped at 0644/0755 with no setuid, setgid, group or world write. The extraction stops cleanly past `maxBytes` of archive, headers and names included (default `MAX_PULL_BYTES`, 1 GiB), or `maxEntries` members (default `MAX_PULL_ENTRIES`, 100,000), keeping every file written before the stop whole. `removeEntries` removes paths under a directory by the same walk, unlinking a link itself and a directory only when empty.
