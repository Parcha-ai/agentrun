A run whose follow-up turn ends without showing an answer now ends completed, with `result.final_answer` `""`: the turn's own answer, which has no text. The earlier answer stays in the timeline. The Claude CLI's `/compact` is one such turn: a summary request and no text. Before, the run sat `working`/`idle` until another message came, because serve ended a run only when its newest row was an answer. Now a claude-agent or codex turn writes its end on the run's root, and the run ends when every message it took has had its turn, whatever the door said meanwhile. A follow-up placed while a turn works is still waited for, on every harness. A claude-agent or codex run whose process died after a turn's last writes, before the turn's end was written, ends once its next process opens: that process writes the missing end when the session holds the turn as over, completed when the turn's answer is on the run's root and interrupted when it is not, so a turn that showed no answer leaves the run waiting for the person (`input_required`). When a message the person sent meanwhile is still waiting, that process starts the message's turn first and writes the missing end inside it, so the run completes only once that message is answered, also when the server restarted with it. A message accepted and not sent yet keeps the run open on any server, also when its process died just after the turn before it ended. A follow-up whose answer stops at its length (max output tokens) is the run's answer, as its timeline shows it.
