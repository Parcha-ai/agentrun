`@parcha/agentrun-computer` is no longer held: the next release publishes it (`npm install @parcha/agentrun-computer@latest`), in the first layer, since it depends on no other package. Its archive holds `dist`, with the daemon for Linux amd64 and arm64 (`dist/computerd-linux-amd64` and `-arm64`, executable) and the Docker egress proxy's code (`dist/docker/egress-main.js`, `egress-proxy.js` and `egress-table.js`, which the proxy container runs from a bind of `dist/docker` and `package.json`), the README, LICENSE and NOTICE. A new subpath, `@parcha/agentrun-computer/mount`, exports the mount rule alone (`WORKSPACE`, `MOUNT_KINDS`, `checkMount`, `readBackOf`, and the types `MountSpec`, `MountReadBack` and `MountKind`): importing it loads `dist/mount.js` and node's built-ins, and no provider, vendor SDK or conformance code. A provider's mount kinds are read with `(await providerModule(id)).MOUNT`, which loads that one provider's file. The package check (`scripts/verify-packages.mjs`) requires both daemon binaries in the archive, each an ELF for its architecture stamped with the package's version, and the egress proxy's three files, imports the root and `./mount` in the clean consumer, checks in a fresh process that `./mount` loads nothing else, runs the installed egress proxy laid out as its container binds it, with nothing beside it, and compiles a TypeScript consumer of both entry points; the release's receipt carries a `computer` smoke. CI's build job and the release workflow's publish job set up Go from `packages/computer/daemon/go.mod` and run `npm run build:daemon -w @parcha/agentrun-computer` after `npm run build`, so the archive they check holds the daemon.
