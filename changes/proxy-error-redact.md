A provider's error no longer hands a harness the provider's credential. The session's model proxy relayed every answer as it came, so a provider that echoes the key it was sent ("Incorrect API key provided: <key>") gave it to the harness, which on a CLI harness runs in the sandbox. Now, in an answer with an error status, and in an error event inside a streamed answer (Messages' `error`; Responses' `error` and `response.failed`), the credential the proxy sent and the values of the headers it added are cut out ("[redacted]") as sent, JSON-escaped, and with "/" escaped. Then the host's redactor runs, when it gives one (`ModelProxyOptions.redact`). An event's name never exempts its data: an error under a healthy event name is cut as an error event, and every other event of a streamed answer has the credential cut too and passes otherwise byte for byte. A header value shorter than eight characters is cut only from an error, and only where it stands as a whole word inside the error's own text, so a value of "1" never touches a status code. An error body still reaches the client as it comes.
