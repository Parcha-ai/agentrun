A desktop's or a phone's agent can keep what it sees: `computer_screenshot` takes `save_as`, a path relative to the run's folder ending `.png`, and saves the screenshot there through the run's own files, whatever disk the computer has. The answer is the image as before, plus `saved as <path> in the run's files` (and `saved` in its structured value). A path outside the folder, an absolute one or one not ending `.png` is refused in words before the computer is asked. A screenshot with `save_as` is held to `write`'s setting as well as the computer's: `write` set to deny refuses it before the computer is asked, set to ask puts it to a person.
A desktop or a phone the run's folder is not mounted in (one with `exec: false`, or a provider that mounts none) tells its model once in the run, as the server's note, that the computer's own disk is not the run's files and is deleted at the end, and that `save_as` and the file tools keep what the user should get. The note goes after a due cap wrap-up, never ahead of it, and a resumed claim does not tell it again. The note is part of such a run's first request: on a pi desktop run on Sonnet it needs $0.055 through a gateway (from $0.052; its byte bound 10,445 tokens) and $0.031 straight to Anthropic (from $0.030, so the README's first-request figure there is $0.04); the documented $0.09 minimums for the five-step run do not change.
