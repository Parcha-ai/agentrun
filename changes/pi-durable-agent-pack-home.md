`packHome`, `readPack` and `importPack` move an agent home as one tar. `packHome(home, { out, maxBytes?, exportRunStore? })` writes `manifest.json` (`agentrun.home/1`: the definition, the skills with their digests, the source's `agent.source`, the sign-ins the source had by key, the run counts, the pack's size) first, then a new `agent.sqlite` built from `EXPORTABLE_KINDS` through `projectForExport` and vacuumed into one clean file, then each carried-back run's `work/` files. Run stores travel only through the `exportRunStore` hook. A run that is still live travels as its index entry only. Symbolic links, hard links, dotfiles, `chrome/`, `repo/` and everything else off the allowlist never travel, and the packer refuses any SQLite file that holds a sign-in kind or has a `-wal` or `-shm` file beside it. A pack over `maxBytes` is refused (`too_large`) before anything is written.
`readPack(file)` judges a pack without writing a home and answers with the contract's `format`, `definition`, `sign_ins`, `size` and `live_runs` checks: the manifest first, an `agentrun.home/N` above this version refused, every member on the allowlist, no `..`, absolute path, link or device, no store with a sign-in kind, the agent store's id, definition and skills as the manifest says. `importPack(file, dir, { replace?, ifRevision? })` writes a pack under the target's owner lock, extracting beside `dir` and swapping in by rename. It refuses another agent, a target with a live run, and a stale `ifRevision` (a `homeRevision`), leaves the target as it was on any refusal, and on a replace keeps the target's own sign-ins, aliases, bindings, `chrome/`, `repo/` and the runs the pack does not have. `AgentHomeError` gains the codes `too_large` and `check`.
