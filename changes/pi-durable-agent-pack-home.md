`packHome`, `readPack` and `importPack` move an agent home as one tar. `packHome(home, { out, maxBytes?, exportRunStore? })` writes `manifest.json` (`agentrun.home/1`: the definition, the skills with their digests, the source's `agent.source`, the sign-ins the source had by key, the run counts, the pack's size) first, then a new `agent.sqlite` built from `EXPORTABLE_KINDS` through `projectForExport` and vacuumed into one clean file, then each carried-back run's `work/` files. Run stores travel only through the `exportRunStore` hook. A run that is still live travels as its index entry only. Symbolic links, hard links, dotfiles, `chrome/`, `repo/` and everything else off the allowlist never travel, and the packer refuses any SQLite file that holds a sign-in kind or has a `-wal` or `-shm` file beside it. Each work file is opened without following a link and must be the file that was listed, so a file swapped for a link while the pack is made is left out; a work directory that cannot be read fails the pack; the pack is read back with `readPack` before it is published. A pack over `maxBytes` or `maxMembers` is refused (`too_large`) before anything is written.
`readPack(file)` judges a pack without writing a home and answers with the contract's `format`, `definition`, `sign_ins`, `size` and `live_runs` checks: the manifest first, an `agentrun.home/N` above this version refused, every member on the allowlist, no `..`, absolute path, link or device, no store with a sign-in kind, the agent store's id, definition and skills as the manifest says. `importPack(file, dir, { replace?, ifRevision? })` makes a new home in an absent or empty directory, and changes an existing one in place under its own owner lock: the lock, `agent.sqlite`, `chrome/`, `repo/`, the home's sign-ins, aliases and bindings, and its runs the pack does not have stay where they are, and one store commit replaces the definition, the skills, the source and the pack's runs, so `homeRevision` only goes up. The pack's run directories move into place before that commit, in the order of a journal in the home; a failure puts every one back, and a crash is settled by the next lock taker (the new home when the commit landed, the old one when it did not). It refuses another agent, a target with a live run and a stale `ifRevision` (a `homeRevision`), and a pack over `maxBytes` before extracting any of it, and leaves the target as it was on any refusal. `AgentHomeError` gains the codes `too_large` and `check`.
