A parked run whose desktop, phone or sandbox was kept at its park on a Docker engine, or on a machine that dials the server, now resumes on the runner that kept it while that runner is there (its word in the last 30 s, the same process, not refusing) and the keep's 10 minutes last, so a server with several runners gets the same machine back instead of a new one. Another runner claims nothing for that run meanwhile, so an answer waits up to the keep's 10 minutes behind a runner whose loops are full, and its computer janitor leaves both the kept row and, in its sweep of each provider's computers, the kept machine to that runner, even once the run is over. A stop or a cancel never waits: any runner claims the run at once and ends it without touching the kept machine (also when the kept row can't be read at that moment), which the runner that kept it ends at the keep's time, or sooner at its janitor's next pass once the run is over. Once that runner is gone, any runner claims the run, starts a new machine, and the timeline says `The desktop wasn't kept: the runner that kept it is gone.`. The kept machine is ended by the runner that kept it while that runner is there, refusing claims or not: a claim that took the kept row and could not reach the machine puts the row back as the park wrote it, marked ending so no claim takes that machine back as the run's, and that runner's own end at the keep's time still deletes it. While that runner is there but refuses claims, any runner claims the run, and one that can't reach the machine starts a new one, says `The desktop wasn't kept: another runner kept it and couldn't take the run, so that runner ends it.`, and at a later park keeps nothing rather than write over that runner's row (its own machine is ended as at a run's end), so no machine is left with no row and no runner to end it. Once that runner is gone, the machine is ended by its host's janitor or by the provider's own deadline. A run's end on another runner spares only the kept machine on the provider the kept row names; a machine of the same id on another provider is released as before. A run kept on an exec vendor's machine or a phone is claimed by any runner, as before. The keep's end is stamped from the store's clock (the database's on Postgres) and every reader judges it on that clock, so a runner whose clock is off from the store's no longer moves when the keep ends; the runner that parked still ends the machine 10 minutes after the park by its own clock. The kept row (`computer_kept:<run id>` in settings) names the runner and its incarnation; there is no schema change.
