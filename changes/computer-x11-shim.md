computerd drives an X display: `screen.shot`, `screen.read` and `input.actions` on the display `DISPLAY` names, in pure Go with no cgo (GetImage for pixels, XTEST for input), and `deadline.extend`. A Docker computer can be a desktop.
- Hello declares `screen`, `input.pointer` and `input.keys`, and kind `desktop`, only while the display answers with XTEST; with none, nothing is declared and each method is `unsupported`, saying why. `input.actions` checks the whole batch first, as `checkActions` does, and also refuses touch actions and pixel scrolls (`unsupported`), points and clicks that are not whole, and text with a control character other than newline and tab; then it runs until the first failure, releasing what the batch held. It waits for the server after each action with a button, a key or a keyboard map change, so an X error stops the batch before its next action and `done` and `failed` say what ran; a cancel stops it at the next key, click or point and answers `aborted`. `type` gives exactly its text with Caps Lock on: it is turned off for the typing and back on after. Characters with no key on the keyboard map are typed through xdotool's keysym remap, which keeps its bindings instead of undoing them. Only a display in this computer is driven (the unix socket, or TCP to a loopback address); any other `DISPLAY` is refused before anything is sent, so this host's X cookie never goes to another server.
- `computerd init --deadline <time> --max-deadline <time>`: `deadline.extend({ at })` moves init's deadline up to the maximum, refusing an earlier time or one past it in words; without `--max-deadline` the deadline cannot move. Docker passes none: its deadline is a label.
- `new DockerProvider({ daemonPath, desktop: {} })` makes kind `desktop` computers on an image with an X server: `create` gives the daemon `DISPLAY` and starts Xvfb through `process.start`, so computerd stays PID 1 and starts nothing itself. `desktop.timeoutMs` bounds every call to the daemon from starting the X server on: a daemon that stops answering fails `create` as `timeout`. `dockerConformance({ desktop })` runs the suite on one; with `test/fixtures/desktop/Dockerfile` (Alpine and Xvfb) and `computerd-fixture` (`daemon/cmd/fixture`, test-only) Core passes 58/58.
