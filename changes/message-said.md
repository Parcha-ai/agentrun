`POST /v2/runs/{run_id}/messages` takes an optional `said`: the person's own words, when `content` is a host's text around them (a preamble, the earlier report, turn instructions). The model still gets `content` alone; the run's learning keeps `said` as the owner's correction (one line of `corrections.md`) and as the follow-up in its compile turn's traces, so a host's scaffolding never lands under `# Learned`. Learning reads each message whole from the run's own record, never as the Timeline row shows it (cut at 2,000 characters): `said` is kept however long `content` is, and a long message sent with no `said` is kept whole, its last words included, no longer cut at 2,000 characters. A `said` that is not a string (`wrong_type`), empty after trimming (`empty`) or longer than 4,000 characters (`too_long`) is 422 `input_invalid` at `said`, nothing written; it need not appear inside `content`. `GET /v2/capabilities` says a server takes it: `features.messages.said: true`, API-only servers included. The generated clients carry the field.
