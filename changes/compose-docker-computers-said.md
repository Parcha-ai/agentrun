Docker sandboxes run from a server in a container, as compose.yaml starts it, on Docker Engine 26 or later. The run's folder and the sandbox's daemon (copied under the data volume, at `.agentrun/computerd`) mount as the named data volume's subpaths, and the sandbox's egress proxy refuses the Docker host's own addresses: the server reads them once at its start through the socket (one short-lived container on the host's network, as nobody, from the proxy's own image, with `host.docker.internal` for Docker Desktop and OrbStack) and adds `AGENTRUN_DOCKER_HOST_ADDRESSES` (a comma list of IP addresses, for a NAT'd or elastic public address no interface shows), shown in capabilities' docker entry as `host_addresses`. With none known under an allow-list, or a layout with no named data volume, or a `DOCKER_HOST` of another machine, docker is unavailable at the start in words that say why, so an agent that names a Docker computer is refused at its run's start instead of failing at create.
