A server saves a plan-billed harness recipe's own keys, sealed in its store for that harness alone. The owner pastes them in the console's new Settings → Harness keys page (`agentrun harness keys` prints its link), or through `PUT`/`DELETE /v2/settings/harness-keys/{harness_id}/{key}` from the owner's signed-in session; the API token reads `GET /v2/settings/harness-keys` and never writes one. Each claim of a run on the harness opens that harness's keys and no other's, lays them on the agent's start alone, never on its tools, and cuts them from the timeline, errors and the agent's output, a replaced or removed value too. With every key saved, the recipe's runs run on them ahead of the owner's own sign-in, and its scheduled and triggered runs and `message_run` trigger turns, refused until now with `HARNESS_KEYS_NOT_SAVED`, run too. A start runs only on the keys its claim opened, all or none: a run no person started (a scheduled or triggered run, a learned workflow's audit shadow or replay) whose claim opened not every one is refused at its claim, never put on the sign-in, a trigger's message to a person's run that started on the sign-in is refused in that run, keys saved since or not, and a variable of a key's name in the server's own environment is never handed to a run. Each key is bound to the recipe file it was saved for (its sha256) and the seal key it was sealed under: a later recipe file that takes the same id never opens it, and the page lists it to paste again, saying why (`reenter`: `recipe_changed`, `seal_key_changed` or `file_unreadable`). A recipe the server is no longer started with keeps its keys, sealed and cut, run by nothing: the page lists them under its id (`named: false`, `kept`), and `DELETE` removes each, as it removes a key a recipe runs on no more or one that no longer opens. Capabilities name each such id (`features.harness_keys.kept`) to the owner's session or a token holder, and to no other caller, so the console keeps offering the page until its keys are removed. `harness-check` still reads its keys from the shell's environment alone.
