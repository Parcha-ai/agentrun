The live sweep around a conformance run now deletes only that run's computers. `dist/conformance/sweep.js --before <file>` mints a run id, records it in the before file and prints it (`{"recorded":n,"file":...,"run":"<id>"}`). Give that id to the run with the conformance CLI's new `--run <id>` (`runConformance`'s `run` option), and `--after <file>` deletes only new computers whose `agentrun.conformance` label is that id. Before, `--after` deleted every new computer carrying the label with any value, so when two runs overlapped on one account, the first run's `--after` deleted the second run's live computers. Breaking: `--after` refuses, with exit 2 and nothing listed or deleted, a before file that names no run (one recorded before this change); record it again with `--before`. Breaking: `--before <file>` refuses, with exit 2 and nothing listed, a file that is already there, where it used to write over it; give each run a before file of its own, such as `before="$(mktemp -d)/before.json"`, so two runs never share one and one run's `--after` never reads another's id. A run started without `--run` gets a fresh id of its own, and `--after` leaves its computers alone, counted in `leftAlone`. The run's own sweep at its end still removes them. Every computer of a run also carries `agentrun.conformance.runner`, an id each run mints for itself, which also names its create requests, and the run's own sweep and list at its end go by both labels, so two processes given one `--run` never find, use or delete each other's computers. `sweepMachines` takes a required `run`.
