`ModalProvider` makes computers that are Modal sandboxes on the VM runtime, through the host's own Modal client: the package names the slice of the JS SDK it calls (`ModalSdk`) and imports nothing from it. It has not run against real Modal yet; its tests use a fake of that slice.
- The daemon is uploaded at create, so nothing is published: the sandbox's command is a POSIX sh entrypoint that waits, bounded, for `/opt/agentrun/computerd` and then `exec`s `computerd init --deadline <iso> --user <uid:gid>`; right after create the provider streams `dist/computerd-linux-amd64` (`daemonPath`) into `sh -c` through `exec`'s stdin in binary mode, which writes it to a part file, prints its sha256 and moves it into place only when it matches. A failed or mismatched upload terminates the sandbox and refuses. `modalCommands()` gives the commands as sent. With `daemonImage` (a registry image pinned by digest) the daemon instead comes in as a layer (`COPY --from`) and is the command itself. `connect()` runs `computerd stdio` through `exec`, so a computer with network none is reached and needs no network for its daemon.
- Capabilities: lifetime `vendor` (Modal's timeout, which is the lifetime: at most 24 hours, or `maxLifetimeMs`; a longer lifetime is refused in words), network `none` or `open` with `networkReadBack: false`, isolation `vm`, os `linux`, user `root` or `uid`. An allowlist, `pids`, a GPU and a change of network are refused in words. `release(ref, "stop")` is refused: Modal has no stop that keeps a sandbox; `delete` terminates and is idempotent.
- The drift check after `create()` and in `attach()`: the sandbox runs, its tags read back as given, hello matches, and `computerd probe`, run through the daemon, reports the computer's user, a kernel that is not gVisor's, and, for network none, no connection to its public addresses. A mismatch terminates the sandbox at create; `attach()` refuses and leaves it running. `network(ref)` reads network none back with the same probe.
- Every SDK call is bounded by a timeout and takes the caller's signal; a create that gives up has its sandbox terminated if one lands later.
- `computerd init` takes `--user <uid:gid>`: it starts as root, gives `$HOME` and the socket's directory to that user (0700), sets `no_new_privs` and becomes it. `computerd probe [--connect <host:port>]...` prints the uid, gid, kernel release and the addresses it reached.
- `ComputerCapabilities.networkReadBack` says whether `network()` reads the policy back from outside the computer (Docker: true). `ComputerErrorCode` gains `"modal"`.
- `dist/conformance/modal.js` is a provider module for the conformance CLI, and `npm run test:modal` the live suite; both run only with `AGENTRUN_COMPUTER_LIVE_MODAL=1`, `COMPUTER_MODAL_TOKEN_ID` and `COMPUTER_MODAL_TOKEN_SECRET` set. The module passes that pair to `ModalClient` explicitly and never uses `MODAL_TOKEN_ID` or `MODAL_TOKEN_SECRET`, which may hold a production token; with only those set it refuses in words. The key goes only to `COMPUTER_MODAL_SERVER_URL`, else the SDK's default server: the module refuses while `MODAL_SERVER_URL` is set and pins the server while it constructs the client, so no `MODAL_PROFILE` or `.modal.toml` profile can redirect it. It reads `COMPUTER_MODAL_APP` and, optionally, `COMPUTER_MODAL_DAEMON_IMAGE`; without it the daemon is uploaded. The drifted provider uploads a daemon built with Go as `<version>-drift`. Every computer of a run lives at most 30 minutes.
- `dist/conformance/modal-sweep.js --before <file>` records every running sandbox in the app carrying `agentrun.computer=1`; `--after <file>` terminates every such sandbox not in that file, reads each back until it has finished (60 s each), prints `{"swept":n,"gone":m,"stillThere":[ids]}`, and exits 0, 1 (one still runs) or 2 (usage, token, refused list; nothing terminated). It reads only the `COMPUTER_MODAL_` token, app and server, the way the module does.
- `ComputerCapabilities.release` declares how release may end a computer: Docker `["stop", "delete"]`, Modal `["delete"]`. Core `provider.stop` holds a provider to it: one that declares stop lists the computer stopped; one that does not refuses `release(ref, "stop")` as `unsupported`, in words, and the computer stays listed and running. The Full `provider.janitor` case also needs `release:stop`. A provider written against `ComputerProvider` adds `release` to its `capabilities()`.
