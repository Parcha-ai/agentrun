A plain `npx @parcha/agentrun` runs a Claude Code agent with nothing else installed: Claude Code installs itself on first use. AgentRun still never ships the Claude Agent SDK. The first run on claude-agent, or the first agent saved on it, installs the version AgentRun pins (`@anthropic-ai/claude-agent-sdk@0.3.286`) from npm into `<data>/harnesses`, with the npm that runs the server, no key of the server's in npm's environment and no install script. The install is pinned by a lock the server ships (`harnesses/claude-agent.lock.json`, every package of the tree by sha512, which `npm ci` holds each tarball to from whichever registry npm is configured for), and it lands whole or not at all: npm installs into a fresh directory, the result is checked there, then renamed into place and made read-only. It is one install at a time: every run that needs it waits for that one, its ready time counted from the install's end, and shows a `phase` row, `Installing Claude Code (first use)…`, while it does. Each claude-agent run then loads the SDK, its CLI and the MCP library from `<data>/harnesses` and nowhere else, never a copy beside the server or a global one. Until it is installed, `GET /v2/capabilities` lists claude-agent with `installs: "on_first_use"`. When npm fails, the run fails and its error names the command that installs it by hand: `npm install --prefix <data>/harnesses @anthropic-ai/claude-agent-sdk@0.3.286`. claude-agent's npx hint (`npx -p … -p @anthropic-ai/claude-agent-sdk@0.3.286 …`) is gone, and codex's and OpenCode's npx lines no longer name the SDK. `@parcha/agentrun-harness-claude` takes the MCP library a host loaded (`mcp`, passed to its tool server) and exports `claudeAgentPlatform()`, the suffix of the SDK's CLI package for this machine.
Upgrading: Claude Code installs itself on first use.
