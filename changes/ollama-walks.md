The setup skill's Local model step says to start Ollama: the server lists its models itself, so the service gets no gateway and no key for it. The first-run walks run on a fake Ollama. On a server with a public address (`--tailscale`, `--public-url`), the skill and the launcher's README say to set `OLLAMA_HOST`, the default address too: only one person's own server asks it unset.
- Breaking: `agentrun service install --env AGENT_MODEL_API_KEY=none` is refused, and a re-install drops it from a service that has it. A service that reached Ollama through `AGENT_MODEL_BASE_URL` then gets `model_key_required`. Remove the gateway with `agentrun service install --env AGENT_MODEL_BASE_URL= --env AGENT_MODEL_GATEWAY_IDS= --env AGENT_MODEL= --env AGENT_MODEL_PRICE=`, start Ollama, and pick the model as `ollama/<tag>`. A service with `--tailscale` or `--public-url`, or an Ollama off port 11434 on this machine, also needs `--env OLLAMA_HOST=<host:port>` set to Ollama's address (port 11434 on that machine by default): such a server lists Ollama only where `OLLAMA_HOST` names it. A re-install that drops the key says so in one line naming this move, and never the key's value. `--env AGENT_MODEL_API_KEY=...` gets its own refusal naming the same move. Where the gateway is on this machine, that refusal and `model_key_required` both say to remove `AGENT_MODEL_BASE_URL`, since AgentRun lists Ollama itself, and add `OLLAMA_HOST=<host:port>` where the server would otherwise lose Ollama's address. A pair given to `--env` with no name before `=` is refused without being repeated.
