`agentrun-serve --share-host` (or `AGENTRUN_SHARE_HOST=1`) starts a share host: a server that answers under `/r/` alone and stores shares in `DIR/shares/`. A share's page is `/r/<id>` (the console's `share.html`, with its asset URLs under `/r/_assets/` and a CSP that loads nothing from any other origin), its stored bytes are `/r/<id>/bundle.json` (`nosniff`, `X-Robots-Tag: noindex`), and its API is `POST /r/v2/shares`, `GET /r/v2/shares` (the caller's own), `DELETE /r/v2/shares/<id>` and a public `GET /r/v2/health`. Every other address is a 404, the console, `/v2`, MCP and every run, agent, key, computer and trigger route among them. A share host starts no runner and has no owner or console session: its API takes one of its tokens (`AGENTRUN_TOKENS`), whose id owns each share it uploads.
An upload is a run's `agentrun.share/1` bundle exactly as `GET /v2/runs/<id>/export` wrote it: canonical JSON at most 8 MiB, the export's closed fields and caps, each file's size and digest and the document's sha256 checked (a mismatch is `400`). The host then scrubs the whole body in cut mode with the values it holds (its keys and tokens). Any value the scrubber finds, or a scrub that fails, refuses the upload with `422 input_invalid` and counts by rule, never a value, and nothing is stored; the host never repairs a bundle. A stored share answers `201 {id, url, sha256}`, its id 128 random bits in base32 and its URL on `AGENTRUN_PUBLIC_URL` (never a Host header; a share host on an address other than loopback needs it to start). A token keeps at most 100 shares (`403 forbidden`, `details.reason: share_quota`, past it); shares never expire. Only the token that made a share deletes it (`204`); its bytes go, and its page and bundle then answer `410`.
On a share page a workflow's graph shows no image from a provider's URL.
