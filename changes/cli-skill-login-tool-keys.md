`@parcha/agentrun` ships an Agent Skills folder, `skills/agentrun-cli`, so a coding agent can drive the server through the CLI. Its `SKILL.md` covers how the CLI finds the server and the token, five recipes as shell blocks (make an agent from a definition file, start a capped run and wait, answer a run that asks, read what it wrote and what it cost, raise a cap or approve a call), the exit codes and one line per command group. `references/commands.md` has one entry per command with its usage, summary, flags and route. Both are generated with the command table by `node scripts/generate-clients.mjs`, and their header holds the table's hash. `--check` fails when either differs from the generated files, or when the skill names a command or flag the CLI does not have. Recipe 5 names the cap and approval commands only once the server's document has them, and until then says to check `agentrun runs --help`.
`agentrun skill install [--claude] [--codex] [--dir DIR]` copies the skill to `~/.claude/skills/agentrun-cli` and `$CODEX_HOME/skills/agentrun-cli` (default `~/.codex/skills`), by default to each of the two whose folder exists, or to `DIR/agentrun-cli`. It prints the paths it wrote.
`agentrun tool-keys set KEY_ID FIELD [--from-env VAR]` saves one field of a tool key. The value is read from stdin or from the named environment variable, never from the command line, and appears in no output or error. A `KEY_ID` that is empty, `.` or `..` is refused, and the request is sent only when its URL, the base URL's path included, is the tool key route.
`agentrun login [--base-url URL]` reads a token from stdin and refuses one typed on a terminal. It checks the token against the server (a refused token is exit 4 and nothing is written), then writes `base_url` and `api_key` to `$XDG_CONFIG_HOME/agentrun/config.json` (else `~/.config/agentrun/config.json`) with mode 0600 in a 0700 directory. `agentrun logout` removes the file. A token that is not a valid header value is refused before anything is sent, exit 4.
Every command refuses a base URL that is not http or https or has a query, a fragment, a user or a password (exit 2), from `--base-url`, `AGENTRUN_BASE_URL` or the config file: such a URL could swallow the path appended to it, so another route answered. `login` saves the token only when the check's answer is the agents list.
A command that sends a secret (`login`, `tool-keys set`, `tool-keys save`, `mcp-servers save|preview`, and `api` to their routes) never prints the server's error body: a refusal prints its status, its `error.code` and a message of the CLI's own, with the same exit code as before. Any copy of a secret in what it does print, as it is, JSON-escaped or URL-encoded, is cut out. Every string value of such a body is a secret except the public fields `scripts/clients/resources.json` names by full path (an MCP server's `url` and `auth.type`, a preview's `name`), which `generate-clients --check` holds to the body's schema. A header's value is always a secret, whatever the header is called.
The `agentrun-serve` skill and the server's `llms.txt` point to the CLI skill for everything the MCP tools do not cover.
