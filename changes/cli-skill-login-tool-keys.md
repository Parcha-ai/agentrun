`@parcha/agentrun` ships an Agent Skills folder, `skills/agentrun-cli`, so a coding agent can drive the server through the CLI. Its `SKILL.md` covers how the CLI finds the server and the token, five recipes as shell blocks (make an agent from a definition file, start a capped run and wait, answer a run that asks, read what it wrote and what it cost, raise a cap or approve a call), the exit codes and one line per command group. `references/commands.md` has one entry per command with its usage, summary, flags and route. Both are generated with the command table by `node scripts/generate-clients.mjs`. `--check` fails when either differs from the generated files, or when the skill names a command or flag the CLI does not have. Recipe 5 names the cap and approval commands only once the server's document has them, and until then says to check `agentrun runs --help`.
`agentrun skill install [--claude] [--codex] [--dir DIR]` copies the skill to `~/.claude/skills/agentrun-cli` and `$CODEX_HOME/skills/agentrun-cli` (default `~/.codex/skills`), by default to each of the two whose folder exists, or to `DIR/agentrun-cli`. It prints the paths it wrote.
`agentrun tool-keys set KEY_ID FIELD [--from-env VAR]` saves one field of a tool key. The value is read from stdin or from the named environment variable, never from the command line, and appears in no output or error.
`agentrun login [--base-url URL]` reads a token from stdin and refuses one typed on a terminal. It checks the token against the server (a refused token is exit 4 and nothing is written), then writes `base_url` and `api_key` to `$XDG_CONFIG_HOME/agentrun/config.json` (else `~/.config/agentrun/config.json`) with mode 0600 in a 0700 directory. `agentrun logout` removes the file. The CLI refuses a config file that is a symlink, belongs to another user or has group or other bits (exit 4).
The `agentrun-serve` skill and the server's `llms.txt` point to the CLI skill for everything the MCP tools do not cover.
