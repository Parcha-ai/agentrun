The web example's server picks each run's prompt before the run starts, when its home keeps prompt variants (`--agent <dir>` makes a new home from that agent's `agent.json` and skills): `choosePrompt` of @parcha/pi-durable-agent asks Jev the home's question about the person's first message, through the model gateway's TypeSafe pass-through (`/typesafe`) or TypeSafe itself on `TYPESAFE_API_KEY`, and when Jev is unsure looks the name up once (a Browserbase web search with `BROWSERBASE_API_KEY`, and Wikipedia's keyless search and summary, both at once) and asks again, else the generic prompt. `startRun` records the choice, and `prompt.json` beside the run holds each pass, what the lookup read, the reason and the guide: the home's base prompt and the chosen variant as they were then, which the run's instructions get on every launch, however the home's variants change after. With a Browserbase key the agent can list `web_fetch` and `web_search`, through Browserbase's own Fetch and Search APIs, which open no browser session; an agent that lists no browser tool gets no browser, and start-run.mjs starts no Chrome for it.
