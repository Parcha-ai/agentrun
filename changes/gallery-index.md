The open-source gallery's data (`examples/`, `scripts/gallery/`). demo.json gains the gallery's authored fields, in its schema: `summary` (the card's one line, at most 140 characters), `category` (one of `vision`, `browsing`, `workflows`, `agents-at-work`, `places-and-machines`, `learning`), `tags`, `extensions` (the open packages it shows), `author` (a GitHub handle), `recording` (its directory beside the example, `recording` by default), `poster` (`{ blob }`, a picture of the recording) and `run` (the scoped live command; `<version>` stands for the release). A demo.json that names a category must carry them all. `examples/gallery.json` holds the landing row's order, a maintainer's choice. `node scripts/gallery/index.mjs` builds the search index, `agentrun.gallery/1`: one JSON of every gallery demo, each value from one source (demo.json for what its author wrote, the recording's manifest for what its run measured: providers, models, date, duration), with no cost, kill or counter, the same bytes for the same commit. It refuses a demo whose demo.json fails the schema or names another folder, an extension that is no workspace package, a poster that is not a picture of the recording, a recording the validator or the leak scan refuses, one over 10 MB or carrying the run's store, and a featured id that is no demo.
