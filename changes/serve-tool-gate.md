**Every tool call passes one gate: each tool is allow, ask or deny, and an ask parks the run until the owner answers**
- `permission` (`allow`, `ask`, `deny`) in `tool_settings`, the agent's own over the server's (`PUT /v2/settings/tools`). An MCP server's wildcard, `mcp:<server>/*`, sets each of its tools, under a tool's own key. By default every built-in tool is allowed and a catalog tool (`monid.<tool>`, `mcp:<server>/<tool>`) asks. So until monid's tools are set to `allow`, an agent that calls them waits for the owner at each call; on a server with accounts off (`AGENTRUN_ACCOUNTS=0`) each call is refused instead, and so is a workflow model node's. `ask` is offered for `read`, `write`, `edit`, `bash`, `fetch_page`, `web_fetch`, `web_search` and catalog tools; any value not offered is `422`. `features.tool_permissions` is now `true`. `capabilities.tools` give each tool's `permission`, `default_permission` and `permissions`, and `GET /v2/agents/{id}`'s `tools` add `permission_from`.
- pi's tools, and claude-agent's and codex's host tools, all pass the gate. `deny` answers the call at once with an error, and the run goes on. `ask` ends the turn: the run is `input_required` and `waiting`, with `pending: {kind: "approval", id, tool, call_id, args_preview, requested_at}` on the run and its summary, a `tool_approval_requested` timeline row after the call's result, and a `run.needs_input` webhook with `pending.kind` `approval`. `POST /v2/runs/{id}/approvals/{approval_id}` with `{decision, note?}` answers it, from the owner's password session only: a bearer token is `403`. On allow the kernel runs the call once, on the run's own coding source, and resumes the session with one message that names the call and carries its result; deny resumes it with the refusal. The same answer again is `204`, another `409` (`already_answered`). The request survives a restart, and a cancel marks it canceled.
- Under `ask`, claude-agent's and codex's own web search, which runs inside the CLI where no call can wait, gives way to the kernel's (`native` picked: unavailable). Under `deny`, `web_search` and `web_fetch` resolve `unavailable: denied`, and the run still starts.
- On a server with accounts off (`AGENTRUN_ACCOUNTS=0`) no one can answer an approval, so an `ask` is refused at each call (`Permission denied: <tool> needs the owner's approval, and this server has accounts off (AGENTRUN_ACCOUNTS=0), so no one can give it: set the tool to allow or deny in the agent's Tools.`), never parked, and `capabilities.tools` give `ask_needs: "password"` on each tool `ask` is offered for.
- The learning lane's end-of-run turn writes no file under `work/.learning/`: its write or edit there is refused (`A note is kept only from your answer: write it in a ```note block, not to a file.`), whatever the tool's permission, since its notes are kept only from its answer. Any other turn's write there follows the tool's permission. The refusal guides the model and is not a security boundary: it reads the path as written, so a write through a link or a shell redirect is not refused. Nothing depends on it, since the host lays `.learning/` from its own store and never reads back a file the run wrote there.
- A workflow call node that calls a tool set to deny refuses its run (`409 agent_not_runnable`, `details.denied`), and so does one set to ask (`details.asks`), since a call node cannot wait for an approval. A tool switched to deny or ask while the run goes refuses its next call node in the gate's words. A model node's asked call is refused, since no node can wait.
- Upgrading: a workflow whose call node's tool is set to ask, by a setting or a default, now refuses its run (`409`, `details.asks`): set that tool to allow for the agent (`definition.tool_settings`). Built-in tools are allowed by default; catalog (`monid.*`) and MCP tools, which ask by default, are no call node's tools here.
- `@parcha/pi-durable-agent`: a revision's `toolSettings` keeps a catalog tool's name (`monid.run`), an MCP server's tool (`mcp:<server>/<tool>`) and its wildcard (`mcp:<server>/*`) as keys, beside a plain name; its timeline's `TimelineKind` declares `tool_approval_requested`.
