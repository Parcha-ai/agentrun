**Every tool call passes one gate: each tool is allow, ask or deny, and an ask parks the run until the owner answers**
- `permission` (`allow`, `ask`, `deny`) in `tool_settings`, the agent's own over the server's (`PUT /v2/settings/tools`). An MCP server's wildcard, `mcp:<server>/*`, sets each of its tools, under a tool's own key. By default every built-in tool is allowed and a catalog tool (`monid.<tool>`, `mcp:<server>/<tool>`) asks. So an agent that calls monid's tools now waits for the owner at each call, until they are set to `allow`. `ask` is offered for `read`, `write`, `edit`, `bash`, `fetch_page`, `web_fetch`, `web_search` and catalog tools; any value not offered is `422`. `features.tool_permissions` is now `true`. `capabilities.tools` give each tool's `permission`, `default_permission` and `permissions`, and `GET /v2/agents/{id}`'s `tools` add `permission_from`.
- pi's tools, and claude-agent's and codex's host tools, all pass the gate. `deny` answers the call at once with an error, and the run goes on. `ask` ends the turn: the run is `input_required` and `waiting`, with `pending: {kind: "approval", id, tool, call_id, args_preview, requested_at, held: false}` on the run and its summary, a `tool_approval_requested` timeline row after the call's result, and a `run.needs_input` webhook with `pending.kind` `approval`. `POST /v2/runs/{id}/approvals/{approval_id}` with `{decision, note?}` answers it, from the owner's password session only: a bearer token is `403`. On allow the kernel runs the call once, on the run's own coding source, and resumes the session with one message that names the call and carries its result; deny resumes it with the refusal. The same answer again is `204`, another `409` (`already_answered`). The request survives a restart, and a cancel marks it canceled.
- Under `ask`, claude-agent's and codex's own web search, which runs inside the CLI where no call can wait, gives way to the kernel's (`native` picked: unavailable). Under `deny`, `web_search` and `web_fetch` resolve `unavailable: denied`, and the run still starts.
- The learning lane's reflect turn writes and edits inside `work/.learning/` without asking under `ask`; never under `deny`, and never on a person's turn.
- A workflow call node that calls a tool set to deny refuses its run (`409`, `details.denied`). `ask` does not apply to call nodes; a model node's asked call is refused, since no node can wait.
- `@parcha/pi-durable-agent`: a revision's `toolSettings` keeps a catalog tool's name (`monid.run`), an MCP server's tool (`mcp:<server>/<tool>`) and its wildcard (`mcp:<server>/*`) as keys, beside a plain name; its timeline's `TimelineKind` declares `tool_approval_requested`.
