The `examples/web` run page reads only through a `RunSource`, so the same page shows a live server's runs (`httpSource`) and a replay from static files (`staticSource`). `mountRunPage(root, source, { theme })` shows the ways to act and the live browser only when the source has them, and builds no absolute URL, so it works under any path; it draws light, dark or the system's (`auto`, the default) from `--ar-*` color tokens a host can override. `writeReplay` is the one writer of a replay's static layout, refusing ids and file paths a page could not ask for, a summary for another id and runs whose paths collide, and swapping the new replay in so a failed write leaves the old one whole, and `pack-page.mjs` writes the self-contained replay page with its Content-Security-Policy in a meta tag. A replay names a dollar figure only for a recording whose manifest says its providers are `real`: otherwise its cost is `null`, its usage rows count model requests with no amount, and the page's header shows no figure. `pack-page.mjs <outDir> --theme auto|light|dark` (and `packPage`'s `theme`) writes the theme into the packed bootstrap, which `replay.js` hands to `mountRunPage`, so a host ships no script of its own; a user message over 600 characters or 8 lines folds behind a "Show the whole message" button in the live page and in a replay, and a replay of a recording whose manifest has a job blob carries the job's `input` on its run record, which the page shows as the run's "Input" with the message the agent got behind a toggle.
