Four fixes from the computer milestone's QA: the live view keeps moving while an input batch waits, a script on a vendor desktop may start a process, the linux-desktop bench's count-errors and new-note tasks need their apps, and a computer row on the Timeline says what failed in the same voice as the rest.
- computerd: a watch's look no longer takes the display's hold. `input.actions` holds the display for its whole batch, waits included, so the live view made no frame for a batch's length (0.3 fps through a batch with waits on E2B). A look's requests all have replies, which go to their own waiter, so it never needed the hold.
- Serve: a `computer_script`'s calls are decided as on the run's computer. The script guard used the run's host-tool gate, whose `computer` flag says where `bash` runs; on a vendor desktop (shell "none" or "local") that gate denies `bash_background`, so `computer.processes.start` was refused while `shell.run` ran. A script's calls always run on the computer, so they now take the computer's defaults: allowed unless the agent's own settings (`bash: ask`, `bash: deny`) say otherwise. A script's `shell.run` on a vendor desktop under approvals "ask", with no `bash` setting, now runs where it was asked before.
- Bench: `exec: "deny"` takes programs away, not the files group, so both tasks could pass with `files.write` alone. `linux.terminal.count-errors` (version 2) gzips its log, so counting it takes a program, and its probe asks for gzip and zgrep. `linux.editor.new-note` (version 2) also checks that a Mousepad window is titled with the saved file's name, and its instruction says to leave Mousepad open. The report no longer says an exec-deny task's agent "worked through the UI"; it says the agent kept the files group.
- Timeline: a failed computer row reads "Could not run the script “…”: …", "Could not take a screenshot: …", not "… failed: …". Firefox ESR and Chrome are named "Firefox" and "Chrome". A no-ui `computer_observe` row names each call it made: "Opened Mousepad, took a screenshot, listed the apps".
