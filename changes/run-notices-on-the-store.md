The outbound webhook (`/v2/settings/webhook`) keeps everything in the one store, on SQLite and Postgres alike, and refuses a private address: the server no longer reads or writes `DIR/webhook.json` or `DIR/webhook-outbox.json`, so a webhook saved before this release is not set and its pending messages are not sent. To upgrade, let pending webhooks drain, then set the webhook again with `PUT /v2/settings/webhook` and give your receiver the new secret it shows once; the two old files can be deleted. A receiver on this machine or a private network is refused unless the operator sets `AGENTRUN_WEBHOOK_PRIVATE_TARGETS=1` where the server starts.
Its URL is a store setting, its secret is sealed in `trigger_settings` (on a runner's redaction list, as the other sealed settings are, and a secret replaced or removed stays on it across restarts), and its messages, their tries and the run notices it told are in the channel tables (Postgres migration 0004, SQLite schema version 6). The server says once at its start when an earlier build's file is left (`condition=webhook_left_over`).
The run notices follow the store's run-change feed, so a run that starts and ends between two reads, or whose end cannot be read for a while, is still told once.
A URL is refused at its `PUT` when it is on a private network or this machine, by address or by what its name resolves to, and each try dials the address it checked. A `PUT` that changes the URL makes a new secret and shows it once (the same URL keeps its secret, and one that no longer opens under the server's key is replaced and shown); the URL and its secret go live together, so a `PUT` the store refuses leaves the webhook as it was. `GET /v2/settings/webhook` and the log show the URL's origin and its last four characters, never the whole URL.
A run that asked a question sends `run.needs_input` once for it: the answer's take clears the run's waiting summary for a reopened run that parked on a question too, and a wait's `webhook-id` comes from its ask, never from the row the run shows last.
