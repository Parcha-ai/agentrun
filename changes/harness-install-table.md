Codex installs itself on first use, as Claude Code does, through one table of the harnesses that install on first use (`src/harness-install.ts`). The first run on codex, or the first agent saved on it, installs the version AgentRun pins (`@openai/codex@0.164.0`, with this platform's binary package) from npm into `<data>/harnesses/codex`; Claude Code's install moves to `<data>/harnesses/claude-agent`. Each is pinned by a lock the server ships (`harnesses/codex/`, every package by sha512) and installs the same way: `npm ci --ignore-scripts --include=optional` into a fresh directory, checked there (for Codex, that its platform package and binary landed, whatever the person's npm config omits), renamed into place and made read-only; a server that stops mid-install stops its npm. A codex run waits for the install and shows `Installing Codex (first use)…` while it does; until it is installed, `GET /v2/capabilities` lists codex with `installs: "on_first_use"`. Codex runs only the binary in that tree, never a copy beside the server; when npm fails, the run's error names the command that installs it by hand. Codex's npx hint (`-p @openai/codex@0.164.0`) is gone. The server image no longer carries a Codex CLI: its build removes `@openai/codex`, its platform packages and its bin link, and `docker/image-check.sh` refuses an image that holds any of them. The hint that restarts AgentRun with OpenCode keeps how it was started: npx's `-y`, `--port` and `--no-open`. `node scripts/harness-locks.mjs` (formerly `claude-lock.mjs`) makes both locks again. `@parcha/agentrun-harness-codex` takes the binary a host installed (`binary: { path, packageVersion }`, checked against the pins) and exports `codexTarget()`.
Upgrading: Codex installs itself on first use; the server image no longer carries a Codex CLI.
