`DELETE /v2/agents/{agent_id}/learning` resets an agent's learning without deleting the agent: its learning folder whole (corrections, learned workflows, their history and the audit ledger), on this server and on every Archil disk its runs used (`503` while one can't be reached, nothing deleted), then its promotion records and grades. Deleting an agent now also deletes its learning folder on a disk a run's launch named. The agent, its runs and their files stay, and the run list, `GET /stats` and `GET /usage` read the same; the next run takes the agent path with nothing learned. Learning reads only the runs after the reset: they alone count toward `compile_after` and feed a compile, a check's replays and audits. A run whose start read the agent's learning before the reset learns nothing at its end, its learning `dropped` with the new reason `reset`. Learning-only runs in flight (replays, audit shadows) are cancelled first; while a run of the agent's own is still going it answers `409 learning_busy` naming the runs, and nothing is deleted. `204` when done, idempotent (an agent that never learned is `204` too), with the owner's session or the token as deleting an agent takes (any other console session is `403 forbidden`), in the API-only profile as well. The TypeScript and Python clients add `learning.reset(agent_id)`, and the CLI `agentrun learning reset <agent_id>`.
