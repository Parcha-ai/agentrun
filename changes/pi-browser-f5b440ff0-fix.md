`@parcha/pi-browser`: `use_website` children take turns when the provider in use shares one browser (a provider says so with the new `sharedBrowser` cap, which `cdpProvider` sets on an endpoint), and a durable child keeps its turn until it has read its report and released its browser. The first call after a release says so first and carries `previous_session`, and a read of a fresh `about:blank` browser says it is fresh instead of a wall. An attach waits for an init an earlier attach left running in Stagehand's extension, instead of failing with "Stagehand initialization is already in progress". A page snapshot or screenshot the browser never answers fails at its deadline as a dropped connection, and a read that hangs again after a working reconnect is told as a stuck page, with `browser_relaunch` as the way out. The coding agent returns the typed `person_driving` result for a refused release or relaunch. A saved lease's private TMPDIR is found after a provider restart. `copyProfile` no longer ends the host process when a file vanishes between its listing and its copy. A blank optional property means not given, not an intent to refuse; a screenshot's question travels with the capture; a classified failure names the browser provider, not Browserbase; a conversation's close evicts its repeat guard and idle entry; an upload that throws is named as the upload. A dropped session the provider still runs is reconnected within a bounded budget (90 s, tries at once, then after 1 s and 3 s, each attach cut at what is left of the budget), then released as lost and told to the next call, unless a person holds, drives or watches it; the answer is `browser_unavailable` with `next: browser_relaunch`, and `CustodyPort.session` takes an optional signal. A stuck-page answer carries the same `next`. A browser the store cannot record a release for is released at the provider anyway, and a close over a failed store releases every session the process still holds, so a failed commit on pi-durable 1.2 or later no longer leaks a paid browser. A cut page action's warning survives a crash between telling it and saving the answer that told it, and the journal keeps the cut a later run's entry replaces. An upload the page never answers fails at 60 s as `possibly_effected`, and its identical retry is refused until the agent looks at the page. `browser_read` gives the judge the page's frames (their origins and the text inside them), so a challenge in an iframe is a bot check and not an empty page. The run's registered values are redacted whole before any text is cut: failure details, the repeat guard's note, web failures, download reasons, and the page text, `find` question and chunks the judge reads. A host that passes no session price is metered at Browserbase's list price, and the session record's `spent` carries `source: "list"` so the host can mark the dollars as an estimate; an explicit price, even one equal to the list's, and a deliberate `null` are not changed. `browser_read` and `web_fetch` descriptions name the redaction marker without carrying the literal. An assigned-session provider shares its one-browser hold across every provider instance built over the same session, so a host that builds the provider per call still gets one browser and one release; a browser recovered after a lost create response is tracked before it is recorded, so a store that cannot record it still lets a close release it. After a person has driven the live view, the model's next call is told so, and the session's snapshot ids are dropped, so an old snapshot id fails as stale whatever the page's URL. A cut `browser_upload` is never judged safe to run again: after a crash its identical retry is refused as `effect_unknown` until a look, and the notice never says it is safe to run again.
