`@parcha/agentrun-pi` accepts pi-durable and chord 1.2: both peer ranges are now `>=1.0.4 <1.3.0` (they ended below 1.2). Pi's own packages (pi-ai, pi-agent-core, pi-coding-agent, pi-tui, typebox) stay `*`, as Pi's package guidance asks. The workspace still develops on 1.1.0.
- CI gains `pi-cross-version`: the package's crash tests, with every first process of a run in an install of the packed packages on pi 1.1.0 and every later process in one on 1.2.0. A run left by a 1.1 process (killed with a tool call in flight, mid-submit, at any crossing of a sweep, or paused) completes on 1.2 with no effect dispatched twice. `scripts/pi-ranges.test.mjs` holds every package's pi-durable and chord ranges below 1.3, and Pi's own packages at `*`.
- **A documented limit.** A run that pi 1.2 left with a tool call in flight cannot be continued by pi 1.1: pi 1.2 keeps that call as a version 2 `pi.tool` task, and 1.1 waits on it. The only thing 1.1 writes is that task's mark from running back to pending, as pi does for any task a dead process left running. Continue such a run on 1.2, and do not downgrade pi under a live run. A test in `pi-cross-version` pins what holds: after the 1.1 process ends, every other row of the store is as it was, and 1.2 then completes the run with no request made twice.
- New in `@parcha/agentrun-pi/durable`: `refuseNewerTasks(harness, context)` and `NewerTaskError`. A host that may open a store on pi-durable before 1.2 calls `await refuseNewerTasks(harness, context)` after `Harness.open` and before `harness.resume()`. When the store holds a tool call that pi 1.2 left in flight, it throws `NewerTaskError` (code `PI_TASK_NEWER`, with the task's `kind` and `version`) instead of letting the run wait; the host then leaves that store to a process on pi-durable 1.2 or later, which continues the run. On pi-durable 1.2 the call does nothing, so a host can make it on every open.
