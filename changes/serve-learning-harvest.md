A learning run writes what it learned with its own file tools, and the server harvests it. At its seed the run gets its agent's `main` at that commit as plain files in `work/.agent/repo`, with the memo's front matter waiting for its sections, and `read`, `write` and `edit` on that working copy only: a file tool its revision did not name is refused by name outside `work/.agent/repo` and never follows a link out of it, so learning never widens what a revision may do. Once the run's end is carried back and its process has ended, the server harvests that copy into one commit on `runs/<run id>` in the agent's queue: refused while the run's process is still alive, refused whole when it would hold the run's input (any value, nested or a JSON number, of 4 or more characters once trimmed, other than a bare yes, no, true or false) or a server secret, and dated the run's end, so the start-time catch-up harvesting it again is the same commit. A run that reached its seed with no working copy is an error, never an empty run. The `learn` tool is gone: a learning revision may still name it, and the name binds nothing; on a revision that does not learn it is `422 not_an_option`. A run that ended before working copies existed is recorded once as `empty`, with that reason.
