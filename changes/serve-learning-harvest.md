A learning run writes what it learned with its own file tools, and the server harvests it. At its seed the run gets its agent's `main` at that commit as plain files in `work/.agent/repo`, with the memo's front matter waiting for its sections, and `read`, `write` and `edit` on that working copy only: a file tool its revision did not name is refused by name outside `work/.agent/repo` (a `read` outside it and `work/.agent/learnings`) and never follows a link out of it, so learning never widens what a revision may do; a tool the revision named keeps the run's `work/`. A learning revision that names a tool that runs a process (`bash`, `powershell`, `code`, or a table tool that spawns one) is `422 not_an_option` by name. The run's instructions say where and how to save what it learned. Once the run's end is carried back and its process has ended, the server harvests that copy into one commit on `runs/<run id>` in the agent's queue: recorded `waiting` while the run's process is still alive (told from a later process with its pid by its boot and start time) and harvested once it exits, or by the next start's catch-up when the server closed first, refused whole when a file or a path it writes or deletes would hold the run's input (any value, nested or a JSON number, of 4 or more characters once trimmed, other than a bare yes, no, true or false) or a server secret, as it is, JSON-escaped, or from 12 bytes on hex, percent, base64 or base64url encoded at any offset, and dated the run's end, so the start-time catch-up harvesting it again is the same commit. A run that reached its seed with no working copy is an error, never an empty run, and one that changed nothing but the memo stub it was seeded with proposes nothing. The `learn` tool is gone: a learning revision may still name it, and the name binds nothing; on a revision that does not learn it is `422 not_an_option`. A run that ended before working copies existed is recorded once as `empty`, with that reason.
