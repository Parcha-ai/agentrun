The redactor now finds more of a held value that a text shows only in part or written another way, and more of a private key:
- A held value of many lines, such as a private key, is found by its lines too: a text that prints its first lines (`head -n 11 key.pem`) or its body with the armor stripped shows `[redacted]` in place of each line. A key's last body line, mostly shorter than the others, is held with its END line, so its last two lines (`tail -n 2 key.pem`) are cut too.
- A string of a held JSON value, at any depth, is held as a value of its own when it has a line break (a service account's `private_key`) or its key names a secret: with its separators dropped and lowered, the key holds `secret`, `password`, `passwd`, `token`, `private`, `credential` or `apikey`, or ends in `key` (`client_secret`, `aws_secret_access_key`, `SessionToken`, `signing_secret`, a one-line `private_key`), or is a name a URL's credential parameter goes by. A key that ends in `uri`, `url`, `id`, `type`, `email`, `endpoint`, `expiry` or `expires`, a public key, `page_token` and `next_token` name none. A JWK's private members (`d`, `p`, `q`, `dp`, `dq`, `qi`, `k`) are held beside its `kty`. Printed alone, it is cut. An array's items have no key, so only the line-break rule holds them. The value's other strings (an id, a project, its URLs) are not, and its own lines are no parts of it, so a pretty-printed service account's public lines (`"token_uri": "https://oauth2.googleapis.com/token",`) show.
- The view that reads JSON's escapes now reads all of them (`\n`, `\r`, `\t`, `\"`, `\\`, `\/`, `\b`, `\f` and `\uXXXX`, not only `\uXXXX`), and reads them twice, for JSON inside JSON. A held value of many lines escaped twice, or with its line breaks written as `\r\n`, withholds the text. Escaped once, it is still cut in place. A text with an escaped backslash is read one level deep too, so a held value that holds a backslash before `n` or `u` (the characters `\n` as written), with its backslash escaped as `\\` or `\`, is still found.
- A held value with a zero-width space, a soft hyphen or another character that renders as nothing between its characters withholds the text, as a value split by whitespace does. A held value that itself holds one is found without it too.
- A held value glued to the end of a run of text too long to read is found, and the answer reads `[redacted]`. Padding the matcher reads as nothing between the value and the run's end (zero-width spaces, soft hyphens, `\n` escapes, `%E2%80%8B`) does not hide it: the run's end is read by the characters the matcher sees, and padding longer than a piece withholds the answer.
- Where a call's result is cut at its read stop, the read past the stop counts JSON's escapes, percent-encoded bytes and characters that render as nothing as the views read them (a zero-width space written as `%E2%80%8B` counts as nothing), so padding of them never hides the rest of a value the stop split.
- A private key block is cut whole, from its BEGIN line through its body to its END line, not its BEGIN line alone, with no held value to cut it by. With its END line within 16 KiB, all between is cut, whatever wraps the body's lines (a code string literal on each, a `#` or `>` before each, an XML or HTML line break, an escape, an armored key's headers). With no END line in reach (a key cut short), it is cut through its body's lines: LF, CRLF or CR line ends, maybe escaped in a quoted string up to four strings deep, blanks and escaped tabs around each line, blank lines, Proc-Type, DEK-Info, Version and Comment headers, at most 1,024 lines of at most 16,384 characters. Text after the body that is no such line stays. A header with no body line after it is cut alone, as before. An answer or a call's result is read in pieces of about 8 KiB, and a piece never ends inside a block whose END line is in reach: it ends before the block's BEGIN line, so the next piece cuts the block whole, and a block longer than a piece is read as one run and shows as `[redacted]`.

An id or hash holding "aba" and nine digits (a run id's last group, a short sha) is no longer cut as a routing number in what learning serves: the routing word must stand alone, as in `ABA 123456789`, `ABA: 123456789`, `ABA#123456789` or `routing number 123456789`, which are still cut.
