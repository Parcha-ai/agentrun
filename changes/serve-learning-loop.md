An agent with learning on remembers, on pi, claude-agent and codex: when a run answers or fails, the server asks the same session one end-of-run turn to add notes to its copy of the agent's learning folder; what it adds is checked, graded by one grader on the agent's own model, and merged into the folder's `main`, where the next run reads it.
- The turn goes through the run's door under a fixed request id, at most once, sent with the origin `reflect` that only the server sets, under the run's cap; the run's answer stays the job's, and the turn's rows are labelled `learning`. `startServe` takes `reflectTimeoutMs` (default 5 minutes).
- As the run settles, before it reads ended or a follow-up can open it again, the turn's `work/.learning/` is moved whole (one rename) to `runs/<id>/learning-turn/`; what it wrote is read from there alone, without following a link, and checked by the server's `checkProposal` before anything is written; a follow-up finds `work/.learning/` laid again from the seed; `MEMORY.md` as the turn left it is ignored. The grader is the server's `gradePrompt` and `parseVerdict`, fail-closed, over each active note's index line and only the superseded notes in full; a call cut off at its bound (`startServe`'s `gradeTimeoutMs`, default 3 minutes) has an unknown cost, never $0; an injection screen runs first only with Jev's key. The merge is one host commit: new notes, superseded ones marked, `MEMORY.md` rebuilt, a `Run-Id` trailer, compare-and-swap on `main`, never twice.
- The run's `learning` gains the states `reflecting`, `proposed` and `merged` and the drop reasons of the console's closed list; a learning timeline row (kind `learning`) is shown for every outcome, `seed_failed` included. Each run's learning end is one line of the learning ledger, `DATA/learning-usage.jsonl` (`{run, agent, state, reason, at, cost, tokens}`), written once its `serve.json` holds it; `GET /usage` reads the grades' cost from it under the meter `learning`, and `GET /stats` gains `learning: {runs, merged, dropped, in_progress}` over its filters, from the ledger and the runs the server holds, never a run's files.
- `@parcha/pi-durable-agent`: `TimelineKind` gains `learning`.
