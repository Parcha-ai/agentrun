Render: a sandbox's labels file is read only where it agrees with the sandbox's name, and a create's sweeps by name ask Render for the sandbox's whole name. The name carries the run's hash and the epoch, set at create; the file is the guest's root's to rewrite. A file that says another run or epoch than the name is treated as unread: a listing that must read it fails closed, naming the sandbox and what differs, and `get` answers the two labels the name carries, so release still terminates it. A create whose labels have both a run and an epoch now looks its sandbox up by that whole name (`computer-<12 hex>-r<run hash>-e<epoch>`) with Render's exact name filter, in its first check, its convergence, its wait to be listed and its sweep after a failed create: one page each, no labels file read, so a workspace of more than 10,000 sandboxes (100 pages) no longer fails the create. Any other listing still reads every page and fails past 100. Rolling back to beta.62, or a beta.62 replica still serving during a rolling deploy, treats the suffixed names as not computers: those sandboxes keep billing until Render ends them at their timeout, at most a day after their create.
