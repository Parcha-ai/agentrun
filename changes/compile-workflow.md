A learning agent now writes its whole job as a learned workflow in a compile turn, which replaces the ask that came after a skill had served 3 runs. The turn runs at the end of a completed run when the agent has 3 or more active notes or 5 or more completed runs, has no learned workflow active or waiting, and compiled nothing in its last 4 runs. It also runs when a workflow handed the run back, or when the money rule stopped one; then it asks for that workflow's next version. The model gets the DSL's own author contract with this server's rules, one worked example (an extract step, a judge step when the run has a decision provider, a decide step that gives its `confidence`, and an escalate step for low confidence), the agent's notes, and the last 5 runs' tool calls, answers and follow-up messages. The draft goes through the static checks and then a dry run. Whatever they refuse goes back to the model, up to 3 more times.
Every attempt is recorded. `GET /runs/{id}/learning` now always has `compiled` (the workflow, the notes it absorbed in `from_notes`, and `attempts` with each one's `ok` and `errors`, or null) and `draft_errors`, which holds the errors of a draft that never passed. A draft that fails also goes into the run's `problems`. When a compiled workflow merges, each note it absorbed gets `compiled_into: <workflow>` in its front matter and is still served to runs the agent does by hand. A run's own note may not set `compiled_into`. The end-of-run look-back no longer asks for a workflow draft.
