API-only (`AGENTRUN_API_ONLY=1`): the token's Composio save now stands on nothing the owner's does, and its Composio users, a run's included, have a namespace of their own. The token's save (`PUT /settings/mcp-servers/{name}/composio`) that is not `per_run` reaches Composio, and its server calls, as `agentrun.token.<user_id>` (no `user_id`: `agentrun.token.agentrun`), a user that, through this install, only the token's own connect link connects; its `user_id` is at most 113 characters. No save names a `user_id` starting `agentrun.token.` in any letter case, the owner's included: `422` under `user_id`, before anything is sent. A run's binding of a per-run Composio server (`mcp_auth.<server>`) stays in that namespace: its `composio_user_id` starts `agentrun.token.` with a user after it, else `422` `not_allowed` under it, and a `connected_account_id` it names is one Composio lists under that user, read at the start or message that hands it (50 a page, at most 10 pages), else `422` `not_allowed` under it, as is one past those pages; Composio not answering that read is `424`, each refusal says which check refused it, and nothing is started. All API tokens share one Composio namespace, so a token's runs can use any account connected under `agentrun.token.*`, and never the owner's; an account connected by hand under such a user is the token's. A backend binds its users as `agentrun.token.<its own id>` and connects their accounts at Composio under those ids. A run's claim refuses a binding outside the namespace too. A server the token saved in 0.1.0-beta.56 or earlier calls as a user outside the namespace, which may be the owner's: every run's claim of it is now refused unsent, in words that say to delete it, and the start names each in one log line (`api_only_composio_outside_namespace`). Delete it and save it again, then connect its account through the new connect link. Where a server the owner saved stands on its auth config, a save over it is `403` and says it can only be deleted; where none does, a save over it moves it to the namespaced user and deletes at Composio every account its record holds as made here under the bare user unless another saved server stands on it. The token's save never uses an auth config a server the owner saved uses: naming one (`auth_config_id`) is `403`, and so is a save whose toolkit's own auth config, as Composio answers it, is that one, before anything is made at Composio. An `auth_config_id` Composio answers under another id (another letter case, say) is `422` under it, for any save. Nor does the token's save stand on an ACTIVE connected account it did not connect: each one Composio already has for that user under its auth config (never one it answers under another user) is `403` before anything is made, unless a server the token saved holds it as one it made. The lookup reads 50 accounts a page, at most 10 pages: past that the token's save is `403`, and an owner's save goes on with the ones it read. `GET /capabilities` lists `AGENTRUN_API_ONLY_MCP_ORIGINS` under `switches`, saying only whether the list is set and that plain http is for a loopback host alone, and the start banner names the per_run save it serves. An `AGENTRUN_API_ONLY_MCP_ORIGINS` entry that is plain `http://` to a host other than a loopback one (127.0.0.0/8, ::1, localhost) now stops the start, naming the entry by its place: list that host's origin as https.
