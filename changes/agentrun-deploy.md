`agentrun deploy DIR --to URL` deploys an agent package folder to another AgentRun (`--to cloud` is the hosted one; `AGENTRUN_CLOUD_URL` overrides its address). It uploads the package, prints the apply's plan (create or revise, the keys and MCP servers the target lacks, each trigger made, kept or removed, the computer), asks before it applies (`--yes` off a terminal), and writes a lock to `DIR/.agentrun/deploy.json`. A second deploy of the same files says it is up to date and sends nothing that writes; changed files make the agent's next revision. A target the package needs keys or connections on exits 3 with nothing made, and an agent edited on the target since the last deploy exits 2 unless `--force`. `agentrun deploy rollback` makes the previous revision current, and `agentrun deploy delete` deletes the agent and the lock. `agentrun deploy AGENT_ID` deploys an agent from this install by its package; `--pause-source` turns its schedules off here once it is deployed.
- `POST /v2/templates/import` takes `{files}`, a package uploaded whole, checked under the GitHub import's limits and in its words, stored as `upload:<name>` with the package's sha256, and replaced by the next upload of that name. An upload asks no publisher trust. A server that serves the API alone takes an upload and refuses a GitHub `source`.
- `POST /v2/templates/{id}/apply` takes `dry_run: true`: it answers `{plan}` from the apply's own reads and checks and writes nothing.
- `POST /v2/templates/{id}/apply` takes `revision` (with `agent_id`) and `sha`, what the caller read: the apply, or its plan, is 412 when the agent's current revision or the package stored under that id is another, with nothing changed. Its answer names the revision it wrote, or kept, as `revision_id`. A plan whose keys are missing lists them even where the model needs one of them, and a plan on a server with no public URL says a Composio trigger is skipped, as the apply does.
- `agentrun deploy delete` removes the lock only when the agent is gone from the target: a 404 to the archive or the delete is followed by a read of the agent, and one still there exits 2 with nothing deleted and the lock kept. `agentrun deploy AGENT_ID` exits 2 for an agent this install does not have or does not export. `--to` takes an address whose path lacks `/v2` (`https://host/api` is `https://host/api/v2`).
- A folder's lock comes with the folder, so its target gets the API key only where this CLI has deployed before, or when it is AgentRun cloud: any other address needs `--to`, and nothing is sent until then.
- A plan lists `MONID_API_KEY` as missing where the package grants a monid tool and the server has no monid key, as the apply refuses it.
- A deploy whose apply skipped a trigger (a connection or a feed the target lacks) leaves a lock that names no package, so the next deploy of the same files applies again and makes the trigger once it can.
- One deploy, rollback or delete at a time per source: another one of the same folder or install agent exits 2 with nothing sent, and a hold left by a process of this machine that has ended is taken. The CLI's own deploy record is changed under a lock. A folder whose `.agentrun`, or its `deploy.json`, is a symbolic link is refused with nothing sent.
