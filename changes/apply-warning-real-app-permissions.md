Applying a template that grants a GitHub tool (release-notes' `issue_write`) on a server whose GitHub MCP server runs on the GitHub App now warns from the App's real permissions, not from what its manifest asks for. Apply reads each installation's own permissions map from GitHub (`GET /app/installations/{id}`), says per tool and per account what is missing ("has Issues: read on acme"), and says nothing when the installation holds it. When the map cannot be read (no App connected, none installed, GitHub out of reach), the warning says the check could not be made (`reason: not_set_up_here`) and never states that GitHub refuses the tool. The reads run four at a time within one four-second limit, so many or slow installations never hold Apply's answer (the agent and triggers are already created; only the warning is best-effort): an account not read in time, or whose map was refused or malformed, is named in a `not_set_up_here` warning as one the server could not check, never passed as holding the permission. Before, an App whose settings showed Issues: read was told it could not write issues even where the call went through.
