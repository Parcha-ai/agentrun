An agent can be exported as a template package: `GET /v2/agents/{agent_id}/package` answers its current revision as the files of a package (`agent.md` with the instructions as its body, `skills/`, `rules/`, an output schema) and their sha256, and `agentrun export AGENT --out DIR` writes them as a folder that `agentrun template validate` reads and any AgentRun applies. `agent.md` always names the model and approvals. MCP tools become needs by their saved server's source and toolkit, and triggers carry no agent and no secret. What names this host (its box, its computer's provider, its pins of this server's tool listings, its place) is left out. The answer's `report` names what can't travel as it is: `blocked` (an MCP server saved nowhere here, on this machine's loopback, or sending its own auth header) and `remade` (webhook, GitHub, Composio and email triggers, browser sign-ins, a paired computer, what the agent learned). `agentrun export` prints both, and with anything blocked it writes nothing and exits 2. A native, CLI learning, SDK or another system's agent, or a workflow, answers `409 not_exportable`.
