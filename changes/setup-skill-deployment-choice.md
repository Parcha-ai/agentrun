The setup skill (`docs/SKILL.md`) asks where AgentRun should run before it installs or deploys anything. The assistant presents four places with one line each (this computer, a machine the person already runs agents on, a hosting provider, AgentRun Cloud) and waits for the answer. "Set it up", "self-host" or "on my machines" no longer counts as a choice, and it never creates a service on Render or another provider the person did not name. Before that question it asks which scheduled, triggered or always-on agents the person already runs and, with permission, reads this machine's cron, systemd timers (system and user), launchd jobs and CI schedules for Claude Code and Codex jobs, so AgentRun goes where those agents live and they are the ones connected. That reading is one script in the skill: it reads the command each job runs, which a list of timers or launchd labels does not show, and returns only where the job is, its schedule and the runtime's name, so a prompt, key or environment value written into a job stays on the machine. A job that starts an agent through a wrapper script is not visible to it, so the assistant asks before concluding there are none.
