A template's `mcp` needs name where their tools come from, `{source: composio | github | url, toolkit, tools, required?, reason?, allow?, pin?}`, never a saved server's name: `server:` is removed, and a package that still has it is refused with the new shape in the message. To upgrade a package, replace `server: <name>` with its `source` and `toolkit` (`source: github, toolkit: github` for GitHub; `source: composio, toolkit: <slug>` for a Composio toolkit, its tools by their action slugs; else `source: url` with the toolkit you will set on the saved server). Inside the package its tools are `mcp:<toolkit>/<tool>`, and an apply's `grants` name them that way.
- Apply maps each need to the saved MCP server whose recorded source and toolkit are the need's; where several are, the one named as the toolkit, else the first, and the apply's new `servers` (`{<toolkit>: <server>}`) picks another. When the server's name is not the toolkit, apply rewrites `mcp:<toolkit>/` to `mcp:<server>/` in the instructions, the skills and the tool settings. The answer's `servers` says which server each need used, or null. A need with none is not set up here: its warning (or a required one's `409`) says how to add one, for Composio the preset with the toolkit and actions filled in.
- Each saved MCP server records `source` and `toolkit`, shown by `GET /v2/settings/mcp-servers` and taken by its `PUT`: the Composio preset records `composio` and its toolkit, a `github_app` server or one at GitHub's MCP address `github`, one on Composio's hosts `composio` (its toolkit named by its owner), any other `url` with the toolkit its owner sets in Settings → MCP servers. `POST .../oauth/start` takes `source` and `toolkit` too, for the server its sign-in saves.
- New display fields: `category` (one of engineering, security, sales, marketing, research, finance, operations, compliance, personal) and `tags` (at most 8). A package may hold `examples/<name>/` with `input.json`, `output.json` (checked against its output schema) and an optional `output.md`, listed as `examples` and never applied.
- The shipped packages say where their tools come from, with a reason each: code-review and release-notes from GitHub, market-monitor's sends and inbound-lead's HubSpot and Slack tools from Composio by their action slugs (`SLACK_SEND_MESSAGE` pinned to the channel; HubSpot's create pinned to notes).
- The console's apply screen shows each need's source, reason and the saved server it will use, a choice where several match, and a link to add one where none does; Settings → MCP servers shows and edits each server's source and toolkit.
