A template's `mcp` needs name where their tools come from, `{source: composio | github | url, toolkit, tools, required?, reason?, allow?, pin?}`, never a saved server's name: `server:` is removed, and a package that still has it is refused with the new shape in the message. To upgrade a package, replace `server: <name>` with its `source` and `toolkit` (`source: github, toolkit: github` for GitHub; `source: composio, toolkit: <slug>` for a Composio toolkit, its tools by their action slugs; else `source: url` with the toolkit you will set on the saved server). Inside the package its tools are `mcp:<toolkit>/<tool>`, and an apply's `grants` name them that way.
- Apply maps each need to the saved MCP server whose recorded source and toolkit are the need's; where several are, the owner picks one with the apply's new `servers` (`{<toolkit>: <server>}`), and an apply with no pick is `422` naming them: a server is never picked for the owner. When the server's name is not the toolkit, apply renames the package's tool names (`mcp:<toolkit>/<tool>` and `mcp:<toolkit>/*`) to `mcp:<server>/...` in the instructions, the skills, the tool settings and the grants. The answer's `servers` says which server each need used, or null. A need with none is not set up here: its warning (or a required one's `409`) says how to add one, for Composio the preset with the toolkit and actions filled in.
- Each saved MCP server records `source` and `toolkit`, shown by `GET /v2/settings/mcp-servers`, when it is saved and from what made it: the Composio preset records `composio` and its toolkit, a `github_app` server is `github`, any other is `url` with the toolkit its owner sets (`toolkit` in the `PUT`, or Settings → MCP servers). `POST .../oauth/start` takes `toolkit` too, for the server its sign-in saves.
- A template eval's fake MCP server stands in for the need it fakes: the eval's own server records it as the need's source and toolkit. With `--server`, a case that fakes a `composio` or `github` need fails, saying to run it on the eval's own server.
- New display fields: `category` (one of engineering, security, sales, marketing, research, finance, operations, compliance, personal) and `tags` (at most 8). A package may hold `examples/<name>/` with `input.json`, `output.json` (checked against its output schema) and an optional `output.md`, listed as `examples` and never applied.
- The shipped packages say where their tools come from, with a reason each: code-review and release-notes from GitHub, market-monitor's sends and inbound-lead's HubSpot and Slack tools from Composio by their action slugs (`SLACK_SEND_MESSAGE` pinned to the channel, `channel_id` held absent; `GMAIL_SEND_EMAIL` to the one address, `to`, `cc`, `bcc`, `extra_recipients` and `from_email` held absent).
- Security: code-review and release-notes pin every GitHub tool, reads too, to the one repository, so a hostile pull request or release body can't have the agent read another repository the GitHub App reaches. Their `repo` parameter is now `owner` and `repo`, and their trigger is held to `<owner>/<repo>`. The free-text searches that can't be pinned are dropped: code-review's `search_code`, release-notes' `search_issues` and `search_pull_requests` (it lists with `list_pull_requests` and `list_issues` instead). Each has an eval case where the body asks for another repository's file.
- Security: inbound-lead reads nothing from HubSpot. It runs unattended on a form anyone can submit and holds `web_fetch`, so a CRM read could be sent out in a fetched URL. Its one HubSpot tool is `HUBSPOT_CREATE_NOTE`, optional: one note, the fit score in its text, on the contact a HubSpot CRM event's own payload names (with none, it answers with the brief and says why). The contact update and the `crm_score_property` parameter are dropped too, since a pin can't limit which fields an update sets. A package that holds `web_fetch` now lists no MCP read.
- The console's apply screen shows each need's source, reason and the saved server it will use, a choice where several match, and a link to add one where none does; Settings → MCP servers shows and edits each server's source and toolkit.
