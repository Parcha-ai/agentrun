Each computer provider is declared once, in a descriptor, and the server names no provider. Code that imports `@parcha/agentrun-computer` changes in three places:
- The package root no longer exports a provider class or its vendor's helpers (`DockerProvider`, `DaytonaProvider`, `ModalProvider`, `BrowserbaseProvider`, `KernelProvider`, `browserbaseRest`, `kernelRest` and their constants), so importing the root loads no provider. Import one from its subpath (`@parcha/agentrun-computer/docker`, `/daytona`, `/modal`, `/e2b`, `/orgo`, `/orgo-desktop`, `/phone-harness`, `/browserbase`, `/kernel`), or build it by id with `providerFor(id, options)`. The root still exports their types.
- A vendor's own failure has the one code `vendor`, with the provider's id in the error's `vendor` field, where it had a code per vendor (`docker`, `daytona`, `modal`, `e2b`, `orgo`, `phone`). Match `code === "vendor"` and read `vendor`.
- A provider written outside the package checks a spec with `checkTenure` (it was `checkLifetime`): `ComputerSpec.lifetimeMs` is optional now, since an agent's own computer (`spec.owner`) has none, and `release` may be asked to `detach`. `ProviderId` is any id.

What a provider declares lives in its descriptor (`src/descriptors/<id>.ts`, checked by `defineProvider`): its label, its keys and the option each fills, settings that are no key (Modal's `modalApp`), mounts, configurations, the default image per kind, and whether it prepares its image (`prepareImage`), runs on this host (`local`) or takes a ledger the server keeps (`ledger`). `PROVIDERS` and the provider registry are derived from the descriptors. A configuration may name the `image` an agent's setting selects it by and the create() `options` that build it (`imagesOf`, `configurationOf`). `ComputerProvider` gains an optional `prepareImage(context)`, the image a computer starts from, built or pulled; Docker's is its `image()`.

Persistent computers are in the provider contract: `capabilities().persistence` declares a provider that keeps an agent's computers; `spec.owner` ({ agent, idleTtlMs? }) makes one the agent's, with no run deadline; `release(ref, "detach")` stops it with its state kept, and `attach(ref, { claim })` brings it back under a new claim, a claim below the epoch it carries fenced. The janitor never deletes an owned computer by a deadline: only once its agent is gone or it has been detached past its idle TTL. Conformance checks `provider.owner` and `provider.detach` on every provider, and `provider.persistence` where persistence is declared.

The server reads each provider from its descriptor: its saved keys fill the options the descriptor names, a setting it declares fills its option from the server's settings or its default, the store's session ledger goes to a provider that declares one, and the image and host options go to one that declares `prepareImage` or `local`. A provider added to the computer package needs no server edit. A provider the key table does not list is no longer refused when its keys are read. A vendor's failure reads "<provider> answered with an error".

An agent's computer may name an image: `computer: { kind, provider, image }`, such as `{ kind: "desktop", provider: "orgo", image: "windows" }`. It selects the provider's configuration of that name, built by its options (Orgo's `os`); absent, the kind's default, as before. GET /computers lists each provider's `images` for the kind, the default first. An image the provider does not offer saves with a warning naming the ones it does, and its runs are refused at their start in the same words.
