The server reads what each computer provider takes from its descriptor and names no provider itself. A provider's saved keys fill the options its descriptor names. A setting it declares (Modal's app, `modalApp`) fills its option from the server's settings, else its default. The store's session ledger goes to a provider that declares one, and the image and host options go to a provider that declares `prepareImage` or `local`. A provider added to the computer package needs no server edit. A provider the key table does not list is no longer refused when its keys are read; whether it can be made is its maker's to say. A vendor's own failure reads in the one `vendor` code's words ("<provider> answered with an error"); an old per-vendor code reads as a failed test.
An agent's computer may name an image: `computer: { kind, provider, image }`, such as `{ kind: "desktop", provider: "orgo", image: "windows" }`. The image selects the provider's configuration of that name, which its descriptor declares with the create() options that build it (Orgo's `os`); absent, the kind's default, as before. GET /computers lists each provider's `images` for the kind, the default first. An image the provider does not offer saves with a warning naming the ones it does, and its runs are refused at their start in the same words.
`ComputerProvider` gains an optional `prepareImage(context)`: the image a computer starts from, built or pulled, for a provider whose descriptor declares `prepareImage`. Docker's is its `image()`. A configuration (`KindCapabilities`) may carry `image` and `options`; `imagesOf` and `configurationOf` read them.
