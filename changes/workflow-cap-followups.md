A workflow run whose cap was raised while the server was at its limit (`max_concurrent_runs`, or the memory for runs) waits for a place, and the place that frees is now kept for it, oldest first: a newer start is refused meanwhile (429 `rate_limited`, "This server's free place is kept for a run whose cap was raised and that waits to open again", `details.kept_for_raised`), so a stream of new starts can no longer starve a raised run. A kept place holds both the count and the memory its run's harness takes, so a raised run on a large harness holds back a smaller start that would fit beside it.
A workflow paused at its cap lets its process go after the hold when its model nodes' verify decisions and model requests are what wait, including two map items waiting at once. A verify decision counts as its node's work by its execution path, and a model request counts for its own node by its conversation's provider session, so the pause names the node that waits: before, either could count for a sibling item (pi runs a node's turn in whatever context started its work), which left the process held for good and the pause naming the wrong item. A wait whose pause could not be written to disk no longer stays counted as waiting, which could let the process go beside a step still at work.
- `@parcha/agentrun-decisions`: OpenRouter's `priceOf(model)` throws `CatalogUnreadable` for a catalog that answers an empty list, or lists the model with no price, and reads it again next time; a capped decision then fails unsent as a connection error, never as the cap's stop.
- `@parcha/agentrun-serve`: a browser session's open record (`agentrun.browser_session_open`) no longer carries `held_usd`, which nothing read.
