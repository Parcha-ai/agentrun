`readPage` no longer holds the event loop on a big page. It handed the whole page to node-html-markdown, which is synchronous and quadratic (it re-reads the end of its growing output after every append, and its parser walks a node's siblings at every append), so a 3.15 MB page of download tables held the loop for minutes: a host's run lost its heartbeat and was fenced, with no answer. Now one linear pass drops the page's script, style, svg, noscript and template blocks and its comments, what is left is cut at `READ_MAX_CHARS` (1,000,000 characters), and a worker thread converts it to markdown in pieces of about 16 KB cut at block boundaries, each wrapped in the lists and tables open around it (a table's first row repeated as its header), so the conversion grows linearly with the page. A conversion that has not finished within `READ_DEADLINE_MS` (5 s, or `deadlineMs`), or that fails, is stopped, and the text is the page's plain text, read on the loop in steps that yield it. The result gains `converted` (`"markdown"` or `"text"`) and, for a page that was cut, `truncated: true` and `html_chars`, the page's whole length; `signal` ends a read, the worker stopped, with its reason. The page's title and links come from the same linear pass in both cases, and no longer include anchors inside `template`, `noscript` or comments. The coding agent's `httpBackup` reads HTML through `readPage` and ends a cut page's text with a line saying so.
