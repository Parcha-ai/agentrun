A deploy parity check: `node scripts/deploy-parity-read.mjs --source URL --source-agent ID --target URL --lock DIR/.agentrun/deploy.json` reads one agent on the install it came from and on the one `agentrun deploy` sent it to, and says field by field whether it is the same agent: every field of its definition but the install's own (its id, revision count and place), so a new field is compared by default; each MCP tool by its server's source and toolkit, in its tools and where its instructions name it; skill files by content hash, from the agent's package; declared keys and triggers. It exits 0 when it is, 1 naming each field missing, changed or extra, or each field an install did not serve, and 2 on bad input. The target token goes to `--target` alone: the lock gives only the agent id, and a lock naming another target is refused with nothing sent. A fixture agent with one of each kind is deployed both ways (a folder, and an install's agent) in the agentrun package's tests, which pin the source agent to the fixture and fail naming any field a deploy drops.
