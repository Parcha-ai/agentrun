A deploy parity check: `node scripts/deploy-parity-read.mjs --source URL --source-agent ID --target URL --lock DIR/.agentrun/deploy.json` reads one agent on the install it came from and on the one `agentrun deploy` sent it to, and says field by field whether it is the same agent: every field of its definition but the install's own (its id, revision count and place), so a new field is compared by default, with the computer compared by its kind and needs alone (the target sets its provider, image and the rest again); each MCP tool by its server's source and toolkit, in its tools and where its instructions name it, by serve's own MCP name grammar; skill files by content hash, from the agent's package; declared keys and triggers. It exits 0 when it is, 1 naming each field missing, changed or extra, or each field an install did not serve, and 2 when it could not check (bad input, or a body it can't read), with one line. A tool's settings in a difference print as a short digest, never the value, since a pin can hold a credential. The URLs are taken as the CLI takes them: http or https with no query, fragment, user or password, refused before any request and never echoed. The target token goes to `--target` alone: the lock gives only the agent id, and a lock written for another target is refused with nothing sent. A fixture agent with one of each kind is deployed both ways (a folder, and an install's agent) in the agentrun package's tests, which pin the source agent to the fixture and fail naming any field a deploy drops.
