An API-only server now serves suggested agents to a scoped request (the `AgentRun-Workspace` header): `GET /v2/suggestions`, `POST /v2/suggestions/scans`, `GET /v2/suggestions/{id}`, its discard, restore and create, `GET /v2/integrations/github` and `GET /v2/integrations/github/repositories`. Each workspace keeps its own suggestions and scans, scanned by its own scout agent; another workspace's suggestion answers the same 404 as an unknown id. The server's GitHub App is its operator's, so a workspace never reaches it: GitHub reads as not connected (`{"connected": false}`, and 409 `github_not_connected` for the repository list and for a create), and a scan reads the public repository anonymously. Connecting, disconnecting and the install callbacks stay refused to a scoped request (403 `not_scoped`).

Where the host starts a workspace's runs (an API-only server with a launch hook), a workspace's scan is reserved with `start: "host"` instead: the answer (200, `status: "starting"`) names the scout agent, the run's `input` and the reservation's `scan`, and nothing starts here. The host starts that run under its own key and billing, then binds it within two minutes by sending `run_id` with `scan` (202 as a started scan; the same bind again answers the same). A bind of a run that is not the scout's in that workspace, with another `scan`, or after the reservation lapsed is 404 `not_found`. A host that will not bind a run releases the reservation by sending `scan` alone (200, `status: "released"`), and the next scan of the repository reserves at once; another `scan`, a lapsed or a bound reservation is 404 `not_found`. A workspace's scan sent there without `start: "host"` is 409 `agent_not_runnable` and reserves nothing.
