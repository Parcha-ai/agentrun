Security: AgentRun now requires Node 24.22.3 or newer (Node's November 2026 security release); the server image runs 24.22.3. Every package's `engines.node` is `>=24.22.3` and `.nvmrc` pins 24.22.3. The patch counts: `npx @parcha/agentrun` and `scripts/check-node.mjs` refuse 24.22.0 to 24.22.2 (and anything older) with one line naming 24.22.3. An upgrader on an older Node runs `nvm install && nvm use` in a checkout, or installs Node 24.22.3 or a later 24, 25 or 26.
- The server image (`packages/serve/docker/Dockerfile`) builds and runs on Node 24.22.3 over `debian:trixie-slim` (pinned to its multi-arch index digest), installed from nodejs.org by `packages/serve/docker/install-node.sh`, which fails the build unless the release's `SHASUMS256.txt` signatures (`.sig` and `.asc`) verify against the pinned release key and the tarball matches its checksum. The official `node:24.22.3` image was not yet published for amd64 and arm64; the image moves back to the official node image next release. Its only Node is the verified one: the build fails on any other `node` binary.
- The Docker egress proxies (the computer provider's `EGRESS_IMAGE`, and the server's on macOS Docker) stay on Node 22.23.4 in this release. That is behind Node 22's own patch, 22.23.5, but none of the release's CVEs reaches them: they speak cleartext `node:http`/`node:net` and pass TLS through CONNECT without terminating it. Every host pulls that image rather than building it, so it moves to whichever official index (`node:24.22.3` or `node:22.23.5`) is published for amd64 and arm64 first, in the next release.
- CI tests on one Node, 24.22.3, the floor and the pin at once: the 24.11.0 leg is gone. The required checks keep their names (`verify`, `lean`).
- What the release fixes and what of it reaches AgentRun: the HIGH HTTP/2, HTTPS and TLS-server issues (CVE-2026-123863, -123864, -123865, -123866, -123874, -126051, -123872) need a Node `http2`, `https` or `tls` server, and AgentRun runs none: the server, the model proxy and the egress proxies listen with `node:http` in cleartext, and the egress proxies pass TLS through CONNECT without terminating it. The `https.Agent` session-reuse issue (CVE-2026-123877) needs `https.Agent`, which AgentRun does not use (outbound calls go through `fetch`, and the Postgres store's TLS is a client the advisory does not name). The proxy-credential error message (CVE-2026-123871) needs Node's built-in env proxy (`NODE_USE_ENV_PROXY` or `--use-env-proxy`), which AgentRun never turns on; a host that runs `@parcha/pi-browser` under `--use-env-proxy` with credentials in `HTTPS_PROXY` could have printed them, and gets the fix. The release also updates the llhttp parser that reads every request the server and the egress proxies receive, and the bundled undici behind `fetch`.
