`web_search` hits carry an optional `snippet` (`SearchHit.snippet`): the provider's excerpt of the page, its markdown links reduced to their text, whitespace collapsed, clipped to `WEB_SEARCH_SNIPPET_MAX` (500) characters and redacted. `createWebExtension`'s `searchSources` (`SearchSource`) are searches tried in order before the provider's own; a source that throws hands the call to the next, a cancelled call is not handed on, `details.primary_failure` names the first failure when a later source answered, a source's answer is priced at the usage it reports, and a source whose optional `available()` answers false is skipped without counting as a failure. `fetchSources` (`FetchSource`) do the same for a markdown `web_fetch`: tried before the provider's fetch, a page one answers is filed exactly as the provider's is under `via: <name>_fetch` and priced at its reported usage, and its failure (a throw, no content, an HTTP error status) hands the read to the provider, whose failure stays the call's. The `web_fetch` description says a fetched page is filed as evidence and is what a claim cites; `web_search`'s says results and snippets are leads, not evidence. The tool's description says a snippet is a lead to the page, not evidence of it.
