A computer mounts the run's folder at `/workspace` (`WORKSPACE`), the one workspace path in every computer. `ComputerSpec.mount` is `{ kind: "bind", path }` (a folder on the provider's host) or `{ kind: "archil", disk, region, folder, token }` (the run's folder inside an Archil disk in its region), and `capabilities().mount` lists the kinds a provider takes. `checkMount(mount, declared)` is the one rule every provider's `check` runs, with no vendor call: a kind the provider does not declare is refused in words; a bind's path is absolute, canonical, an existing directory, with no NUL; an Archil mount's disk, region, folder and token are non-empty strings, the folder relative to the disk's root with no `..`. The Archil token is never in a refusal, a label, a read-back (`MountReadBack`, `readBackOf`: `{ kind: "archil", disk, region, folder }`) or an error.
- `DockerProvider` declares `mount: ["bind"]` and binds the folder read-write with `--mount type=bind,src=<path>,dst=/workspace`; `HOME` and the default workdir stay `/work`. It never chowns or chmods the folder: `create` refuses, after reading the host and before `docker run`, a folder its computer's user (the spec's, or `docker.user`) cannot write and search, by the owner's, group's or others' bits as the kernel picks them. On a host that remaps user ids (`docker info` names `userns` or `rootless`: `host().remap`) the folder's owner is not the computer's user, so a bind is refused there in words before any `docker run`, and by `check` once the host is read; a computer with no mount is made as before. `check` refuses an Archil mount and a path `--mount` cannot hold (a comma, a double quote, a line break).
- `attach` and `list` read the mount back from `docker inspect` (`mountOf`): `{ kind: "bind", path }`, or `{ other: "<words>" }` for a read-only bind, a volume or two mounts at `/workspace`, which `attach` refuses. The drift check holds a computer to the bind it was asked for (that path, read-write, `rprivate`) and to no other mount.
- The conformance suite has a `mount` group, Full until the cutover decides: `mount.run-folder-bind` and `mount.run-folder-archil` ("mounts the run's folder": a file written outside is read at `/workspace`, one written inside is read outside, and a program run with `cwd: "/workspace"` sees it; the mount reads back as asked, with no token) and `mount.undeclared-kind` (each kind a provider does not declare is refused by `check` and `create` in words). A provider module exports `mountFor(kind)` to give each case a fresh run folder (`RunFolder`), and `runConformance` takes `mountFor`; `--provider docker` gives a bind of a new folder under the temp directory.
