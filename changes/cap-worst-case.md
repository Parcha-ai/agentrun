---
packages: @parcha/agentrun-serve, @parcha/agentrun-kernel, @parcha/agentrun-client, @parcha/agentrun
kind: breaking
---
A run's cap is never passed: every model request is held at its worst case, its whole input priced uncached (at the cache-write rate when that is dearer), so a cache miss can no longer take a run past its `max_cost_usd`. The `expected` cap mode, which priced the input from the previous request's cache and let a miss go over by a bound, is gone, and with it the `cap_mode` setting.
- Breaking, for API clients: remove `cap_mode` from what you send. A run start (`POST /agents/{agent_id}/runs`, `POST /runs`) that still sends it is refused `422` with `{"field": "cap_mode", "reason": "not_allowed"}`, and an agent definition (create or update) that still sends it is refused `422` with `definition.cap_mode` `not_allowed`. The generated clients and the CLI no longer have it (`--cap-mode` is gone). Every run now behaves as `strict` did. A stored agent revision or run launch that still holds a cap mode is read as if it had none. An inline agent's version (`POST /runs` with `external`) that first ran with a cap mode keeps it in its stored body, so running that version again with the field dropped is `409 external_body_conflict`: publish a new version and run that.
- Breaking: `cost.overshoot_bound_usd` and the budget pause's `overshoot_bound_usd` are gone from the run's view. The generated TypeScript and Python clients and the CLI (`--cap-mode`) lose them too.
- A request is not parked for want of room to answer: its output is clamped to what the cap has left after its input at the worst case, and it is refused only when that input plus the least answer (1,024 tokens) does not fit. The in-flight hold and the CLI harness's reserve for its answer are counted at the worst case too.
- A Codex or OpenCode request on an OpenAI model (gpt-4o and later, the o-series, gpt-oss) that its provider did not count (through a gateway, or when OpenAI's count failed) is held at a local count of its input in place of its bytes: o200k_base over the body as sent, plus a tenth, 16 tokens an item and 256 a request, with encrypted reasoning at its bytes and each image at its billed size, and never above its bytes. A capped run through a gateway that parked on its bytes (a $0.50 lead list asked for $0.52) now goes on. OpenAI's own count, where it comes, is still used. Any other model keeps its byte bound.
- New dependency of the kernel: `gpt-tokenizer` 4.1.2, MIT, pure JavaScript with no dependencies of its own; 9.3 MB packed and 28 MB unpacked, of which only o200k_base's ranks are loaded, on the first count.
- A run whose requests read the cache spends less than it is held at, so it pauses earlier than under `expected`: raise the cap by the cached share of its input if a run that used to finish now pauses.
- A capped run on a ChatGPT plan model (`chatgpt/…`) is admitted. Its model requests are billed to the plan: each is held at $0, its output is never limited on dollars, and it adds $0 to the cap's spend and to the wrap-up's reserve. A paid tool beside them still counts and stops the run at the cap. A model with no price that is no plan's model is still refused under a cap.
- On a ChatGPT plan, a 429 that says the plan's usage limit is reached (`usage_limit_exceeded` or `subscription_sharing_usage_limit_exceeded`) ends the run with "Your ChatGPT plan's limit is reached. Manage usage in your ChatGPT settings, then run it again.": no retry, no switch to a key, no raise-the-cap pause.
- Kernel: `CapModel.plan`, `PLAN_LIMIT_WORDS`, `PLAN_LIMIT_CODE`, `ProviderPolicy.finalError` and `ModelProxyOptions.onFinal` are new, and so are `ProviderPolicy.countInputLocally`, `responsesLocalInputTokens`, `localInputOf`, `o200kTokens`, `o200kModel` and `LOCAL_COUNT_MARGIN`.
- Kernel: `CapMode`, `RecentRequest`, `CapOptions.mode`, `Admission.boundUsd`, `RefusalFigures.boundUsd`, `DECISION_OUTPUT_TOKENS` and `ModelRequest.inputTokensCounted` are gone. A decision is held at its model's most completion tokens.
