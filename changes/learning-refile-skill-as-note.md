A standing rule for every reply or report that a run proposed as a skill is kept as a note: the grader judges it mis-kept (a skill loads only when a job calls for it, a note is served whole on every run) and re-files it, and the merge writes `<name>.md`, with the skill's description and body, in the skill's place, pending when risky. One that would be no note, or one past the run's 8 new notes (a re-filed note counts as one), is dropped, saying it belongs in a note. At the merge, any note the run keeps (a re-filed skill's too) whose name the agent's notes already hold, another run having merged one meanwhile say, no longer fails the whole learning run: the same text is no change; a note that supersedes the note of its own name replaces it; any other is left out alone, saying a note of that name was added since or was there already, and the rest of what the run learned merges. A learning run that stopped after its merge's commit and before recording it resumes merged, its notes learned, never dropped as already there. The grader's verdict gains the decision `note`, a skill's alone. Learning keeps one copy of each rule: a new note whose body is exactly an active note's (whitespace and case aside), under another name, is refused at the end-of-run checks (`duplicate`) and left out at the merge, and of two new notes with the same body only the first is kept; a near one stays the grader's to judge, and a note that supersedes the one it repeats still updates it. Upgrading: nothing to do.
