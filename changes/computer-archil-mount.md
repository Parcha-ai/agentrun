`DaytonaProvider`, `ModalProvider` and `E2BProvider` mount the run's folder from an Archil disk: each declares `mount: ["archil"]` (`MOUNT`). For a spec with `mount: { kind: "archil", disk, region, folder, token }`, `create` runs the shared Archil steps (preflight, the takeover of the run's lower epochs, mount or revoke with the token on the helper's stdin, serve) as root through the vendor's own exec, after the daemon is in place and before init starts, then reads the mount back from inside. The token reaches the helper's stdin alone: never an argument, a label, a tag, metadata, a read-back or an error.
- `MountReadBack`'s archil arm gains `exclusive` and `epoch` (the computer's `agentrun.epoch` label). `readBackOf(mount, epoch?)` keeps the epoch optional; an Archil mount with none reads back as `{ other }`, in words.
- `box/` ships the root helper `agentrun-archil` (mount, revoke, serve, checkin; root only, never through sudo) and the image recipe: archil 0.10.1 pinned by sha256, the tool user `agentrun-tool` 2510:2510, no sudo and no sudoers file, the image's user root. A mount gives the folder's top to the tool user right after it, whatever owner the disk's object API made it with. The image installs no firewall: init and every tool run in a network namespace of their own.
- computerd gains `sync-serve` (the helper's serve: a resident sync on /run/agentrun-archil/archil.sock, folder 0750 and socket 0660, root's and group 2510; one fixed request byte runs `archil sync`, coalesced, and answers its exit code; it holds no token and exits when the mount goes or its socket is removed) and the `mount.sync` call, which trusts only a root-owned 0750 folder of the tool user's group and a root-owned socket.
- An Archil spec takes network `"none"` and the run's `agentrun.run` and `agentrun.epoch` labels, its folder `agents/<agent>/runs/<run>/work` of that run. Its tools run as `agentrun-tool`, 2510:2510: Daytona and E2B take an Archil spec only from a provider made with `daemonUser: "2510:2510"`; Modal makes that an Archil spec's default user and refuses any other; E2B refuses a spec label named `agentrun.mount`.
- The vendor network stays on, for root to reach Archil: Daytona's network is open, Modal drops `blockNetwork`, and E2B keeps internet access on with public traffic off. The tools' network `"none"` is init's own.
- Daytona: each root step is a toolbox session command of its own, the token sent as its input with no echo; the label `agentrun.mount` records the mount's kind and source.
- Modal: the sandbox's command is always the entrypoint, which waits for a root-made gate (`/opt/agentrun/archil-mounted`) as well as the daemon, so no tool runs before the folder is mounted. The spec tag records the mount as it reads back, under the claim's epoch. `ModalTimeouts` and `E2BTimeouts` gain `mountMs`, the bound of each root step.
- E2B: each root step is a background root command with stdin (`sendStdin`, then `closeStdin`); the metadata `agentrun.mount` records the mount's kind and source.
- `connect()` on an Archil computer syncs the folder after every call that may change it, coalesced; a failed sync fails the call. `release` lets the folder go (a final sync, then checkin) while the computer runs, then deletes it, and succeeds once it is gone: a folder not let go cleanly loses nothing, so it is said through the provider's new `onNote` option, never as a failed release. `list()` reports the recorded mount under the epoch label; `attach` reads it back from inside and refuses drift.
- The conformance suite: `src/conformance/archil.ts` gives every remote provider's module one Archil run folder (`archilRunFolder`, `archilSettings`, `ARCHIL_ENV`), reached from outside through the disk's object API (the host's `disk` SDK, or one given). The Daytona, Modal and E2B modules export `mountFor("archil")`, reading `COMPUTER_ARCHIL_DISK`, `COMPUTER_ARCHIL_REGION`, `COMPUTER_ARCHIL_TOKEN`, `COMPUTER_ARCHIL_API_KEY` and `COMPUTER_ARCHIL_S3_URL`. New cases: mount.archil-durable, mount.archil-takeover, mount.archil-token and mount.archil-isolated-durable; a case may record what it saw without asserting it (`CaseResult.observed`), and the CLI puts what a provider says through `onNote` in the report's `providerNotes`. An Archil computer's `network()` reads `"none"` from the daemon, its own loopback alone, since its vendor network is open for root.
