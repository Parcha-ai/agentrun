An agent can start each run in a checkout of the pull request that started it, without ever holding a GitHub token. An agentic definition's new `checkout: pull_request` (a template's manifest sets it with `checkout: pull_request`) has the server fetch the pull request its GitHub event names before the first turn, into `repo/` of the run's folder, detached at the head, with its base and their merge base fetched beside it (refs `pr/head`, `pr/base`, `pr/merge-base`; read the change with `git diff pr/merge-base pr/head`). The fetch is one server command on the run's folder, so it works the same in Mode 1 and on Archil's exec in Mode 2. It uses an installation token of the server's GitHub App, narrowed to that repository and `contents: read`. The token never lands in the folder, the checkout's git config, the remote's URL, the agent's environment or the log. With no App, or one not installed there, the fetch is anonymous, which works for a public repository. The run's system prompt says what was checked out, or why nothing was, so the agent can read the change through the GitHub MCP instead. The checkout is removed when the run's claim ends. `checkout: none` clears it on an edit; an edit that leaves it out keeps it.
A GitHub event's payload tag now also carries the pull request's `base_sha`. The server's Docker image installs `ca-certificates`, so git on the server can reach GitHub over HTTPS.
