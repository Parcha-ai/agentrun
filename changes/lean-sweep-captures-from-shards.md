The `lean` job takes about 2 minutes, down from about 16. It no longer runs the DSL, pi and example test suites a second time to collect the workflows for the validator sweep: on Node 22.23.2 the `core` and `examples-<n>` test shards record them while their tests run and keep them as an artifact, and `lean` waits for the test shards, reads their captures (`node spec/lean/sweep/collect.mjs --captures <dir>`), builds only the DSL and runs the proofs, the conformance cases and the sweep. That saves about 13 runner-minutes on every pull request, merge-queue and `main` run. The capture hook now runs in the test's own thread, which keeps the capturing shards at their usual speed (the off-thread hook made a DSL test file about a third slower), and each capture is written to a temporary file and renamed into place, so two test files recording the same workflow at once no longer leave a torn file that failed the sweep. The risks: `lean` now reports after the slowest test shard instead of on its own, and it fails when a capturing shard failed or its captures are missing, since the corpus would be incomplete. `lean` is not a required check, and `verify` does not need it.
