The computer package ships a documents image, for an agent that writes decks, documents and sheets in a box with no network: the folder `packages/computer/documents`, the default image's base and programs (its Debian packages from snapshot.debian.org at one instant) plus python-pptx, python-docx and openpyxl for `python3`, pinned by version and sha256 with everything they need, and pptxgenjs, docx and exceljs for `node`, at exact versions with their dependencies as the registry stood at that same instant, linked as `/node_modules` so a script in any folder loads them. Build it and name its tag in `AGENTRUN_DOCKER_IMAGE`; the serve README's "The box's image" has the commands. On Daytona, `box/build-daytona.py --documents` builds the box image with the same layer on top as its own snapshot, `agentrun-documents-<hash>`, for `AGENTRUN_DAYTONA_SNAPSHOT`. The box image's recipe, its hash and its `agentrun-box-<hash>` snapshot are unchanged. Neither is published.
A sandbox's `computer.needs` may now name a library as well as a program: a Python package by its pip name, which the box's `python3` has installed, or a Node package a script of its `node` requires, such as `["python-pptx", "pptxgenjs"]`. The claim's one check finds each as a program on the PATH, else as such a library; a box that lacks one ends the run `failed` before any model request, and where everything it lacks is the documents image's, the words name that image's build (Docker) or its snapshot (Daytona). A server before this release reads such a name as a program, and fails those runs in words.
