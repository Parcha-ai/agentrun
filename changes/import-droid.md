`@parcha/agentrun-import` reads Factory's Droid CLI, a new source (`droid`): each session's `~/.factory/sessions/<cwd slug>/<id>.jsonl` (some in `sessions/` itself), under `$FACTORY_HOME_OVERRIDE` instead of the home where the environment names it. `normalizeUsage("droid", …)` reads Droid's `tokenUsage`: `inputTokens` already leaves the cache out, and `thinkingTokens`, part of `outputTokens`, is kept as `reasoning`.
- Droid writes no request's tokens to disk. A session's tokens are the running total in the `<id>.settings.json` beside its transcript (`tokenUsage`, its own calls alone), put on its last request, the others 0 and marked `folded` (a new optional field on an assistant turn: its usage is counted in a later request of the session). serve reads a folded request's zeros as known, not unmetered, so the run's catalog estimate prices the request that carries the total. A session with no settings file, or no `tokenUsage` in it, is unmetered. Droid writes no dollar cost, so `cost` is that total at the catalog's list price for the model the settings name (else the last request's), `null` with no model or one the catalog does not list (a BYOK `custom:` model).
- Each assistant message is one request; each record counts once by its `id`, so a fork's copies of its source's records count in the source alone. A `Reader` may name `lineage(file)` (the session a file holds and its `parent`); `inOrder` reads each fork after the sessions it was forked from, so a source resumed after its fork keeps its records. A fork that made no request of its own, its total all zeros, adds no request. A Worker, whose `session_start` names its `callingSessionId`, counts under that session, with no turns of the person's. A turn whose provider refused or never answered (`agent_turn_outcome` `model_*`) is one more request, failed, its error the reason with turns and `"API error"` without.
- `agentrun-serve import` imports Droid sessions as runs (`--from droid`, `imported_from.source` `"droid"` in the API and its clients), the harness pi's. `droidSessionId` is the one rule for a session's id, the reader's and serve's.
