kind: breaking

An agent's learning (its corrections, learned workflows, promotions, grades and audits) is now kept as versioned rows in the server's store, SQLite or Postgres, in place of a git folder on the agent's disk and settings keys. Runners must be upgraded with the server: a server upgrade adds the tables (Postgres migration 0032, which raises the runner floor to 32, and SQLite schema version 17), and a runner of an earlier release is refused at its open (on Postgres, `RunnerBelowFloor`, naming the version it must know), since it would still keep learning in the folder and settings keys. Each agent starts again from nothing learned. Learning kept before the upgrade (a learning folder on disk or on an Archil disk, and the old settings keys) is not migrated, nothing reads it, and nothing removes it at the upgrade, but `DELETE /runs/{id}` still scrubs that run from it as before: its corrections line and learned workflows come off the local folder's current files in a host commit (its merges stay in the folder's git history until the agent's purge), its diff files go, the agent's learning folder goes from an Archil disk the run's launch named, and its grade and its promotion copies come off the old `learning.grades` and `learning.promotions` keys. An agent's purge removes the folder and those two keys whole, as before. Nothing else of it is removed, and `learning` stays a reserved folder name in an agent's home. Version ids (`main`, `commit`, a run's `learning.seed`) are now opaque save ids, still 40 hex characters. A run's purge deletes its learning rows in the same transaction (its notes, workflow versions, grades, and the promotions and audits of what it alone wrote), so nothing of it is refused or served later. The purge is itself a save, so a change computed before it is computed again, and a run that read the agent's learning before another run's purge has its learned files dropped (reason `purged_since_seed`, new in the closed list of a run's learning reasons); an owner's correction alone still lands. The purge also blanks what other promotion records and SDK runs' inboxes copied from the run (an inbox names every run that wrote a file of a workflow it delivered, its `README.md` as well as its `workflow.json`). A revision whose promotions the purge deletes keeps its K in the agent's reset ledger while another run is still billed against it, so the runs that carry its spend keep the same `share_usd`, `learning_usd` and `all_in_usd`; the entry goes with the purge of the last such run. Its learning diff goes too, and like every route of a purged run, `GET /runs/{id}/learning/diff` answers `410 purged`. The agent cost read drops its `degraded` field, and learning no longer runs git or a learning script except for that scrub. An API-only server (`AGENTRUN_API_ONLY=1`) now serves `GET /agents/{id}/learning/audits` with its token too, beside the loop, promotions and cost reads, so a backend's Learning tab can read an agent's audit ledger.
