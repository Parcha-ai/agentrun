kind: breaking

An agent's learning (its corrections, learned workflows, promotions, grades and audits) is now kept as versioned rows in the server's store, SQLite or Postgres, in place of a git folder on the agent's disk and settings keys. Runners must be upgraded with the server: a server upgrade adds the tables (Postgres migration 0030, which raises the runner floor to 30, and SQLite schema version 16), and a runner of an earlier release is refused at its open (on Postgres, `RunnerBelowFloor`, naming the version it must know), since it would still keep learning in the folder and settings keys. Each agent starts again from nothing learned. Learning kept before the upgrade (a learning folder on disk or on an Archil disk, and the old settings keys) is left where it is, neither migrated nor cleaned up, and `learning` stays a reserved folder name in an agent's home. Version ids (`main`, `commit`, a run's `learning.seed`) are now opaque save ids, still 40 hex characters. A run's purge deletes its learning rows in the same transaction (its notes, workflow versions, grades, and the promotions and audits of what it alone wrote), so nothing of it is refused or served later. The purge is itself a save, so a change computed before it is computed again, and a run that read the agent's learning before another run's purge has its learning dropped (reason `purged_since_seed`, new in the closed list of a run's learning reasons). Its learning diff goes too, and like every route of a purged run, `GET /runs/{id}/learning/diff` answers `410 purged`. The agent cost read drops its `degraded` field, and learning no longer runs git or a learning script. An API-only server (`AGENTRUN_API_ONLY=1`) now serves `GET /agents/{id}/learning/audits` with its token too, beside the loop, promotions and cost reads, so a backend's Learning tab can read an agent's audit ledger.
