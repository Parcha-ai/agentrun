An agent's learning (its corrections, learned workflows, promotions, grades and audits) is now kept as versioned rows in the server's store, SQLite or Postgres, in place of a git folder on the agent's disk and settings keys. A server upgrade adds the tables (Postgres migration 0027, additive); what an agent learned before the upgrade is not carried over, so each agent starts again from nothing learned, and a learning folder left on an Archil disk is no longer read or removed. Version ids (`main`, `commit`, a run's `learning.seed`) are now opaque save ids, still 40 hex characters. A run's purge deletes its learning rows in the same transaction (its notes, workflow versions, grades, and the promotions and audits of what it alone wrote), so nothing of it is refused or served later, and `GET /runs/{id}/learning/diff` answers 404 for it. The agent cost read drops its `degraded` field, and learning no longer runs git or a learning script.
