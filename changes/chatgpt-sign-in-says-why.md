A ChatGPT sign-in that ends without signing in now says why. OpenAI's tab says "Authentication successful" before the server exchanges the code, and a failure after that point (OpenAI refusing the code, an answer the server can't read, no route to OpenAI, a save that fails) used to leave the plan reading not signed in with nothing said anywhere. `GET /settings/chatgpt` now carries `problem`, the reason in words, until the next start, sign-in or sign-out. A plan OpenAI gives no use of says "This ChatGPT plan can't be used here", a workspace whose admin turned off open-source apps names the setting (External access → OSS → Use ChatGPT plan), and any other refusal names OpenAI's code and says a Free plan can't be used. Settings → API Keys shows it under Continue with ChatGPT, and the server logs `event=chatgpt chatgpt=sign_in_failed reason=…` (OpenAI's status and error code, never a token or a code). `agentrun` started from a terminal says that line on stderr each time, where before it showed none of the sign-in's lines. A pasted address that fails the same way is refused with the same words.
