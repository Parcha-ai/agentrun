A ChatGPT sign-in that ends without signing in now says why. OpenAI's tab says "Authentication successful" before the server exchanges the code, and a failure after that point (OpenAI refusing the code, an answer the server can't read, no route to OpenAI, a save that fails) used to leave the plan reading not signed in with nothing said anywhere. `GET /settings/chatgpt` now carries `problem`, the reason in words, until the next start, sign-in or sign-out. A plan OpenAI gives no use of says "This ChatGPT plan can't be used here", a workspace whose admin turned off open-source apps names the setting (External access → OSS → Use ChatGPT plan), any other refusal says a Free plan may be the reason, and a sign-in that waits out its 10 minutes says it timed out. The words are fixed: OpenAI's code goes to the log alone. Settings → API Keys shows it, under who is signed in too, and the server logs `event=chatgpt chatgpt=sign_in_failed reason=…` (OpenAI's status and error code, or `timed_out`; never a token or a code). `agentrun` started from a terminal says that line on stderr each time, where before it showed none of the sign-in's lines, and says `changed_failed` too: a sign-in saved whose change the server failed to take, which it now takes again at its next read of the sign-in instead of after a restart. A pasted address that fails the same way is refused with the same words.
