`GET /v2/runs/{run_id}/usage` (`runusage/5`) now says which charges were the infrastructure's own redo. A turn is worked again when the claim working it is cut: its runner drained for a deploy (SIGTERM), its runner died, it lost its lease, or the turn was tried again. Each line, browser session and computer interval carries `attempt` (1 for a turn's first, 2 for its first redo, and so on) and `billable`, which is false for an attempt that was cut and done again. A turn's charges are split into one line per attempt. The run also reports `infra_usd`, the sum of the lines that are not billable: 0 for a run nothing cut. This is data only: `total` and `cost.usd` still hold every line, and nothing is charged differently. A run from before this read keeps `attempt: null` and `billable: true` on every line.

Each claim writes its turn and attempt in its own transaction to the store's new `run_attempts` table. Postgres gets it from migration `0024_run_attempts.sql`, which is additive (a runner of the earlier version never reads it). A SQLite store gets it at the server's open, and a runner waits for that server. Each row holds `cause`, why the attempt before it was cut: `drain`, `crash`, `lease_lapse` or `retry`. A runner's release writes the cut attempt's own word for `drain` and `retry`. A runner that loses its lease writes `lease_lapse` while it can still reach the store. A lapse with no word reads as `crash`. A claim's `turn` and `attempt` are on `Claim`.

Each model request a claim sends to the server's model gateway carries the run, turn and attempt as LiteLLM's spend-logs metadata, in the header `x-litellm-spend-logs-metadata` (`{"agentrun_run_id":…,"agentrun_turn":…,"agentrun_attempt":…}`). That lets a gateway's spend logs be matched to the run's lines call by call. "The server's model gateway" means `AGENT_MODEL_BASE_URL`, or `ANTHROPIC_BASE_URL` on its origin. The header is sent on pi's routes and Claude Code's, never to a vendor's own endpoint. Codex's adapter takes no extra headers, so its requests carry none yet.
