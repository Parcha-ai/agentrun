The console's trigger forms (a schedule, a webhook, a GitHub trigger, an app trigger, a feed trigger and an email trigger) now take the picked agent's typed input as the run bar does. An agent whose input_schema has fields shows them under the message and sends them in `target.input` beside `content`, and the server's refusal of one of them is said at that field. An agent whose schema the fields can't show takes its whole input as JSON. Editing a schedule keeps its typed input and anything else in it the form doesn't show, saves a field left alone exactly as stored (a list item's spaces, a blank item or an empty value included), and a schedule whose input has no message can be edited again. On a webhook, GitHub, app, feed or email trigger, a message left blank beside typed fields is sent as `""`, so each run still gets its event; a whole JSON input goes exactly as written, and the form says the event comes in its `content`. A trigger's page lists its typed input beside the message. In every trigger form's Agent picker, agents that share a name each show their id beside it.
