A new computer provider, `freestyle`: a Linux sandbox on a Freestyle VM, over Freestyle's REST API with no SDK. It takes `FREESTYLE_API_KEY`, the name Freestyle's own SDK and CLI read, and loads from `@parcha/agentrun-computer/freestyle` or `providerFor("freestyle", { apiKey })`. Its machines dial the server, as Render's do: Freestyle's exec answers once the command ends, and its SSH gateway publishes no host key to pin, so create waits for the VM to run and starts `agentrun-dial` in one exec as root, with the boot env as that command's env, never written in the VM. A computer starts from the box image's snapshot in the key's account, slug `agentrun-box-<recipe hash>`, or from another snapshot by id or slug. `prepareImage()` finds the box snapshot, or builds it once: it boots `freestyle/ubuntu`, runs `install.sh` detached, polls its exit file, snapshots the VM, and deletes the build VM. Freestyle's base snapshots are refused. Once create's POST has made a VM, a later failure deletes it, and that error is never a refusal. Labels are packed into the VM's metadata, `ttlSeconds` is set to the backstop, and the janitor ends a computer at its deadline. Serve offers it as a box once `AGENTRUN_BOXES` lists `freestyle`, the key is set and the server has a public address, and the launcher holds `FREESTYLE_API_KEY` with the other secrets. No live run has been made yet: exec's env reaching its command as root, a detached process outliving the call, a taken slug's 409, a deleted VM's 404, the metadata filter, amd64 and root's network namespace, and the public-egress rule's name lookups are unverified until then. `install.sh` doesn't build on Ubuntu 24.04 yet: its `desktop` step stops on `firefox-esr`, which Ubuntu doesn't package.
