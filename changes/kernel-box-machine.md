A harness's own tools run only in the host's box. `openLocalMachine` takes the host's box (`MachineBox`: a `Box`, where its record goes, what it binds read-only, the model's socket and port) or `unsandboxed`, the operator's word that there is none, and every child then starts in a box, one at a time, through the session's box slot. The machine reports what it was given as `isolation`.
- `@parcha/agentrun-kernel/host` adds the box seam (`Box`, `BoxSpec`, `BoxRecord`, `BoxRecorder`, `BoxedChild`, `Reaped`, `Isolation`, `BoxError` and its codes) and `boxSlot`. A box's record is written before its spawn; a second start while the last box is live or not counted empty is refused (`box_busy`); a box is reaped as its child exits, and `close()` fails if a reap found a process left (`box_not_empty`). The session's last box (`previous`) is reaped before anything starts.
- Both adapters take `box`. With the CLI's own tools on and no box, or a box the host found unavailable, the turn fails with an `Unavailable` (`box_unavailable`) that names why. Neither adapter probes bubblewrap any more, and neither falls back on its own: in a box, Claude Code's and Codex's own sandboxes are off, the box being the boundary.
- Breaking: the Claude adapter's and harness's `unsandboxedCommands` option is gone; `box: "unsandboxed"` says the same, from the host. Codex's `sandboxMode` other than `danger-full-access` is refused in a box (`box_nested`), and its `codex.sandbox` verdict is no longer written or read.
