A harness's own tools run only in the host's box. `openLocalMachine` takes the host's box (`MachineBox`: a `Box`, where its record goes, what it binds read-only, the model's socket and port) or `unsandboxed`, the operator's word that there is none, and every child then starts in a box, one at a time, through the session's box slot. The machine reports what it was given as `isolation`.
- `@parcha/agentrun-kernel/host` adds the box seam (`Box`, `BoxSpec`, `BoxRecord`, `BoxRecorder`, `BoxedChild`, `Reaped`, `Isolation`, `BoxError` and its codes) and `boxSlot`. A box's record is written before its spawn; a second start while the last box is live or not counted empty is refused (`box_busy`); a box is reaped as its child exits, and `close()` fails if a reap found a process left (`box_not_empty`), including the reap of a box that failed to start after it was recorded (`BoxSlot.settled`). The session's last box (`previous`) is reaped before anything starts. `watchClose` keeps a machine's failed close for a harness that closes its machine without reading the verdict: the Claude Agent and Codex adapters run each drive through it, so a turn whose box a reap found a process left in ends failed with `box_not_empty`, never clean.
- Both adapters take `box`. With the CLI's own tools on and no box, or a box the host found unavailable, the turn fails with an `Unavailable` (`box_unavailable`) that names why. Neither adapter probes bubblewrap any more, and neither falls back on its own: in a box, the Claude Agent CLI's and Codex's own sandboxes are off, the box being the boundary.
- Breaking, and how to migrate:
  - `unsandboxedCommands` is gone from the Claude adapter and harness. A host that set `unsandboxedCommands: true` passes `box: "unsandboxed"` instead: the same meaning, now said by the host, and logged.
  - A host that turns a harness's own tools on gives the adapter a box (`box: MachineBox`) or `box: "unsandboxed"`. Without either, those sessions fail with `box_unavailable` where they used to run on whatever the machine had.
  - A Codex host running in a box leaves `sandboxMode` unset (or `danger-full-access`): `workspace-write` and `read-only` are refused there (`box_nested`). Codex no longer writes or reads its `codex.sandbox` verdict.
