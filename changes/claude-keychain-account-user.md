kind: breaking

On macOS, signing Claude Code in from the console now saves the login's Keychain item under the Mac user the server runs as, so `claude auth status` in that person's terminal reads it signed in, as AgentRun's badge does. Before, the claude CLI that AgentRun starts for the sign-in, the status check and a run got no `USER`. The CLI names the Keychain item's account by `USER`, and without it the account was `unknown`. The badge, asked the same way, read signed in, while the person's own `claude`, which has `USER`, looked under their name and read signed out. Those three now carry `USER` and `LOGNAME` set to the user the server runs as, as the system names it (`os.userInfo()`), even when the server itself was started without `USER`, as a service launchd starts may be, or with another user's.

Who breaks: anyone who signed Claude in from the console on macOS before this release. That login reads signed out once the server is updated, since its item is under `unknown`. What to do: sign in again under Settings → Model keys. The old item stays in the Keychain under the account `unknown` and still holds a valid login, which nothing reads any more. Delete it in Terminal with `security delete-generic-password -a unknown -s "Claude Code-credentials-<hash>"`, where `<hash>` is the first 8 hex characters of the SHA-256 of the login folder's path: for AgentRun's own folder, `D="<data>/claude-login"` (`<data>` is the server's `--data`, `~/.local/share/agentrun/agents` by default), then `security delete-generic-password -a unknown -s "Claude Code-credentials-$(printf %s "$D" | shasum -a 256 | cut -c1-8)"`. Keychain Access can delete it too.
