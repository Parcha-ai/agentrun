Mention the bot in Slack to start a run, and reply in the thread to steer it. `PUT /v2/settings/slack` sets the server's Slack app (`{signing_secret, bot_token, app_id?, post_answer?}`, the bot token checked with Slack's `auth.test`, both kept sealed under the seal key and never shown again), and `POST /v2/hooks/slack` is its Event Subscriptions Request URL, with no token: each request is checked by Slack's v0 signature on its raw body, and `url_verification` is answered only after that. A trigger with `source: {kind: "slack", channels}` starts one capped run for each thread in which the app is mentioned in a channel it lists; every later message in the thread is a message to that run, and answers the run's question when it asks one. A channel is one trigger's (`409 channel_taken`). Slack's retries, and the same message told as both `app_mention` and `message`, are one firing, keyed by the message itself. A bot's message, a person of another workspace, an edit and a direct message are ignored, and so is another app's event when the app's id is set. A trigger keeps a thread for 30 days after its last message, and its 1,000 latest; a bot token Slack refuses turns posting off until the app is set again. The message reaches the run marked untrusted. One line is posted in the thread when the run needs its person and when it ends, saying how to go on (a question by a reply in the thread, a tool call waiting on approval in the console), with a link to the run when the server has a public address, and the final answer too with `post_answer: true`, escaped so it mentions no one; posts wait in an outbox and are tried again on the webhook's schedule.
