`GET /v2/capabilities` lists the switches only the operator sets at the server's start, under `switches`: `AGENTRUN_MCP_ALLOW_LOOPBACK`, `AGENTRUN_WEBHOOK_PRIVATE_TARGETS`, `AGENTRUN_BOX_ALLOW` and `AGENTRUN_BOX_CPUS`, `_MEMORY` and `_PIDS`, each with `on`, the `value` the server read (never a secret) and what it `allows`. A refusal one of them causes now names the variable, the value that allows it and the restart it takes, with the same error code as before: a webhook URL on a private network or this machine (`PUT /v2/settings/webhook`, 422 `input_invalid`) says `...which this server does not send to; restart the server with AGENTRUN_WEBHOOK_PRIVATE_TARGETS=1 to allow it, only on a machine you alone use`, and so does a try's log entry; an MCP server on loopback says `restart the server with AGENTRUN_MCP_ALLOW_LOOPBACK=1 to allow it, only on a machine you alone use.` in place of `set ... when starting the server, ...`; a computer that needs a network under `AGENTRUN_BOX_ALLOW=none` says `restart the server with AGENTRUN_BOX_ALLOW set to a host list`. A client that matched the old words should match the error code, which is unchanged. The switches stay environment-only: no route or console page sets them. The README has a table of them ([start-time switches](README.md#start-time-switches)).
