The server's redactor finds secret shapes and held values with one matcher (`redact/match.ts`) whose work grows with a text's length alone: each shape is read from its prefix forward, and no run is read again at each place in it. What it cuts is what it cut before, with these widenings:
- A text that holds a held value only part of which a cut covers is now withheld whole. A credential parameter's value cut in place, with the rest of the same held value past a line break (`?token=<first half>` then `<second half>` on the next line), used to show the second half; the check for a held value now reads the text as it came, not the text after its cut. The same holds where an answer or a call's result is read in pieces and the split falls at a piece's edge: the whole answer or result is withheld. A held value's find is checked against the cuts each piece already made, so a value split inside one piece still blanks only that piece.
- An answer or a call's result read in pieces is checked once more as it is about to be shown, and withheld whole if that text holds a held value, however its pieces were put together (each cut, or an unread run shown as `[redacted]`, between them).
- A JWT is found from the first `eyJ` of its run of a part's characters at every site that looks for one, so a token glued to a word (`id_eyJ...`, `x9eyJ...`) is found too. The credential gate of the console's build (the console the server serves) can now fail a build whose bundle holds such a glued token, where it passed before. The computer's phone words cut it too.
