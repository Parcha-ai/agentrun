A `tar.pull` on a Daytona computer over `connect: "exec"` now comes through its toolbox's `GET files/download`, not the stdio bridge, which on Daytona is a session command's log read at about 0.3 MB/s. A synced folder reads each new directory (a `git clone`'s `.git`, an `npm install`'s `node_modules`) and each changed file past one chunk (512 KiB) with a `tar.pull`, so the call that makes them in `/workspace` no longer waits on the bridge for their bytes. The daemon still begins the pull, so a path its user can't read is refused as before. The tar is then made as the daemon's user (`setpriv --reuid --regid --clear-groups`, with `find` and GNU `tar` from the image) in `/run/agentrun-read`, a directory only root can enter, named and filtered as the daemon names its entries (relative to the directory, a hard link as a file of its own, sockets, devices and pipes left out). It is downloaded whole, then removed, and the daemon's pull is ended. A tar is at most 256 MiB (its file-size limit) and one connection makes one at a time. If a step fails (a directory the user can't read, a file changed while it was read, `find` or `tar` missing, the bound), the daemon's pull is read from its first byte, as before.
