`agentrun-serve` learns. An agentic revision may list `learn` in `tools`, which gives its runs `@parcha/pi-agent-learn`'s `learn` tool, guarded at each call with the host's secrets and the run's input. `POST /v2/agents/{id}/learn` with `{"run_id": ...}` takes a completed run of such a revision, guards what it noted again, and commits the agent's next revision, current: the current definition and skills plus one skill per lesson at `learned-<12 hex>/SKILL.md`, with the note `learned from run <run_id>`. It answers `201 {revision, note, learned}`. `"dry_run": true` runs every check and the guard, commits nothing, and answers `200 {learned: [{path, text}], base}`; a Learn that passes that `base` commits exactly what the preview showed, or is `412 precondition_failed` once the agent's current revision has moved; a run that is another agent's, of a revision without `learn`, not final, not completed, or that learned nothing is `409 not_learnable`, and a lesson the guard refuses is `422 input_invalid` naming the rule, never the value. Capabilities list `learn` among the tools and say `features.learn: true`. AgentRun Server's page puts it on a completed run of such a revision in two steps: "Learn from this run" previews each lesson whole, as text, and "Commit as a new revision" commits exactly that preview, or asks for a new one after a 412.
