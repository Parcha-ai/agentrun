A capped run no longer prices a request as if nothing were cached after an approval, a deny, a raise or a smaller request of its own, and a Codex or Claude Code run no longer has a tool call refused with "Budget nearly spent" while the request that asked for it is still streaming and the cap has room for both.
- The recent requests: the cap keeps the session's answered requests of the last 4 minutes and prices each request from the one on its model with the biggest body no bigger than its own. A smaller request between two of the conversation's own (Codex sends one while a tool runs; a summary, a child's) no longer resets the history, so the conversation's next request stays warm. Before, a $0.50 Codex run's next request after one was priced all fresh, held all that was left, and was told "About $0.43 left of this run's budget: finish now" on a $0.08 job.
- Resume: the recent requests are kept with the run, so the first request after a new claim is priced from them, warm when they ended under 4 minutes ago and uncached after that, the same rule as inside one claim, on every harness. Before, a $0.15 Codex run paused after a deny with "needs at least $0.22": its next request was priced all fresh.
- In flight: a CLI harness's request is now sent with the most output whose worst case still leaves the run's wrap-up reserve (one typical step and one least answer) free, so a call it makes mid-response finds room. A $0.50 Codex request that held $0.36 and a $0.12 bound at its whole 32,000-token ask is now sent with fewer tokens, and its call passes. When the request's least and the reserve do not both fit, it is admitted as before, with the most what is left buys, and a call it makes is refused for the reserve as before. pi starts a tool only once its response is complete, so its requests are sized as before.
- The cap's guarantees are unchanged: no request is held past what is left, a warm price that guesses wrong costs at most the request's bound beyond its hold (as any cache miss under `expected`), every hold settles to what the request cost, and turns sum to the run's cost.
- Kernel cap (private, not in the package's index): `ModelCapRequest.previous` is `recent` (a list of `RecentRequest`, was `Previous`), `previousOf` on `beforeRequestOf` and `runCap` is `recentOf`, and `previousAfter` is `recentAfter`, with `warmFrom` picking the request a price reads. `JudgeState.keepUsd`, and `keepBackUsd` on `beforeRequestOf` and `runCap`, tell the rule what the host keeps back beside a request.
