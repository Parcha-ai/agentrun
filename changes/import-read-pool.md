`parseHome` reads a home's files on a pool of worker threads, `threads` of them (default: the cores the process may run on, at most 8; `threads: 1` reads every file in order on the calling thread, as before). Each read is taken in the import's order and kept only when none of the records it added, or asked for and did not hold, is one an earlier file holds; any other file is read again in order, so the totals are the same whatever the thread count. `readAhead` caps the bytes of finished reads waiting to be taken (default 1 GiB, or a sixteenth of the machine's memory when less), plus at most one read in flight per thread; it does not cap the process's memory; files of 64 MiB and over go first. Options out of range (`threads: 2.5`, `workerOldMb: 0`) are refused with a RangeError. The `agentrun-import` CLI takes `--threads` and `--read-ahead`. Each worker's old generation is capped at `workerOldMb` (64): a line over an eighth of it, or a file that runs a worker out of memory, is read on the calling thread, and past two losses a thread the pool stops. On a 73.7 GB home at 8 threads the import took 90.9 s (median of 5, spread 29.2 s) at a peak of 1.83 GiB: 4.85x this tree's one thread (`threads: 1`, 441.1 s, x1, the same run) and 4.0x the previous release's one thread (365.1 s, x1, a separate run on a quieter box); with 256 MiB of read-ahead, 136.5 s (x1). Measured beside other work (load 17 to 45), on the pool before the review's fixes; at the shipped code a paired run (x3) found no slowdown (median paired delta -0.5%), and paired one-thread runs against the previous release did not settle a difference at that load (load 30 to 95; the head slower in 4 and 3 of 5 pairs, median paired deltas +11.4% and +11.8%). A call with a `state`, or with readers of its own, reads on the calling thread as before. Without a `requests` hook, each request is priced as its file is read and kept as its cost alone (8 bytes, not its model, tokens and time); with the hook, every request is kept to the totals as before.
