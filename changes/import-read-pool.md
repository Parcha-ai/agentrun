`parseHome` reads a home's files on a pool of worker threads, `threads` of them (default: the cores the process may run on, at most 8; `threads: 1` reads every file in order on the calling thread, as before). Each read is taken in the import's order and kept only when none of the records it added, or asked for and did not hold, is one an earlier file holds; any other file is read again in order, so the totals are the same whatever the thread count. Finished reads waiting to be taken hold at most `readAhead` bytes (1 GiB); files of 64 MiB and over go first. Each worker's old generation is capped at `workerOldMb` (64): a line over an eighth of it, or a file that runs a worker out of memory, is read on the calling thread, and past two losses a thread the pool stops. On a 73.7 GB home at 8 threads the import took 90.9 s (median of 5, spread 29.2 s), against 441.1 s on one thread (`threads: 1`) and 136.5 s with 256 MiB of read-ahead, on the same tree, at a peak of 1.83 GiB; measured beside other work (load 17 to 45). A call with a `state`, or with readers of its own, reads on the calling thread as before. Without a `requests` hook, each request is priced as its file is read and kept as its cost alone (8 bytes, not its model, tokens and time); with the hook, every request is kept to the totals as before.
