Daytona computers run on the shared machine-host adapter: a Daytona computer is named from its create's request id, its daemon starts detached, create probes its network none from inside and waits for the listing, and release waits for gone through the adapter. Breaking: a Daytona computer's network can no longer be changed after create (`network(ref, policy)` refuses any change with `refused`, where it narrowed one to none before and answered `invalid` for open or an allowlist); `DaytonaProvider.listLabelled` and `probe`, `daytonaCommands`, `DaytonaCreateOptions`, the `startMs`, `deleteMs`, `stopMs` and `listedStableMs` timeouts, `dist/conformance/daytona-sweep.js` and the `daytona:sweep` script are gone (sweep a live run with `dist/conformance/sweep.js --provider daytona`, whose output names `gone` where Daytona's said `notFound`); attach no longer reports `cpus` and `memoryMb`. Create closes Daytona's D-Bus session bus (`/tmp/dbus-*`) to the computer's user before init starts, through the new optional host fact `vendorSockets`. A write to a Daytona computer's daemon that Daytona answers with its own 500 is sent again (up to three tries); one that may have been read is not.
