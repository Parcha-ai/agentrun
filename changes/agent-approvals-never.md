An agent can run unattended. Its definition takes `approvals`: `ask`, the default, is the tool gate as its settings say; `never` allows each tool that would ask instead, decided by the gate at each call, so a tool granted later and an MCP tool (`mcp:<server>/<tool>`, which asks by default) are covered on every harness. It never lifts a deny, whether set on the server or in the agent's own `tool_settings`, nor anything else the gate refuses before it decides between running and asking. A workflow's call node on a tool set to ask runs under `never`. The agent read serves `approvals`, its tools say an allow came from `unattended` (`permission_from`), and the run read serves the run's own `approvals`, as it started. A template's manifest takes `approvals`, and an apply's `overrides.approvals` sets it. A value other than `ask` or `never` is a `422` naming `definition.approvals`. Upgrading: nothing to do; an agent that names none asks, as before.
