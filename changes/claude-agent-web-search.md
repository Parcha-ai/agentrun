`claudeAgentAdapter({ webSearch: true })` turns on Claude's own WebSearch, and nothing else of the CLI's: the model may call it, the PreToolUse hook lets it through with its intent recorded before it runs (safe to repeat after a crash), and the system prompt's note names it. The CLI runs each search as a request of its own through the session's model proxy, which then admits Anthropic's web search server tool exactly as the pinned CLI sends it (`web_search_20250305`, at most 8 searches, the domains the model named); every other hosted tool, a later web search version, and every server tool's block stay refused. Each search the provider reports (`usage.server_tool_use.web_search_requests`, read from a stream's last `message_delta` or a whole body) is booked at $10 per 1,000 searches (`CLAUDE_WEB_SEARCH_USD`) on top of the host's `price`, into the session's cost and so its spend cap. A request with the web search tool reports no input bound (`inputTokensMax` undefined): the provider bills the pages it reads as input. In `@parcha/agentrun-adapters`, `ProviderPolicy.serverInputOverhead` may now return `undefined`, a policy's word that a body has no input bound: the model proxy leaves `inputTokensMax` undefined (never 0) and, unlike a throw or a non-count, reports no failure. WebFetch stays off. Default off: a session without the option runs as before.
