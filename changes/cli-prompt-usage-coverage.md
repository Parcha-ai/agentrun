Capture reported token usage for new Codex and Claude Code CLI learning prompts, deduplicating native response records within each prompt. The dashboard's unified `analytics.usage` includes retained source observations and recorded runs, using verified session identity to group potentially overlapping usage. When exact overlap is unavailable, the total keeps the larger coherent source or recorded view as a lower bound, with incomplete coverage explicit. A stale or zero source report cannot erase a larger completed prompt total; distinct immutable CLI turns can sum, while upload dates alone do not prove separate native execution. Range and session filters apply to the combined total; unavailable cache breakdowns, partial boundary days, missing reports and the 90-day source retention limit stay explicit. Unbound observation identities cannot be matched to separately recorded runs. Missing, ambiguous or incomplete prompt usage remains unknown; existing run completions are not rewritten. An enabled CLI learning profile with no recorded prompts explains that its next source prompt starts capture and that earlier conversations are not imported automatically.

The dashboard and Agents page share one connected-agent inventory. Source sessions and AgentRun agents appear together, including profiles awaiting their first captured prompt, and the separate observed-session sections are removed. Selecting a source session filters its reported usage without treating the session as a completed run or requesting a server-agent run endpoint.

Ordinary analytics reads project the saved accounting and identity fields instead of transferring full CLI policies and SDK replay records. Historical identity still selects the right source usage across date ranges. PostgreSQL records containing unsupported Unicode escapes retain the earlier JavaScript parsing path for that record, preserving their counters and exact native identity.
