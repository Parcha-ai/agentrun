An agent can carry a default spend cap. A definition's `max_cost_usd` (agentic only) above 0 sets the agent's default, kept with its revision, as `maxCostUsd` on the agent store's agentic body, and read back in `GET /v2/agents/{agent_id}`; a run started with no `max_cost_usd` of its own takes its revision's default, and a run's own cap wins. An edit that leaves the field out keeps the agent's default, so leaving a field out never removes a spend limit, and only `max_cost_usd: 0` clears it (no default; through MCP's agents_revise too, where null is refused). A workflow definition with one above 0 is `422 not_allowed`, since a workflow run's spend is not capped here; 0 changes nothing there. A trigger's `start_run` target may now leave out `max_cost_usd` when its agent has a default: each firing takes the default as it stands when it starts, a target with neither is `422`, and a firing that finds neither fails rather than start an uncapped run.
