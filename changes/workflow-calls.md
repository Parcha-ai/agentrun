A run now records every learned workflow call it made, and why its first choice did or did not serve. `GET /runs/{id}` and each runs list row carry `workflow_calls`: one entry per call, the platform's before the agent's first turn and the agent's own alike. Each entry has its `workflow`, its `digest`, its `caller` (`platform` or `agent`), its `outcome` (`answered`, `handed_back`, `failed`, or `refused` for a call refused before any node ran, by the tool or at its gate when an ask is declined or the cap is wrapping up) and the `usd` its nodes booked. `usd` is null when that is not known or another call ran beside it, a sibling subagent's on pi included. The same runs also carry `first_choice`, the reason the platform ran a learned workflow first or did not, for example `served`, `none_fit`, `not_promoted`, `cost_stop`, `no_by_hand_cost` (10 served runs and no by-hand cost to hold them to, so the agent takes the run and its `learned_workflow` tool leaves that workflow out) or `past_unread`. Both fields are null where `path` is. SDK runs keep no call record, so their `workflow_calls` is empty. The money rule now counts a run whose agent called a workflow, not only one the platform served: a run the platform served first is charged to that workflow alone, a run only the agent called to each workflow it ran, and a refused call to none. A run whose first call was refused names no workflow: its `path` and `workflow` are the agent's. A workflow over its by-hand cost stops whoever made its calls: it no longer runs first, the agent's `learned_workflow` tool leaves it out, and the run records `cost_stop`. When the agent's past runs can't be read, the money rule fails closed: nothing runs first (`past_unread`), the tool runs no learned workflow, and the learning view reads every workflow as cost-stopped. A run claimed again after a crash still keeps what its workflow did first, its answer or its handback, even when that claim can't read the past. Runs that ended before this release recorded no calls; the money rule charges each as its `path` and `workflow` say, as before, so a workflow stopped today stays stopped. The learning ledger keeps each run's calls, through a new additive column on SQLite and Postgres. `path` and `workflow` read as before.
