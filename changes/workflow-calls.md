A run now records every learned workflow call it made, and why its first choice did or did not serve. `GET /runs/{id}` and each runs list row carry `workflow_calls`: one entry per call, the platform's before the agent's first turn and the agent's own alike. Each entry has its `workflow`, its `digest`, its `caller` (`platform` or `agent`), its `outcome` (`answered`, `handed_back` or `failed`) and the `usd` its nodes booked. `usd` is null when that is not known or another call ran beside it. The same runs also carry `first_choice`, the reason the platform ran a learned workflow first or did not, for example `served`, `none_fit`, `not_promoted` or `cost_stop`. Both fields are null where `path` is. The money rule now counts a run whose agent called a workflow, not only one the platform served. A workflow the agent keeps calling at a cost over its by-hand cost stops running first, as one the platform served would. Runs that ended before this release recorded no calls, and they count toward no workflow. The learning ledger keeps each run's calls, through a new additive column on SQLite and Postgres. `path` and `workflow` read as before.
