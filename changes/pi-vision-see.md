Breaking: `look` is not a tool, and its exports are removed (`LOOK_TOOL`, `ToolContract`, `JsonSchema`, `VisionHandle.tools`, `install.look`, and the caps `LOOK_PAGES_PER_CALL`, `LOOK_FRAMES_PER_CALL`, `LOOK_MAX_USD`, `LOOK_CONCURRENCY`); no version built `look`, so only a host that imported these names changes, and it passes its own caps where it wants one (`plan(facts, selector, limits, "ask", { pages, frames })`, `priceLook(..., capUsd)`), since there is none by default.
- An agent looks at many pages, a long video or many images by writing code. `handle.see(env, call)` is `vision.see`, a global for a host's code-mode sandbox (`globals: [vision.see(api.env, await callContext(api, context))]` with pi-codemode), described to the model by `VISION_SEE`. It takes `{ ask, paths?, images?, fragments? }`, reads paths through the call's environment, fits each image to the eyes' limits, packs the images into as few requests as the eyes take (`packRequests`, which the guard uses too), and returns `{ text, model, costUsd, receipt, kept? }`, one part a request when there are several. Each request is a look filed and told once, its answer kept as the call's memo, so a call run again after a crash pays and tells once. A look that cannot be made throws `SeeMiss` with its miss code. `allow` is asked with `tool: "vision.see"`, and events name it.
- The `look` skill ships in the package (`skills/look/SKILL.md`, declared under `pi.skills`): many PDF pages with pdftoppm, a long video by frames with ffmpeg, many images, a cropped region, and installing poppler or ffmpeg.
