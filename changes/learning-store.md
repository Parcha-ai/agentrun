kind: breaking

An agent's learning lives in one learning store, the local git folder under the data directory by default with no setting at all, or code.storage when the server and its runners are started with `AGENTRUN_CODE_STORAGE_NAME` and `AGENTRUN_CODE_STORAGE_KEY` (optional `AGENTRUN_CODE_STORAGE_API_URL`). The learning folder on an agent's Archil disk is gone. Who breaks: a server whose agents learned into an Archil disk's learning folder (Mode 2 runs); their next runs learn into the store from an empty start, and the disk's old `learning` folder is no longer read, written or removed. What to do: nothing for a single host; for runners on other hosts, set the code.storage settings on the server and every runner (a runner apart from its server's disk without them refuses to learn, in words naming them).
- Every reader and writer goes through the store: the learning routes, runners, grades, audits, a reset, a purge, an SDK run, a run's end and its seed. A save is one commit on `main` by compare and swap on the head it read; a run's merge leaves its marker file (`.agentrun/runs/<run>`) in the same commit, so a run merges once.
- On code.storage each agent is one repository at a time, `agentrun-<server id>-<agent id>-g<generation>`, the server id 12 hex digits; every token is checked to name an id starting `agentrun-<this server's id>-`, no call follows a redirect (the bearer token goes nowhere else), and no call lists repositories. A reset moves the agent to its next generation and deletes the old repository; an agent's delete deletes every generation it had, each by its exact id. The start logs one line naming the org and the repositories' form, never the key. The key is read by name, never logged, never in argv, and never handed to a run.
- A local folder's merges made before this release (recorded as `refs/agentrun/runs/<run>` and `.agentrun/diffs/<run>.json`) are not carried over: their run diffs answer 404, and the folder's learning itself reads as before. Let running learning runs finish before upgrading: a run that committed its merge but not its end under the old release can merge again when it is recovered.
- code.storage is on when `AGENTRUN_CODE_STORAGE_NAME` is set; the key or URL set without it changes nothing, and the start says so.
- A Mode 2 run no longer needs serverless exec on the Archil disk to learn: an Archil plan without it learns and serves as before.
- `DELETE /agents/{id}/learning` and an agent's delete answer `503 unavailable`, retryable, while code.storage can't be reached, the agent's learning and records kept.
- A code.storage read that answers 404 for a repository that exists (a history, listing or diff read while the agent moves generations) is `503 unavailable`, retryable, never read as an empty history; an agent reads as having learned nothing only when its repository is confirmed absent, or holds no `main`.
