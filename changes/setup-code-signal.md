Setup at a public address takes the right setup code however the console was opened. `GET /v2/auth/session` says, before a password is set, whether setup takes the code the server printed (`setup_code: true` at a public address, `false` on an open setup, never the code itself), and the console's setup form shows its Setup code field whenever it does, with where to find the code ("Find the setup code in the server's log (on Render, the Logs tab), or open the link the log prints."), and sends no setup until a code is in it. The server's API token (AGENTRUN_TOKEN) works in that field too, compared as the Authorization header's is; a wrong one counts as a wrong code. A setup with no code is refused without counting against the printed code; the fifth wrong code voids it and prints a new one at once, and the refusal says a new one is in the log. A setup link opened in the same tab after the page loaded fills the field too. Before, a first visit at the plain address showed no field, its tries with no code voided the printed code without printing a new one, and the right code from the log was then refused as "not the setup code". At an https public address, the console's pages also carry Strict-Transport-Security (max-age one year); over http or on loopback with no public address, none.
