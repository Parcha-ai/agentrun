The runner's hold of Claude Code's refresh lock on AgentRun's own login folder, where each run is a user of its own, is steadier. A runner whose new lock is gone at its first touch (another holder took it) waits for that holder and takes its renewal, instead of failing the ask. A runner whose read of its own lock or `.takeover` directory fails on release (an I/O error, not the lock gone) reads it once more and removes it while it is still its own, instead of leaving it for the 60 s stale time. A failed read of the lock just before or after the renewal is sent is logged as `lock_unread`, no longer as `lock_lost`, which now means only that another holder took the lock. A renewal whose save could not read the login's file (an I/O error, not the file gone) keeps the renewed pair in memory and saves it at the next ask, logged as `file_unread`, instead of forgetting it: when Anthropic rotated the refresh token, that pair held the only one left, and later asks could not renew. An ask that reads the login's file while a renewal that got a new refresh token is still saving it now waits for that renewal and is handed its token, instead of being refused for the refresh token the renewal just spent. The runner's reader of the login now says each renewal's outcome on the runner's log, as `event=claude_login` lines with no token in them (a renewal that failed or was refused, a save held, a lock lost or unread); before, it said none. And a run that is a process of its own no longer reads the login's setting again at its start: it runs on the login only if its claim read it on, so turning the login on or off just after such a run is claimed never moves it onto a login its claim did not check, or off one it did.
