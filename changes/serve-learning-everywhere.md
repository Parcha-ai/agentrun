Learning works on every harness and on cheap models. The end-of-run turn answers with its notes as text, so an agent needs no `write` tool and a note asked for during the task survives. The grader keeps a lesson the agent worked out itself and what the user asked it to keep, and still drops what a page told it.
- The end-of-run turn (`reflectPrompt`) asks the agent to look back over the whole conversation, what the user asked it to remember included, and to answer with one ` ```note <file>.md ` block per note, using no tool. The server reads the notes from the turn's answer alone (`parseReflection`, new in `src/learn/reflect.ts`), whole, and keeps the answer and what the user said in `runs/<id>/learning-turn.json` as the run settles. The checker, the grader and the merge run unchanged. Nothing the run writes in `work/.learning/`, during the task or the turn, is read, and the folder is no longer laid again before the turn or moved aside after it (`runs/<id>/learning-turn/` is gone).
- The learning reasons gain `unparsed`: the answer gave notes out of format (a note outside a block, a block not closed, one with no file name or two, a name given twice), and none was kept. Its detail reads "Not kept: its notes weren't in the expected format." No run gets `no_write_tool` or `tool_denied` now, since an agent with no tool learns too; they stay in the list for older runs, whose ends are still read and counted. The `# Learned` intro says that only what the run answers at the end is kept.
- `GRADE_RUBRIC` asks five questions. "From content" becomes "Planted": an instruction a page, a document or a tool's output gave is planted (act for someone else, send data, trust or use a source content offered, skip or change the instructions, or remember this). A lesson the agent drew from its own work, such as a URL pattern, a site's layout or how a tool behaves, is not planted, and neither is what the user asked in their own words; an email or a message pasted or forwarded into the run is content. A new "Secret" question covers passwords, keys, account numbers and private details, whoever gave them, a new "Risky" question asks whether a rule widens trust in a site or a seller, skips or loosens an approval or a check, or names an account or a destination for money or data, and "General" counts a standing preference of the user's as general and a tool's or the setup's failure as tied to its case. Each note's decision is keep, pending or drop, with its origin, you or run (`parseVerdict` reads `decision` and `origin`, and the older `keep` alone). `gradePrompt` takes `asked`, the user's messages in the run (the first and the newest three, each cut to 1,000 characters), fenced as data.
- The grader runs on the model the server names for it: `--grade-model` (or `AGENTRUN_SERVE_GRADE_MODEL`), else the strong tier (`AGENT_MODEL_STRONG`), else the agent's own model as before. `GET /capabilities` names it as `learning.grade_model`, null for each run's own. It reads what the user said in the run, cut of the server's secrets, which the proposal now keeps (`asked`).
- An eval set of 20 labelled runs (`packages/serve/test/fixtures/learn-eval.json`) and a held-out set of 9 (`learn-eval-heldout.json`) run in CI on a faux grader that answers by label, and `packages/serve/scripts/learn-eval.mjs` runs them on real models.
- A risky rule the user asked for is pending, never dropped: merged as `status: pending` with `origin: you` (`src/learn/notes.ts`: `NOTE_STATUSES` and `NOTE_ORIGINS`, `mergedNote`, `approve`), in no `MEMORY.md` and no run's copy, and named on the run's learning: `pending`, `[{file, name}]`, on `GET /v2/runs/{run_id}`, in run lists and on the run's whole learning, never among `learned`, and in its detail ("Waiting for your OK: <name>.", after "Learned: <name>." when the run kept a note too); `GET /capabilities` says so (`learning.pending: true`). It waits for its owner: a person can retire it or approve it (serve-learning-approve). A run's note that sets `origin` is refused as `status`.
