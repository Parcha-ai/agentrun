A new computer provider, `tensorlake`: a Linux sandbox on a Tensorlake sandbox (a microVM), over the Tensorlake API and SSH, with no SDK. It takes `TENSORLAKE_API_KEY`, the name Tensorlake's own SDK reads, and loads from `@parcha/agentrun-computer/tensorlake` or `providerFor("tensorlake", { apiKey })`. A computer starts from one of Tensorlake's images, `"tensorlake/ubuntu-minimal"` by default, or a sandbox image registered in the key's project, so it is a sandbox alone: no desktop and no Archil mount. The exec is SSH to the sandbox's own sshd as `tl-user`, which the sandbox proxy turns on for a key the process makes and reaches through its TCP tunnel, with the sshd's host key pinned by the fingerprint the proxy's SSH enable names: an enable that names none is refused, so no command runs through an sshd that can't be verified. A sandbox carries no labels, so its name carries the run's hash, the epoch and the deadline, and every other label is in a root-only file read through the processes API. The idle threshold is set to the backstop's span with auto resume off, and the janitor ends a computer at its deadline, within a day. The Agent37 WebSocket tunnel moved to `src/hosted/ws-tunnel.ts` and Render's `eachAtMost` to `src/hosted/process.ts`, both shared now, with no change to either provider. Serve offers it as a box once `AGENTRUN_BOXES` lists `tensorlake` and the key is set, and the launcher holds `TENSORLAKE_API_KEY` with the other secrets. No live run has been made yet: the SSH enable and its host key, sshd on loopback 22, tunnel traffic as activity, `sudo` in the processes API, a 63-character name and a taken name's 409, a deleted sandbox's read, `sandbox_url` in every read, amd64, root's network namespace, the plan's longest idle threshold, the vendor listeners and 75 s of SSH silence are unverified until then.
