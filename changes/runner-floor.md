A runner on Postgres no longer needs the store's schema to match its own version exactly. The server can migrate first while the earlier release's runners keep running, as long as the migrations are additive. Each store keeps a runner floor: the oldest schema version a runner's build must know. A migration marked `-- runners: breaking` raises the floor to its own version. Every runner reads the floor again every 10 s, whether or not it holds runs. When the floor rises above its version, it claims nothing more, drains, hands its runs back and exits 3. A runner that starts below the floor exits 3 and says to run a runner of the server's release. A runner on a store its server has not migrated yet still exits 3, as before. Runners of earlier releases still need an exact match, so roll this release's runners with its server as before; from this release on, a runner keeps running beside the next releases' additive migrations.
- `agentrun-serve store-schema [--data DIR]` prints the store's schema version and runner floor beside this build's version, and what this build's server and runner do on that store, as one line of JSON. It reads only: no lock, no migration. `--build` prints the build's own versions with no store. `GET /v2/capabilities` carries the same live values in `store_schema` (`version`, `runner_floor`, `known`), for a deploy check that refuses a build older than its store.
- A Postgres migration that drops or renames anything, changes a column's type, makes a column NOT NULL, or adds a NOT NULL column with no default must carry the `-- runners: breaking` header. A test fails one that does not. Migrations up to 0022 predate the rule and count as breaking; 0023, the first the lint reads, is additive. A SQLite runner still opens only its own schema version.
