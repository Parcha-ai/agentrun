**A job at an effort for an output type: a run takes a profile pack, and serve ships a `default` one**
- serve ships a default profile pack, `default`, with the skills it names. Each effort loads one skill: `effort-low` (one wide pass of searches, then write once), `effort-medium` (a plan, concurrent search batches, corroborated claims, a thesis, one check before finishing) and `effort-high` (a six-phase loop ending in a three-pass review gate); the pack sets no thinking level, so a run thinks at its effort. The effort skills refer to tools by what they do (a web search, a page fetch, read, write and edit), since the tools an agent has vary, and each loads the run's writer skill right before it writes the deliverable.
- Output types: `report` and `decision` load `report-writer` and write `report.md` (plain markdown, an action title, inline citations on every claim and a `## Sources` list); `answer` loads no writer and writes no file; `slides` loads `slides` and writes one self-contained `slides.html` with keyboard navigation; `dashboard` loads `data-visualization` and `html-app-architecture` and writes `dashboard.html`; `website` loads `html-app-architecture` and `anti-slop-design` and writes `index.html`. The pack names no default output, so a run writes a file only when it asks for an output type. No binary format (spreadsheet, document, PDF, presentation file) is offered: producing one needs a shell, which serve does not give an agent.
- Every bundled `SKILL.md` has front matter with its `name` and a `description` and passes the skill check the native harnesses run, so each one loads natively.
- The `slides` skill is adapted from frontend-slides by Zara Zhang (MIT License), whose license ships beside it and is credited in serve's NOTICE.
- `defaultPack()` reads the pack and the directory of its skills; the build copies `src/packs` to `dist/packs`, and the package check confirms the pack and each of its skills are in the published package.
- `POST /v2/agents/{agent_id}/runs` takes `profile`, the name of a pack this server ships or a pack object (version 1), and `output`, an output type of that pack. `output` alone uses the shipped `default` pack, when the server ships one. The pack is resolved when the run is made, for the run's `effort` (medium when it names none) and its output: the effort row's skills, then the output's writer skills. The result is pinned in the run's `serve.json` under `profile` and shown on the run as `profile` (null when it named none): the pack's name, the effort row, the row's thinking level when the pack sets one, every skill in order, and the output type with its file and its writers.
- Each skill the pack names is taken from the agent's revision first, so the caller's own skill wins, and else from the shipped pack's bundled skills, which are staged into the run's workspace beside the revision's. A skill neither holds is `422` naming it, and so is an unknown pack name (listing the shipped ones), a pack with issues (each by its field under `profile`), an output type the pack does not name, `output` with no profile when the server ships no default, and either field on a workflow run.
- The run's system prompt carries the ordered mandate after the instructions: the skills in the pack's order, the run's writer skill last, right before the deliverable, and the file the deliverable goes to (or the final message), in one wording on every harness. The run thinks at the pack row's thinking level when the pack sets one, else as before: its effort, its revision's thinking, `AGENT_THINKING`, then medium. A run that names an effort but no pack loads no pack, and a run that names neither field is unchanged.
- Capabilities list `profiles`, the packs this server ships, with their efforts and output types. `profile` and `output` on RunCreate, `Run.profile` and `Capabilities.profiles` are this server's own, marked `profile/1`; RunCreate's `revision`, accepted until now without being documented, is marked `serve/1`, and a test ties RunCreate's properties to the fields the route takes.
- The shipped `default` pack is one a run can use: capabilities list it in `profiles`, `profile: "default"` names it, and an `output` with no `profile` uses it. A run that names neither field is unchanged, effort alone included. serve reads the pack once when it starts, so a broken pack fails the start rather than a run.
- `GET /v2/runs/{run_id}/output` names a run's output as the profile pack it was made with pinned it: `{run_id, type, path, url}`, its file in the run's workspace and that file's address (`GET /v2/runs/{run_id}/files/{path}`), or `path` and `url` null when the output is the run's final answer. An HTML output's address (slides, dashboard, website) asks for a download (`?download=1`), to open locally: the server never runs a run's scripts on its own origin. It reads nothing on disk: the files routes say whether the file is there, and its size. It answers during the run and after it, archived runs included. A run made with no profile, or whose profile gave it no output, is `404 not_found` saying which. Capabilities say so with `features.runs.output`; the route and the flag are this server's own, marked `output/1`.
- A `codex` run gets its revision's skills, and its profile pack's, natively, as a `claude-agent` run does. Each skill the Codex adapter's own check takes (`skillProblems`, the check every adapter runs) goes to the adapter: Codex lists it to the model by its name and description, the model reads its `SKILL.md` and the files it names with `read_skill_file`, and the system prompt no longer writes it out. A skill the check refuses stays written out in the system prompt, and so do all of them when together they hold more than 1 MiB. `read_skill_file`'s description (`@parcha/agentrun-adapters`) now says how to open a skill listed by its name and description: with it, its `SKILL.md` first, then the files it names. `pi` runs still have every skill written out in the system prompt. A run on the faux harness (`--faux-harness`, for tests) now splits its skills as the harness it stands in for does, and its script is told which skills that harness's adapter would load.
