An agent that learns now tidies what it learned. After a run's learning merges, the server queues one consolidation run for the agent when 5 or more merges have landed since the last one was queued and its active notes are past the 8 KB budget, or when a skill and its workflow draft have drifted apart (one changed without the other). That run is not listed with the agent's runs. It asks once for replacements, and that paid request is never repeated: its answer is kept as it returns, so a consolidation that resumes after a crash reuses it: one note for each group of notes that say the same rule, each keeping every rule of the notes it replaces, and a skill and its draft written back to describe the same steps. Then it goes through the same checks, grade and merge as a run's learning, so a replacement that loses or changes a rule is dropped and the old notes stay. It is graded on the server's grade model, its cost (its ask and its grade) counts in the learning meter of `GET /v2/usage`, and an agent has at most one consolidation queued or running at a time. A draft it rewrites is checked against the agent's tools and their settings as a run's is, and one that calls an MCP tool with no declared price waits for the owner's OK, as a run's does. A skill and its draft it rewrites both merge together or not at all. Every learning grade, a run's too, now also drops a new skill or workflow draft whose steps differ from its pair's, given together or beside the other as the agent's learning holds it. Upgrading: nothing to do.
