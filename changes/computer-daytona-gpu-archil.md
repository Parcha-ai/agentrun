Daytona GPU computers can be made from our own GPU snapshot. `box/build-daytona.py --gpu H100` builds box/Dockerfile (root, our helper) as the snapshot `agentrun-archil-gpu-h100-<recipe hash>` with one H100, in region earth, and `DaytonaProvider`'s `gpuSnapshot` option names it (the conformance module reads `COMPUTER_DAYTONA_GPU_SNAPSHOT`). Its GPU is the one its name says. A Daytona GPU computer still takes no mount, since Daytona's GPU host gives no `/dev/fuse`. An Archil computer's preflight now reads `/dev/fuse`, and refuses without it in words: "this computer has no /dev/fuse, so the Archil folder can't be mounted". `GpuCapability.unmounted` carries a provider's own reason its GPU computers take no mount, and checkGpu gives it. serve refuses a GPU computer in Mode 2 in one sentence with that reason and what to use instead, the same at the save, at the run's start, at the claim and in Settings' `gpu.why`. Daytona: "A Daytona GPU computer can't mount this run's folder: Daytona's GPU runtime gives it no /dev/fuse. Use a GPU computer from the library, or this sandbox without a GPU." Modal: "A Modal GPU computer can't mount this run's folder yet: Archil's FUSE mount isn't proven on Modal's gVisor runtime (#2279). Use a GPU computer from the library, or this sandbox without a GPU."
