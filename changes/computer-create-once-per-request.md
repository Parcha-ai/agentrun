Orgo, Browserbase, Kernel and the local browser make one computer per create request id: a create retried with the same `requestId`, while the first starts or once it is up, answers the computer the first made; the same id with another spec is refused `exists`; and the same id after this provider released its computer is refused `exists` ("was made for this request and has ended: create with a new request id"). On Browserbase, Kernel and the local browser, a request whose browser ended on its own (a timeout or a deadline, with no release) is refused `exists` in the same words. A create with no `requestId` is refused `invalid` on each.
- Orgo (Linux desktop): the computer's name begins with `computer-<12 hex of sha256(requestId)>`, then the run's hash, the epoch and the deadline; before it makes a computer, create lists the workspace's computers and answers the request's, compared by its labels, image and sizes. Two processes whose creates of one request both made a computer end up with one: each lists the workspace again after Orgo's answer and once its computer is up, and a create whose computer is not the request's oldest deletes its own and answers the oldest. A create aborted by its caller during either list deletes its own computer and is `aborted`.
- Browserbase and Kernel: the `agentrun.create` label holds the request's name; before it makes a browser, create lists the running and starting browsers with that label and answers the request's, compared by its labels. Two processes whose creates of one request both made a browser end up with one: each lists the label again after the vendor's answer, and a create whose browser is not the request's oldest releases its own and answers the oldest, refused `exists` when that one has ended. A create aborted by its caller during that list releases its own browser and is `aborted`. Each POST also writes an `agentrun.attempt` label of its own (`ATTEMPT_LABEL`), and a create whose reply is lost finds and releases the browser by that label alone, so it never releases another create's browser of the same request.
- Local browser: a browser's id and directory are the request's name, `computer-<12 hex>`, claimed with `mkdir`; a create on the same root that finds the directory answers that browser, compared by its labels and network. The create writes a claim (its pid and the time) right after the `mkdir`, and a directory with no `browser.json` whose claim's process is gone, or that is older than a create takes, is refused `exists` at once: an earlier create of the request did not finish.
