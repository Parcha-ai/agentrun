An agent's page in the console runs the agent and shows its analytics. A run bar under the header takes an agentic agent's first message, or a workflow agent's input as JSON (prefilled with its example, else its fields empty), and an effort from the server's `features.efforts` ("default" sends none). A started run opens on its page; a refusal (a `409 agent_not_runnable`, a `422` with its fields) is shown in the bar, and sending again is the same request under the same `Idempotency-Key`. An archived agent has no run bar. The Runs tab shows each run's effort, and an Analytics tab, on a server whose `GET /v2/stats` answers `analytics`, shows the agent's tokens, time, success, cost, success by harness and effort, top tools, and runs and tokens per day over the last 7 or 30 UTC days or every run, drawn with Mission Control's analytics components: a token sum says how many runs it holds, unmetered requests are named, and a cost not known is never $0.
- serve's runs index (`GET /v2/runs`, `GET /v2/agents/{id}/runs`) now carries a run's `effort` as `GET /v2/runs/{id}` does: optional, absent for a run started with none, marked `effort/1` in the served OpenAPI document. The document also lists every other field a run answer carries beyond the contract, marked `serve/1`: `revision`, `kind` and `archived_at` on `Run` and `RunSummary`, and `error` on `RunSummary`. Before, a run or a runs-index answer did not meet the document's closed schemas.
