`PUT /settings/mcp-servers/{name}/composio` takes two optional fields. `price_usd` (a finite number, 0 or more, as any `prices` value) prices every granted action the server lists at that amount a call, as the server's `prices`: each call is held under its run's cap and booked as the run's tool cost, so it shows in its trace span's `usd` and the run's `cost.usd`. Before, every Composio call read $0, not metered. A preset save that names no price keeps the server's prices for the actions it still lists, whatever its new address: before, each preset re-save dropped the prices an owner had set on the server, leaving those calls unmetered and outside the cap. `auth_config_id` (`ac_…`) makes the MCP server and its connect link against an auth config you already have at Composio, such as your own OAuth app's, in place of the Composio-managed one. It is read first: one Composio doesn't know, of another toolkit, or disabled is `422` under `auth_config_id` before anything is made, and from that save on it is yours: no delete or later save removes it, even when AgentRun made it for this or another saved server. A malformed value of either is `422 input_invalid` on its field before Composio is asked anything. A save with neither works as before. A Composio trigger on a saved server now watches, and makes its connect link for, the account under that server's own auth config (the managed one or the one `auth_config_id` named), so an account under another config no longer makes the trigger's create `composio_account_ambiguous`; a server saved before this keeps the listing across every config and the managed config's link.
