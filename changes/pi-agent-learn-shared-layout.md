**Pi's learning loop moves onto the layout every harness shares (`@parcha/agentrun-learn`'s SPEC.md), and `curate` merges a run only after the step 1 checker and an injection screen.** `@parcha/pi-agent-learn` now depends on `@parcha/agentrun-learn`, which a release now publishes just before it.
- `proposeLearning` writes the run's branch from the commit the run was seeded from: the memo, `memos/<run id>.md` (the host's facts in its front matter, `harness: pi`; `outcome` and `costUsd` are new options), a note per lesson, fact or correction in the learning format, one more `uses` on each learning a `used` mark names, `learnings/INDEX.md`, a draft per saved workflow (`workflows/<name>/workflow.json` and `README.md`), and `uses/<run id>.json`. The inbox is retired: `inbox/<run id>.md`, `inbox/<run id>/workflows/<name>/`, `renderInbox`, `parseInbox`, `inboxPath`, `inboxWorkflowDir` and `inboxWorkflowFiles` are gone; `runBranchFiles` and `readRunBranch` write and read the branch. A seed that is not a commit of the repository refuses the proposal. A second `used` mark of the same learning, or one naming no active learning, no longer reaches the branch.
- `curate` refuses a run whose branch the checker refuses (`tools`: the host's tool list), and every run when it has no `screen` or the screen lacks its judge or its threshold: "no injection screen". Both halves are the host's, and this package holds no threshold. A score at or over `threshold` refuses that note, skill or draft, and so does one the screen could not judge.
- Breaking, and what to do about each:
  - **No screen refuses every run.** A host adds one line to its `curate` call, passing pi-browser's page judge and its page-injection threshold: `screen: { classify: async ({ text }) => (await decisions.classifyPage({ url: "", status: 200, contentType: "text/markdown", text })).injection, threshold: INJECTION_THRESHOLD }`.
  - **The checker fails closed without the host's tools.** A draft that names a tool is refused unless the host passes `tools`, the names of the tools it binds (a Pi host passes its registered tools' names).
  - **A draft with a code node, or a call via shell or executor, is refused at any depth**, even of a kind curate admitted before (with the admitter's `allowExecutableCode`). An agent drafts the workflow with model, judge and tool-call nodes over the host's tools instead; a revision already on main stays on main.
  - **A run seeded from a commit that is not in the agent's repository is refused** at propose. A host seeds a run from a commit of that repository's `main` (`seedLearning`), or proposes it unseeded, and the branch then starts at `main`.
- `curate` writes main as a merge commit. Its second parent is the run as it lands, a commit on the run's base with exactly what curation took (`Landed-Run`), so nothing it refused becomes reachable from main, and `git revert -m 1` undoes a run. The run's memo lands with the verdict as its `## Review` section, `learnings/INDEX.md` is kept in step, and so is `retireLearning`'s commit, which is an operator's act outside the loop. A workflow's README is the agent's: it passes the screen and a note's questions and lands on main as written; one that does not stays off main, the workflow is judged without it, and main gets a README that points at the workflow's skill.
- Workflows live at `workflows/<name>/` (records, `latest`, `workflow.json`, `README.md`); `trial.json` stays in the skill folder. Every read tries `workflows/<name>/` and then `.pi/agentrun/workflows/<name>/`, so an older repository keeps working with no migration. `repoWorkflowDir`, `readWorkflowFile` and `liveRevisionAt` are new; `workflowDir` names the folder in a working directory's DSL store. The guard allows a run what its branch holds and the curator what main holds; `CAPS.inbox` is now `CAPS.memo`, `CAPS.index` is new, and `CAPS.files` is 64, the checker's cap.
