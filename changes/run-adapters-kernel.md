`@parcha/agentrun-adapters/kernel` and `@parcha/agentrun-adapters/process`: the durable kernel a harness adapter runs on, over the run's session store, and the shared layer for harnesses that run as a child process.
- An effect is its intent, then at most one outcome, each durable before what follows: a completed or failed effect is answered from its records and never runs again. When a drive opens, an intent a dead process left open is run again if its tool is `safe`, and recorded failed and interrupted if it is `never` ("it may or may not have taken effect"), never run again.
- One drive runs a key once at a time: a second `effect()` call for a key already in flight in that drive, even one issued before the first's intent is durable, is refused with `Fatal` and its function does not run.
- Input is placed before it is sent, and a withdraw that lands first wins: a placement that names a withdrawn submission (from a `pending()` read before the withdraw) places nothing, and its effect throws `Restart` without running, so the rebuilt drive sends only what is still pending.
- A large native record is kept as a blob in the session's own records, named by its content's sha256: `writeBlob` refuses a hash that is not its text's (`TypeError`), and `readBlobs` returns a blob only when one write's pieces are all there and join to text with that hash, so a write again under another piece size never mixes with the first.
- `./process` has the native journal, the transcript fold, the recovery note, the tool bridge, the hook-pair calls of a harness's built-ins and the inbox. These are copied from another project and listed, with each file's upstream blob and sha256, in `vendor/durable-harness/UPSTREAM.json`; `NOTICE` credits it.
- One process writes a session at a time, and the store enforces it. `SessionStore` is now `read(key)` and `open(key)`, which returns the session's writer and fences every writer opened earlier for that key, whether or not the new one has written anything; a fenced writer's `append` is refused with `SessionFenced` and writes nothing. The runner opens one writer per attempt before it reads the session and passes it to the adapter as `SessionIO.writer` (it was `store`); a runner whose writer is fenced ends `fenced`, not final, and delivers nothing. `openDrive` takes the writer (it took `store` and `key`), and a stale drive's refused write is a `Restart`. A host's store must implement `open` with this fence.
