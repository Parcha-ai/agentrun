The API token no longer binds a per-run Composio server to a Composio user the owner connects on the install: the user any preset server the owner saved calls as (not one the token saved, and not a per-run one), and the default `agentrun`. On a start (`POST /v2/agents/{agent_id}/runs`, a launch hook's firing start included), an inline start (`POST /v2/runs`) and a message (`POST /v2/runs/{run_id}/messages`), the token's `mcp_auth.<server>` binding of one is `422 input_invalid` at `mcp_auth.<server>.composio_user_id` (`not_allowed`), and nothing is written. The owner's users are read at each request, so a user the owner connects later is refused from then on. The owner's session binds any user, and on an API-only server only `agentrun` is refused. Each binding is now sealed with who handed it (`by`, the token or the owner's session, a new field of the stored launch seal), and each claim reads the owner's users again: a token's binding of a user the owner has connected since has its calls of that server answered, unsent, that the user is the owner's, until a message hands `mcp_auth` again or a new run starts.

Upgrading: a run in flight across the upgrade whose binding names a user the owner connects here was sealed with no mark, so its calls of that server are refused at its next claim in the same words, until its binding is handed again on a message (from the owner's session, for the owner's user) or a new run starts. There is no other migration step. A per-run server still lends the install's Composio key to whoever starts a run, and a token can still name a user the owner connected directly at Composio, outside this install: save one only where the token's callers own that Composio project's users.
