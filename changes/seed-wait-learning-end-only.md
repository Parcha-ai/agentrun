A new run now waits on another run's correction only while that run's learning step runs after its job (the compile turn after a follow-up, a grade's words, or a message a person sent during the run's first job), not during the person's follow-up turn itself. A run launched while a follow-up turn is still running starts from its agent's learning as it is then, with no wait. A run launched once the corrected run reads `completed` still waits for the correction, as before, also when a person sends that run another message while its learning step runs (the step still merges the correction first). When the runner loses the run's claim or shuts down during the wait, the wait ends at once and the runner starts nothing, so another runner takes the run over. A run waits at any claim before its first turn: one handed back before that turn waits and reads its agent's learning again on its next claim. A claim that cannot read the run's own row or journal before the wait hands the run back to be tried again, instead of failing it or starting without the wait. The wait polls less often the longer it lasts (250 ms, doubling to 2 s), and starting a learning run reads the commands of the agent's running runs in one query per 50 runs.
