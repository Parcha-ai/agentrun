Mention the server's handle on a GitHub issue or pull request, or assign an issue to it, to start a run. `PUT /v2/settings/github` sets the server's GitHub webhook (`{webhook_secret, token, handle, assignee_login?}`, both secrets sealed under the seal key and never shown again), and `POST /v2/hooks/github` is its payload URL, with no token: each delivery is checked by `X-Hub-Signature-256` on its raw body, with `X-GitHub-Event` and `X-GitHub-Delivery` each once, before anything else. A trigger with `source: {kind: "github", repos, post_answer?}` starts one capped run for each issue or pull request in a repo it lists, from a comment that mentions the handle (on an issue, a pull request's conversation or its diff) by the repo's owner, a member of its organisation or a collaborator who is the delivery's sender, or from an issue assigned to `assignee_login`. A repo is one trigger's (`409 repo_taken`). A redelivery, and the same comment under another delivery, are one firing, keyed by the comment. A bot's event, the handle's own comments, an edit, a comment that mentions no one and anyone else are ignored. The event text reaches the run marked untrusted. The Slack trigger's thread map is now one map of conversations for any source, Slack's thread and GitHub's issue or pull request alike.
