Mention the server's handle on a GitHub issue or pull request, or assign an issue to it, to start a run. `PUT /v2/settings/github` sets the server's GitHub webhook (`{webhook_secret, token, handle, assignee_login?}`, both secrets sealed under the seal key and never shown again), and `POST /v2/hooks/github` is its payload URL, with no token: each delivery is checked by `X-Hub-Signature-256` on its raw body, with `X-GitHub-Event` and `X-GitHub-Delivery` each once, before anything else. A trigger with `source: {kind: "github", repos, post_answer?}` starts one capped run for each issue or pull request in a repo it lists, from a comment that mentions the handle (on an issue, a pull request's conversation or its diff) by the repo's owner, a member of its organisation or a collaborator who is the delivery's sender, or from an issue assigned to `assignee_login`. A repo is one trigger's (`409 repo_taken`). A redelivery, and the same comment under another delivery, are one firing, keyed by the comment. A bot's event, the handle's own comments, an edit, a comment that mentions no one and anyone else are ignored. The event text reaches the run marked untrusted. A later mention on the issue or pull request is a message to its run (it answers the run's question, and opens a completed run again); a comment that mentions no one reaches nothing. One comment is posted when the run needs its person and when it ends, saying how to go on (a question by a mention, a tool call waiting on approval in the console), with a link to the run when the server has a public address, and the final answer too when the trigger's source sets `post_answer: true` (default false), defused so it mentions no one and references no issue. Comments wait in an outbox, tried again on the webhook's schedule and as GitHub's rate limit says; a token GitHub refuses turns posting off until the settings are saved again. The Slack trigger's thread map is now one map of conversations for any source, Slack's thread and GitHub's issue or pull request alike.
