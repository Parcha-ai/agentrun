A run whose model provider takes a request and then sends nothing now ends failed, in words that name the stall, rather than staying working. Before, the session's model proxy waited on the transport. Node's fetch cut such a request after 5 minutes as "terminated", and every harness asked again. pi wrote a "Model request failed: terminated" row each time and retried up to 8 times. Codex retried with no row at all. claude-agent and goose each waited out two silent requests and then parked on a spend-cap refusal ("Waiting for you to raise the cap"), never naming the stall. pi's and Codex's runs showed working until they were cancelled.

The proxy now stops a forwarded request that goes `stallMs` with nothing from the provider, before its headers or between two pieces of its answer. The default is `MODEL_STALL_MS`, 240 s. Time spent waiting on a slow client is not counted. A host route that holds back part of what its provider sends tells the proxy so through `heard` on the request's init (`ProviderHeard`), and the bound starts again. serve's translated routes do this for a thinking block they send whole, a text-tools reply they read whole, and an answer asked whole, so a model that thinks for longer than the bound is not stopped. The client is told "the model sent nothing for 240 s, so the request was stopped" (code `model_stalled`). Before the answer began, that comes at the refused status. After, it comes as the stream's last `error` event, its own event even when the stall left the client inside one. A client does not retry on these words. The request is booked once, at an unknown cost. A host with `onFinal` (claude-agent, goose, opencode and codex) ends the turn in those words, and the turn's next answer request is refused until the host opens its next turn. pi ends the turn because it does not retry those words. The run's timeline shows "Model request failed: the model sent nothing for 240 s, so the request was stopped".

A model on the host's own machine (an Ollama model) can say nothing for minutes while it loads or reads a long prompt. On such a model, the proxies of pi, Codex and claude-agent wait as long as those CLIs already do: `LOCAL_MODEL_STALL_MS`, 30 minutes. So do the proxies of a local model tier (a subagent's or a learned workflow's), of a workflow's model nodes, and of an SDK ask. For Codex and claude-agent, the adapter's `streamIdleMs` is also the proxy's bound. serve now sends a local model's requests, and pi's own requests to its proxy, without Node's 5-minute cut, so the proxy's bound is the one that ends a silent local model on pi and Codex. Before, that cut came first, and pi retried a slow local model's turn as "terminated" every 5 minutes. Claude Code's own client still drops a request that sends nothing for 5 minutes and asks again, so claude-agent on a silent local model retries rather than reaching the 30 minutes. goose and opencode keep the proxy's 240 s on a local model.

`MODEL_STALL_MS`, `LOCAL_MODEL_STALL_MS`, `MODEL_STALLED`, `stalledWords` and the `ProviderHeard` type are exported from `@parcha/agentrun-kernel/host`. `ModelProxyOptions.stallMs`, pi's `PiAdapterOptions.stallMs`, and the Codex and claude-agent machines' `proxy.stallMs` set the bound.
