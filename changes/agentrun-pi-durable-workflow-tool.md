`@parcha/agentrun-pi/durable` gives a pi-durable session the agentrun tool. `createWorkflowTool(host)` returns one extension that carries the tool and the workflow task: the host installs it and lists the tool's name in the agent definition. Its describe, inspect, dry-run, save, load and list are the coding-agent tool's, run by the same code, over the project store `host.projectDir` names. Its run starts the inspected draft as one background `agentrun.workflow` task of the calling conversation, writes the run's progress to the call's running output, and answers with the outcome. The same draft and input asked for again, after a restart too, reach the same run and make no effect twice; `again: true` starts a fresh run of them, which a later run reaches. Code nodes run only through the host's `runCode`. A workflow uses only the tools the host registers in `tools`, as a call's tool and as an agent node's tools, and inspect names any other. A root agent offers the tools of the extensions it lists: list the tool's extension beside any other the conversation needs. `createWorkflowExtension`'s `start` and `read` take a tool's `api` as their caller (`WorkflowCaller`), naming the conversation in `options.conversationId`.
