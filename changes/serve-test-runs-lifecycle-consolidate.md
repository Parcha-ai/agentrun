serve's run and lifecycle tests drop 11 tests that rebuilt a setup another test already runs, and move their checks into that test. timeline-append.test.mjs is gone: stop-compacted.test.mjs's six-message compacted run now checks that its timeline holds every message in order, plus each answer. A run whose process served and then died with its server is opened again exactly once by the next one, now checked in recovery.test.mjs's relaunch test, which replaces the same test in launch-loss.test.mjs. A released run carried back by the next server is now checked in the locked-run-store test. A torn run record is checked in the adopted-run test. A model failure's `run_failed`, message and null result are checked in the run-schema test. A follow-up after a restart is checked in the restart test of `runs.test.mjs`. The `?archived` filters and `/usage` of an archived run are checked in the first archive test. Serve's cancel mark being the one the run's guard reads is checked in the cancel-before-attach test. A reopen giving its place back to a new start is checked in the two-follow-ups test. Nothing written after close is checked in the slow-start restart test. Tests that slept so a request would reach the server first now wait for the server's own record of it: they send the request under an `Idempotency-Key` and wait until a probe under the same key reads `idempotency_mismatch`. That covers the start and the follow-ups that wait for a place, a follow-up that waits for a run's end to be written, and the follow-up and start whose run or agent is archived while they wait. The archived follow-up is now checked for 409 `not_continuable`, where before it only had to be anything but 202. The cancel-before-attach test waits for the cancel mark instead of 1.8 s of sleeps. The test of a record unreadable for over 5 s waits for the server's warning, not a fixed 6.5 s. The follow-up test no longer says "or cancelled" in its name, because `runs.test.mjs`'s cancel test checks that.
