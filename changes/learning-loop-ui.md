The console's Learning tab now walks through the self-learning loop. A strip at the top shows five stages: the notes learned, the workflow they compiled into, the run where it took over, how much cheaper runs got, and where it is unsure. Each stage has a state and says what happens next ("1 of 3 notes, 0 of 5 runs: a workflow compiles at 3 notes or 5 runs"). The cost chart marks each promotion record on the run it first affected, with a lettered flag for a new revision, a promotion, a hold or a refit; the flags have a key, a hover and table rows. Replay runs are drawn as hollow rings and left out of the rolling mean. Runs with an unknown path or cost are counted in a chip. The headline gives the server's own before and after with the hand-back rate since the takeover. The learned workflow card says whether each revision is serving, served, refit, held or replaying, with the replay's numbers in one line. It shows each step's guard on the step in the graph ("jev ≥0.70") and lists the guarded steps: how often each handed back, and each run's p split into right, wrong and not graded. A learning feed lists compile turns (the notes that went in, each attempt, and the checks' own words when a draft was refused) next to the promotion records. A note compiled into a workflow says so. New: `GET /agents/{id}/learning/loop` (the agent's compile turns and guarded steps, `agentrun agents get-learning-loop`), and each workflow revision now has a `digest`.
