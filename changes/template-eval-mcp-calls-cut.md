A template eval no longer shows a fake MCP server's call arguments raw. The llm grader's `<mcp-calls>` block and the report's `mcp_calls` were built from each fake's own log, the arguments whole, so a value the run's cut holds (a server key, a handed key, a key-shaped string) that the agent passed to a fake tool reached the grader's provider and the report as typed. The timeline's copy of the same call was cut. Both now come from the run's timeline under its cut: the faked servers' calls that reached a fake, so the grader sees what reached the fake, cut. A call the run refused before it ran, or one that never left, is left out. A refused call is still in the report's `calls`, now marked `refused: true`. The fake's own log is read only to match a `tool_used` grader's `args` on a faked tool, and is never shown. learn-bench builds its steps' records the same way.
- Each answer of a fake MCP server now starts with a line `fake-call <nonce>`: 128 random bits per call, which the fake logs with the call. A timeline call is paired with the logged call whose nonce its result carries, never by comparing arguments, so a failed call with the same arguments as one that ran, an argument the timeline cut, a held value shown as `[redacted]`, or keys in another order can't swap which call shows. Under an eval the agent sees that one extra line per fake answer. It is removed wherever the agent may have copied it before an llm grader, a regex grader or the report reads it: the answer, the calls, the files, the mailbox and the handed result. Tools outside an eval's fakes are unchanged.
