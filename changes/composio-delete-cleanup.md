Deleting a Composio server in Settings → MCP servers now also removes what its save made in your Composio account, not just the Composio MCP server. That covers the connected account its connect link started (the pending link with it) and the auth config it made.
- **Kept while shared:** what another saved server still uses stays until the last of them is deleted.
- **Never deleted:** anything that was there before the save, such as an auth config or account you already had.
- **The answer:** a Composio server's `DELETE /v2/settings/mcp-servers/{name}` answers `200 {deleted: true, composio: {removed, note}}`. The note says what it removed, what it kept and why, and what is left when Composio refused or didn't answer (`removed: false`). The server is forgotten here either way. Before, a full removal answered `204` with no words.
- **Older servers:** a server saved before this change has no record of what its save made, so its delete removes only the Composio MCP server, as before.
- **A failed save:** a save that fails after Composio made something removes what it made (the MCP server, the account its connect link started, the auth config it made), never what it found. When Composio refuses that too, the error says what is left there. A save refused on a field (422) also says it in `details.composio`, and the console shows it under the field's words.
- **A save over a server:** saving a Composio server again removes the Composio MCP server the earlier save made, once the new one is saved. Saving it as another `user_id`, or with another toolkit, also removes the account or auth config the earlier save made and the server no longer uses, unless another saved server uses it. The save's answer then carries `composio: {removed, note}`, as a delete's does. While Composio triggers use the server, a save as another `user_id` or auth config is refused (`409 composio_in_use`, naming them), as its delete is; a save that keeps what they run as goes through.
- **Moved off Composio:** an ordinary `PUT /v2/settings/mcp-servers/{name}` that points a Composio server at another address removes what the preset made for it in Composio, as its delete would, and answers `composio: {removed, note}` too. It is refused (`409 composio_in_use`) while Composio triggers use the server.
- **One at a time:** Composio saves and MCP server deletes now run one after another, so a delete never removes an auth config or account that a save still in progress is reusing. An ordinary save of a Composio server lists its tools at once, and takes its turn only to write the server and clean up. If a Composio save over the server moved it meanwhile, a save that keeps the credential is refused (`412 precondition_failed`) and writes nothing, so it never points the server back at the MCP server that save removed. Other MCP servers' saves don't wait.
- **The console:** it shows the note, as a success when nothing is left.
