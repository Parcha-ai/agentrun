A workflow can check in code that the quotes its answer gives are in the pages it fetched: the new `quote_missing` predicate. A compiled workflow whose answer quotes fetched pages must use it as its quote check, never a judge.
- `{"predicate": "quote_missing", "path": "answer.evidence", "field": "quote", "pages": ["page"]}` holds when a quote at `path` (a string or a list of them; with `field`, records each holding its quote at `field`) is in no string under `pages`, the state paths this run's call steps wrote, each string read alone. Both sides are compared lowercased, with curly quotes straight, en and em dashes as `-` and whitespace runs as one space, then once more as letters and digits alone. A quote under 8 characters is not checked. On an `escalate`, the `escalate.evaluated` event carries `quotes_checked` and `quotes_missed`, counts only, never quote or page text. It is a mechanical predicate, so `not` takes it. Validation refuses an empty `path` or `pages`, a page path that overlaps the quotes' path, a page no input key or earlier node produces, and in a `poll` a page outside the call's declared result.
- The learning checks refuse a workflow draft whose output schema has a `quote` or `quotes` property and which fetches pages with a call step, unless each place in the answer holding quotes is read by an escalate on `quote_missing` (a quote key whose schema is a union of shapes is a place per shape; quotes no one `path` and `field` read, such as under two lists, are refused), a step of the top-level chain after the answer is written, whose `pages` hold pages as fetched (never a model's summary). The refusal names the predicate to write. The compile prompt says the same: a judge, an `ask` or a guard is never the quote check.
