A secret write refused to the API token now says where to finish it. The refusal is the same `403 forbidden`; its message ends "Finish it in the console: <link>", and `error.details.console_url` is that link: the console page for the operation (Settings → MCP servers, Model keys, GitHub, Email, Computers, Workspace, Webhook, a trigger's page, an agent's page). For an MCP server's save or sign-in, the link opens the add form (or a saved server's Change form, `?change=<name>`) filled with the server's name, its URL, the kind of credential (`none` for a save that sends no auth) and its toolkit, so the person pastes only the secret and saves; a Composio save opens the Composio form with its toolkit and actions, and one over a saved server's name saves under that name (`?change=<name>&preset=composio`). A save of a kind of credential the form can't fill (`per_run`) links to the page alone. The link never holds a token, a header, a client secret or a key. A URL with a user or password, a query parameter named like a credential, a key-shaped path segment or value, a key that spans path segments or a query's `+`, or a host label that could be an id (20 or more letters and digits with a digit, or a UUID) is left out of the link. The calendar and Claude Code login routes have no console page yet, and their refusal has no link. The setup skills now say that the person saves secrets in the console, and that an assistant opens this link for them instead of asking for the secret in chat.
Clients that compared the refusal's message to the exact sentence should check that it starts with that sentence: "Saving, replacing or removing a secret takes the owner's signed-in session in the console; the API token can't write secrets."
