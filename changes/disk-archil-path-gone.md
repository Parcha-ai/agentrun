---
packages: @parcha/pi-durable-disk
kind: breaking
---
pi-durable-disk no longer places a run on an Archil disk, supervises it, or forks it. It is now a durable run journal and CLI for one host: a run is a local directory (`localRun`), and placing a run on an Archil disk or in a remote box is agentrun-serve's job. Deleted: the Archil claim (`acquire`, `takeOver`, `revoke`, the mount token, `ARCHIL_SCOPED` and the `./bin/archil-scoped` export), `withClaim` and `readReleased`, `readRunFile` and `listRunFiles` over the disk's control, `archilPlace`, the supervisor (`ensureRunning`, `readRunStatus`, `archilControl`, `deleteRunTree`, the start mark), the local, Docker and Daytona host drivers (`localHost`, `dockerHost`, `daytonaHost`, `daytonaRest`, their errors and prices), `requestRun` and `ServeError`, and `fork` and `forkLocal`. The CLI's `supervise`, `release` and `fork` commands are gone, `status` takes only `--dir`, and `run` takes only `--dir` (`--disk`, `--region`, `--mount-root`, `--archil` and `--token-stdin` are unknown options). `openDurableRun` and `openRunLease` need `acquire` (`localRun`'s); `mountToken`, `mountRoot`, `force` and `host` are gone, and `openClaimDir` no longer reads the mount table (`fstype`, `mountinfo`). The package no longer depends on the `disk` SDK. The internals entry drops the mount-token, delegation and Daytona helpers. `localPlace` and its run-file reads stay.

Upgrading: open a run with `openDurableRun(ref, { ...localRun(dir), ... })` or `pi-durable-disk run --dir DIR`. To run on an Archil disk or in a remote box, use agentrun-serve.
