packages: @parcha/agentrun-serve, @parcha/agentrun-kernel
kind: breaking
---
On the runner, a learned workflow node that names a tier (`fast`, `strong`) now runs on the host's model of that tier (`AGENT_MODEL_FAST`, `AGENT_MODEL_STRONG`) instead of the run's own model. Its requests take the run's one route and stay under the run's cap, and each is booked at its own model's price. A tier the host names no model of still runs on the run's own model. A tier whose model can't be reached fails the workflow call and names why; it never runs on another model. This holds on every harness: pi, Claude Agent, Codex and OpenCode. On a CLI harness the tier's requests go through a proxy of their own beside the CLI session's, never through the CLI. A tier's model key saved in Settings → Model keys is opened for that tier's requests alone. It never goes into a tool's environment. A tier whose model has the same id as the run's model is still held and booked at the tier's own price. `AdapterSession.port` and the run ledger's `models` take an optional `tier`. The kernel's `ModelRequest`, `ModelProxyOptions` and in-flight records carry an optional `route`, and the cap's `modelOf(id, route)` prices a request by model and route.
Who breaks: a host that already sets `AGENT_MODEL_FAST` or `AGENT_MODEL_STRONG` changes with no action. Its learned workflows' nodes of that tier now run on that model and at its price, and when that model can't be reached the learned_workflow call fails where it used to run on the run's own model.
Upgrading: a host whose `AGENT_MODEL_FAST` or `AGENT_MODEL_STRONG` names a model it can't reach should unset it or make the model reachable; learned tier nodes now run on it.
