When serve lets a run's claim go (the run ends, is stopped, or parks), it now releases every cloud browser that carries the run's labels and the claim's epoch and that nothing the run holds names: not a session's browser by id, and not a browser whose session tag a held, not yet created session still owns. Before, a browser one create of a request made and then lost (its reply lost, its recovery keeping it because an older browser was answered) ran unheld until the vendor ended it, up to 6 hours on Browserbase and about 72 hours on Kernel: the janitor refuses vendor-lifetime providers, and a later claim's sweep releases only lower epochs. A browser another run made, or a later epoch's, is never touched.

What the run holds is read after the vendor's list answers, and it counts every browser the run's custody held in that process, released or not: a browser the vendor still lists a moment after its own release is billed by its own record and never charged again. A browser whose create the process still has in flight is left to that create and named.

Each browser released this way is charged on the run from the time its vendor listing says it was made, through the same booking every other browser charge takes, and the run's timeline and root record say so: `AgentRun: Released 1 browser a create race left running (<id>); this run did not hold it, and its time is in the run's cost.` A browser the release could not end is named too, as running to its vendor's lifetime. When a session's release by its tag ends such a browser beside the session's own, it is charged there under the same key (`unheld:<id>`), so it is charged once whichever release ends it, and a reopen books that charge once.

`@parcha/agentrun-computer` adds `releaseUnheld(provider, run, epoch, held)`, which lists the run's computers and releases each of that epoch the `held` predicate (sync or async, asked after the list) refuses, and `ComputerInfo.createdAt`, which the Browserbase and Kernel listings now fill. Its README also names a gap it leaves: a create's lookup that answers a lost create's browser while a newer one runs, which that create's last read then releases; the lookup's holder loses one call and its page state, as its next call finds the browser ended and opens a fresh one. `@parcha/pi-browser` adds the `onRaceReleased` option, called with the ids a release by a session's tag ended besides that session's own.
