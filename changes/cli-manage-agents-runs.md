`npx @parcha/agentrun` manages agents and runs from the terminal: `agents list|get|create|update`, `runs start|get|list|message|stop|cancel`, `triggers ...`, `usage`, `stats` and a command for every other operation the server's OpenAPI document offers (an operation the server turns off has none), plus `api METHOD PATH` for any route. `npx @parcha/agentrun help` lists them and `<command> --help` gives a command's arguments. Path parameters are positional, query parameters and a body's top-level scalar fields are flags (`--max-cost-usd 2`), and `--body JSON|@FILE|-` gives the whole body, its fields under the flags. The response's JSON goes to stdout (indented on a terminal, one line when piped) and an error's to stderr; exit codes are 0 ok, 1 the server refused, 2 bad usage, 3 the server cannot be reached, 4 no token or the token refused. A command whose body carries a secret (`tool-keys save`, `mcp-servers save|preview`) takes its body only from stdin or a file.
The server and token come from `--base-url`, else `AGENTRUN_BASE_URL` and `AGENTRUN_API_KEY`, else `base_url` and `api_key` in `$XDG_CONFIG_HOME/agentrun/config.json`, else the server started on this machine with the same `--data` (default `~/.agentrun`). The token is never a flag and never printed, and the local server's token goes to that server only. With no positional argument the command still starts the server, and `import` and `reset-password` are still the server's.
`agentrun-serve` writes `DIR/.server.json` (`{base_url, pid, token_file}`, mode 0600, never the token) once it listens and removes it on a clean exit; a file whose server is gone is reported as such, exit 3. The command table is generated from the server's document by `node scripts/generate-clients.mjs`, and `--check` fails when the committed table differs.
