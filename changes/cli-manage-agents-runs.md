`npx @parcha/agentrun` manages agents and runs from the terminal: `agents list|get|create|update`, `runs start|get|list|message|stop|cancel|raise-cap`, `triggers ...`, `usage`, `stats` and a command for every other operation the server's OpenAPI document offers, plus `api METHOD PATH [--header 'NAME: VALUE']` for any route. An operation the server turns off has no command, and neither has `learning approve`, which takes the owner's password session in the console and refuses every token. `npx @parcha/agentrun help` lists the commands and `<command> --help` gives a command's arguments. Path parameters are positional, each encoded whole (`learning read AGENT skills/find-policies/SKILL.md`) except a file's path, which keeps its slashes (`home read AGENT notes/a.md`); query parameters, header parameters (`--idempotency-key`, `--if-match`) and a JSON body's top-level scalar fields are flags (`--max-cost-usd 2`); `--body JSON|@FILE|-` gives the whole body, its fields under the flags, and `--body-type TYPE` sends a body of another type the route takes as it is (`files create --path notes.txt --body @notes.txt --body-type text/plain`). A JSON body with no flags goes byte for byte. The response's JSON goes to stdout (indented on a terminal), a file's bytes exactly as the server sent them, and an error's JSON to stderr; exit codes are 0 ok, 1 the server refused, 2 bad usage, 3 the server cannot be reached, 4 no token or the token refused. A command whose body carries a secret (`tool-keys save`, `mcp-servers save|preview`, and `api` on any path that leads to one) takes its body only from stdin or a file.
The server and token come from `--base-url`, else `AGENTRUN_BASE_URL` and `AGENTRUN_API_KEY`, else `base_url` and `api_key` in `$XDG_CONFIG_HOME/agentrun/config.json`, else the server started on this machine with the same `--data` (default `~/.agentrun`). The token is never a flag and never printed, a key that is not a valid header value is refused before any request, and the local server's token goes to that server only. The local token is read from `DIR/.token` alone, and the config file, `DIR/.server.json` and `DIR/.token` are used only when they are regular files of the user's own with no group or other permission (exit 4 otherwise). `api` refuses a PATH with a `.` or `..` segment, plain or encoded, or an empty one. A reader that closes stdout early (`| head`) ends the command quietly. With no positional argument the command still starts the server, and `import` and `reset-password` are still the server's.
`agentrun-serve` writes `DIR/.server.json` (`{base_url, pid, token_file}`, mode 0600, never the token; `token_file` is absent when the token came from `AGENTRUN_TOKEN`) once it listens and removes it on a clean stop, before it lets go of the data directory and only while the file still names it, so a server started next on that directory keeps its own; a file whose server is gone is reported as such, exit 3. The command table is generated from the server's document by `node scripts/generate-clients.mjs`, with names in `scripts/clients/resources.json`; its header hashes only what the table is made of, and `--check` fails when the committed table differs.
