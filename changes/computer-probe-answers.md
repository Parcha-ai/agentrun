Network none, read from inside a computer, now holds when nothing answers within 10 s: `computerd probe` counts a target reached only when bytes come back from it, not when a TCP connection is accepted. A target is `host:port`, tried over TCP, or `host:port/udp`, sent a DNS query over UDP. Each TCP target gets a request by its port (443 a TLS ClientHello, with no server name for an IP address; 80 an HTTP `HEAD`; 53 a DNS query; any other port an HTTP `HEAD`); a UDP target gets one DNS query. Each has 10 s to connect and 10 s to answer, and at most 4 KiB is read. Any byte back is an answer: a ServerHello, a TLS alert, an HTTP status line, a DNS response with the query's id, a banner, or bytes of no expected protocol. UDP has no accept, so a UDP target with no reply is refused. The probe's JSON line keeps `reached` (now the targets that answered) and adds `accepted` (a connection accepted, then nothing back) and `results` (each target's protocol, outcome, bytes and detail).
- A provider refuses network none only on an answer. A connection accepted with nothing back is recorded, never refused and never hidden: `create` now returns `CreatedComputer`, a `ComputerRef` with optional `notes`, and `attach`'s `AttachedComputer` gains `notes`, such as `network: none; accepted with no answer (no bytes came back): 1.1.1.1:443`. This is for vendors whose firewall accepts every outbound connection and then closes a denied one (E2B documents this). The conformance report gains `computerNotes` (`[{ computer, note }]`, absent when empty), every note a create returned, and the text report prints each as `note <computer>: <words>` above the verdict.
- What the rule can and cannot detect: it detects a TCP or UDP path that carries bytes back within 10 s on a probed host:port. It cannot detect a one-way leak, a port that is not probed, or a client-first server that silently drops what it is sent (such a TCP target reads `accepted`; only an operator's own `probeTargets` can meet one).
- The Modal provider is the one that probes today. Its default targets add DNS over UDP to `1.1.1.1:53/udp` and `[2606:4700:4700::1111]:53/udp`, its `probeTargets` option takes `host:port/udp`, and a probe report with no `accepted` list is refused in words. Its 30 s bound on the probe covers the probe's longest run (20 s). Docker and Daytona read their network back from the vendor, and a probe there is refused outright, so their results do not change.
