An uploaded template package's name is now its workspace's own. On an API-only server, two workspaces (the `AgentRun-Workspace` header) can each upload a package of the same name, and each gets `201` and its own package under the same id, `upload:<name>`. Before, the second upload was `409 name_taken`, which also told that workspace another one held the name. Each workspace's read, list, apply, reimport and delete reaches its own package alone, so a workspace's delete never removes another's. An agent's purge removes the upload it was applied from in the agent's workspace alone. A request with no workspace keeps the packages of none: on a server with no workspaces nothing changes, and on an API-only server a request with no header no longer sees, replaces or is refused by a workspace's package.
Upgrading: Postgres migration `0035` and SQLite version 19 key `imported_templates` by workspace and id. Each row keeps the workspace it already had, and a row with none stays in none, still one package a name there. Migration `0035` drops the key on the id alone, so it raises the runner floor to 35: drain and stop runners of earlier builds before this build's server starts. On SQLite a runner of an earlier build refuses the store at its start, or stops at its next schema read. During a rolling deploy, a server of an earlier build that is still serving fails the uploads it takes once `0035` is applied.
