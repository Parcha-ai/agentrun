A key no longer leaves the server, or a suggested agent's client, for a base URL with a user or password, a query or a fragment. The refusal names the URL's origin at most, never its password or query.
- A suggested agent's client (TypeScript, JavaScript and Python) refuses an `AGENTRUN_BASE_URL` with a user, a password, a query or a fragment before it sends anything, as AgentRun's SDK does. Before, it sent the request, and a failed fetch printed the whole URL, password included. It also follows no redirect: a start or a read answered with one throws, so the key goes to `AGENTRUN_BASE_URL` alone. Before, Python's urllib carried the key to any host a redirect named, http included. A client file written before this release still takes such an address and follows redirects.
- A workflow's Jev decisions on TypeSafe's route take `TYPESAFE_BASE_URL` by the same rule as the key check, and building a run's decision providers throws by the variable's name on one it refuses. Before, TypeSafe's SDK read the variable itself and sent `TYPESAFE_API_KEY` there, http included.
- A tool key's check sends no key to a `BROWSERBASE_BASE_URL`, `KERNEL_BASE_URL` or `TYPESAFE_BASE_URL` that `httpsBase` refuses, or to an `ANTHROPIC_BASE_URL` the model path's gateway rule refuses. The key is kept as not checked, and the reason names the variable. An `ANTHROPIC_BASE_URL` ending in `/v1` is checked at `<base>/v1/models`, where runs send, not at `<base>/v1/v1/models`.
- A saved sign-in's Browserbase and Kernel calls refuse a `BROWSERBASE_BASE_URL` or `KERNEL_BASE_URL` that `httpsBase` refuses, naming the variable, before any call.
- A browser session's attach refuses a `BROWSERBASE_CONNECT_BASE_URL` that is not https or wss, or has a user, a password, a query or a fragment, naming the variable. Before, an unparsable one quietly fell back to Browserbase's own host, and any other went into use.
- The OTLP trace export refuses an `OTEL_EXPORTER_OTLP_ENDPOINT` or `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` with a user, a password, a query or a fragment: no exporter is built on it, nothing is sent, and the server and its runs carry on. The runner's start says once that tracing is off and why, naming the variable and the endpoint's origin alone (`[otel] tracing is off: OTEL_EXPORTER_OTLP_TRACES_ENDPOINT takes no user or password, since the key goes to it: https://collector.example:4318`). http stays allowed there, as OTLP allows it, so a local collector keeps working. `/v1/traces` is added to the general endpoint's normalized form, so a bare trailing `?` or `#` no longer puts it in a query; a traces endpoint, once checked, is used as given.
- `agentrun native connect` refuses a server URL (`--url`, `AGENTRUN_BASE_URL`, `AGENTRUN_URL` or the recorded one) with a user, a password, a query or a fragment, naming where it came from, before it sends the server's token.
- `@parcha/agentrun-computer` exports `httpsBase`, and `keyBase`, the same rule over a list of schemes.
- Breaking: the key check, the sign-in calls and Jev's TypeSafe route now take `BROWSERBASE_BASE_URL`, `KERNEL_BASE_URL` and `TYPESAFE_BASE_URL` only as https URLs, and `BROWSERBASE_CONNECT_BASE_URL` only as https or wss, with no user, password, query or fragment; the OTLP endpoints and native connect's server URL refuse a user, password, query or fragment; a suggested agent's client refuses any redirect. An http gateway set in one of the first four used to be accepted; point it at https, and move a credential in an OTLP endpoint to `OTEL_EXPORTER_OTLP_HEADERS`.
- Breaking: beta.59 traces to an OTLP endpoint with a user, a password, a query or a fragment, with those parts cut from its log lines; from this release tracing is off for such an endpoint, and the runner's log says why as it starts.
