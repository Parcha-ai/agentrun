A run started while another run of its agent is still keeping a follow-up's or a grade's correction now starts from that correction. Before, the run's learning was read when it was started: a host that launched the next run as soon as the corrected run read `completed` (its compile turn can still run for minutes after that) got a run with nothing learned, though the correction merged a moment later. Now the new run waits, at any claim before its first turn, for those rounds to end, then reads its agent's learning again. Only rounds already going count: a run holding a person's words (a follow-up, a grade's words, or a message during its first job) whose learning step runs after its job ended. A run that is queued or waiting on a person never delays a new run. The wait lasts at most 3 minutes by default, and a runner sets its own limit with `AGENTRUN_LEARNING_ROUND_WAIT_MS` (`0` for no wait). When the limit passes, the run starts from its agent's learning as it is then and is never refused. A stop or cancel asked during the wait ends it at once. A run claimed again after its first turn keeps the start it ran on. A run started with no such round open starts as before. `GET /v2/runs/{run_id}/learning` also gives `seed_failed` (why a run started with nothing learned: `unreadable`, `not_copied` or `other_disk`; null when its learning was read), `seed_waited` (`ended` when the rounds it waited on ended, `timed_out` when the limit passed first; null when it waited on none) and `learned_chars` (the length of the # Learned text it was given).
