The console treats secrets as write-only, the same way on every page that holds one. Each secret (a model or tool key's field, an MCP server's credential) is one row: what it is (the key's own name, or "Bearer token"; never its internal name), Set or Missing, where it comes from ("Set in the environment", greyed, with nothing to paste over it; "Pasted here"; "From sign-in"), and when it last changed. Paste, Replace and Remove appear only where the server's session read says `secrets_writable` (the owner's password session; on a server with no accounts, the console session the launcher opened on loopback), never on a token alone. Otherwise the page says once why: "Sign in with your password to change secrets.", on a server with no accounts, "This server has no accounts: set secrets in its environment, or turn accounts on to change them here."; or, in a browser on the API token alone, "Open the console from the server's link to change secrets."; and the model-key card offers no key to paste, and an MCP server's form offers no bearer token, header values or OAuth client secret. No value is ever shown. An MCP server's credential is one row (its bearer token, its headers' values, or its sign-in); a sign-in's has no paste, and its Sign in is offered only where secrets may be changed.
