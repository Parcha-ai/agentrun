`curl -fsSL https://agentrun.ai/install | sh -s -- --tailscale` and `agentrun service install --tailscale` also serve AgentRun over HTTPS on your own Tailscale network only, at the `https://<machine>.<tailnet>.ts.net` address `tailscale status --json` names. They run `tailscale serve --bg --https=443` to AgentRun's port 7340, where the server keeps listening on loopback only, and they start it with that address as `AGENTRUN_PUBLIC_URL`, so its first visit asks for the setup code in the log. They never use Funnel. Where Funnel is on for that address, or the address already serves something else, they change nothing and say why.
- With Tailscale missing, not running, logged out or without HTTPS certificates, AgentRun installs and starts anyway. The installer prints the steps (the download link for this OS, `tailscale up`) and the command to run again, and exits 0. It never installs Tailscale, logs in or runs sudo. On Linux, Tailscale refuses `tailscale serve` to a user who is neither root nor its operator; the installer then prints the one `sudo tailscale set --operator=$USER` line.
- `agentrun service uninstall`, or `--no-tailscale` on either command, runs `tailscale serve --https=443 off` only while the entry still points at AgentRun, and touches no other serve setting. An install with neither flag keeps AgentRun on the tailnet if it was there.
