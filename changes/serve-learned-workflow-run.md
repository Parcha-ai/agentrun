A run whose agent learned a workflow runs it as one tool, `learned_workflow {name, input}`, on pi, claude-agent and codex, with no edit of the agent's definition. Only a workflow whose `README.md` sets no status (or `active`) is the run's: one held for its owner's OK, or retired, is not. The tool's description names each workflow with its README's line, 8 KiB of lines in all, and the run's pin names the ones it gets (`workflows`), each kept whole in the run's directory, and the ones over that budget or holding a secret (`workflows_left_out`); the list is fixed when the run starts, so an approval or a retire takes effect at the next run, and a README whose front matter does not read one way is not read. A call checks the workflow again against the agent's own tools as its run resolves them and refuses one whose call node names a tool the agent was not granted, whose model node names any tool (the merge refuses that too), that holds a node its runner cannot run (a judge, pick or sift node needs a decision provider a run is not given; the merge refuses that too), or that holds a code node or a shell or executor call, before any of its nodes runs. It runs with the workflow DSL: each model node on the run's own model, in a session of its own with no tool of its own, and each call node `via: "tool"` on a tool the agent has, its paid requests booked under the call. Its model requests are the run's, under its cap and on its timeline as `learned_workflow` side requests (on claude-agent and codex against one total with the harness's own, and on the harness's own route: on OpenRouter alone, through OpenRouter; claude-agent through the operator's own gateway at `ANTHROPIC_BASE_URL` is offered no learned workflow, nor is any harness at an origin its requests could not follow, and its pin says why in `workflows_off`; opencode takes codex's route), and a call a crash cut off is never run again.
