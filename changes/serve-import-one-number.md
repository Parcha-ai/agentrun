An imported run's page and its stored metrics give one number, and every subagent request counts once. Each of a run's subagents' requests is written into its transcript as a request with no answer of its own there, its usage and cost with it, so the timeline's usage row, the run's cost and its metrics count the same requests and tokens; the timeline shows no extra row. A session written in several files under one id (a Codex thread resumed later, a Claude Code session resumed in another directory and copied into that project's folder) is one run, its files merged in order through the same record count; the import used to keep only the first file while the dry run counted them all. Each subagent's file counts once: a Codex child in its thread's run (it used to count once per file of the thread), a Claude Code subagent with the session file beside its folder. A record a file copies moves no time at work, whatever its type (a copied system or meta record used to add its gaps again), and a file holding only copies adds nothing to its session. The import reads a project's files in one order, Claude Code's by folder and oldest written first, so the first file holding a copied record keeps it whichever way the import is run. A session's files sit in the project of its first file by start. A subagent tied to no session brings its own subagents' usage into the summary's totals. Merged, a session's cost is counted once (Claude Code writes a running total, which a moved copy carries on), its turns follow the order its files ran, and its state and answer are those of the file that ended last. A subagent's failed request keeps its known zero tokens: a `REQUEST_COST` mark with `failed: true` has its counts taken as they are, as a failed answer's are.
