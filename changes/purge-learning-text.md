A run's purge (`DELETE /v2/runs/{run_id}`) now takes the run's text out of its agent's learning, history and all: every commit of the learning's main is rebuilt without the feedback lines the run's merges added to `corrections.md` and without its merges' reasons (each merge kept, empty of its text), each snapshot rebuilt, and one commit by the host on top marks `.agentrun/purged/<run>`, so no round of the run merges again and a `DELETE` sent again does nothing. No byte of the old history is kept: the local folder moves main by compare and swap, removes every other ref, expires its reflog and prunes; code.storage builds the new history in the agent's next repository generation, moves the agent to it and deletes the old repository, and a purge cut short leaves the live repository untouched for the next one to finish. What it costs the owner: every commit id of the agent's learning changes (a promotion record's commit id then names no commit, and its champion is read at main); on code.storage about 0.3 s a commit (the local folder is fast), the agent's learning waiting meanwhile; a run of the agent in flight merges nothing, as after a reset; every other run's history and diffs are kept. The learning's history reads (`GET /v2/agents/{agent_id}/learning`, its `/log`, a workflow's `/revisions`, and a champion read by its digest in `/promotions`) no longer serve the purged run's merges; a log page's cursor read before the purge starts again at main's first item. It covers the agent's one learning store, local or on code.storage. A second `DELETE` of a purged run runs it again, so a run purged before this release loses its text the same way; it is `204` with no body as before, and `503 unavailable` while the learning store can't be written.
