A saved sign-in is never forgotten while a run it was handed is still going: `DELETE /v2/agents/{id}/sign-ins/{key}` is `409 sign_in_held` with `details.handed_to` naming the run, its lease let go or not (a run waiting for its person, or one whose process went more than 30 minutes ago). Before, forgetting it then removed the pointer, so a restarted server could no longer read it back, and a run that had repeated it served it in its timeline and answer.
- A launch keeps that it handed a run the sign-in under the same lock forget asks under, so a forget never slips between the two.
- A forgotten pointer is kept sealed in the agent's sign-ins file, the newest 32 per agent, only to cut it: a run that ended before the forget, or was opened again on a new sign-in since, still has it cut from its timeline, answer and error after a restart. It is never listed, served or handed to a run. A run whose marked pointer can't be read back (it does not open under this server's seal key, live or forgotten, or it was dropped past the 32 kept; for a run handed several, once any was dropped) is hidden or withheld, as one whose sign-in does not open is.
- A run's error is cut of the values its rows and answer are cut of, in its view and in the run lists, and kept cut in its `serve.json`.
- A run list's row for an ended run the server has not read serves its error and review cut of the agent's sign-in's pointer, and withholds them, saying why, when the run was handed a sign-in (its serve.json's mark) that can't be read back here. A run's view serves its review's reason cut, as its error is, and withholds it while the run is hidden, as a list row does.
- A run still going whose `serve.json` is there but can't be read or parsed, of an agent whose revision grants the browser, is not taken up: it is stopped and ends failed saying why, and its rows are not read, since which browser it had and whether it was handed the sign-in went with that file.
- A hidden run's files are refused as its graph is: `GET /runs/{id}/files` and a file's read answer `403 forbidden` while the server can't read the browser sign-in the run was handed, since a page it saved signed in holds what it saw.
