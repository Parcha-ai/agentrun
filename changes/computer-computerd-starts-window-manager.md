computerd starts a desktop's window manager itself, and Daytona gives a desktop again, on `connect: "dial"`. `init --window-manager` (with `DISPLAY`) has computerd start xfwm4 once the display answers, as the computer's user, in a network namespace root makes, on a session bus of its own; hello's new optional `windowManager` (`starting`, `running`, or `ended` with why and the manager's last stderr lines) says how it went. A hosted provider passes the flag only for a desktop whose host's facts say `windowManager` (E2B, Fly Machines, Cloudflare, Modal, Agent37, Daytona; Docker's desktop runs none), and create waits on the fact; an ended manager fails create in its words. Against a computerd whose hello has no `windowManager`, the client starts the manager through `process.start`, as before. No user namespace is needed any more, so a host that refuses the tool user one (Daytona's Sysbox under `kernel.apparmor_restrict_unprivileged_userns=1`) runs the manager too. A Daytona desktop is made from the operator's snapshot of box/Dockerfile over dial; on `connect: "exec"` the constructor refuses `kind: "desktop"` in words that say why.
