Template packages: one folder that makes a working agent, applied by one call. A package is `agent.md` (its YAML front matter is the whole manifest, its body the agent's instructions), `skills/<name>/SKILL.md` in the Agent Skills format, `rules/*.md` (shipped beside each skill's SKILL.md) and `evals/<case>/` in the plugin-eval layout (`prompt.md`, `graders/*.md`). The manifest names the package (`name`, the agent's `display_name`, a SemVer `version`, `description`, `license`, `author`, `repository`), the harnesses it prefers, its model as a tier with a preferred model, its `effort`, `tools`, the MCP servers and tools it uses (`mcp: [{server, tools, required?}]`), typed `parameters`, the `secrets` it needs by name, its `budget` (required with triggers), `learning`, `triggers` (each named), its `output` schema and `checks`. `GET /v2/templates` lists the packages the server ships, and `POST /v2/templates/{name}/apply` with `{parameters, overrides?: {model}}` makes the package's agent and its triggers through the same code as `POST /v2/agents` and `POST /v2/triggers`, all or nothing: parameters that do not check are a 422, a missing secret or required MCP server is `409 agent_not_runnable` with nothing made, an MCP server the package can do without is skipped with a warning, one the server has saved has the package's tools of it granted and set to allow, and a trigger the server refuses deletes the triggers made before it and the agent. The agent's model is the package's preferred one when the server runs it, else the server's model for the tier (fast `AGENT_MODEL_FAST`, balanced `AGENT_MODEL`, strong `AGENT_MODEL_STRONG`), and `overrides.model` wins. The agent records `package: {name, version, source, ref, sha, parameters}`, shown on `GET /v2/agents/{id}` and kept by an edit; a package's version is never `definition.version`, the revision number. The server checks every package it ships at its start, and a broken one stops the start. The CLI gains `agentrun template list`, `agentrun template apply` and `agentrun template validate DIR`, which runs the server's own check on a folder.
- The first package is `code-review`: a code review agent for one GitHub repository (`parameters.repo`), named `Code review: <repo>`, on pi, with the fast tier and `openrouter/particle-ai/particle-1` preferred, low effort, each run capped at $0.50, learning off. Its review skill proves each finding against the code and answers with findings JSON (`findings.schema.json`), and, when its tools are a GitHub MCP server's instead of a shell, posts one review with inline comments, never an approval. It uses six tools of a GitHub MCP server named `github` where the server has one saved, and none where it does not. It has no triggers yet.
- pi-durable-agent: a revision may keep `package`, a JSON object its host writes, as part of what makes it that revision; and the store gains `deleteAgent(id)`, which undoes a create: it removes an agent with no runs that was never archived, with its revisions, and refuses any other.
