A runner in its own process (`agentrun-serve runner`, beside a server started with `--no-runner`) now reaches an MCP server on loopback when its operator set `AGENTRUN_MCP_ALLOW_LOOPBACK=1` for it as for the server, as the runner inside the server's process already did. Before, every call such a runner made to that server was refused as a private address, nothing sent.
The runner takes the opt-in only when it shares the server's loopback. A server started with the variable leaves a note in its data directory (`mcp-local-install.json`: its own addresses and, on Linux, its booted kernel and network namespace; elsewhere its host name). The runner reads the note at each claim and reaches loopback only when the note is there and names its own loopback. It never reaches the server's own ports. A runner without the variable, one that sets `AGENTRUN_RUNNER_LIVE_HOST` (on another host), one in another container on a shared volume, and one on another machine stay refused. A server started without the variable removes the note. Each runner says on stderr, once per change, whether it takes the opt-in.
On a server started without the variable, a run of a revision saved before pins (so pinned at its first run) whose MCP server is on loopback was refused (409) with "save the agent again to pin it", though a save is refused too. The 409 now names the cause: `its server <name> can't be listed here to pin it: 127.0.0.1 is this machine; set AGENTRUN_MCP_ALLOW_LOOPBACK=1 when starting the server, ...`. With the variable set on the server, such a revision is pinned at its first run and runs, as before.
