`DaytonaProvider`, the second computer provider, over Daytona's v0 REST API with `fetch` and no new dependency. A snapshot is the computer's image; `image: "default"` sends none, so Daytona uses its default snapshot. Capabilities: kind `linux`, daemon `child` (init is a session command of Daytona's toolbox), groups `exec`, `files` and `processes`, lifetime `vendor` (the sandbox's TTL), `maxLifetimeMs` 30 days, network `none`, `open` or one allowlist (up to 100 domains on ports 80 and 443, or 10 IPv4 CIDRs), and `release` `["stop", "delete"]`. `create` takes `autoStopMinutes` and `autoDeleteMinutes`, pushes `computerd` in through the toolbox, installs it root-owned at a path no other user can change, and starts `computerd init --user 1000:1000` as root; init drops itself to 1000:1000 with no groups, no capabilities and `no_new_privs` on every thread. `connect` runs `computerd stdio` in a session of its own; init and the bridge refuse a daemon whose path a user other than root could have changed. The drift check reads the sandbox and the daemon back at create and attach. `release` waits until Daytona reads the computer gone or stopped. Four live runs reached the default snapshot; the last passed Core 53/53.
- The sandbox is the only boundary: a program in a Daytona computer can become root through Daytona's toolbox, which listens on port 2280 with no authentication and runs commands as a user with passwordless `sudo` in the default snapshot. The daemon's user is hygiene, and `networkBlockAll` limits egress only.
- `dist/conformance/daytona.js` runs the conformance suite on Daytona, reading `COMPUTER_DAYTONA_API_KEY` and the other `COMPUTER_DAYTONA_*` settings by name, never `DAYTONA_API_KEY`; its computers stop after 30 idle minutes and a stop deletes. `dist/conformance/daytona-sweep.js --before <file>` and `--after <file>` delete the labelled sandboxes a run left behind.
- `ComputerCapabilities` gains `stopDeletes` (a stop ends in deletion; Core `provider.stop` holds a provider to it, and Full `provider.janitor` skips) and `allow`; `ReadBackSpec` gains `snapshot`; results gain a `daytona` error code. The conformance CLI takes a module's `conformanceImage()` when `--image` names none and prints its `conformanceNotes`.
