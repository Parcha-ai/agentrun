`exportStore(source, out, options)` in `@parcha/agentrun-pi/durable`: the one exporter of a run's store for a reader who is not the run. It writes a NEW SQLite file (pi-durable's own schema, so the readers and SQL over a run store work on it) holding only what an allowlist keeps: the documents whose kind is on `options.exportable.kinds` (a host's list, such as `@parcha/pi-durable-agent`'s `EXPORTABLE_KINDS` with its `projectForExport`) or on `EXPORT_KINDS` (the DSL's own kinds a run page reads), as whole values per revision, and the conversations and entries a timeline reads, with each image moved to a `blobs` row. Every other kind is dropped; the saved sign-in, lease, binding and alias kinds are never kept, even when a caller lists them. Every kept value is scanned with `@parcha/agentrun-pi/credentials` and the caller's exact secret values, and a hit refuses the export naming the kind, key and path, never the value. The file is vacuumed, closed with no `-wal`, `-shm` or `-journal` beside it, and at most 10 MB (`ExportRefused`, code `too_large`, above that). The source is opened read-only in one read transaction and never changed.
