`GET /v2/capabilities` names each harness's default model: `harnesses[].default_model`, the model this server runs for that harness when a definition names none (`provider/model-id`), or null where it runs none (the harness does not run here, or no default model here runs on it; claude-agent never takes a gateway's model). It is the model a save and a run resolve, through one function (`harnessModel`, which `blockersOf` now calls too), so capabilities and saves cannot disagree. The console reads it: the editor's Model field and the agent page offer each harness the default the server names for it, so a codex agent behind a gateway is offered the gateway's default, and a claude-agent agent is told to choose a model. A server that does not name them keeps the console's earlier rule, pi alone. Capabilities also name the routing prefix this server puts before a gateway's model ids, `models.route_prefix` (`agent-model`; null with no gateway), and the console takes exactly that off a model's label, never a first segment read off the id, so a gateway id with no routing prefix keeps its provider. The exported `capabilities()` helper resolves each harness's offer itself and returns a promise of the document the route serves, `default_model` included, so a direct caller's document passes the published schema. The published document's `Capabilities.models.source` takes on `gateway` and `providers` (marked `models/2`): it held only the contract's `managed`, `chatgpt`, `env` and `faux`, so every answer of a server without `--faux` failed the schema the server publishes.
