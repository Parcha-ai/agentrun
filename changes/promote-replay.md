A learned workflow's new draft or revision now serves first only after it is replayed on the agent's last 20 graded inputs and its accuracy there is within 2 points of the agent's on the same inputs. Grade a finished run with `PUT /runs/{id}/grade` (`{"correct": true | false, "expected"?: {...}, "source"?: "feedback" | "eval"}`); the grades the agent's runs carry are the inputs a replay uses. A replay starts one run per graded input the workflow fits, with `metrics.path` `replay` and `metrics.replay: {of, outcome}`, at the workflow's cost, and meanwhile the revision promoted last (the champion) keeps serving, or the agent when none was promoted yet. A replayed input the workflow hands back (it escalated: an escalate node or a guard) counts as the agent's recorded answer for it, never as a failure; one it failed on (a step failed) is no evidence and is left out of the score, and a replay with fewer than 5 inputs answered or handed back holds the revision. A replay run has the agent's tool credentials as a served run does: an MCP server's `per_run` credential is the one the claimed run was handed, sealed for the replay alone. A replay never sends a write: each tool is a read or a write (an MCP tool by its server's annotations, read only when `readOnlyHint` is true and `destructiveHint` is not; the built-ins `web_fetch`, `web_search`, `pdf_pages` and `llm` read; anything else writes). A read runs live once a replay, through a cache seeded from the graded run's recorded calls on the same tool and arguments. A write is answered from the graded run's recording when a call there has the same tool and arguments, else that input is skipped (`metrics.replay.outcome` `skipped_write`, with `skipped: {tool, step}`), neither right, wrong nor failed; a replay whose every input was skipped holds the revision, its reason saying it needs a write the recording doesn't have. A replay run runs only while its revision replays: a superseded, promoted or held revision's replay run, or one whose claim cannot lay its revision, ends failed without asking the agent. A replay's answer is right when it matches the grade's `expected` fields, or when it says what the graded answer said and that answer was right. With fewer than 5 graded inputs it fits, the workflow serves on its passing dry run, as before, and its record says so.
`GET /agents/{id}/learning/promotions` lists each decision as `{workflow, digest, at, decided: "promote" | "hold" | "replaying" | "superseded", source: "replay" | "dry_run" | "refit" | "graded", reason, replay?: {of, n, agree, agent_acc, wf_acc, delta, handed_back, skipped_write}, runs?, refit?: {from, guards: [{node, was, threshold, fit?}]}, commit?, superseded_by?}` (`commit`: the learning commit holding that revision's workflow.json), and `serving: [{workflow, digest, replaying}]`: which revision serves and which one replays. A held revision never serves; the champion keeps serving, also on inputs the folder's revision no longer takes (a new required field). One revision replays at a time: the newest revision (the one the learning folder's main holds; a run pinned to an older commit never counts as newer) supersedes the one replaying, whose replay runs are cancelled (what they spent stays on them) and whose record says `superseded` with `superseded_by`. A wrong served grade asks for a revision and never stops the champion. Escalation never holds a workflow. Two things do: the money rule, and graded runs it served more than 2 points under the agent's graded runs by hand, checked once per 20 new graded runs it served (each grade carries a sequence number the check counts from, so the check keeps coming once the 500 kept grades are full).
At that check, and when a replay holds, each guarded step's threshold is refit to the cheapest one that keeps the replay's accuracy within the bar (a hand-back its guard made, whose answer nobody read, counts wrong at a threshold that would have let it through, so a threshold never comes down on no evidence), and a `both` guard's `fit` is refit (a logistic over its self and Jev reads) when it has 30 graded rows with 5 wrong. A refit that moves a threshold commits the workflow as a new revision, promoted on the rows it was fit on; its money-rule count starts over.
A run its learned workflow answered alone, on a CLI-shaped record, now reads its booked cost on `GET /runs/{id}` (it read `null`).
Breaking: a learned workflow draft that gives two steps one label (a child workflow's step read `parent/child`) is refused at learn time and before a call, as a saved workflow already was (`DUPLICATE_LABEL`): a label names one step, its guard's threshold, replay score and refit included.
