A new computer provider, `boat`: a Linux sandbox on a boat.dev sandbox (a Firecracker microVM with its own kernel, in boat's EU regions only; boat's docs say "You cannot pick a region"), over boat's REST API and SSH with no SDK. It takes `BOAT_API_KEY`, the name boat's own SDK reads, and loads from `@parcha/agentrun-computer/boat` or `providerFor("boat", { apiKey })`. A computer starts from boat's Ubuntu 24.04 base, `"ubuntu-24.04"`, a snapshot the account saved, or a share code. It is a sandbox only: no desktop and no Archil mount. boat's REST commands take no stdin, so the exec is SSH as boat's sudo user, each command and kill under `sudo -n --`, with the provider's own key and the sshd pinned by the sha256 of the host key boat answers. The pin is required: an answer with no host key this provider reads is refused before any connection, and an sshd showing another key is refused in the handshake, before a username is sent. The shared SSH exec gains `sudo`, a login's `hostKeyType` (the handshake asks for the pinned key's type alone, so an sshd holding several host keys shows the pinned one) and a TCP tunnel, which Morph now uses too. A create carries the request's name as its `Idempotency-Key` and the computer's whole lifetime as `ttlSeconds`, so boat's 3600 s default never applies, and extend moves it. Serve offers boat as a box once `AGENTRUN_BOXES` lists `boat` and the key is set, and the launcher holds `BOAT_API_KEY` with the other secrets. No live run has been made yet. These stay unverified until then: root's network namespace under sudo, the host key's form, the sshkey call at ready, a read in the middle of a delete, and label values byte for byte.
