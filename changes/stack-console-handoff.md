Build agents from a brief or the full template catalog using a remembered coding-agent dropdown or the API playground. Handoffs preserve complete template settings and prepared requests, and the server serves its matching setup skill. Imported GitHub templates retain their full package identity and reviewed commit across configuration, prompts and prepared requests, alongside publisher trust, pinned installation and visible provenance.
Setup, build, edit and run prompts read that skill from the selected server, so its instructions match the deployed build.
Development handoffs reach the same server's setup skill through Vite, and successful skill-file edits disable identical repeat saves while preserving later edits and revision guards.
Deleting learning or an agent's spend cap from an edit sends the API's explicit reset, including after switching between JSON and Form.

Template handoffs retain the owner-selected MCP server for each source and toolkit, including prepared API requests. Unread or ambiguous accounts wait for selection; a removed prepared account requires a fresh request instead of switching accounts. Agent edits preserve explicit model and tool-setting resets when switching between JSON and Form before saving.

Keep unfinished Playground requests, selected options, uploaded attachments and displayed responses when setup import refreshes the agent list, including a failed refresh that can be retried. Replacing the authenticated client resets cached console state immediately; signing out also discards the previous session's request. A selected agent removed or archived during refresh requires a fresh choice.
Template handoffs use the server's compiled parameter schema and shared input fields, retaining false, zero, scalar arrays, defaults and reviewed consent while rejecting unknown or lossy prepared values.
Complete JSON definition edits preserve removed fields through JSON/Form switches: deleting an unattended approval policy sends no override and restores the server’s asking default. Confirmed default resets become clean without allowing a duplicate revision request; failed edits keep their unsaved-change guard.

Editor tool, skill and workflow groups retain their accessible names and linked help, refusal and warning text.

Edit and run handoffs follow the loaded agent’s native or SDK binding. They direct changes to the original source or backend, without appending a managed-definition request; editable JSON cannot change that handoff identity. Managed requests keep their full prepared JSON and revision precondition. Prepared template requests retain the selected package model and reject choices no longer offered.

Copy confirmation and manual-copy fallback stay associated with the current prompt and coding-agent selection, including when clipboard responses arrive out of order.

After clearing an agent's default spend cap, the request is considered saved when the server omits the cleared cap. Repeated sends stay disabled until another setting changes.

Complete JSON edits now use supported reset values and explain settings that cannot be removed through this API. Saved-response comparison preserves real computer changes and blocks unchanged repeat saves after canonical readback.

Workflow and agentic edits now normalize fields from the requested definition, so changing a workflow into an agentic agent preserves its new instructions and model settings.
