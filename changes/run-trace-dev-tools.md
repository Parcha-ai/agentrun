A run's trace: `GET /v2/runs/{id}/trace` serves each model request that answered and each tool call of a run as one span, and the console's run page has a Dev tools tab that reads it. Use it to see where a run's time and money went and why a call failed.
- A span has its kind, its name (the model or the tool), when it started and ended, how it ended, and the span it ran under. A model request also has its tokens (input not read from cache, cache read, cache write, output, and thinking tokens where reported), and its cost. A tool call also has the head of its arguments and of its output, as the Timeline shows them, and what was charged under it (a browser session's time, a paid tool's fee), or that its tool has no price set.
- The trace says only what the run's record keeps, in `model_requests`: `priced` (each request has its cost), `tokens_only` (a workflow run: its model nodes' requests carry tokens and no cost, since the cost is booked for the run, and each of its decisions is a span with its own cost), or `not_recorded` (a CLI harness's record keeps no request, so the trace is its tool calls). A computer's own time is billed by its provider and is in no span. One read serves the run's first 2,000 spans and counts the rest in `dropped`.
- The Dev tools tab shows the run's totals, every request and call on one time axis and in one table (filter by kind or words, sort by duration, size or cost, zoom the axis), and a panel for the span you open: its tokens by line and the share read from cache, its cost, the request that called it and the calls it made, and a call's arguments and result. Its Breakdown view says what stands out (what failed, the slowest call, the most expensive request), where the time and the cost went, each request's input and cost in order, and the same by model and by tool. Export JSON saves the trace as served.
- The TypeScript client has `runs.trace(runId)`, the Python client the same operation, and the CLI `agentrun runs trace RUN_ID`.
