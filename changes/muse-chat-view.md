A recording can be opened as a phone chat of the agent's work: `chat.html?r=<id>&muse` is a different layout over the same events, in the viewer's own agentrun.ai look (its tokens, square corners, hairlines, flat cards, JetBrains Mono for labels and titles, orange the one accent), and without `&muse` a recording reads as before (a test pins the default view byte for byte). A square avatar at the top, one picture file the build ships beside the page (`muse-avatar.webp`), floats over the conversation with the agent's name (the host's `reference.label`, else the recording's title) and its state: "Waiting for you" when a hold is open, "Done" once the run delivered and the end of the conversation has been scrolled into view, else "is working". The header and the composer are transparent: the chat scrolls under them behind a soft blur and fade. The person's words are a hairline box under a "You" label, the agent's replies sit under its name with the files it names as chips, and its thinking and the steps between are folded and quiet. The browser is a card inline in the chat: the frame the steps ended on and a status line, "Your agent is driving the browser" (no button: the shipped browser viewer has none); a hold, read from the `browser.sessions` and `browser.handoff` rows alone, reads "Handed the browser over: <what was asked>" and then "Handed back · <outcome>". Where the run waited for a person to sign in, a "Secure Store" card marks it, from the browser's own `browser.profiles` document (the address it gains, then its verification; "Signed in · remembered" when it was already there). The host's artifact is a "What I remember" card (times as a fixed date, no file names or web addresses), read by decoding the recording's embedded `data:` page in the viewer itself, so it reads under a host whose policy allows `connect-src 'self'` only. No report page beside it, and every web address is shortened to its host.
