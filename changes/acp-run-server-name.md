Under a recipe that names AgentRun's MCP server per start (`ar` and 6 random hex digits: Cursor's, Antigravity's, any with the title tie), a run now keeps the name its first start minted and gives it again at each later start. Before, a resumed Cursor run asked the host's gate for every call of AgentRun's own tools: Cursor keeps, with its session, the name it was first given and titled the call under it, which the new start no longer spelled, so the title tie read it as another server's. A recipe's new `mcpConfigs` lists the MCP config files the agent reads (`~/path` in its HOME, any other path in its work directory; Cursor's: `~/.cursor/mcp.json` and `.cursor/mcp.json`). One that declares a server under the run's name has that name refused at the start: AgentRun's server gets a fresh name, kept from then on, the run gets a notice naming the file, and a call titled under the old name goes to the host's gate as that server's. The file is never edited. Owner recipes in serve take `mcpConfigs` too. Recipes on the fixed `agentrun` name (Goose's) are unchanged.
