Under a recipe that names AgentRun's MCP server per start (`ar` and 6 random hex digits: Cursor's, Antigravity's, any with the title tie), a recipe that lists the MCP configs its agent reads (`mcpConfigs`, new) now has a run keep the name its first start minted and give it again at each later start. Before, a resumed Cursor run asked the host's gate for every call of AgentRun's own tools: Cursor keeps, with its session, the name it was first given and titled the call under it, which the new start no longer spelled, so the title tie read it as another server's. `mcpConfigs` lists the MCP config files the agent reads (`~/path` or `$HOME/path` in its HOME, any other path in its work directory; Cursor's: `~/.cursor/mcp.json` and `.cursor/mcp.json`). A recipe that lists none (Antigravity's) still names the server afresh at each start. One that declares a server under the run's name has that name refused at the start: AgentRun's server gets a fresh name, kept from then on, the run gets a notice naming the file, and a call titled under the old name goes to the host's gate as that server's. A config that is no regular file, too large to read (over 1 MiB) or fails to read, or one that does not parse as JSON but names the run's server or holds a `\u` escape, counts as declaring it. The file is never edited. A run that began before this change keeps no name yet: its first start after it mints one, and a resumed Cursor session's calls under the old name ask the gate for the rest of that session. Owner recipes in serve take `mcpConfigs` too. Recipes on the fixed `agentrun` name (Goose's) are unchanged.

A proxy-billed recipe with the title tie (which takes Goose's facts) now finds its tools in meta `tools_call` under the run's own server name (`ar3f12ab__look_up`); before, only `agentrun__` names were read as AgentRun's.
