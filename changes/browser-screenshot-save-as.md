The browser's `screenshot` tool takes an optional `save_as`: a path relative to the workspace, ending `.png`, `.jpg` or `.jpeg` (`shots/home.png`). The capture is filed as evidence as before, and the same bytes are also written to that path. Missing folders are created and an existing file is replaced. The answer gets a `saved: <path>` line, and its details get `save_as: { path, saved: true }`. A `.png` name captures a PNG. An absolute path, a `..` segment, a name that is not an image, or a name whose format contradicts `type` is refused before the browser is called, so nothing is captured or filed. If the size budget retakes a PNG as a JPEG, the capture still comes back and is filed, but nothing is written under the `.png` name: the answer says `not saved: ...` and its details give `save_as: { path, saved: false, reason: "format_changed", message }`. Without `save_as`, the tool behaves as before.
  - `WorkspaceFiles` (pi-browser's host port) gains an optional `write(rel, bytes)`. A host without one refuses `save_as`. pi-browser's own `workspaceFiles(root)` writes through no link, its parent folders and the file itself included, and replaces the file whole. serve writes through the run's Workspace, the same write the agent's write tool uses.
  - On serve, the run's gate holds a browser screenshot that has `save_as` to `write`'s setting, as it already holds `computer_screenshot`'s. An agent not given `write` is refused, `write` set to deny refuses it, `write` set to ask asks a person, and a path inside a folder an MCP tool's file setting reserves is refused. A screenshot without `save_as` is held to the browser's setting alone.
