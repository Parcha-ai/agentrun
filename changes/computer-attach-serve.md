Pair a person's own computer with the server: Settings → Computers → Pair a computer shows a code (`POST /v2/computers/pairings`), the computer's driver, on any OS, trades it for its own token (`POST /v2/computers/pair`, no server token; a driver whose hello serves no kind of computer is refused, naming what it lacks, and so is a browser driver, whose CDP connection the attach path cannot carry yet; `POST /v2/computers/pairings` answers the pairing's `id`, which the computer its code makes carries as `pairing`, so the console tells its own code was used) and attaches over `GET /v2/computers/attach` (a WebSocket, subprotocol `agentrun.computer.0.2`), and an agent whose computer is `{"kind": "desktop", "provider": "<its cmp- id>"}` uses it: a run claims it at its start and releases it at its end or its lifetime. `GET /v2/computers` lists the paired computers under `paired` as their drivers' last hellos say (os, device, screen, groups, features, and `unserved`, why one serves no kind), online or offline, with the run that holds one and when that hold ends, and `DELETE /v2/computers/{computer_id}` removes one, closing its connection. Only the runner beside the server can use a paired computer. `node dist/attach-conformance-cli.js` runs the binding's conformance cases against any driver that pairs with the code it prints.

Who breaks: the store's schema is version 8 (SQLite) and Postgres gains migration `0006_paired_computers`, so a SQLite store an older build made is refused at the start as a version this build does not know; start on a new data directory. `GET /v2/computers` answers a required `paired` array.
