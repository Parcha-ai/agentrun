`curl -fsSL https://agentrun.ai/install | sh` installs AgentRun on macOS or Linux (x64, arm64) with no Node.js needed. It downloads from nodejs.org the newest Node.js on the major line of the launcher's `engines` floor that is at least that floor, so later security releases come with the next install, and checks it against that release's `SHASUMS256.txt`. It installs that Node and the launcher under `~/.agentrun` (`node/`, `lib/`, `bin/agentrun`), leaving any other Node, nvm or Homebrew alone. It adds one `PATH` line to your shell's startup file when none is there, and starts AgentRun as a service of your user, which keeps running after the terminal closes and starts again at login. Where there is no service manager, as in a container, it starts AgentRun in the background until the machine or container stops. Either way it returns once AgentRun answers and prints its address. `--no-start`, `--version V`, `--node-version V` and `--service` change that; running it again upgrades.
- `agentrun service install|status|start|stop|restart|logs|upgrade|uninstall` runs AgentRun as a launchd LaunchAgent on macOS or a systemd user unit on Linux, with `--no-open` and the launcher's data directory and port rules, logging to `~/.agentrun/logs/agentrun.log`. `status` prints the console's address and health. On Linux it prints the one `sudo loginctl enable-linger` line when lingering is off, and never runs sudo itself.
- `agentrun stop` stops the AgentRun the installer started in the background: a SIGTERM, then a SIGKILL after 45 seconds, and it returns once the launcher and its server have both ended. The installer stops it the same way before it starts another version, including one from before `agentrun stop`.
- `agentrun --version` prints the launcher's version. On a Node.js below the floor, the launcher's error names the installer's command.
