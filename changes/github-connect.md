Connect GitHub: a server makes its one GitHub App with GitHub's app-manifest flow, and a `github` trigger source runs on it. `POST /v2/integrations/github/connect` answers the manifest form the console posts to GitHub (the public hook `/v2/hooks/github`, its callback and setup URLs, pull requests write and contents, metadata and issues read, the `pull_request` and `issue_comment` events) under a single-use state bound to the browser; the callback converts GitHub's code and keeps the App's private key and webhook secret sealed (never its client secret), and the installed redirect records an installation GitHub confirms to the App's JWT. `GET /v2/integrations/github` shows `{app_id, slug, installations}`, and `DELETE` disconnects it, turning every github trigger off and keeping them. A trigger `{kind: "github", accept: [...]}` keeps no secret: one signed event fires every github trigger whose accept takes it, each its own firing (keyed by the body's SHA-256) and run, with the installation and repository on the payload's tag; an ignored body keeps its key for the day, since GitHub does not sign `X-GitHub-Event`. The App's installation deleted or suspended turns every github trigger off (`disabled.reason: "connection_lost"`). It needs `AGENTRUN_PUBLIC_URL` (`409 no_public_url`) and a seal key; a github trigger with no App connected is `409 not_connected`. A server-wide pushed source may now fan one event out to every trigger that takes it. Upgrading: nothing to do.
