`examples/apollo11`, on the showcase demo template (`npm run demo:apollo11`), reads NASA's Apollo 11 archive through `@parcha/pi-vision`: a lead that is never shown an image asks the eyes about the mission's film in windows, the scanned air-to-ground transcript page by page and sixty Hasselblad photographs, three fan-outs in one workflow (`job.ts`), and delivers the landing minute by minute as `agentrun.cited/1`, every row citing the looks it rests on (`#page=`, `#t=`, the look's key), with the photo sort's accuracy against NASA's captions and the mission times the eyes read checked against NASA's typed transcript. `sources.json` fixes every file by URL, size and SHA-256. The default reads a committed slice of them (`slice/`, 680 kB: three transcript pages, 18 s of film, five photographs, each fixed by size and SHA-256, cut by `slice/cut.sh`, sources in `ASSETS.md`) on fakes, $0 and with no network; `--live` reads the landing hour, and every input that reads NASA's own files downloads them with `--live` or `--fetch-sources`; `--live` with your own provider key or a gateway (`--model` and `--eyes-model` name any pi-ai model, the eyes one that takes images); `--kill` at the `vision.filing` crossing, holding the filings that reach the evidence sink after it, with looks paid, kept and repeated folded from the store; `--input` variants (the gallery's take, the whole archive, the weak-eyes pass, which `see_also` links); `--max-usd`; and an `agentrun.recording/1` recording that keeps the images the eyes were shown. `demo.json` names the keys and programs, and `SETUP-PROMPT.md` is a setup prompt to paste into a coding agent. The source export accepts a PDF only under `examples/apollo11/slice/`, the slice's scanned pages.
