The `code-review` template is 0.3.0: it reviews a pull request on its own read-only checkout, in a box, and its answer ranks each finding `P0`, `P1` or `P2` and scores the change's risk from 1 (safe to merge) to 5 (do not merge). Its agent has a computer (`computer: default`, the server's Docker box) and `tools: [read, bash]`: it clones the repository at the PR's head (`pull/<n>/head`, never a fork's URL), reads the change from the merge-base with `git diff`, `grep -n` and ranged `sed -n`, and never builds, installs or runs the PR's code. A server with no box refuses the apply (422, `definition.tools[1]`), saying that bash runs only in a box and how to turn the Docker box on; nothing is made. Where the clone fails, it reads through the GitHub MCP tools. A reader of its findings JSON changes: `severity` (`important`, `nit`, `pre-existing`) is gone, replaced by `priority` and a `pre_existing` flag; `claim` is `failure`, which ends with `Evidence: path:line "text"`, a line a command in the run printed; each finding has a `title`; the answer adds `risk_score`, `risk_reasons`, a `coverage` line per reviewed file and the `dropped` candidates with their reason (free text; `limit` past the `CODEREVIEW.md` limits, 10 findings by default).
- The reviewer reads its own `rules/CODEREVIEW.md` (a checklist, priority examples, what never to flag without evidence), then the repository's `docs/CODEREVIEW.md` (or `CODEREVIEW.md`) from the base, which adds to it; without one, `REVIEW.md`. It tries to break each changed function with a concrete input or order of events, follows each promise the change makes to the other side and to its tests, and reports every candidate with the lines behind it; it drops one only as a duplicate or under a never-flag rule it cites. A repository may add `.agents/skills/code-review-knowledge/SKILL.md`, its invariants by path glob; the reviewer reads the sections that match the changed paths.
- The posted review leads with the risk score and its reasons (Greptile's confidence is 6 minus the risk), lists the findings, the pre-existing ones, what was skipped and what was fixed since the last review. Each inline comment starts with its own priority and ends with its fingerprint in an HTML comment, which a re-review reads to never post a finding twice.
- A review costs at most 30 tool calls before it posts, and at most $1.00 a run.
