Applying a template again can update the agent it made instead of making a second one. `POST /v2/templates/{name}/apply` takes an optional `agent_id`: the apply writes a new revision of that agent, answered 200 with the same id, and its runs and learned notes stay. The parameters and grants are checked as a fresh apply checks them. Its triggers are matched by name: one the agent has is changed in place (a feed trigger keeps the items it has seen, a webhook trigger keeps its secret, and one the owner turned off stays off), a new one is made, and one the package no longer has is removed; a trigger the owner added to the agent is left alone, and a removal that fails is done by the next apply. What the package sets and its new version leaves out (an input or answer schema, a checkout, a default cost cap, learning) is removed from the agent; the harness, computer and sdk references the host set are kept. Two updates of one agent run one after the other, and an update whose read of the agent went stale before it wrote (an edit, or an update on another server) answers 412 `precondition_failed` with nothing changed. An agent not made from that template is refused with 422 under `agent_id`, saying where it came from, and an unknown id is 404. A fresh apply of a template whose same parameters already made a live agent still makes one, with a `duplicate` warning naming that agent. The agent keeps only a keyed digest of the parameters it was applied with, never the parameters. In the console, a template that already made an agent shows "Update <agent>" next to Apply.
