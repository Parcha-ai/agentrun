A host tool's input schema reaches the Claude Agent model whole, or the session is refused. The Agent SDK takes a tool's schema as zod, and the bridge that builds it from JSON Schema (`@parcha/agentrun-adapters/process`) carried a subset and quietly turned the rest into "any", so the model could see, and call the tool with, a looser input than the host declared. The bridge now inlines local `$ref`s (pydantic's `$defs`; a remote, unknown or recursive one is refused by name), carries a union of one schema and null (an Optional field) as that schema made nullable, carries `title`, `examples` and `default` as annotations the model reads (they check nothing and fill nothing in), and also carries the common validation keywords (`minLength`, `maxLength`, `pattern`, `format` email/uri/url/uuid/date-time/date, `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf`, `minItems`, `maxItems`). A tool whose schema uses anything else (`allOf`, `not`, `oneOf` between real alternatives, `uniqueItems`, `patternProperties`, a tuple, a keyword on the wrong type, ...) is refused when its session opens, naming the tool and where (`toolSchemaProblems`), so a runner refuses the node at its start instead of running it on a weaker schema. A node's output schema reaches the model the same way, through its `submit` tool, so a node whose output schema uses such a keyword is refused on this adapter too. `schemaHash(schema)` (`@parcha/agentrun-adapters`) is the sha256 of a schema's canonical JSON (keys sorted at every depth), for parity tables and pins. `SCHEMA_CORPUS` (`@parcha/agentrun-adapters/testing`) is a shared corpus of schemas, each `{ hash, source, schema, example? }` (pydantic's own output, the example workflow's submit tools, edge cases), which each adapter's tests run for the schema-parity table.
