A look says when its model call began and which tool call it ran under, so a timeline can draw the call as a bar under that tool call. `LookEvent` and the record's `facts` gain `startedAt` (epoch milliseconds, taken when the request to the eyes, to Jev, to the speech model or to a recording's source began) and `parentToolCallId` (the id of the tool call the look ran under, from the new optional `CallContext.toolCallId`; it is `parentToolCallId` and not `toolCallId` because a tool's own events already carry `toolCallId` as their own call's id). The pi-durable adapter sets `CallContext.toolCallId` from pi's id for the tool call, so a look a script makes through `vision.see`, `vision.judge` or `vision.transcribe` is under the tool call that ran the script, and a look the guard makes is under the tool whose result held the image; a host with its own context sets it itself. A failed look carries both in `MissEvent.record`, a request that threw included. A look that made no request (a native look, an answer read back from a memo, a judgment Jev's port refused before it sent anything, such as a state over the host's limit, which now files a cost of 0 as any unsent look does) has no `startedAt`; a caller that names no tool call leaves `parentToolCallId` out; such a look files exactly as before. A receipt's header gains `startedAt` and `parentToolCallId` lines when a record has them.
