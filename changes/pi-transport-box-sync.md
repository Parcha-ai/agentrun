`@parcha/pi-transport/sync` moves a run's files between the host and a box that shares no disk with it, on top of `extractTar`. `seedDir` copies a host directory into a box path (a host link is never followed, modes are capped at 0755, `readOnly` paths go without a write bit) and returns a `mark`: the box's listing with the SHA-256 of each file sent. `pullDir` brings back what changed since the mark: the box lists the directory and a path comes back when it is new or listed differently, never by comparing the box's clock with the host's, with `exclude` and `mirrorDeletes` (off by default); every member goes through `extractTar`, and two names of one inode both arrive as files. `seedAgentHome` and `pullAgentHome` keep an agent home's `learning/` host-owned (seeded read-only, never pulled back, never removed), and a home pull never overwrites or removes a host file another run changed since the seed: it replaces the host's copy only while that copy is still the bytes the mark's SHA-256 records, and counts the rest as `host_changed`.
A box's listing is read up to `maxListingBytes` (default `MAX_LISTING_BYTES`, 64 MiB), on every path that lists a box, checkpoints included: past it the box's program is stopped and the call is `too_large`, so a box cannot make the host hold an unbounded listing.
An `exclude` pattern that starts with `/` is now anchored at the root (`/learning` is the top-level `learning` only); before, such a pattern matched nothing.
