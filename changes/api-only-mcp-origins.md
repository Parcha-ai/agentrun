API-only (`AGENTRUN_API_ONLY=1`): list the origin of every per_run MCP server the API token saved in `AGENTRUN_API_ONLY_MCP_ORIGINS` before upgrading, or token-saved per_run servers are refused. Every API-only start now holds the list it starts with (an empty one when the setting is unset), and a run that grants a token-saved per_run server at an origin off it fails with nothing sent, as does an agent's save that pins it. The start logs one line, `api_only_mcp_off_list`, with the count and names of those servers. A server the owner saved is not governed by the list.

An API-only server (`AGENTRUN_API_ONLY=1`) can now take a per_run MCP server save from its token, at origins its operator names in `AGENTRUN_API_ONLY_MCP_ORIGINS` (comma-separated, for example `https://mcp.example.com`). A backend in front of the server can save its gateway (`PUT /v2/settings/mcp-servers/{name}` with `"auth": {"type": "per_run"}`) on a fresh install or after a store reset, without turning API-only off for the save. Runs still bring their own credential in `mcp_auth`, and the server keeps none. A body that carries a credential is `403`, and so is a save over a server the token did not save or one that seals a credential. A per_run body at any other origin, any other auth type and a Composio server's name are the profile's `404`. Each refusal comes before anything is sent to the address. With the setting unset or blank, the save is a `404` as before. A loopback origin still needs `AGENTRUN_MCP_ALLOW_LOOPBACK=1`. A wildcard entry stops the start. The list also holds after the save: drop an origin and restart, and a run that grants a server the token saved there sends it nothing and fails in words saying why.
