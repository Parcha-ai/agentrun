A Groundbox provider: `providerFor("groundbox", { apiKey })` makes each computer a Groundbox sandbox, a Firecracker microVM started from the box image (the public tag its `prepareImage()` answers, which Groundbox turns into a disk at the first create), or from a spec's own image: `"default"` (the team's default template, else Groundbox's own Ubuntu image), a template of the key's team, or any other public image. It is a `MachineHost` on the shared adapter: `src/groundbox.ts` calls Groundbox's REST API with `fetch`, and the daemon runs as a child of one resumable command of the WebSocket command stream, handed to `framedExec`: when a socket closes, as every one does within the hour, a new one attaches from the last output position read, so no output is lost or read twice, and each stdin write is one answered call that writes the command's fifo. The daemon is uploaded through the files API. Network none, open and a list are init's, and the run's folder is a synced folder. Its lifetime is the janitor's, by the deadline label, and Groundbox's own timer ends every sandbox at the adapter's backstop; a computer may live up to 30 days less 6 minutes, a day by default. `list` is one call, filtered by `live=true` and the labels as metadata. A spec's `cpus` (whole, 1 to 16) and `memoryMb` (whole GiB, at most 4 a CPU) are the sandbox's size. With `kind: "desktop"` a computer is a desktop: the box image's Xvfb and xfwm4, started through the daemon as on E2B and boxd (Groundbox's own image, which lacks xfwm4, is refused for it). No Archil mount yet. Groundbox's own image keeps toolchains under `/opt` deeper than the isolation probe searches, so `isolation.vendor-agent` can't pass on it; on the box image it does. Settings takes `GROUNDBOX_API_KEY`. `AGENTRUN_COMPUTER_LIVE_GROUNDBOX=1 COMPUTER_GROUNDBOX_API_KEY=... npm run conformance -w @parcha/agentrun-computer -- --provider groundbox` runs the conformance kit on real Groundbox, and `sweep.js --provider groundbox` checks it left nothing behind.
