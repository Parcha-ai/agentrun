A tool with a `file` setting now files more of what its server sends, and its summary says more about errors without showing their words.
- A protocol-level error is filed like any other answer. This covers a JSON-RPC error, or an HTTP error the client throws. The tool's result is the same summary with `isError: true`. Before, the result showed the first 300 characters of the server's message.
- An error answer's summary ends with one more line, built from the error's structure and never from its words. The line gives the HTTP status, the JSON-RPC code, and when to retry. The retry time comes from a `retry_after`, `retryAfter`, `retry_after_seconds`, `retry_after_ms` or `retryAfterMs` field of a JSON error (at its top, in its `error` or `data`, or in a JSON-RPC error's `data`), or from the Retry-After header. The status and the Retry-After are the call's own response's, also when other calls to the same server run at the same time. A 429 or 503 with no retry time says to retry later. When the error has none of these, as with a plain-text error, the line says `Error: no status or retry time given.`
- The tool gate refuses the agent's own `read`, `write` and `edit` (claude-agent's `Read`, `Write` and `Edit` too, and a computer script's file ops) when the path is in a folder one of the agent's `file` settings names, or under it. The error names the setting. The check reads the path as written, resolving `./` and `..`, against every name the run's file tools take for its folder: its full path, a computer's `/workspace`, and a CLI harness's working folder. It reads no file, so it doesn't follow links. Before, these tools could open the folder. `bash`, on the runner or a computer, is not gated by path: a command, a link it makes, or any program the run starts can still open the folder. A template that must keep the model off the answers grants no `bash`, or runs its skill's code where the model can't read the output.
- The shape names a key only when it reads as a plain name: lowercase words joined by `_` (`has_more`), or camelCase (`pageInfo`), with any leading `_`, at most 32 characters. Keys with digits or capitals after a prefix (`cus_NffrFeUfNV2Hib`, `txn_1Q0001`) and all-capitals keys are counted instead. A key that is data but looks like a plain word, such as a username like `marisol_q`, is still named.

Upgrading: a runner on a release from before `file` existed ignores the setting. Such a runner shows a filed tool's answers to the model whole, as if the setting weren't there, and the server raises no error or warning about it. Before applying a template that relies on `file`, update every runner that can claim its runs to this release. A runner that has `file`, but runs a release older than the server that wrote the setting, refuses every call of the tool, naming the setting. That runner also needs the update. A runner that has `file` but is older than this release still files answers, but it shows a protocol error's first 300 characters to the model, and it doesn't refuse the agent's `read`, `write` or `edit` in the folder. It raises no error or warning about either, so update it too.
