# Changelog

## [Unreleased]

## 0.1.0-beta.24 (2026-10-22)

- First release of `@parcha/pi-durable-agent`: an agent home for pi agents, one directory of pi-durable stores (`agent.sqlite`, and one run store per run) that keeps an agent's definition, skills, saved sign-ins and every run. `createAgentHome` and `openAgentHome` keep the agent's identity, its
  definition (no model or thinking level: the host picks them), its skills, and each host's alias and tool bindings.
  Each run is a `@parcha/pi-durable-disk` run directory, `runs/<id>/` with `store/run.sqlite` and `work/`, so
  `pi-durable-disk run --dir` runs it; `runPaths` gives its paths. `startRun` seeds a run's store and workspace from the
  home and takes the save lease on each browser profile no live run holds; only the lease holder gets a profile's saved
  sign-in, and another run gets it `held`, with no `ref`, and signs in on its own. `durableProfileStore` is pi-browser's
  `ProfileStore` over the run's `browser.profiles`; `carryBack` copies back the profiles the run may save, releases its
  leases and completes its entry in the runs index, once per run. Writers queue on the home's `owner.lock` and fail with
  `AgentHomeError` (`busy`) after 5 seconds.
- New subpath `@parcha/pi-durable-agent/timeline`: one human-readable timeline of a pi-durable run, with no dependency and no Node built-in, so a page, the run viewer and a harness can import the same code.
  `timelineOf(entries)` turns a stored conversation into rows shaped as Grep's public `TimelineEvent` (its 13 fields and caps), plus the open kinds `user_message`, `waiting` and `usage` and the optional fields `seq`, `conversation_id`, `round`, `parent_tool_use_id`, `session`, `path` (the file a "Saved" row is about) and `usage`. `timelineReducer().apply(events)` does the same live from `watchEvents` batches, as `pi-durable-disk` serves them on `GET /events`; both go through one per-entry function, so live and replay give equal rows.
  `groupTimeline(rows)` pairs calls by `tool_use_id`, groups them by round, folds adjacent calls of one tool, nests a call's inner calls and a subagent's rows under it, and never dedupes a call. `renderText` prints rows or groups as plain text. `registerLabel` adds a host's own tool labels. A row never carries a live-view URL, a context id or a cookie, and every summary, preview and text (a person's own message excepted) keeps a URL's origin, path and query keys but drops its query values, fragment and userinfo, as pi-browser does for the URLs a model sees.
- `createAgentHome` refuses a definition `id` that is not one URL segment, `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$` (letters, digits, `.`, `_` or `-`, at most 128, not starting with a punctuation mark), with `AgentHomeError` (`invalid`). A caller that passed an id with a space, a slash or another character must pass one that matches, or omit it and take the minted UUIDv7, which always matches. Homes created before keep their ids, and `refreshAgentHome` still takes a home's own id. New: `homeRevision(home)`, the agent store's head commit number, which every write that changes the home moves and no read does; with the identity's id it is the home's version, for an ETag. `refreshAgentHome(home, { ..., ifRevision })` is a compare-and-swap on it, checked under the home's lock before `from` and before anything is written: a home whose head commit is not `ifRevision` is refused (`stale`), naming both numbers.
- `EXPORTABLE_KINDS`, `SECRET_KINDS` and `projectForExport(kind, value)`: what an exporter may copy out of an agent home. The exporter copies only the four listed kinds (`agent.identity`, `agent.definition`, `agent.skills`, `agent.runs`) and drops every other kind, an unknown one included; `projectForExport` returns a deep copy, with the caller's `host` removed from an `agent.runs` record, or `undefined` to drop the document. Saved sign-ins, save leases, and each host's aliases and tool bindings are on `SECRET_KINDS` and never leave the home. A test fails on any kind the package defines that is on neither list.
- New subpath `@parcha/pi-durable-agent/export`: `EXPORTABLE_KINDS`, `SECRET_KINDS` and `projectForExport`, the same module the root re-exports, with no import at all. A writer that only filters kinds loads it with `node:sqlite` alone, where the root loads pi-durable, chord and pi-ai; `examples/web`'s replay writer now does.
- An agent home follows its repo at a commit. The host reads the definition and skills from git and passes them in with the commit's sha (40 or 64 lowercase hex digits): `createAgentHome(dir, { ..., sha })` and the new `refreshAgentHome(home, { sha, definition, skills })` write them with `agent.source` (`{ sha, refreshedAt }`) in one commit, and a refresh replaces the skill set (a skill path not in it is removed), keeps the agent's id and renames the identity after the definition; with `from`, a refresh is a compare-and-swap, refused (`stale`) unless the home is at that sha (`null`: none yet), so a host that read an older commit cannot move the cache back. `startRun` records the home's sha on the run (`agent.runs`, and `sha` on what it returns), and `startRun(home, { host, sha })` refuses with the new `AgentHomeError` code `stale` while the cache is at another commit, or at none. `agent.source` is on `EXPORTABLE_KINDS`, and an exported run keeps its sha. A home without `agent.source`, every home made before this, is not tied to a repo and is read as before.
- An agent home on a disk, first step: `carryBack`, `readAgentHome`, `homeRevision` and the new `prepareRun` take `{ access }`, a `HomeAccess` of `claim(fn)` (run `fn` on the directory that holds `agent.sqlite` while the host holds it alone; the package takes `owner.lock` inside it) and `runStore(run)` (a local, closed copy of the released run's store, which the package only reads, from a copy of its own). Without it, `localAccess(home)` is today's local directory. A start is now two halves: `prepareRun` checks the sha, takes the save leases and records the run inside the claim, touching nothing under `runs/`, and returns a `RunSeed`; `seedRun({ storePath, workDir }, seed)` writes the run's store and skills and can run again on a half-written directory, and refuses a seed that gives a sign-in to a run that does not lease it. `startRun` is the two in a row under one hold of the home, its results unchanged: a start whose seeding fails is undone under that hold, with no run directory, no record and each lease it took back as it was, and when the undo fails too the error is an `AggregateError` carrying both. `undoPrepare(home, seed, { access })` is that undo for a host's own start; it acts only while that start is still the run's and touches only leases exactly as it set them, so a retried or stale undo changes nothing (`{ undone: false }`). The package takes no dependency on pi-durable-disk; the README shows binding the access and the seed to it.
- `packHome`, `readPack` and `importPack` move an agent home as one tar. `packHome(home, { out, maxBytes?, exportRunStore? })` writes `manifest.json` (`agentrun.home/1`: the definition, the skills with their digests, the source's `agent.source`, the sign-ins the source had by key, the run counts, the pack's size) first, then a new `agent.sqlite` built from `EXPORTABLE_KINDS` through `projectForExport` and vacuumed into one clean file, then each carried-back run's `work/` files. Run stores travel only through the `exportRunStore` hook. A run that is still live travels as its index entry only. Symbolic links, hard links, dotfiles, `chrome/`, `repo/` and everything else off the allowlist never travel, and the packer refuses any SQLite file that holds a sign-in kind or has a `-wal` or `-shm` file beside it. Each work file is opened without following a link and must be the file that was listed, so a file swapped for a link while the pack is made is left out; a work directory that cannot be read fails the pack; the pack is read back with `readPack` before it is published. A pack over `maxBytes` or `maxMembers` is refused (`too_large`) before anything is written.
  `readPack(file)` judges a pack without writing a home and answers with the contract's `format`, `definition`, `sign_ins`, `size` and `live_runs` checks: the manifest first, an `agentrun.home/N` above this version refused, every member on the allowlist, no `..`, absolute path, link or device, no store with a sign-in kind, the agent store's id, definition and skills as the manifest says. `importPack(file, dir, { replace?, ifRevision? })` makes a new home in an absent or empty directory, and changes an existing one in place under its own owner lock: the lock, `agent.sqlite`, `chrome/`, `repo/`, the home's sign-ins, aliases and bindings, and its runs the pack does not have stay where they are, and one store commit replaces the definition, the skills, the source and the pack's runs, so `homeRevision` only goes up. The pack's run directories move into place before that commit, in the order of a journal in the home; a failure puts every one back, and a crash is settled by the next lock taker (the new home when the commit landed, the old one when it did not). It refuses another agent, a target with a live run and a stale `ifRevision` (a `homeRevision`), and a pack over `maxBytes` before parsing or extracting any of it, and leaves the target as it was on any refusal. A new home is made with `rmdir` and a rename: the target is never deleted recursively. The journal's phases are terminal and written durably before any evidence is removed (`committed` as soon as the store's commit returns, `rolled-back` once every run directory is back), so recovery can be stopped anywhere and repeated; recovery never deletes a run directory it cannot put the other version of back, and a failed import does not remove the evidence recovery keeps. A pack with a global or a doubled pax header, or a pax header of more than 64 fields, is refused. `AgentHomeError` gains the codes `too_large` and `check`.
- `homeRevision(home, { access })` fails with `AgentHomeError` (`missing`) when the directory the access claims holds no `agent.sqlite`, as `readAgentHome` already did. It opened the store without checking and threw SQLite's "unable to open database file". Without `access` it was already `missing`.
- The README opens on what the package does for a reader who has not seen it: an agent home that keeps the agent's definition, skills, saved sign-ins and every run, and moves as one directory or one pack, so the agent's next run starts signed in. It has an Install section, a section on what a saved sign-in is (the provider's reference, kept as it is and not encrypted, to be treated as a password; a pack and an export leave it behind, so a new machine signs in again), and a pointer to the runnable `examples/web`. The Library section now names every export of `.`, `./export` and `./timeline`, with the `AgentHomeError` codes each function throws and a table of what the codes mean. `test/readme.test.mjs` runs the quickstart in an empty project laid out like an install and compares its output with the README's, and fails when a code block is not named, when an export or an error code is not in the README, or when a link would break on npm. The repository README lists the package in both package tables, and the `examples/web` README says that starting a run needs a Browserbase key and a model endpoint until pi-browser's live view lands, and points to the keyless quickstart.
- `readPack` and `importPack` fix two defects in reading a pack.
  - A pack member under `runs/<id>/` is refused when the pack's index does not list the run, even when the id is named like an `Object` property (`constructor`, `toString`, `valueOf`): such a member used to pass the check, and `importPack` extracted it into the home.
  - The pack file is closed when its scratch directory cannot be made (a full or unwritable temporary directory), where it used to stay open.
- Prompt variants in the agent home: a new kind, `agent.prompts`, keyed by id, holds one `base`, one `generic`, any number of `overlay`s and at most one `question` (`{ role, label, text, when?, criteria? }`). An overlay's `when` is its selection rule, `{ question, option, threshold }`: the question's id, the option the variant needs and its least probability. The question's text is a Jev choice question, and its `criteria` describe options by name; every question also has the option `other`. `setPrompts(home, variants, { ifRevision?, access? })` replaces the set in one commit under the home's lock and refuses one that is not exactly one base and one generic, with unique ids that are one URL segment, labels of at most 200 characters, texts of at most 64 KiB, thresholds from 0 to 1, and rules that name the set's question and an option no other overlay needs (`AgentHomeError` `invalid`; `stale` for a moved `ifRevision`). An equal set writes nothing. `readAgentHome` returns `prompts`.
  - `choosePrompt(prompts, input, { judge, lookup?, signal? })` picks the variant a run starts with. The judge, a Jev runner or any function of its shape (the package imports no Jev), answers the question about the input; the overlay whose option meets its threshold is chosen, the highest probability winning. When none is, an optional lookup runs once and the judge answers again with what it found. Otherwise the generic. It returns `{ variant, instructions, passes, lookup, reason }`: the base's text and the variant's, each pass with its model, cost and latency, whether a lookup ran and what it read (never its text), and why. A judge or lookup failure gives the generic, never an error. An answer whose choice is not one of the offered options, that gives a probability for another option, or whose probability or confidence is not a number from 0 to 1 is a judge failure; the probabilities' sum is Jev's to check. An error's message is cut to 500 characters, so `reason` always fits the 2,000 characters `startRun` takes.
  - `startRun` and `prepareRun` take `prompt: { id, reason }`, the variant the host chose, and record it on the run's `agent.runs` entry; an id that is not one of the agent's variants is refused. Prompts are on `EXPORTABLE_KINDS` and travel in a pack; `importPack` with `replace` takes the pack's set, removing every variant the pack does not have (the whole set when it carries none). `readPack` refuses a pack whose prompts are a set `setPrompts` would refuse (the `format` check), so `importPack` never writes one; a pack with no prompts is still taken.
- A session vault in the agent home: `sessionVault(home, { hostKey, maxSessionCookieAgeMs?, runId?, access?, now? })` keeps a signed-in browser session for the agent's next run as ciphertext only, behind the `SessionVaultPort` a browser host calls (`capture` at release, `restore` at create, `forget`). A session is a local Chrome's cookies and localStorage, or a Browserbase or Kernel context id.
  - Each session is AES-256-GCM in a new secret kind, `agent.vault`, under its own item key, bound to its agent, session and kind; it also holds the session's origins and capture time, and a restore refuses a row whose clear origins or `capturedAt` differ from them, so a changed row can neither stretch the session-cookie cap nor cut a provider context down. The item keys are wrapped by the home's vault key and that by the host's key (`HostKey`, `{ id, wrap, unwrap }`; `localHostKey(id, bytes)` for a key held in the process), in `vault.keys` beside `agent.sqlite`, owner-only, outside the store so that a key can be destroyed. The first capture binds the vault to the host key; any other is refused with a new `AgentHomeError` code, `key`.
  - `forget` destroys a session's item key, so its earlier revisions can never be read; a capture destroys the key before it; `forgetAll` destroys every key. A capture keeps only the origins it names, a restore returns only the origins asked for that were captured (a host-only cookie counts for its own host only, a domain cookie for the hosts under it too), a provider context comes back only to a restore that names every origin it was captured for (its own `origins`, when the browser host records them, are kept and given back as they came), a persistent cookie keeps its expiry, and a session cookie comes back for at most 24 hours (`maxSessionCookieAgeMs` may only lower it). A capture is dated by its state's `capturedAt` (a time still to come counts as now), and one older than the session already kept is ignored. With `runId`, a capture is refused while another live run holds the session's save lease.
  - `agent.vault` is on `SECRET_KINDS`: never exported, packed or seeded into a run. A pack's manifest names the saved sessions in `vault` and carries no value and no key file. `handedOut()` lists what restore returned, for a redactor.
- `@parcha/pi-durable-agent` is no longer held: its manifest drops `"private": true`, so a release publishes it to npm, at the workspace version, after `@parcha/pi-transport`. Its README's install lines pin the pi packages to 1.3.0 (pi 1.4 is not supported yet; a later release widens the range). Its quickstart runs in an empty directory after one `npm install` of the package and the pi packages it runs with: CI runs it that way from the packed package (`scripts/stranger/pi-durable-agent.json`), and also runs the README's install line as written, with the packed package in place of `@beta`.
- The session vault no longer keeps a provider context for more origins than its capture allows. A context's own `origins` that go beyond the capture's are refused (`AgentHomeError` `invalid`, naming the fault and no origin or context id) and nothing is written, since an opaque context cannot be cut down and would keep those origins' sign-ins. A restore gives a provider context back only to a request that names every origin it was captured for and every origin it records; any other gets `null`.
