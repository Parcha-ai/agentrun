# Changelog

## [Unreleased]

- The harness has no Jev cap. Every typed question is sent; `--max-usd` is the run's dollar stop, and TypeSafe rate-limits. `capJudge` and `JEV_CAPS` are gone from the package's exports: `priceJudge(runJudge)` prices an answer at Jev's list price as before. A demo.json that still sets `models.judge.caps` is refused at load: remove it.
- New package `@parcha/agentrun-harness`: a reference harness, the host we use to run AgentRun demos and tests, meant to be read and forked. It moved from `examples/reference/` (history kept), so an example runs from an npm install. It exports `run`, `demo` (the supervisor that kills a run's process anywhere and resumes it), `localHost`, `placeAt`, the recorder and supervisor, `codeOf` and `cost`, with `./scan` (the one credential and machine-path scanner), `./child-app` (the app module `pi-durable-disk run --app` takes as a file: `import.meta.resolve('@parcha/agentrun-harness/child-app')`) and `./place`. The pi family (`pi-ai`, `pi-durable`, `chord`, `pi-codemode`) and `typebox` are peers; `@parcha/pi-transport` is an optional peer that only a demo declaring `boxes` needs. It is not on npm yet, so such a demo runs from a checkout, and from an install it says so in one line. Its types need nothing from pi-transport (`Boxes` is its own type). A demo's repository root comes from the demo (`options.root`, else the nearest folder above the demo's file with a `package.json` or `.git`), never from the package's own location, and a recording made in another project names that project's GitHub `origin` as `owner/name` (else `unknown`) and the @parcha packages it loaded. `examples/reference/` keeps the example job, and every example imports the package by name.
- The recorder takes the agent's report. `report/index.html` in the run's work directory and the files it reaches (`src`, `srcset`, `poster`, stylesheet `href`, CSS `url()`, relative links, transitively) are recorded as blobs, and the manifest gets `artifact { title, entry, files }`. A file the final page does not reach is dropped, and a report that loads a file it does not hold, or that has a script, an `on*` attribute, a `data:` URL, an iframe, object, embed, form, base or meta refresh, refuses the recording. The validator checks the paths, the blobs, the entry and each `data-look`; the gallery's gate repeats the machine-path scan on blobs that are not text. New runtime dependency: `htmlparser2` (MIT).
- A command the agent runs gets only `PATH`, `HOME`, `TMPDIR` and `LANG` from the host. The agent's `bash` tool and code mode's `tools.bash` run with `inheritEnv: false`, so a provider key the host holds for its own model calls (a live run's declared keys) never reaches a command, and a prompt that makes the agent run `printenv` reads none. A command that needs a key goes through a host tool.
- `finishRecording` no longer fails with `ENOTEMPTY` when a writer that outlived its kill (a place that refused it) adds a file to the spool while it is removed: the removal is retried for up to two seconds, and any other error, or one that lasts, is thrown as before.
- A recording publishes only inert blobs. The validator and the gallery gate take a blob's extension from an allowlist (`png jpg jpeg webp gif webm mp4 pdf json jsonl txt md csv vtt`; `html`, `htm` and `css` only as the files of `manifest.artifact`; `svg`, `xml`, `js` and any other never), and the recorder records an `image/svg+xml` output, or any other extension it is handed, as text. Every blob that is not media is scanned as text, in the validator, the gate and the live follower. The scan knows the Google, fal, ElevenLabs, xAI, Groq, Hugging Face, Slack and Stripe key shapes, and a bare `/home/<user>`, a Windows profile, `/root/` and a macOS temp folder as machine paths.
- A recording, and the run's own `events.jsonl`, no longer hold a browser session's live-view URL: the reference host writes each session row (`launched`, `updated`, `released`) with `liveView: null`. A viewer's address is a full-control token, and a recording is read by anyone who has it. The reference host shows no session to a person, so nothing of its own needs the address; a host that does asks the provider for it (`BrowserProvider.liveView(ref)`), never the recorded row.
- A workflow node is offered the tools it declares (`tools`), else every tool the run installs, as the DSL runner does, and `submit`; code mode's `tools.bash` and `vision.*` stay inside its `code` tool. A run with `browser: false` (a demo's `browser: false`) installs no browser: no browser tool, no browser prompt section, and the host's browser is never asked.
- The recording scan (the recorder's finish, the follower, the validator and the gallery's gate) refuses a URL that carries a credential: a token-bearing query parameter or fragment, a live-view, debugger or connect URL, a DevTools websocket path, or Kernel's live-view path. The message names the kind and the parameter, never the value. A recording that holds one is not published.
- A demo whose `demo.json` declares a required program (`programs`: `{ cmd, why, required }`) that is not on this machine's `PATH` is refused before anything starts, and the error names each missing program and what it is for. A run on fakes still runs the agent's own commands, so before this a missing `pdftoppm` or `ffmpeg` ended the free vision demo as `the model did not answer (model_error)`. Programs needed only for `--live` are checked only on a live run, and a demo that brings its own place is not checked here.
- A workflow node that names no thinking level now runs at `medium` in the harness, as in the DSL's runner (Miguel's ruling: thinking is never off, and the default is medium). A node that carries `off` runs at `medium` too. A node's own level still wins.
- `@parcha/pi-transport` is on npm under the beta tag: the guide and the harness README give the install line, `npm install @parcha/pi-transport@beta`, and a demo that declares `boxes` without it installed says to run that line, no longer that the package is not on npm.
- **The recording scan passes a root workflow node's and a root loop's pointers, and takes each pointer name whole**
  - A run whose root is a `workflow` node records `/root/workflow/root/...`, and one whose root is a loop records `/root/iterations/<n>` and `/root/iterations/<n>/body/...`. The scan (`credentialIn`, the recorder, the validator and the gallery gate) read both as root's home and refused the recording as "machine path"; it now passes them, and only these shapes: `/root/workflow/notes.txt` and `/root/iterations/x` are still root's home.
  - It also passes the pointers the DSL's validation names in a root child workflow, so an authoring agent's validation result can be recorded: bare `/root/workflow`, `/root/workflow/name`, `/root/workflow/schemas` and `/root/workflow/schemas/<id>` (one segment, `~0` and `~1` escaped, nothing after it), `/root/workflow/input[/schemaId]` and `/root/workflow/output[/schemaId|/path]`.
  - Stricter: a folder in root's home whose name starts with a pointer name and goes on with `.` or `-` passed before and is now refused as "machine path", for example `/root/steps.bak`, `/root/body-old` and `/root/default.cfg`.
- **The install's quick start says how to keep the run and where to watch it**
  - `node demo.mjs --record ./rec` keeps an `agentrun.recording/1` folder, and the hosted run viewer plays it in the browser, with nothing uploaded.
- The cost fold (`cost`, which `--max-usd` and a demo's spend cap read) and the recording validator read `agentrun.decisions` in both of its forms: the single document (a `receipts` list) and the keyed documents (one row each, `key` its place). A keyed row counts once, however often a snapshot lists it, and a row with no cost makes the cost unknown, never 0.
  - `durableDecisions(file)` (`@parcha/agentrun-pi/durable`) reads a store file's decision rows in commit order in either form; `durableDoc(file, "agentrun.decisions").receipts` is nothing in the keyed form.
  - A recording that holds both forms is refused by the validator: one form per recording.
  - It is the first commit of the change that makes the keyed form, released with it (the harness pins `@parcha/agentrun-pi` exactly).
- A demo's tools can make boxes on providers of the demo's own: `DemoOptions.providers` (`({ live, env, root }) => ({ name: provider })`), handed to the tools as `context.providers`. The entry taps each, so every box a tool makes is on the recording: `box.created` `{ box, provider, facts, role? }`, a `box.exec` `{ box }` per command (never the command) and `box.ended` `{ box }`, and a host `box.receipt` when the box ends, or when the process ends with it open, with `usd_per_second`, `cost_usd`, `source` and `priced` null, so the run's cost reads unknown. Every box line names its box by its label (`box-1`, `box-2`), never by the provider's id, and `demo.json`'s `boxes` lines now do the same. A box the tool made carries its label (`box.label`) for the tool's result. An agent's own tools (pi extension tools) get the same tapped providers through `DemoOptions.providerExtensions` (`({ providers, live, place }) => Extension[]`), called once in each process right after the tap, on fakes and live; it is refused without `providers`. A receipt for a box still open is written also when the run or the result hook fails. The next process of a run writes the receipts of the boxes a killed process left open; it does not end those boxes, which their own lifetime ends. The provider ids go only to `--box-ids <dir>` (`DemoOptions.boxIds`; default `box-ids.internal/` in the run's directory): one file per label, each claimed by an exclusive `link(2)`, so two processes never take one label; a run whose ids directory, given or default, resolves inside the recording is refused before it starts. A disk with no exclusive link, a read-only mount, a directory that exists but takes no files, an ids path that is a file and a damaged label file each refuse the run by name. A demo with a place of its own and `providers` is refused: the two would need one labeller. Because `demo.json`'s boxes now write `box.exec` too, the box-loss test in `examples/reference-demo-ledgers.test.mjs` expects those lines, and `examples/vision-agent/agent.ts`'s value flags know `--box-ids`.
- A host line written by a process that has no supervisor (a run's child, a tool box's `box.receipt`) is now the supervisor's kind of line: no event-level `gen`, the process it is about in `data.gen`, as RECORDING.md 3.1 says. Before, `recorder.host()` without a supervisor stamped the process's `gen` on the line. `finishRecording` numbers the supervisor's space (live host lines with no `gen`) once, in order, since the supervisor and each process counted from 0.
- A supervised demo run's tool-box receipts are the supervisor's again (RECORDING.md 3.1: the supervisor writes every live host line, and a process writes none). A `box.receipt` for a box a demo's provider made went through the run process's recorder, which has no supervisor, so the line carried an event-level `gen` and its own `seq`: the viewer's format check flagged every one. The supervisor now sets `HOST_LINES=supervisor` for its processes when it owns the box ids directory; such a process (`supervisedChild(env)`, exported from the harness's boxes module) keeps each box's end and the process that made it in the box's file and writes no line, and the supervisor writes each receipt once from that directory, with the process in `data.gen`. A run whose ids directory the supervisor does not own keeps the process's receipt.
- A demo with a place of its own can pass `providers` when that place shares the run's one labeller: it hands each run process its host box as `HOST_BOX` (`{ provider, key, run }`), which the process claims first, and lets the supervisor read the run's files through two new optional `Place` members in disk's per-path shape, `readRunFile(path)` (`null` for a missing file) and `listRunFiles(dir)` (`[]` for a missing directory); any other failure throws. The supervisor reads the labels from `box-ids.internal/` and parses them itself, so the place's host boxes and the tools' boxes are `box-N` in one numbering across the run. At the final read a host box with no label refuses the recording, naming why (never claimed, unreadable, or not read inside the bound). A place without the reads keeps the supervisor's numbering and is still refused beside `providers`.

  Security: text a run produced leaves the harness only redacted. A run process's stderr and outcome message, a tool's output and a provider's error reached the result `demo()` returns, the `--json` output, the summary and any error `demo()` throws raw, with or without `--record`. Each now passes the new root export `processText(text, redact?)` (the run's tracked redaction when it records; in every mode, a line that still holds a credential's shape is withheld whole), and a result or ledger the new root export `handedOut(value, redact?)`. A run process's own error line keeps its redaction and adds the credential pass. A key split across lines, or encoded, is not caught.

  An error `demo()` throws is now a COPY of the error the run raised: a native error of the same class (its prototype, so `instanceof` holds, and a structured clone keeps its message and stack) with its message, stack, name and code, every value of its cause chain, an AggregateError's `errors` and its own enumerable properties redacted by the same pass. Its identity is not the original's, its non-enumerable and symbol properties are not carried, a value that is neither text, a number, a plain object, an array nor an error is withheld, and the names of what was withheld are in its `withheldProperties`.
- The web example records a run: with `RECORD_DIR` set, the agent app writes an agentrun.recording/1 directory with the harness recorder from inside the run (every document's lines, none dropped, pi's live events and the frames the frame store keeps), and start-run.mjs finishes it once the run has exited, with the agent's `report/index.html` as `manifest.artifact`. The Browserbase key and project id, the browser profile's id, live views and any URL parameter that carries a credential (its name with its value: `token`, `key`, `apiKey`, a signature) are `[redacted]`, email addresses a page printed are `[email]`, a session's id is a label of its hash, a document's `liveView` is null, and the machine is scrubbed; the run and the finish both scan for every id. A replay (`writeReplay`) takes the same browser ids, credential parameters, email addresses and live views out of its rows, text files and records, by the one set of rules both use (`agent/redact.ts`). The agent answers in the chat; the site-report skill writes report files (`report/index.html`, one script-free page) only when the person asks for a report, and the host writes `report/remember.html`, the recording's artifact entry (what the agent keeps: its signed-in sites, its memory files and its runs, never a ref). The agent keeps its memory as files in `work/memory/` (a memory skill: an index, the person's preferences, the accounts it works on); the host seeds the folder into each run and takes it back into the home from the run that owns the sign-in (a plain folder that does not travel in a pack yet), and GET /agent returns the files. With a local Chrome, each run's downloads land in its own `work/downloads/`. The harness entry exports `redactorOf`, `runScrub`, `scanSecretValues`, `scanPlaced` and the `Secret` type, so an example that records a run of its own uses the harness's redaction and scans. `AGENT_MODEL_API=anthropic-messages` runs an Anthropic model over the Messages API at the gateway's root, with pi-ai's own entry, so its thinking is recorded.
- A box label claimed in the run's box ids directory is now durable before it is used: after the winning `link(2)` of `box-N.json` (and of a host box's `host-<key>.json`), the harness fsyncs the ids directory itself, then hands the label out. A fix to merged behaviour: the linked file was fsynced but its directory entry was not, so a crash could keep a synced recording line naming `box-N` and lose `box-N.json`, and the next claim would take `box-N` again, two boxes with one label in one recording.
  The same holds for a label's receipt state (`open`, `ended`, `written`), rewritten by `rename(2)`: the directory is fsynced before the new state is relied on, so a crash can no longer bring back a state that says a written receipt is unwritten and have the same box's receipt written twice (a cost counted twice).
  The ids directory itself is durable in its parent when the ledger makes it (and in each made ancestor's parent), before the first label; and a label or key handed out AGAIN (a retry that finds the tools' entry, a restarted process's host label, a host key read back) is made durable before it is returned, as a new one is.
  A directory that cannot be fsynced refuses the claim by name (`cannot be made durable`): the label is never used, and the box is destroyed as for any label that cannot be kept.
- `cost()` rounds every figure once to 1e-8 dollars, so a sum of many small prices no longer carries float noise (a live run printed `$0.8724838500000002`) and sub-cent precision stays. The summary, `--json` and the manifest agree. The summary prints cents at or above one cent (`$0.87`) and two significant digits below it (`$0.0035`).
- `localPlace().release()` now stops any child it started that is still running (SIGKILL), and waits for it to exit. Before this, an attempt the supervisor gave up on left its child running. One example is an `--operator-kill` control that could not be removed. `demo()` then returned with an orphaned process that was still writing under the run's scratch directory, and removing that directory could fail with `ENOTEMPTY`.
