# Changelog

## [Unreleased]

## 0.1.0-beta.29 (2026-11-03)

- **The Codex adapter takes the host's skills, and its sessions no longer see Codex's bundled ones**
  - `codexAdapter({ skills: [{ name, files }] })`: Codex lists each skill to the model by its name and description, and the model reads its `SKILL.md` and its other files with `read_skill_file`, the shared read-only host tool (Codex has no shell here). The skills are written into each session's `CODEX_HOME` at the start of every drive, where Codex lists a user's skills in a turn with its built-ins off; it lists none from a working directory's `.agents/skills` there. A host tool named `read_skill_file` is refused when the adapter has skills.
  - Codex's bundled skills (imagegen, openai-docs, skill-creator, skill-installer) are off in every Codex session, with skills or without (`[skills.bundled] enabled = false`). Before, Codex installed them at every start and listed them to the model, so a session was shown skills its host never gave it.
  - The skills are checked when the adapter is made, and a bad one throws before the binary is looked for. The check, `skillProblems`, and the skill's shape, `HostSkill`, are now in `@parcha/agentrun-kernel` beside `readSkillFileTool`. The Claude adapter's `skillProblems` and `ClaudeAgentSkill` are that check and shape, re-exported, so nothing changes for its users; the Codex adapter exports the same `skillProblems`.
  - The local Codex machine takes a seed of files for one of its private directories (`seed: { dir, files }`, each file's text by its relative path), written at acquire and again after every wipe. A path that is absolute, empty, climbs or starts with a dot, or a directory not the machine's own, is refused when the machine is made.
- The Codex adapter says what Codex 0.164.0 does to a tool's schema, so no difference is silent. Codex sanitizes the schema its model is given: it strips bounds, patterns, formats, titles, defaults and a few annotations, and it drops or retypes a few shapes (a tuple `items`, `prefixItems`, `patternProperties`, `if`/`then`/`else`, `not`, a non-scalar or untyped non-string `enum`/`const`, `contains`, `dependentRequired`, `propertyNames`, a boolean `items`, constraints inside `allOf`). Checking a session now refuses each of those shapes by tool, JSON pointer and keyword, before anything is paid. For the stripped keywords, the tool's description lists them in plain words under one fixed heading, sorted by pointer, so the model still reads them; the host and the DSL keep checking against the original schema. The measurement is recorded for the public schema corpus and replayed offline.
- A Codex session can turn on Codex's own web search, live: `codexAdapter({ webSearch: "live" })` sets `web_search = "live"` in Codex's config, and the session's model proxy admits exactly the hosted `web_search` tool the pinned binary then sends (and a `tool_choice` naming it) and refuses any other web search tool; every other hosted tool is dropped or refused as before. Each search a response ran (its `tool_usage.web_search.num_requests`) is added to the response's price at OpenAI's $10 per 1,000 calls, so it counts in the session's cost and the host's budget; a model with no known search price, or a response that does not say how many searches it ran, is booked at an unknown cost. A request that offers web search has no input bound (a search's content is billed as input), so a cap that holds each request's worst case treats its input as unknown. Off by default, and off is unchanged. `CodexWebSearch` is the option's type.
- The harness packages are published from this release under their final names: `@parcha/agentrun-adapters` is `@parcha/agentrun-kernel`, `@parcha/agentrun-claude-agent` is `@parcha/agentrun-harness-claude`, `@parcha/agentrun-codex` is `@parcha/agentrun-harness-codex`. Their subpaths, directories, harness ids and `AGENTRUN_*` environment variables do not change.
  - Messages these packages raise start with `agentrun-kernel:`, `agentrun-harness-claude:`, `agentrun-harness-codex:`.
- New package `@parcha/agentrun-harness-codex`, held (not on npm yet): Codex as an AgentRun harness. `codexAdapter(options)` is an `AgentAdapter`, so `createHarnessRunner(codexAdapter(...), { store, tools })` runs a DSL `agent` node on Codex 0.164.0's app-server.
  - Codex's built-in tools are off. A classic model is offered exactly the host's tools and `submit`; a code-mode model is offered code mode's `exec` and `wait`, which reach the host's tools by their own names. A test runs the pinned binary against a scripted model that calls every built-in and checks that nothing runs, writes or spawns.
  - Codex's model traffic goes through a per-session proxy on the loopback interface that holds the provider key, forwards only `POST /v1/responses`, fixes the model, stores nothing at the provider, drops Codex's own web search and every tool that is not the session's (refusing any other provider-hosted tool), and asks the runner before every paid request.
  - The adapter checks the Codex binary it will run against the pins when it is made: the platform package's version, the binary's sha256 and the version it reports. A mismatch or a missing binary is a typed error. A relative `CODEX_BIN` is resolved from the host's working directory, and that absolute path is the one checked and run.
  - Codex runs in the session's own directories with an empty working directory and an allowlisted environment.
  - Sessions are durable in the store the host lends: a session a process died inside resumes from its records, and a `never` tool's cut-off call is reported, never repeated, and a call delivered twice runs its tool once.
- A turn that a halt ended with a reason now ends `failed`, naming it, never `interrupted` with the reason dropped: a harness's spend cap, its transcript mirror, a refused spawn. Only the session's own stop (its interrupt or its close, told apart by identity with the kernel's `SessionHalt`) and its host's stop end a turn `interrupted`. `abortedOutcome` decides it, and both adapters use it. This changes how spend-cap and mirror halts end a turn: a host that read `interrupted` for them now reads `failed` with the reason.
- A model that runs its tools in code mode, such as gpt-6-sol, now runs on the Codex adapter; it was refused before any request. The adapter no longer reads the binary's model catalog or refuses a code-mode model when a session is checked, and the proxy passes Codex's `exec` and `wait` (and drops the sub-agent and user-input tools listed beside them, and refuses a code-mode request that allows parallel tool calls). A host tool the script calls arrives as a nested call under an id of Codex's own, which no line of the session's log carries, so a `never` tool called that way was declined for good; it now runs once, as soon as the `exec` it runs under is in the log.
- After a crash, a host tool's call that was cut off is told to Codex by the replay policy the run's log recorded when it started, as the recovery note of the same turn tells it. Before, the output Codex got for a `safe` call said it may have taken effect, while the note said it was safe to repeat: the drive that opens after a crash marks a safe call for a retry, which the output's own rule did not count as interrupted.
- A Codex session no longer tells the model its files are read-only. Codex sent a `<permissions instructions>` developer message ("`sandbox_mode` is `read-only`: The sandbox only permits reading files") about its own sandbox, which binds only its built-in tools, and those are off. The host's tools write. A model that believed the message refused to write at all and ended its turn with no tool call. The adapter now sets `include_permissions_instructions = false`. Codex's sandbox itself stays read-only.
  - A model Codex's catalog marks multi-agent V2 (luna, sol) is no longer told it can spawn sub-agents. `multi_agent = false` turns off only V1, so Codex still built V2's collaboration tools, which the model proxy dropped, and sent `<multi_agent_role>` and `<multi_agent_mode>` messages describing them. The config now sets `[agents] enabled = false`, which turns off both versions.
  - `CODEX_INSTALL` is exported: the pinned install line (`npm install --save-exact @openai/codex@<version>`) that `CodexNotInstalled` names, so a host can print it without copying its format.
- Codex dies with the process that started it. The session machine starts Codex with a watch on its parent (the host's `parentWatched`, inside the host's confinement), so a host that is SIGKILLed and runs no close leaves no Codex behind, on a box with or without `setpriv`. A confinement prefix must exec Codex in place, as `setpriv` does: a wrapper that forks and stays as the parent defeats the watch.
- A call that Codex's rollout holds with no output now gets one from the log whenever a thread resumes, before any turn is sent, and not only under a recovery note. A turn that ended without answering a call (one interrupted mid-call, or settled instead of resumed) left it unanswered, and the next turn's history, with a call left open, was refused by the provider. A cut-off code-mode `exec` is answered first, as a custom tool output built from its nested calls. Every other call gets the generic output, of the kind the call asks for: a custom tool call such as Codex's own `apply_patch` gets a custom tool call output, and a host tool that happens to be named `exec` is answered as the function call it is. A `never` call the ended turn completed is answered as recorded only when a recovery note resumes that turn; a new turn that calls it again runs it. A `wait` of code mode that was waiting on a cell when the session stopped is told so, and that the cell's script was cut off, not that it never started.
- `codexAdapter` refuses a `webSearch` other than `"live"` with a `TypeError` that names the package as its other errors do, `agentrun-harness-codex: webSearch is "live" or absent`; it began `agentrun-codex:`, the package's name before the rename.
- Checking a harness's binary against its pins no longer reads the whole binary into memory, and runs once per binary in a process. `verifyCodexBinary` (the codex binary, 294 MiB) and `verifyClaudeAgentCli` (claude-agent's CLI, 231 MiB) each read the file whole to hash it, and agentrun-serve checked each again for every model it resolved: twice per harness in its start's probe, then once per save and once per run check, and a run's own process once more when it made its adapter. One start probe peaked at 395 MiB of memory, 675 MiB with a default model, past a 512 MiB container's limit. The hash now reads 1 MiB at a time, and a check that passed is kept for the process while the binary stays the same file (its path, device, inode, size, and modification and change times, with the pins); touched or replaced, it is checked again, and a failed check is never kept. The kernel's `@parcha/agentrun-kernel/host` exports both parts, `sha256OfFile` and `checkedOnce`.
- A claude-agent or codex run works in the run's workspace, the directory its file tools write to. Before, the CLI's working directory was an empty one beside it (`runs/<id>/harness/work`): Claude told its model that path, so a file written at its absolute path was refused as "outside the workspace", and the answer quoted the server's data directory. In QA this happened in 3 of 4 Claude runs that wrote a file.
  - `SessionIO.cwd`: a host may name the session's working directory, its workspace. The Claude and Codex adapters run their CLI there, and keep their own state in the session's private directory as before. git stops at the workspace's parent. serve passes the run's `work/`.
  - A file tool's refusal, an error such as ENOENT, and a write's or edit's result on claude-agent and codex name paths in the workspace relative to it (`notes/a.md`, `../escape.md: outside the workspace`), never by the server's data directory. A read's result is the file's own text and is not changed.
- The model proxy now tells the host, before a paid request is sent, the most input tokens it can be billed for. A spend cap could only count a request's cost once it was billed, so a single request whose input alone was over what was left of the cap was still sent and paid. `beforeRequest` now carries `inputTokensMax`: the UTF-8 bytes of the body exactly as it is sent, plus the input the provider adds that the body does not carry. A byte-level BPE token covers at least one byte, so this never undercounts the body, however dense its text. Each `inFlight` entry carries its own `inputTokensMax` until that request answers, so a cap can hold every open request at its own bound. When the provider's addition cannot be read, `inputTokensMax` is undefined, never 0, and a cap treats that input as unknown.
  - What a provider adds is in one place, `providerInputOverhead(api, shape)` from `@parcha/agentrun-kernel/host`. `api` is pi's API kind, and `shape` is whether the request has tools, its tool_choice and its image count. Each figure is the largest the provider documents for any current model:
    - `anthropic-messages`: the tool-use system prompt the Messages API adds to a body with tools, 675 tokens for tool_choice auto or none and 804 for any or tool, plus 4,784 tokens for each image, its high-resolution tier's maximum.
    - `openai-responses`, and the Azure and Codex Responses kinds: no prompt of their own, and 73,800 tokens for each image. That is 30,000 patches, the most an image may have, times 2.46, the largest model multiplier.
    - `openai-completions`, which OpenAI-compatible gateways speak too: nothing for its per-message formatting, since the body's bytes already bound it; 804 tokens when the request has tools, whatever its tool_choice, the largest Anthropic tool-use prompt, since a gateway may route to an Anthropic model; and 73,800 tokens for each image.
    - Every other API kind, among them pi's `mistral-conversations`, `bedrock-converse-stream`, `google-generative-ai`, `google-vertex` and `pi-messages`, and a faux `faux:<id>`: nothing for text, an assumed 2,048 tokens when the request has tools, and 73,800 tokens for each image. The tool allowance for these kinds is assumed, not documented; it is documented only for `anthropic-messages`, the OpenAI Responses kinds and `openai-completions`. `providerInputOverhead` never returns undefined: only a body that cannot be measured is unmeasured.
  - Images are billed by their area, not their bytes, so a small compressed image of large dimensions is counted at its maximum. A Codex body with a file input (a PDF, billed by its pages) is left unmeasured.
  - A provider policy says what its provider adds with `serverInputOverhead(body)`. The Claude and Codex policies read their body's shape and use the figures above.
  - The faux adapter in `@parcha/agentrun-kernel/testing` measures its prompt's UTF-8 bytes for each request, as a real adapter's proxy measures its body.
  - `inputTokensMaxOf(policy, body, sent)` is exported from `@parcha/agentrun-kernel/host`.
  - The proxy serializes the body once before admission and sends exactly what it measured. A body that cannot be serialized is refused before the runner is asked, so it is never booked.
