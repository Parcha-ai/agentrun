# Changelog

## [Unreleased]

- New package `@parcha/agentrun-learn`, held (not on npm yet): self-learning on any harness, as files. `SPEC.md` is the contract of an agent's own learning repository: `learnings/INDEX.md`, notes at `learnings/L-<12 hex>.md`, skills at `.agents/skills/<name>/SKILL.md`, workflow drafts at `workflows/<name>/workflow.json` with a `README.md`, and a memo per run at `memos/<run id>.md` on the run's own branch, `runs/<run id>`. It also sets the merge policy: what passes the checker, then an injection screen, then the review merges automatically, with a person's approval an option at the merge step.
  - `agentrun-learn check --base <ref> [--head <ref>] [--branch runs/<run id>] [--run-base <ref>] [--tools <file>]` validates a run's branch before any merge, in a plain checkout, a pre-push hook or CI; `checkBranch` and `checkRun` do the same from code. It is structural only, and reports `{ ok, problems }`.
  - It refuses locked paths in any spelling: `AGENTS.md`, `agent.json`, the loop's own `reflect` and `review` skills, `.agentrun/`, hooks (`.githooks/`, `.husky/`, the `core.hooksPath` folder), `.github/`, `package.json`, `SPEC.md`, and any path the host locks.
  - It reads git objects with plumbing only, so no hook, filter or driver of the repository runs. It refuses `.gitattributes`, `.gitmodules`, symlinks, gitlinks, executables, Git LFS pointers and any path outside the layout. pi-git-remote's hostile-repository corpus runs through it in the tests.
  - It checks the formats: the memo's front matter, which the host writes, with its `run` equal to the branch's and its `base` the commit the run started from (in full or 12 digits or more); the memo's sections; notes (a note the Pi learning loop wrote is valid); the index; and skills. It checks the caps (4096 bytes a note, 8 new notes a run, 4096 bytes for the index, 64 changed paths; over a cap is refused, never cut), and refuses characters a reader does not see (the Pi learning guard's rule), text shaped like a secret and the values of `--refuse-values-from-env NAME,...`. A refused value is never printed.
  - A workflow draft must pass the DSL's own `validateWorkflow`, with `executeCode: false` (a code node is syntax-checked and never run) and the host's tool list (`--tools`) as its `tools` option. With no list, a draft that names a tool is refused. A draft merges without a person, so a `code` node, or a `call` node via `shell` or `executor`, is refused at any depth: code nodes run in the host process unless the host isolates them, and no host on the open platform does today; allowing an isolating host later is a deliberate change.
  - A run's branch may carry its own `uses/<run id>.json`, the host's workflow-use receipts (JSON, at most 32768 bytes, never merged), and the memo's front matter may say `untrusted: true|false`. A branch that touches a workflow's records, `latest` or `trial.json`, which only the host writes on `main`, is refused (`host_owned`).
