# Changelog

## Unreleased

First release of `@parcha/pi-vision`, versioned with the other packages of the repository it is published from (the release PR dates this section and gives it the workspace version).

- The package's skeleton: every entry and module its interface declares; parts not built yet throw `NotBuiltError`.
- The model contract: `read`'s media arguments and the description hosts already ship, held string for string by a snapshot test; `withReadMedia(tool)`; the `look` tool's schema and description (registered by no adapter yet); the static section; the miss codes.
- The host contract's types: `VisionOptions`, `VisionHandle`, `Eyes`, `Limits`, `EvidenceSink` and `LookRecord` (pi-browser's sink shape), `ImageProcessor` and `PreparedImage` (pi-durable's), `Provider`, `SourceProvider`, `Part`, `Plan`, `Fit`, `LookEvent`, `MissEvent`; `VisionEnv`, a structural subset of pi-durable's `ExecutionEnv` that pi-durable's environments satisfy as they are.
- Budgets: the default profile and every budget as a named constant with its source; `resolveLimits(model, host)` reads a pi-ai model's `inputLimits` and combines them with a host's route limits.
- The planner: `plan(facts, selector, limits, mode)` turns a source into the parts to send, each with the fragment it covers and its pixel and byte budget, and states what it reduced (`as_is`, `downscaled`, `tiled`, `sampled`, `windowed`, `text_only`, `refused`) with the numbers. Pages render at `min(150, floor(72 * maxEdge / long edge in points))` dpi; a long image or page is cut into overlapping tiles of at most 1,568 px; nothing is shrunk under 1,200 px on its long edge, and what would be is refused with `over_budget` and the sizes. A look's requests (`lookRequests`) and its price before the first request (`priceLook`, refused over $0.25 unless the host sets its own cap) come from the plan.
- Fragments: `#page=3`, `#page=1-37`, `#t=60,90`, `#xywh=percent:x,y,w,h`, built and parsed.
- `./testing`: fake eyes (scripted answers, a ledger, a sentinel key), a fixture directory and a PNG writer, and the provider conformance suite with a fake provider that proves it.
- The leak check, in `./testing`: sentinels (a fake eyes key, and a signed link whose signature and token are each found alone), `LeakScan`, which searches results, details, receipts, derived names and bytes, memos and errors for them in every form a leak takes, and `limitViolations`, which holds a result's images to the route's limits the way the guard does (edges, bytes, count, a quarter of the request, a route that takes no images).
- Video: `probeVideo`, `videoFrames` (frames found by seek, never an fps filter over a long span), `videoClip` (a window by stream copy, else one re-encode at 1280 px and 6 frames a second, stopped at the inline budget: never the whole file), `videoAsIs` (a file within the inline budget, no program run), `videoWindow` and `describeVideo`, each returning its result or a typed miss; `ffmpegProvider()` runs ffmpeg and ffprobe through the environment, opens only local files in real video containers, and keeps nothing it derives. Without ffmpeg every operation but `videoAsIs` is a `needs` miss.
- `read`'s media half (`readMedia`): the kind from the file's first bytes, arguments checked and a strict route's zero values dropped (`withoutStrictDefaults`), each kind served by its reader, a document's text paged like a file, a recording read by handle through its source, and what cannot be done as a miss with a failed receipt; `readsAsText` for a host's read-only check. The guard (`guardResult`): every image block fitted to the lead's limits or withheld, never kept unfitted, then shown natively when the lead takes images (`Limits.image.native`: the model's own `input`, or the host's word) or answered by the eyes, the answer kept as the call's memo before the result, the blocks of one unit (`details.media.units`: an image's tiles, a read's pages, a video's frames) looked at together in requests of at most the eyes' images, unit ids that do not match the blocks dropped and said (`units_dropped`), every look filed (`receiptFacts`: `original`, `shown`, `shown_blocks`, `shown_bytes`, SHA-256, key, tokens, price). Eyes on pi-ai (`piAiEyes`): one request a look, thinking never off, cut at 120 s, usage and a price from the model's rates (null when it has none).
- The package's own readers (`PACKAGE_KINDS`), `read`'s default: an image fitted or tiled with the sentence that maps it back; a PDF's text with page marks and its scans named, or its pages rendered at the planner's dpi with their text layer beside them; office documents and spreadsheets read with nothing installed, saying what is not shown; a video as frames by seek, or for a lead that takes video the file or a window cut from it. The readers use the providers and the image processor the host passes, as passed; what none of them can do is a typed miss. A result's images in all are held to a quarter of the request (re-encoded smaller, else looked at by the eyes, else withheld), and the eyes are asked within their own image count and request bytes. A cause's first line (`linkSafe`) keeps only a link's origin and path, in a miss, a receipt, an event and a provider's detection.
- A look or a miss at an image the guard met names the tool the model called: `LookEvent.tool` and `MissEvent.tool` are a string, pi's call name through the pi-durable adapter and `CallContext.tool` for a caller of `fit` or `guardResult` (`callContext(api, context, tool)` sets it for a host's own tool), and `read` when a caller names none. With no path in the result, the event's `source` and the record's `args.path` are `a <tool> result`, and `a tool result` when no tool is named.
- `VisionOptions.scope` gets the host's conversation id as a string; the pi-durable adapter passes pi's own `ConversationId` second, which pi's documents and `harness.snapshot` take. In that adapter a `scope`, `eyes` or `limits` callback that throws gives a media `read` a `look_failed` miss that `onMiss` hears of, and a plain text file still reads; the guard still removes the images it could not check.
- A source `read` holds in memory reaches its reader from memory, and is written into the environment only when a program that names its path runs (poppler, ffmpeg), once a read: an environment that refuses writes still reads images, PDFs and office documents.
- The pi-durable adapter writes a result's blocks under both `output` (pi-durable 1.2) and `content` (1.0 and 1.1), and reads `output`, else `content`: on 1.2 a result with only `content` reaches the model empty, and the guard would never see another tool's images. `piResult` returns both keys.
- A cancelled read leaves nothing behind: its temp directory, and a derivation or a document's text it was putting in place, are removed with a context of their own, since pi's environments refuse every operation once the call's signal is aborted. Every cleanup in the package follows that rule.
- It depends on `unpdf`, `@hyzyla/pdfium`, `fflate` and `@xmldom/xmldom`. `@earendil-works/pi-durable` and `@earendil-works/chord` (1.0.4 to 1.2.x), `@earendil-works/pi-ai` (`*`: the host's copy, as Pi's package guidance asks of a package that imports it) and `@silvia-odwyer/photon-node` are optional peers. The package is developed on pi 1.1.0, and its suite also runs on pi 1.2.0 and on 1.0.4, each with one copy of every pi package. sharp is passed in by a host, never a dependency or a peer, so its LGPL code stays out of the package's dependency graph.
