## 0.1.0-beta.17 (2026-10-18)

- A look says when its model call began and which tool call it ran under, so a timeline can draw the call as a bar under that tool call. `LookEvent` and the record's `facts` gain `startedAt` (epoch milliseconds, taken when the request to the eyes, to Jev, to the speech model or to a recording's source began) and `parentToolCallId` (the id of the tool call the look ran under, from the new optional `CallContext.toolCallId`; it is `parentToolCallId` and not `toolCallId` because a tool's own events already carry `toolCallId` as their own call's id). The pi-durable adapter sets `CallContext.toolCallId` from pi's id for the tool call, so a look a script makes through `vision.see`, `vision.judge` or `vision.transcribe` is under the tool call that ran the script, and a look the guard makes is under the tool whose result held the image; a host with its own context sets it itself. A failed look carries both in `MissEvent.record`, a request that threw included. A look that made no request (a native look, an answer read back from a memo, a judgment Jev's port refused before it sent anything, such as a state over the host's limit, which now files a cost of 0 as any unsent look does) has no `startedAt`; a caller that names no tool call leaves `parentToolCallId` out; such a look files exactly as before. A receipt's header gains `startedAt` and `parentToolCallId` lines when a record has them.
- `MissEvent` carries the failed look's `record`: the `LookRecord` the guard, `read`, `vision.see`, `vision.judge` and `vision.transcribe` filed for it (`status` `failed`, a `body` that says why, `facts.key`, and in `facts` what the eyes charged: `cost_usd`, tokens, null when the price is unknown, absent when a request threw). A look the host's sink files nothing for, such as a screenshot no tool named, reached `onMiss` with `receipt: null` and nothing to file, so a failed look the eyes still charged for was missing from the host's looks and its cost. A host that keeps looks files the record like any other; a host that ignores it is unchanged. A miss made before any look (the host's own setup failing) has no record.
- The `transcribe` skill ships in the package (`skills/transcribe/SKILL.md`, beside `look` under `pi.skills`): strip a long video's audio once, cut it in ten-minute chunks, transcribe each in code mode with `vision.transcribe` (the host's speech-to-text model; its key and its price stay with the host), write one `transcript.tsv` of start, end and words in seconds of the whole video (each video in its own folder under `.hear`, emptied when a different recording takes its path), and search it with `rg` to cite `file#t=seconds`. Each chunk's rows are kept beside it, so a chunk is sent once and a run cut short pays for nothing twice; files are renamed into place only when complete (a failed write never is), a different `CHUNK` cuts the audio again and drops the old rows, and the transcript step stops at a chunk with no rows rather than leave a piece of the video out.
- The `verify` skill: whether a PDF has each mark a checklist names (a seal, a signature, a stamp, a number, two numbers that must agree), answered yes or no with the mark's box on its page, cited as `file.pdf#page=N&xywh=percent:x,y,w,h`. The checklist is a JSON file (the kinds of page, and per mark a short name, its question, its box and what it looks like when it is there), so another kind of document is another file, not other code. Two code-mode programs: every page rendered through its crop box (the page PDF.js and other viewers show, so a box in percent of the render is a box in percent of the page) and one `vision.judge` request a page for its kind and each mark's noul and box; then each mark kept from the page where Jev is surest, its box only when the noul says it is there, two marks that must agree cut out larger and asked side by side, and a yes-or-no table. No new function.
- A video read by a lead that takes images but not video now goes to eyes that take video as one clip with its sound (the file within the eyes' inline budget, or the `from_s..to_s` window), the same as for a lead that takes no images; the lead reads the eyes' answer in place of 8 frames. Frames stay for eyes that take no video and for a host with no eyes, and a lead that takes video still gets the video itself. For a host this is one eyes request per video read, filed and kept like any look: on a measured set it cost about $0.001 for an 8 s window, $0.005 for 60 s and $0.02 for 5 min at list price, where the lead's own 8 frames had cost $0.0002 to $0.006. When no such clip can be made, a file or window over the eyes' inline budget among them, this lead is shown its own 8 frames as before; a lead that takes no images still gets the `over_budget` miss that names a shorter window.
- The `find` skill finds a thing by Jev's noul alone (0.8 or more), and calls its box `loose` when Jev's confidence in the box is under 0.6 instead of failing the find: asked about the same frame for the same thing, Jev drew the same box each time with a confidence anywhere from 0.31 to 0.83, so a confidence bar failed a correct answer at random.

  A passing find whose box has no size (so no fragment) is cited at its second alone, with `noBox`. When a phrase is heard more than once, the skill picks the hit the question means by the rows before and after each hit and its place in the recording (each hit now carries `place`, percent of the way through), prefers the event itself over a recap, title, preview or replay, watches the candidates when the words cannot decide, and says which it picked and why.
- The `find` skill names each search by one word (letters, digits and dashes, like `.find/umbrella`), and its first step refuses any other name before it asks anything: the folder goes into every path and shell command as it is, so a name with spaces or quotes broke the paths the steps handed to `vision.judge`.
- A miss reason no longer carries the host's absolute paths. An error from the file system, a program, a provider or a model route names the directory the host ran in (`ENOENT: no such file or directory, lstat '/srv/run/work/shots/gone.png'`, `spawn /usr/local/bin/pdftotext ENOENT (cwd /srv/run/work)`), and that line reached the model, the filed record, the host's `onMiss` and the error `vision.see`, `vision.judge` and `vision.transcribe` throw, so a published recording held a machine's directories. `firstLine` and every miss now cut an absolute path (POSIX, drive-letter or `file:` URL) to its last part: `lstat 'gone.png'`, `spawn pdftotext ENOENT (cwd work)`. `nodeVisionEnv`'s own errors cut the paths they name (an error's `path` and `dest`) exactly, whatever the directories are called. A relative path, a link (cut to its origin and path as before) and the slashes of `and/or` or `3/4` are untouched. A bare request path such as `POST /v1/messages` in a provider's error is also cut to its last part.
- The PDF engines (pdf.js for text, PDFium for pages) now run in a child process of their own, with the same time, heap and pixel caps, no environment variables and no output. A file that made an engine run out of heap past the point where V8 can still stop a worker thread used to abort the whole host process; it now ends the child, and the call is an `over_budget` miss. A host that cannot start a child process gets a `needs` miss for the PDF engines.
- Every name the package exports has a doc comment: `createVisionExtension`, `piAiEyes`, `VisionOptions`, `VisionHandle`, `Provider`, `EyesAnswer`, `LookRecord`, `EvidenceSink`, `VisionEnv`, `MissCode`, the providers, the transcribers' option types, the test kit and the rest, 86 in all. An editor shows them on hover and the published declarations carry them. `test/api-docs.test.mjs` fails when an export of any entry has none, naming it.
- The README installs from npm with `@beta` and no longer tells a reader to build a tarball, says plainly that pi-vision is a pi-durable extension that needs a pi-durable host (a plain `pi install` loads only the skills, and the `vision.see` they call is not defined there), that it is ESM only and what it needs (Node 22.19, Photon for images, ffmpeg for video), and names pdf.js as what `unpdf` runs. Every code sample in it declares what it uses: the programs run and print what the README shows, and the host excerpts type-check, in `test/readme.test.mjs`; a code block added to the README is a failure there until the test names it. The stranger spec checks the README's install line.

## 0.1.0-beta.16 (2026-10-18)

- The `find` skill: when a phrase is said in a long video, and the second a thing is first seen and its box, for cents. A phrase comes from the `transcribe` skill's transcript alone: every time it is said, each with the rows around it, so the agent picks the one the question means and names the others. A thing that is seen is found coarse to fine: the transcript's words or chapter titles narrow the search to windows, `vision.judge` scores a frame every few seconds, the span is halved to a minute, `vision.see` watches that minute with its sound and names the second, and `vision.judge` checks that frame and the seconds either side and draws the box: `film.mp4#t=1024&xywh=percent:31,6,49,52`. Each step's price, when to stop (found, likely, not found, budget) and one code-mode program a step; no new function.
- `vision.judge`, a code-mode global beside `vision.see` (`handle.judge(env, call)`, described to the model by `VISION_JUDGE`): Jev answers typed questions about images in one request: `choice`, `noul`, `score` and `box`, with their probabilities or a box and its confidence. The images (paths read like `see`'s, or image blocks) go in `state.images` by reference, named by their fragments; `examples` are images the questions' instructions or criteria name by reference (classification by example); `state` adds fields of the script's own. A box answer also has `fragment`, its region as `#xywh=percent:` of its image, mapped back through the fit and through a crop's own region. Each judgment is kept before it is filed and told, on the conversation like `see`'s looks, so a call run again, or a new call after a cut one, pays and tells once, at the price the judge gives (an unknown one filed as unknown). A judgment that cannot be made is filed as the medium it was about, like `see`'s misses. A host passes Jev as `VisionOptions.jev`: `{ judge, model? }`, `judge` being what `@parcha/agentrun-jev`'s `createJevRunner` returns; pi-vision hands it each image as PNG or JPEG bytes and asks `jev-1.14.0` unless `jev.model` names another. `allow` is asked with `tool: "vision.judge"`.
  - `fitImage` takes a Jev-shaped profile: `minEdge` (a smaller image is grown, else padded, and `content` says where its pixels are; a tile under it is padded too), `formats` (the types kept as they are) and `baseline` (a progressive JPEG is re-encoded); a processor with only `prepare` is held to them too; `imageHeader` says when a JPEG is progressive. Jev's limits and model are `JEV_*` constants.
  - The `look` skill gains Jev patterns as code: classify every page or frame, Jev before and after the eyes, classify by example (words and an example together), presence and box, tiles then a box, and a box's edges checked. Its window cut adds `-fflags +bitexact`, so a WebM window cut again is the same bytes and its paid answer is found again.
- `vision.transcribe`, a code-mode global beside `vision.see` (`handle.transcribe(env, call)`, described to the model by `VISION_TRANSCRIBE`): one audio or video file in, its words with their start and end in seconds out, with the provider, the model, the price and the receipt. The host picks the speech-to-text model in `VisionOptions.transcriber` and holds its key; `@parcha/pi-vision/transcribers` builds fal's queue (`falTranscriber`, fal's own `Key` auth or a gateway's bearer key), ElevenLabs' (`elevenLabsTranscriber`, `scribe_v2`) and OpenAI's (`openAiTranscriber`, `whisper-1`), each answering in one word shape. A file over the provider's limit is an `over_budget` miss that names it, and never words without times: a model that answers with text alone (OpenAI's `gpt-4o-transcribe` models, refused before any request) is an `unsupported` miss. Each transcript is filed and told in a look's shape as tool `transcribe` (`LookRecord.tool` gains `"transcribe"`; its body the words as rows of start, end and words), priced per audio minute (unknown when no price is known, never $0), and kept, so asking again pays nothing.
  - The kinds gain `audio` (MP3, WAV, Ogg, FLAC, M4A, told by their bytes); `allow` is asked with `tool: "vision.transcribe"`.
  - `./testing` gains `fakeTranscriptionFetch` (each provider's documented request and answer) and `SENTINEL_TRANSCRIBER_KEY`.
- The `look` skill cuts a video window by encoding it without B-frames, not by stream copy, so its second 0 is the window's start for every decoder: a copy starts at the keyframe before the window, and a decoder that ignores the edit list counted its seconds from there. The bitexact flags still make the same window the same bytes, from an MP4 or a WebM. Its PDF pages render with `-cropbox`, the area a citation's `#xywh=percent:` is of, not the whole sheet with its margins.

## 0.1.0-beta.15 (2026-10-16)

- `read` of a video on a lead that takes no images, with eyes that take video, gives the eyes the file or the asked window as one clip within their inline budget. Before, the eyes got 8 frames by seek. Eyes that take no video still get frames, and a lead that takes images or video still sees the video itself as before.
  A window cut from a video keeps its sound: a stream copy keeps the audio track, and the one re-encode carries it as mono AAC at 48 kbit/s.
- A paid look is kept on the conversation, not only on the tool call that paid for it: the pi-durable adapter keeps a tool call's `vision:look:<key>` answers and `vision:told:<key>` marks in a conversation document (`vision.kept`), committed right after the answer, so a later call of the same conversation that asks the same finds it. On a host whose code-mode tool is not replay-safe, pi never runs a cut call again: a kill after the eyes answered and before the look was filed made the next script ask and pay again, and the first payment never reached the host. Now that call reads every answer back at $0, tells the host once of a look whose filing was cut, and again as kept of one it was already told. An answer or mark already kept on the call's task, where these memos lived before, is read from there and never paid for again, so a replay-safe call a crash cut before an upgrade still reads back what it paid for. A hook's memos (the guard's) stay on its task.
- A look that misses is filed as what it was about. A `vision.see` miss about one medium (a video over the eyes' budget, a video the eyes do not take, an image that will not fit, a path that does not read) names that medium as the agent named it, its kind, the SHA-256 of its bytes and the page or window its name cites. Before, the record had an empty path, kind `image` and the hash of no bytes. A miss before any medium is read names the request's media, kind `unknown` and no hash. A `read` miss of a page or a video window carries that page or window, as a look of it would.

## 0.1.0-beta.14 (2026-10-16)

- Breaking: `look` is not a tool, and its exports are removed (`LOOK_TOOL`, `ToolContract`, `JsonSchema`, `VisionHandle.tools`, `install.look`, and the caps `LOOK_PAGES_PER_CALL`, `LOOK_FRAMES_PER_CALL`, `LOOK_MAX_USD`, `LOOK_CONCURRENCY`); no version built `look`, so only a host that imported these names changes, and it passes its own caps where it wants one (`plan(facts, selector, limits, "ask", { pages, frames })`, `priceLook(..., capUsd)`), since there is none by default.
  - An agent looks at many pages, a long video or many images by writing code. `handle.see(env, call)` is `vision.see`, a global for a host's code-mode sandbox (`globals: [vision.see(api.env, await callContext(api, context))]` with pi-codemode), described to the model by `VISION_SEE`. It takes `{ ask, paths?, images?, fragments? }`, reads paths through the call's environment, fits each image to the eyes' limits, packs the images into as few requests as the eyes take (`packRequests`, which the guard uses too), and returns `{ text, model, costUsd, receipts, kept? }`: the text has one part a request when there are several, each headed by its fragments and receipt, and `receipts` holds one receipt a request, in order. Each request is a look filed and told once, its answer kept as the call's memo, so a call run again after a crash pays and tells once. A look that cannot be made throws `SeeMiss` with its miss code. `allow` is asked with `tool: "vision.see"`, and events name it.
  - The `look` skill ships in the package (`skills/look/SKILL.md`, declared under `pi.skills`): many PDF pages with pdftoppm, a long video by frames with ffmpeg, many images, a cropped region, and installing poppler or ffmpeg.
- Accept pi 1.3: the `@earendil-works/pi-durable` and `@earendil-works/chord` peer ranges now end below 1.4, with the floors unchanged (1.0.4, and 1.1.0 for `@parcha/pi-browser`). pi 1.3.0 pins its own packages to exact versions, so an install is all 1.2 or all 1.3; CI runs every package's whole suite on a 1.3.0 family as well as on 1.2.0.
  - On pi-ai 1.3, a tool call whose arguments are not a JSON object reaches no tool: pi-durable refuses it and shows the model the text it sent. A durable node's `submit` then spends none of its submissions. Before 1.3 the tool ran with `{}`, so `submit` answered with the schema's violations and counted one submission.
- A `vision.see` call that its code-mode script stopped (a deadline or an abort) files no miss and tells `onMiss` nothing: a path read that failed because the call was cancelled was filed as an `unreadable` miss of that file. The call now rejects with the stop's reason. The eyes request already stopped with the script, on pi-codemode 1.1, 1.2 and 1.3 alike: nothing is kept, filed or told for a request stopped before its answer, and the same call asked again pays once.

## 0.1.0-beta.13 (2026-10-14)

First release of `@parcha/pi-vision`, versioned with the other packages of the repository it is published from (the release PR dates this section and gives it the workspace version).

- The package's skeleton: every entry and module its interface declares; parts not built yet throw `NotBuiltError`.
- The model contract: `read`'s media arguments and the description hosts already ship, held string for string by a snapshot test; `withReadMedia(tool)`; the `look` tool's schema and description (registered by no adapter yet); the static section; the miss codes.
- The host contract's types: `VisionOptions`, `VisionHandle`, `Eyes`, `Limits`, `EvidenceSink` and `LookRecord` (pi-browser's sink shape), `ImageProcessor` and `PreparedImage` (pi-durable's), `Provider`, `SourceProvider`, `Part`, `Plan`, `Fit`, `LookEvent`, `MissEvent`; `VisionEnv`, a structural subset of pi-durable's `ExecutionEnv` that pi-durable's environments satisfy as they are.
- Budgets: the default profile and every budget as a named constant with its source; `resolveLimits(model, host)` reads a pi-ai model's `inputLimits` and combines them with a host's route limits.
- The planner: `plan(facts, selector, limits, mode)` turns a source into the parts to send, each with the fragment it covers and its pixel and byte budget, and states what it reduced (`as_is`, `downscaled`, `tiled`, `sampled`, `windowed`, `text_only`, `refused`) with the numbers. Pages render at `min(150, floor(72 * maxEdge / long edge in points))` dpi; a long image or page is cut into overlapping tiles of at most 1,568 px; nothing is shrunk under 1,200 px on its long edge, and what would be is refused with `over_budget` and the sizes. A look's requests (`lookRequests`) and its price before the first request (`priceLook`, refused over $0.25 unless the host sets its own cap) come from the plan.
- Fragments: `#page=3`, `#page=1-37`, `#t=60,90`, `#xywh=percent:x,y,w,h`, built and parsed.
- `./testing`: fake eyes (scripted answers, a ledger, a sentinel key), a fixture directory and a PNG writer, and the provider conformance suite with a fake provider that proves it.
- The leak check, in `./testing`: sentinels (a fake eyes key, and a signed link whose signature and token are each found alone), `LeakScan`, which searches results, details, receipts, derived names and bytes, memos and errors for them in every form a leak takes, and `limitViolations`, which holds a result's images to the route's limits the way the guard does (edges, bytes, count, a quarter of the request, a route that takes no images).
- Video: `probeVideo`, `videoFrames` (frames found by seek, never an fps filter over a long span), `videoClip` (a window by stream copy, else one re-encode at 1280 px and 6 frames a second, stopped at the inline budget: never the whole file), `videoAsIs` (a file within the inline budget, no program run), `videoWindow` and `describeVideo`, each returning its result or a typed miss; `ffmpegProvider()` runs ffmpeg and ffprobe through the environment, opens only local files in real video containers, and keeps nothing it derives. Without ffmpeg every operation but `videoAsIs` is a `needs` miss.
- `read`'s media half (`readMedia`): the kind from the file's first bytes, arguments checked and a strict route's zero values dropped (`withoutStrictDefaults`), each kind served by its reader, a document's text paged like a file, a recording read by handle through its source, and what cannot be done as a miss with a failed receipt; `readsAsText` for a host's read-only check. The guard (`guardResult`): every image block fitted to the lead's limits or withheld, never kept unfitted, then shown natively when the lead takes images (`Limits.image.native`: the model's own `input`, or the host's word) or answered by the eyes, the answer kept as the call's memo before the result, the blocks of one unit (`details.media.units`: an image's tiles, a read's pages, a video's frames) looked at together in requests of at most the eyes' images, unit ids that do not match the blocks dropped and said (`units_dropped`), every look filed (`receiptFacts`: `original`, `shown`, `shown_blocks`, `shown_bytes`, SHA-256, key, tokens, price). Eyes on pi-ai (`piAiEyes`): one request a look, thinking never off, cut at 120 s, usage and a price from the model's rates (null when it has none).
- The package's own readers (`PACKAGE_KINDS`), `read`'s default: an image fitted or tiled with the sentence that maps it back; a PDF's text with page marks and its scans named, or its pages rendered at the planner's dpi with their text layer beside them; office documents and spreadsheets read with nothing installed, saying what is not shown; a video as frames by seek, or for a lead that takes video the file or a window cut from it. The readers use the providers and the image processor the host passes, as passed; what none of them can do is a typed miss. A result's images in all are held to a quarter of the request (re-encoded smaller, else looked at by the eyes, else withheld), and the eyes are asked within their own image count and request bytes. A cause's first line (`linkSafe`) keeps only a link's origin and path, in a miss, a receipt, an event and a provider's detection.
- A look or a miss at an image the guard met names the tool the model called: `LookEvent.tool` and `MissEvent.tool` are a string, pi's call name through the pi-durable adapter and `CallContext.tool` for a caller of `fit` or `guardResult` (`callContext(api, context, tool)` sets it for a host's own tool), and `read` when a caller names none. With no path in the result, the event's `source` and the record's `args.path` are `a <tool> result`, and `a tool result` when no tool is named.
- `VisionOptions.scope` gets the host's conversation id as a string; the pi-durable adapter passes pi's own `ConversationId` second, which pi's documents and `harness.snapshot` take. In that adapter a `scope`, `eyes` or `limits` callback that throws gives a media `read` a `look_failed` miss that `onMiss` hears of, and a plain text file still reads; the guard still removes the images it could not check.
- A source `read` holds in memory reaches its reader from memory, and is written into the environment only when a program that names its path runs (poppler, ffmpeg), once a read: an environment that refuses writes still reads images, PDFs and office documents.
- The pi-durable adapter writes a result's blocks under both `output` (pi-durable 1.2) and `content` (1.0 and 1.1), and reads `output`, else `content`: on 1.2 a result with only `content` reaches the model empty, and the guard would never see another tool's images. `piResult` returns both keys.
- A cancelled read leaves nothing behind: its temp directory, and a derivation or a document's text it was putting in place, are removed with a context of their own, since pi's environments refuse every operation once the call's signal is aborted. Every cleanup in the package follows that rule.
- A tool call cut by a crash and run again no longer reports a look as paid twice, nor pays a recording's reviewer twice. A look whose answer is read back from the call's memo (`vision:look:<key>`, so this attempt asked nothing) has `LookRecord.facts.kept: true` and the receipt line `kept: true`, whether or not its host was told before. `LookEvent.kept` is `true` only when the host heard of the look in an earlier attempt (the guard keeps `vision:told:<key>` once the look is filed and `onLook` has returned, and nothing when `onLook` throws, so the pi-durable adapter now passes the host's `onLook` through as it is): do not charge it again. A look read back whose host was never told reaches `onLook` without `kept` and is charged once; a call cut after `onLook` returns and before that memo is kept reaches `onLook` again without `kept` (at least once). A recording read by handle keeps its source's answer the same way, so a rerun asks the reviewer once. The result's `usage` still carries every look once, since pi counts a result's usage only when it commits that result.
- It depends on `unpdf`, `@hyzyla/pdfium`, `fflate` and `@xmldom/xmldom`. `@earendil-works/pi-durable` and `@earendil-works/chord` (1.0.4 to 1.2.x), `@earendil-works/pi-ai` (`*`: the host's copy, as Pi's package guidance asks of a package that imports it) and `@silvia-odwyer/photon-node` are optional peers. The package is developed on pi 1.1.0, and its suite also runs on pi 1.2.0 and on 1.0.4, each with one copy of every pi package. sharp is passed in by a host, never a dependency or a peer, so its LGPL code stays out of the package's dependency graph.
- A failed look's record says what it cost, so one miss no longer makes a run's cost unknown. A miss filed before any request to a model (no eyes, eyes that take no images or no video, an image over a limit, every miss of `read`) has `cost_usd: 0`, `tokens_in: 0` and `tokens_out: 0`. Eyes that answered with no text file that answer's tokens and price, and a recording whose source answered with no text files that answer's price and `provider` (`kept: true` when it was read back). A request to the eyes, or a recording's source, that threw may have been billed: its record has no `cost_usd`.
- A live eyes check, `node packages/pi-vision/test/live/eyes.mjs`, runs the built package as a host composes it (`read` and `fit` from `./durable`, eyes from `./eyes/pi-ai`) against a real model: a scanned letter whose identifier the eyes must read exactly, page 2 of a two-page PDF read with `page`, and the receipts (each paid look priced with tokens, a miss with no eyes at $0). It runs on a maintainer's machine with a key, never in `npm test` or CI. `PI_VISION_LIVE_EYES` names the model as pi-ai's catalog does, the key is the variable pi-ai reads for the provider, and `PI_VISION_LIVE_BASE_URL` points it at a gateway. Its last line is `ok: pi-vision live eyes passed` or `not ok: <step>: <reason>`.
  - `npm test` and `npm run test:binaries` take `--concurrency N` (after `--`) or `TEST_CONCURRENCY=N` to cap how many test files run at once; the flag wins, a value that is not a positive integer exits 2 with the reason, and unset keeps Node's default.
