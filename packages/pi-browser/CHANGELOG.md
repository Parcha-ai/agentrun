# Changelog

## Unreleased

## 0.1.0-beta.24 (2026-10-22)

- `@parcha/pi-browser`: a new entry, `@parcha/pi-browser/providers/chrome-args`, exports `chromeArgs()` (the local Chrome's flags, with `--remote-allow-origins` narrowed to the one extension Origin) and `extensionOrigin()`, for a host that starts its own Chrome for Stagehand and should not copy the list. The README names the action-policy refusal under the pi coding agent.
- `@parcha/pi-browser`: a `web_fetch` backup's refusal (a private or local host, too many redirects, a redirect out of http(s), a page that is not text, one over 5 MiB) reaches the model as `refused`, not as a retryable `command_failed` that said "Try once more". A provider's 429 on a create or an attach is `rate_limited` on the browser plane, as it already was on the web plane (retryable when the call acted on nothing; an effectful call says to take a snapshot first). The coding agent refuses a whitespace-only Browserbase or Kernel key as `auth`, naming the key, as the providers read keys. The provider reset also lets go of profile writer claims, so a claim left before a reset no longer refuses a later session. `directFetch` is undici's fetch with no silent fallback to the proxied global fetch: a failed undici load is a broken install and now throws. The live-grid and ask-site examples (in the repository, not the npm package) keep a tile on the open page after a popup closes, run through a symlink, import cleanly from a script read through stdin, and work on an IPv6 host. The rest of the batch changes no behaviour: one way to build a refusal in core, `BrowserFailure` declares `next` and `evidence`, the failure classifier reads facts through one typed reader, the two hosts share their keep-for-a-person and redaction rules, and the extension worker, the sealed Stagehand's create-once-more step and the pi-durable adapter's internals are named, tested modules.
- `@parcha/pi-browser`: three security fixes. The local Chrome's DevTools socket accepts only the Stagehand extension's Origin, not every Origin: the provider launched Chrome with Stagehand's default `--remote-allow-origins=*`, and in a real Chrome for Testing 155 a web page in the run's own Chrome could open the browser-wide DevTools socket when given its URL. The provider now computes the one Origin the extension's service worker connects from (Chrome names an unpacked extension by the SHA-256 of its real path) and allows exactly it; a directory that cannot be resolved refuses the launch as `browser_unavailable` and never opens the socket to every Origin. The pi coding agent refuses to browse under a `deny` or `ask` action policy it cannot hold: it never opened the request observer that enforces that policy, so every request the page sent went out, irreversible ones included; every browser tool now answers `browser_unavailable` naming the action policy (`web_fetch` is unaffected, and `allow` browses as before). A navigation policy the provider cannot enforce refuses the session, naming `navigation.block` or `navigation.allow` and the provider: before, the local, Kernel and assigned providers accepted either and applied neither, and no provider enforces a block list; an allow list is enforced where the new optional `ProviderCaps.navigationAllow` is set (Browserbase). A live durable session reused later meets the same check as a new one at create: the session record keeps the allow list the provider applied at create, and a reused session that was started with no list, or a wider one than the policy now sets, is refused with the same named refusal (a record from before this change fails closed).

## 0.1.0-beta.23 (2026-10-22)

- `@parcha/pi-browser`: a Chrome that exits before it opens its debugging port now fails the create with the last ten lines it wrote to stderr (a partial first line dropped, each whole line redacted for the common key shapes and then shortened, control characters dropped). When the sandbox is on and Chrome aborted or named the sandbox, the failure is the typed `browser_unavailable` and says to set `sandbox: false` or `PI_BROWSER_NO_SANDBOX=1`; before, only a SIGABRT said so, and Debian's Chromium in a container exited 1 and gave only its exit code. Chrome's stderr is a file in the lease's private directory, emptied once the port is open and whenever it passes 256 KB. A tail window with no newline in it shows nothing, a Chrome a restarted host recovers through `attach` has its file bounded the same way, and a launch whose `spawn` throws closes the file and removes the lease's private directory instead of leaking both. The README's Quick start names the container setting and `--init`, documents the local Chrome's options including `sandbox`, and creates its session inside the `try`, so a failed create leaves no profile root; its pi range now reads 1.1 to 1.3. The pi coding agent's untyped tool errors reach the model redacted: a failure that was not a typed browser failure (a workspace read that fails before `browser_upload`'s own handling, for one) used to be rethrown with its raw message, so a registered key in it reached the model and the session file; every failure now comes back typed and redacted. A handoff gives the host the browsed page's URL with its query and fragment scrubbed and its title redacted, as `onSession` always did; the viewer's own URL stays whole there, since the host needs its token.
- `@parcha/pi-browser`: the README's Quick start names the container setting (`PI_BROWSER_NO_SANDBOX=1`, or `sandbox: false`, and `--init` so a killed Chrome is reaped), documents the local Chrome's options including `sandbox`, and creates its session inside the `try`, so a failed create leaves no profile root. The entries list names `/providers/assigned` and `/recorder`, and says the core loads the two HTML packages on demand. Doc comments in the source sit on the declaration they describe, and the live view's docs name both host channels that receive the viewer URL.
- `@parcha/pi-browser`: the README's Install block has a line for a pi-durable host that pins `@earendil-works/pi-durable`, `chord` and `pi-ai` to 1.3.0, and says pi 1.4 is not supported yet. pi 1.4.0 is npm's latest and the peer range stops below it, so the same names unpinned stop `npm install` with ERESOLVE. The first screen's pi range reads 1.1 to 1.3, the range of the peers.

## 0.1.0-beta.19 (2026-10-20)

- `@parcha/pi-browser`: a live view for the cdp provider, from the new `@parcha/pi-browser/live-view` export. `createLiveView` serves a viewer page and a loopback WebSocket for one person at a time: the first message must be the hello with the session's token, a wrong or missing token, a bad Origin or a second viewer is refused, the screencast frames are never written anywhere, the viewer says it is connecting and refuses input out loud until it is ready, and the view ends when the session is released. `liveViewProvider` wraps the cdp provider and reports the viewer's URL to `onSession` and nowhere else. While a person drives the viewer, every browser tool call (and `browser_release` and `browser_relaunch`) is refused with a typed, retryable `person_driving` before it does anything, the person's input is discarded while the agent acts (one shared gate per session, `drivingGates`), and an idle window never releases a session a person drives or watches. Custody can hold a session for a person behind a per-session fence: `CustodyPort` gains `current()`, a page action the fence stopped before any driver call got through is settled as not sent, and a held session the provider ended no longer holds up the conversation. `FrameRecorderOptions.hold` keeps a person-driven session out of the recording (one `frame.gap` marks the span), and when a hold lifts one frame is captured on demand so the replay does not end at the hold. `RunAction` types the actions of `run` per op. `browser_upload` runs behind a `WorkspaceFiles` port (it refuses swapped parents, pipes and host-private files, and is journaled like a run), `browser_downloads` works, and a `use_website` child is offered neither. A site child's browser can be the session the host reserved for it: the new `@parcha/pi-browser/providers/assigned` export never creates or ends a browser, takes its assigned session as the run's only browser, and is never relaunched or idled away. A screenshot's result carries the captured image's own facts in `details.media` (`kind`, `path`, `mime`, `bytes`, `width`, `height`, `ask`), and a screenshot can capture one region, by clip, snapshot id or CSS selector. The index exports custody's vocabulary, and a session's record and `relaunch`'s answer say the settings the provider applied. `browser_request_handoff` hands the browser to a person for a step only a human can do, such as a 2FA or a captcha, and waits durably for the host's answer. It is listed only when the host gives a `HandoffPort`, a rerun never asks again once the answer is kept, `done`, `cancelled` or `expired` give the session back under a new fence, and every other call answers `waiting_for_human` meanwhile. A refusal from the port, or a failure before it answers, gives the session straight back.
- `@parcha/pi-browser`: `use_website` children take turns when the provider in use shares one browser (a provider says so with the new `sharedBrowser` cap, which `cdpProvider` sets on an endpoint), and a durable child keeps its turn until it has read its report and released its browser. The first call after a release says so first and carries `previous_session`, and a read of a fresh `about:blank` browser says it is fresh instead of a wall. An attach waits for an init an earlier attach left running in Stagehand's extension, instead of failing with "Stagehand initialization is already in progress". A page snapshot or screenshot the browser never answers fails at its deadline as a dropped connection, and a read that hangs again after a working reconnect is told as a stuck page, with `browser_relaunch` as the way out. The coding agent returns the typed `person_driving` result for a refused release or relaunch. A saved lease's private TMPDIR is found after a provider restart. `copyProfile` no longer ends the host process when a file vanishes between its listing and its copy. A blank optional property means not given, not an intent to refuse; a screenshot's question travels with the capture; a classified failure names the browser provider, not Browserbase; a conversation's close evicts its repeat guard and idle entry; an upload that throws is named as the upload. A dropped session the provider still runs is reconnected within a bounded budget (90 s, tries at once, then after 1 s and 3 s, each attach cut at what is left of the budget), then released as lost and told to the next call, unless a person holds, drives or watches it; the answer is `browser_unavailable` with `next: browser_relaunch`, and `CustodyPort.session` takes an optional signal. A stuck-page answer carries the same `next`. A browser the store cannot record a release for is released at the provider anyway, and a close over a failed store releases every session the process still holds, so a failed commit on pi-durable 1.2 or later no longer leaks a paid browser. A cut page action's warning survives a crash between telling it and saving the answer that told it, and the journal keeps the cut a later run's entry replaces. An upload the page never answers fails at 60 s as `possibly_effected`, and its identical retry is refused until the agent looks at the page. `browser_read` gives the judge the page's frames (their origins and the text inside them), so a challenge in an iframe is a bot check and not an empty page. The run's registered values are redacted whole before any text is cut: failure details, the repeat guard's note, web failures, download reasons, and the page text, `find` question and chunks the judge reads. A host that passes no session price is metered at Browserbase's list price, and the session record's `spent` carries `source: "list"` so the host can mark the dollars as an estimate; an explicit price, even one equal to the list's, and a deliberate `null` are not changed. `browser_read` and `web_fetch` descriptions name the redaction marker without carrying the literal. An assigned-session provider shares its one-browser hold across every provider instance built over the same session, so a host that builds the provider per call still gets one browser and one release; a browser recovered after a lost create response is tracked before it is recorded, so a store that cannot record it still lets a close release it. After a person has driven the live view, the model's next call is told so, and the session's snapshot ids are dropped, so an old snapshot id fails as stale whatever the page's URL. A cut `browser_upload` is never judged safe to run again: after a crash its identical retry is refused as `effect_unknown` until a look, and the notice never says it is safe to run again.

## 0.1.0-beta.15 (2026-10-16)

- `@parcha/pi-browser`: a session can ask for a named saved profile. `SessionSpec` and `BrowserPolicy` take `profile: { name, save }`, `ProviderCaps` gains `profiles`, and the session record names the profile (the name only; older records read as none). The local Chrome (`cdp`) keeps a named profile in its own directory, and a session can work from a copy that is never saved; Kernel keeps one through its own profiles (created on first use, one saver per profile); Browserbase keeps one as a context made on first use and remembered by name. A provider that cannot keep a profile, a profile beside a context id and a bad name are refused with the typed envelope before any session or record is made. A host can pass an optional `crossing` callback that is called at the two page-action moments a kill sweep needs (after one page action's answer is committed and before the next is dispatched; after a page action's driver call returned and before its answer is committed). `use_website` calls in one turn now run at once, each child in its own browser. `browser_release` on a session that already ended, or is ending, answers `already_released: { reason, at }` and one sentence beside `released`, which keeps its meaning.
- `@parcha/pi-browser`: a `snapshot` or `browser_read` that lands in a document a navigation replaced waits for the new one and reads once more, instead of failing with Chrome's "Cannot find context with specified id". The held-runtime reset (Stagehand's extension) fails on a target list the browser never gives, instead of reading it as "nothing held", and closes its last wake page before the socket goes, so a runtime still held no longer refuses the next attach. `exportFrameTracks` bounds each blob read by the session's deadline and the abort signal.

## 0.1.0-beta.14 (2026-10-16)

- Accept pi 1.3: the `@earendil-works/pi-durable` and `@earendil-works/chord` peer ranges now end below 1.4, with the floors unchanged (1.0.4, and 1.1.0 for `@parcha/pi-browser`). pi 1.3.0 pins its own packages to exact versions, so an install is all 1.2 or all 1.3; CI runs every package's whole suite on a 1.3.0 family as well as on 1.2.0.
  - On pi-ai 1.3, a tool call whose arguments are not a JSON object reaches no tool: pi-durable refuses it and shows the model the text it sent. A durable node's `submit` then spends none of its submissions. Before 1.3 the tool ran with `{}`, so `submit` answered with the schema's violations and counted one submission.
- `@parcha/pi-browser/recorder`: `exportFrameTracks` turns the recorded frames into one `frame.track` line per session: a WebM (VP9, constant `fps`, default 10) plus an index that maps run time to video time across gaps, with a slate while a gap lasts. `handle.drain(harness, ctx, signal?)` on the pi-durable adapter's handle resolves once no browser release is still running, so a host waits for it before it closes the harness. The index exports custody's vocabulary by name (`CustodyPort`, `AttachedSession`, `ToolOutput`, `BrowserFailureError`, `BrowserDriver`, `DriverFactory`, `DriverOptions`, `Overrides`) so a host can write its own tool.
- `@parcha/pi-browser`: a `cdp` kill never signals pid 1, pid 0, its own pid, or a process group the pid does not lead. A session's record and `browser_relaunch`'s answer name only the settings the provider applied (Browserbase applies proxies, verified, geolocation, region and context; Kernel and local Chrome none). A screenshot's `ask` comes back in `details.media.ask`. A classified failure names the browser provider, not Browserbase. A conversation's close evicts its repeat guard and idle entry. A page action's journal entry outlives its answer, and an identical retry waits for a look. Stagehand's extension losing its own CDP connection is a dropped browser, not the model's code error: a read reconnects and runs once more, a run is not repeated. A held Stagehand runtime is freed through its own close and never by closing its service worker, which under load was sometimes never restarted. Every Chrome the `cdp` provider starts gets a temporary directory of its own, removed with the lease, so Chrome's leftover entries no longer land in the host's `TMPDIR`.

## 0.1.0-beta.13 (2026-10-14)

First release of `@parcha/pi-browser`. It is versioned with the other packages of the repository it is published from; the release PR dates this section and gives it the workspace version.

- A browser for pi agents: `snapshot`, `run`, `screenshot`, `browser_read`, `browser_relaunch`, `browser_release`, `web_fetch` and `web_search`, with session custody that survives a crash, evidence filed with its SHA-256, typed failures, and credentials kept out of anything a model, a document or a log can see.
- Entries: `.` (the host-neutral core), `./durable` (the pi-durable adapter), `./coding-agent` (the pi coding agent's extension, what `pi install` loads), `./providers/browserbase`, `./providers/kernel`, `./providers/cdp`, `./driver/stagehand`, and `./testing` (a fake provider and driver, public on purpose).
- It depends on Stagehand, undici, zod and two HTML packages. `@earendil-works/pi-coding-agent`, `@earendil-works/pi-durable`, `@earendil-works/chord` and `@browserbasehq/sdk` are optional peers.
- `examples/live-grid`: one pi agent fans a task out to up to ten child agents, each in its own browser, and a local page shows them all live (a CDP screencast of a local Chrome, or a cloud provider's live view). The Kernel provider now gives a live view, and `./coding-agent` exports `findChrome`.
- pi versions: the pi-durable adapter runs on pi-durable 1.1 and 1.2. pi-durable 1.2 reads a tool result's `output` and treats a result with only `content` as empty, so every durable tool result (browser, web and site tools) carries the model's text under both keys; the pi coding agent's results are `content` in every version and are unchanged. Peer ranges: `@earendil-works/pi-durable` and `chord` `>=1.1.0 <1.3.0` (1.0.4 cannot build the adapter: `use_website` reads a child's last report by scanning entries in descending order, which 1.1 added); `@earendil-works/pi-coding-agent` stays `*`, as pi's package guidance asks. A test on pi 1.2 checks that no tool result reaches the model without its text.
- `use_website` (listed when the host passes `sites`): a model hands a task to an agent that works one granted website in its own browser, through a `SiteRunPort`. Only the declared answer, a started run or a report, reaches the model. `localSites()` runs each task as a child agent: a pi session in the coding agent, a task-owned conversation in pi-durable, with the browser tools and never `use_website`, and its browser released when it reports. `examples/use-website` is a runnable demo.
- `@parcha/pi-browser/recorder`: `frameRecorder` screencasts each browser session over DevTools (a local Chrome, Browserbase and Kernel all speak it) and hands `agentrun.recording/1` `frame` and `frame.gap` lines, with their JPEGs, to a sink you pass. It is read-only beside the session's own connections and writes nothing itself. Capture is JPEG at quality 60, at most 800 px wide and 10 frames a second per session. A gap is written, never filled (`process_killed`, `session_released`, `credential_on_page`). No frame is kept while a credential or a one-time code is on the page, and a live-view URL is never recorded.
- `@parcha/pi-browser`: `web_fetch` percent-encodes the characters RFC 3986 refuses before the provider sees the URL, and the redactor scrubs a registered secret in every spelling `web_fetch` can give it, including the half-encoded `#` form and a trailing `%` the URL completes. A `cdp` release that cannot remove the session's profile directory tries again when files arrive in it (ENOTEMPTY), and when it still cannot it names every directory left behind. A `cdp` release whose lease names a browser it does not own leaves the profile a live Chrome still runs on. A browser released with its directory left behind is over: the coding agent never reuses it, and retries the directory removal as cleanup.
